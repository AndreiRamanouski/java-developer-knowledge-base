# Module Import Declarations (Java 25)

> **Applies to:** Java 25+ · **Last updated:** 2026-11-21

## Overview

> **Status:** Final in Java 25 ([JEP 511](https://openjdk.org/jeps/511)). Preview in Java 23 ([JEP 476](https://openjdk.org/jeps/476)) and Java 24 ([JEP 494](https://openjdk.org/jeps/494)).

`import module M;` imports, on demand, every public top-level type in every package that module `M` exports — plus the packages exported by modules that `M` requires transitively. It's a shorter way to say "give me the whole API of this library" without a wall of package imports.

You do **not** need to write a modular application to use it. Code on the class path can import modules too; the module just has to be resolvable (every JDK module is).

---

## 1. Basic Usage

```java
import module java.base;      // java.util, java.util.stream, java.time, java.io, java.nio.file, ...

public class Report {
    public static void main(String[] args) throws IOException {
        List<String> lines = Files.readAllLines(Path.of("orders.csv"));
        Map<String, Long> byCountry = lines.stream()
                .skip(1)
                .map(l -> l.split(",")[2])
                .collect(Collectors.groupingBy(c -> c, TreeMap::new, Collectors.counting()));
        System.out.println(LocalDate.now() + " " + byCountry);
    }
}
```

Without the module import, this file needs six separate imports (`java.util.*`, `java.util.stream.*`, `java.nio.file.*`, `java.io.*`, `java.time.*`…).

Useful modules to know:

| Import | Brings in |
|---|---|
| `import module java.base;` | The core API: `java.lang`, `java.util`, `java.util.concurrent`, `java.util.function`, `java.util.stream`, `java.io`, `java.nio.*`, `java.time`, `java.net`, `java.math`, … |
| `import module java.sql;` | `java.sql`, `javax.sql` — and, transitively, `java.logging`, `java.transaction.xa`, `java.xml` |
| `import module java.net.http;` | `java.net.http` (`HttpClient`, `HttpRequest`, …) |
| `import module java.se;` | The entire Java SE API (it `requires transitive` every SE module) |

Third-party modular JARs work the same way, as long as they are on the module path or are automatic modules.

## 2. Resolving Ambiguous Names

Two imported modules can export types with the same simple name. Using that name is then a compile error:

```java
import module java.base;   // exports java.util.Date
import module java.sql;    // exports java.sql.Date

class Audit {
    Date created;          // ✗ error: reference to Date is ambiguous
}
```

Resolve it with a more specific import. Shadowing rules, from strongest to weakest:

1. **Single-type import** — `import java.sql.Date;`
2. **Package on-demand import** — `import java.sql.*;`
3. **Module import** — `import module java.sql;`

```java
import module java.base;
import module java.sql;
import java.sql.Date;      // ✓ wins over both module imports

class Audit {
    Date created;          // java.sql.Date
    java.util.Date legacy; // fully qualified still works
}
```

## 3. Relationship to Compact Source Files

A compact source file (see [Compact source files](8.%20Compact%20source%20files%20and%20instance%20main%20methods%20(Java%2025).md)) behaves as if it starts with `import module java.base;`, so small programs and scripts need no imports at all.

---

## 4. Best Practices

- ✓ **Great for** scripts, prototypes, tests, teaching material and JShell sessions.
- ✓ **Fine in application code** for `java.base`, if your team agrees on it — it removes import churn.
- ⚠️ **Be careful with broad modules** (`java.se`, large libraries): more names in scope means more chances of ambiguity, and readers can't tell where a type comes from at a glance.
- ⚠️ **IDE "optimize imports"** settings may expand or collapse module imports. Agree on one style and set it in your formatter config.
- ⚠️ A module import makes the code depend on the module's *exports*. If a library later exports a new package containing a clashing simple name, your code can stop compiling until you add a single-type import.

---

## Summary

```java
import module java.base;           // whole core API
import module java.net.http;       // a specific JDK module
import java.sql.Date;              // single-type import breaks ties
```

- Imports all exported packages of a module (and of its `requires transitive` dependencies).
- Works for non-modular code on the class path.
- Ambiguities are compile errors; single-type and package imports shadow module imports.
