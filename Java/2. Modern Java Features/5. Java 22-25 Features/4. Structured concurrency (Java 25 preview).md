# Structured Concurrency (Java 21–25, Preview)

> **Applies to:** Java 25 (preview — needs --enable-preview) · **Last updated:** 2026-11-21

## Overview

> **Status:** Still a **preview** API in Java 25 ([JEP 505](https://openjdk.org/jeps/505), fifth preview). Earlier previews: Java 21 ([JEP 453](https://openjdk.org/jeps/453)), 22 ([JEP 462](https://openjdk.org/jeps/462)), 23 ([JEP 480](https://openjdk.org/jeps/480)) and 24 ([JEP 499](https://openjdk.org/jeps/499)). It was incubating in Java 19–20.
>
> **Java 25 redesigned the API.** `new StructuredTaskScope.ShutdownOnFailure()`, `ShutdownOnSuccess`, `throwIfFailed()`, `joinUntil()` and subclassing `StructuredTaskScope` are gone. You now open a scope with a static factory (`StructuredTaskScope.open(...)`) and choose its policy with a `Joiner`. All examples below use the Java 25 API. Preview APIs can change again, so check the JEP for the JDK you run.
>
> Compile and run with preview features enabled:
> ```bash
> javac --release 25 --enable-preview Main.java
> java --enable-preview Main
> ```

Structured concurrency treats a group of related tasks running in different threads as a single unit of work. A `StructuredTaskScope` is opened in a `try`-with-resources block, subtasks are *forked* inside it, and the owner thread *joins* them before leaving the block. Because subtasks can't outlive the block that created them, you get:

- **No thread leaks** — when the scope closes, every subtask has finished or been cancelled.
- **Cancellation that propagates** — when the policy decides the outcome is known (one subtask failed, or one succeeded), the scope cancels the rest by interrupting their threads.
- **Clear error handling** — `join()` either returns the outcome or throws one exception that wraps the subtask failure.
- **Observability** — thread dumps (`jcmd <pid> Thread.dump_to_file -format=json dump.json`) show subtasks grouped under the scope that owns them.

Subtasks run in virtual threads by default, and they inherit the `ScopedValue` bindings of the thread that opened the scope. This guide covers the problems with unstructured `ExecutorService` code, the Java 25 `StructuredTaskScope` API, the built-in joiners, error handling, timeouts, nesting and context propagation, practical patterns, and migrating from `ExecutorService`/`CompletableFuture`.

## 1. The Problem with Traditional Concurrency

### Why We Needed Structured Concurrency

```java
/**
 * THE PROBLEM WITH EXECUTORSERVICE
 * 
 * Traditional concurrent programming issues
 */

import java.util.concurrent.*;
import java.time.Duration;

public class TraditionalConcurrencyProblems {
    
    /**
     * Problem 1: Thread leaks
     */
    public static void threadLeaks() {
        ExecutorService executor = Executors.newCachedThreadPool();
        
        try {
            // Submit tasks
            Future<String> future1 = executor.submit(() -> {
                Thread.sleep(5000);  // Long-running
                return "Result 1";
            });
            
            Future<String> future2 = executor.submit(() -> {
                Thread.sleep(10000);  // Even longer
                return "Result 2";
            });
            
            // Get first result with timeout
            String result = future1.get(1, TimeUnit.SECONDS);
            System.out.println(result);
            
            // BUT: future2 still running!
            // Thread leak! Task outlives scope!
            
        } catch (Exception e) {
            // Exception occurred, but tasks still running!
            e.printStackTrace();
        } finally {
            executor.shutdown();
            // Tasks may still be running...
        }
        
        /**
         * PROBLEMS:
         * 
         * ✗ Tasks outlive their "parent"
         * ✗ Thread leaks
         * ✗ Resource waste
         * ✗ Hard to track lifetime
         * ✗ No automatic cleanup
         */
    }
    
    /**
     * Problem 2: Complex cancellation
     */
    public static void complexCancellation() {
        ExecutorService executor = Executors.newCachedThreadPool();
        
        try {
            Future<String> task1 = executor.submit(() -> slowOperation("Task 1"));
            Future<String> task2 = executor.submit(() -> slowOperation("Task 2"));
            Future<String> task3 = executor.submit(() -> slowOperation("Task 3"));
            
            // Wait for first to complete
            String result = task1.get();
            
            // Manually cancel others
            task2.cancel(true);  // Must remember to cancel!
            task3.cancel(true);  // What if we forget?
            
            return result;
            
        } catch (Exception e) {
            // Need to cancel all on error
            // But which ones are still running?
            // Complex error handling!
        } finally {
            executor.shutdown();
        }
        
        /**
         * PROBLEMS:
         * 
         * ✗ Manual cancellation required
         * ✗ Easy to forget
         * ✗ No automatic cleanup
         * ✗ Error-prone
         * ✗ Boilerplate code
         */
    }
    
    private static String slowOperation(String name) throws InterruptedException {
        Thread.sleep(5000);
        return name + " completed";
    }
    
    /**
     * Problem 3: Exception aggregation
     */
    public static void exceptionAggregation() {
        ExecutorService executor = Executors.newCachedThreadPool();
        
        try {
            Future<String> task1 = executor.submit(() -> {
                throw new RuntimeException("Task 1 failed");
            });
            
            Future<String> task2 = executor.submit(() -> {
                throw new RuntimeException("Task 2 failed");
            });
            
            Future<String> task3 = executor.submit(() -> {
                return "Task 3 ok";
            });
            
            // Collect results and exceptions
            try {
                task1.get();
            } catch (Exception e1) {
                // Got first exception
                try {
                    task2.get();
                } catch (Exception e2) {
                    // Got second exception
                    // How to aggregate them?
                    // Create custom exception with both?
                    // Just throw first? Lose information!
                }
            }
            
        } finally {
            executor.shutdown();
        }
        
        /**
         * PROBLEMS:
         * 
         * ✗ Manual exception collection
         * ✗ Easy to lose exceptions
         * ✗ No standard aggregation
         * ✗ Complex error handling
         * ✗ Verbose code
         */
    }
    
    /**
     * Problem 4: Context propagation
     */
    public static void contextPropagation() {
        ThreadLocal<String> context = new ThreadLocal<>();
        context.set("Important context");
        
        ExecutorService executor = Executors.newCachedThreadPool();
        
        try {
            Future<String> task = executor.submit(() -> {
                // Context NOT propagated!
                String ctx = context.get();  // null!
                return "Context: " + ctx;
            });
            
            System.out.println(task.get());  // "Context: null"
            
            /**
             * PROBLEM:
             * 
             * ✗ ThreadLocals not inherited
             * ✗ Security context lost
             * ✗ Tracing context lost
             * ✗ Manual propagation needed
             */
            
        } catch (Exception e) {
            e.printStackTrace();
        } finally {
            executor.shutdown();
        }
    }
    
    /**
     * Problem 5: Unclear lifecycle
     */
    public static void unclearLifecycle() {
        /**
         * LIFECYCLE CONFUSION:
         * 
         * When does a task finish?
         * - When Future.get() returns?
         * - When executor shuts down?
         * - When interrupt flag is set?
         * - When task actually stops?
         * 
         * What if task ignores interrupt?
         * What if task is stuck in native code?
         * What if exception is thrown?
         * 
         * No clear parent-child relationship!
         * Tasks are "fire and forget"
         * Hard to reason about lifetime
         */
    }
    
    /**
     * What we want
     */
    public static void whatWeWant() {
        /**
         * DESIRED PROPERTIES:
         * 
         * 1. Clear lifecycle:
         *    - Tasks have parent-child relationship
         *    - Child tasks cannot outlive parent
         *    - Automatic cleanup
         * 
         * 2. Automatic cancellation:
         *    - Cancel on first success (race)
         *    - Cancel on first failure (fail-fast)
         *    - Cancel on timeout
         * 
         * 3. Exception handling:
         *    - Automatic aggregation
         *    - No lost exceptions
         *    - Clear error reporting
         * 
         * 4. Context propagation:
         *    - ThreadLocals inherited
         *    - Security context maintained
         *    - Tracing context preserved
         * 
         * 5. Simplicity:
         *    - Less boilerplate
         *    - Obvious semantics
         *    - Hard to misuse
         * 
         * 
         * Structured Concurrency provides all of this!
         */
    }
    
    public static void main(String[] args) {
        System.out.println("=== Traditional Concurrency Problems ===");
        threadLeaks();
        contextPropagation();
    }
}
```

## 2. StructuredTaskScope Basics

### Open, fork, join, close

```java
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.StructuredTaskScope.Subtask;

public class BasicScope {

    record User(String id, String name) {}
    record Order(String id, double total) {}
    record Dashboard(User user, Order order) {}

    Dashboard loadDashboard(String userId) throws InterruptedException {
        // 1. OPEN: the default joiner waits for all subtasks to succeed
        //    and cancels the rest as soon as one fails.
        try (var scope = StructuredTaskScope.open()) {

            // 2. FORK: each subtask runs in its own virtual thread
            Subtask<User>  user  = scope.fork(() -> findUser(userId));
            Subtask<Order> order = scope.fork(() -> fetchLatestOrder(userId));

            // 3. JOIN: wait for the outcome. With the default joiner this
            //    throws StructuredTaskScope.FailedException if any subtask failed.
            scope.join();

            // 4. Results are only available after join()
            return new Dashboard(user.get(), order.get());
        } // 5. CLOSE: guarantees no subtask thread is still running
    }

    User findUser(String id) throws InterruptedException {
        Thread.sleep(100);
        return new User(id, "Alice");
    }

    Order fetchLatestOrder(String userId) throws InterruptedException {
        Thread.sleep(150);
        return new Order("o-42", 99.90);
    }
}
```

**Rules the API enforces:**

| Rule | What happens if you break it |
|---|---|
| Only the thread that opened the scope (the *owner*) may `fork`, `join` and `close` it | `WrongThreadException` |
| `join()` must be called before using results | `Subtask.get()` throws `IllegalStateException` |
| No `fork` after `join` | `IllegalStateException` |
| Scopes must be closed in the reverse order they were opened (`try`-with-resources does this for you) | `StructureViolationException` |

### The Subtask handle

`fork` returns a `Subtask<T>`, not a `Future`. It has no blocking `get()` — by the time you call `get()`, `join()` has already waited.

```java
try (var scope = StructuredTaskScope.open(StructuredTaskScope.Joiner.awaitAll())) {
    Subtask<Integer> task = scope.fork(() -> compute());

    scope.join();

    switch (task.state()) {
        case SUCCESS     -> System.out.println("Result: " + task.get());
        case FAILED      -> System.out.println("Failed: " + task.exception());
        case UNAVAILABLE -> System.out.println("Cancelled or not completed");
    }
}
```

- `state()` — `SUCCESS`, `FAILED` or `UNAVAILABLE` (cancelled, or not finished yet).
- `get()` — the result; throws `IllegalStateException` unless the state is `SUCCESS`.
- `exception()` — the exception; throws `IllegalStateException` unless the state is `FAILED`.

### Configuration: name, thread factory, timeout

The second argument of `open` is a function that adjusts the scope's configuration:

```java
import java.time.Duration;
import java.util.concurrent.StructuredTaskScope;
import java.util.concurrent.StructuredTaskScope.Joiner;

try (var scope = StructuredTaskScope.open(
        Joiner.<String>awaitAllSuccessfulOrThrow(),
        cf -> cf.withName("checkout")                   // shows up in thread dumps
                .withThreadFactory(Thread.ofVirtual().name("checkout-", 0).factory())
                .withTimeout(Duration.ofSeconds(2)))) { // deadline for join()
    // ...
}
```

## 3. Joiners: Choosing the Scope's Policy

A `Joiner` decides two things: **when to cancel the scope** (stop waiting and interrupt the remaining subtasks) and **what `join()` returns**. Java 25 ships five:

| Factory method | Cancels the scope when | `join()` returns | `join()` throws `FailedException` when |
|---|---|---|---|
| `awaitAllSuccessfulOrThrow()` *(default for `open()`)* | any subtask fails | `null` | any subtask failed |
| `allSuccessfulOrThrow()` | any subtask fails | `Stream<Subtask<T>>` of all subtasks | any subtask failed |
| `anySuccessfulResultOrThrow()` | any subtask succeeds | the first successful result `T` | every subtask failed |
| `awaitAll()` | never | `null` | never — inspect each `Subtask` |
| `allUntil(Predicate<Subtask>)` | the predicate returns `true` for a completed subtask | `Stream<Subtask<T>>` of all subtasks | never |

### Fail fast: all must succeed (replaces `ShutdownOnFailure`)

```java
List<Product> loadProducts(List<String> ids) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(Joiner.<Product>allSuccessfulOrThrow())) {
        ids.forEach(id -> scope.fork(() -> productService.load(id)));

        return scope.join()          // Stream<Subtask<Product>>
                    .map(Subtask::get)
                    .toList();
    }
    // If any load() throws, the other loads are interrupted and join()
    // throws StructuredTaskScope.FailedException with that exception as the cause.
}
```

### First success wins (replaces `ShutdownOnSuccess`)

```java
String fetchFromFastestMirror(List<URI> mirrors) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(Joiner.<String>anySuccessfulResultOrThrow())) {
        for (URI mirror : mirrors) {
            scope.fork(() -> download(mirror));
        }
        return scope.join();   // first successful download; the others are cancelled
    }
}
```

### Wait for everything, decide yourself

```java
record Health(String service, boolean up) {}

List<Health> checkAll(List<String> services) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(Joiner.<Boolean>awaitAll())) {
        Map<String, Subtask<Boolean>> checks = new LinkedHashMap<>();
        for (String s : services) {
            checks.put(s, scope.fork(() -> ping(s)));
        }

        scope.join();   // never throws FailedException with awaitAll()

        return checks.entrySet().stream()
                .map(e -> new Health(e.getKey(),
                        e.getValue().state() == Subtask.State.SUCCESS && e.getValue().get()))
                .toList();
    }
}
```

### Custom joiner

Implement `Joiner<T, R>`. `onComplete` is called from the subtask threads, possibly at the same time, so the joiner must be thread-safe. Return `true` from `onFork`/`onComplete` to cancel the scope.

```java
/** Collects every result and every failure; never cancels. */
class CollectingJoiner<T> implements StructuredTaskScope.Joiner<T, CollectingJoiner.Outcome<T>> {

    record Outcome<T>(List<T> results, List<Throwable> failures) {}

    private final Queue<T> results = new ConcurrentLinkedQueue<>();
    private final Queue<Throwable> failures = new ConcurrentLinkedQueue<>();

    @Override
    public boolean onComplete(Subtask<? extends T> subtask) {
        switch (subtask.state()) {
            case SUCCESS -> results.add(subtask.get());
            case FAILED  -> failures.add(subtask.exception());
            case UNAVAILABLE -> { }
        }
        return false;  // keep going
    }

    @Override
    public Outcome<T> result() {
        return new Outcome<>(List.copyOf(results), List.copyOf(failures));
    }
}

// Usage
try (var scope = StructuredTaskScope.open(new CollectingJoiner<Invoice>())) {
    batch.forEach(inv -> scope.fork(() -> send(inv)));
    var outcome = scope.join();
    log.info("sent={}, failed={}", outcome.results().size(), outcome.failures().size());
}
```

A joiner that stops after *N* successes (e.g. "any 2 of 3 replicas agree") is the same shape: count successes in `onComplete` with an `AtomicInteger` and return `true` once the count reaches *N*.

## 4. Exception Handling

### What `join()` throws

| Exception | Meaning |
|---|---|
| `InterruptedException` | The owner thread was interrupted while waiting. The scope is cancelled. |
| `StructuredTaskScope.FailedException` (unchecked) | The joiner's policy failed — e.g. a subtask failed under `awaitAllSuccessfulOrThrow()`. `getCause()` is the subtask's exception. |
| `StructuredTaskScope.TimeoutException` (unchecked) | The configured timeout expired before the outcome was known. The scope is cancelled. |

### Unwrapping the cause

```java
OrderView loadOrder(String orderId) throws InterruptedException {
    try (var scope = StructuredTaskScope.open()) {
        var order    = scope.fork(() -> orders.find(orderId));
        var shipping = scope.fork(() -> shippingClient.status(orderId));

        scope.join();
        return new OrderView(order.get(), shipping.get());

    } catch (StructuredTaskScope.FailedException e) {
        // Translate the subtask's exception into your domain exception
        switch (e.getCause()) {
            case NotFoundException nf -> throw new OrderNotFoundException(orderId, nf);
            case IOException io       -> throw new DownstreamUnavailableException(io);
            case Throwable t          -> throw new IllegalStateException("Unexpected failure", t);
        }
    }
}
```

### Partial results instead of failure

When some subtasks are optional, use `awaitAll()` and look at each `Subtask`:

```java
ProductPage loadPage(String sku) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(Joiner.awaitAll())) {
        var product         = scope.fork(() -> catalog.load(sku));          // required
        var reviews         = scope.fork(() -> reviewService.top(sku));     // optional
        var recommendations = scope.fork(() -> recommender.similar(sku));   // optional

        scope.join();

        if (product.state() != Subtask.State.SUCCESS) {
            throw new ProductUnavailableException(sku, product.exception());
        }
        return new ProductPage(
                product.get(),
                reviews.state() == Subtask.State.SUCCESS ? reviews.get() : List.of(),
                recommendations.state() == Subtask.State.SUCCESS ? recommendations.get() : List.of());
    }
}
```

### Subtasks must respond to interruption

Cancellation works by **interrupting** subtask threads. Blocking JDK calls (`Thread.sleep`, socket and file channel I/O, `BlockingQueue.take`, `Future.get`, `HttpClient.send`) respond to interruption. A tight CPU loop doesn't — check `Thread.currentThread().isInterrupted()` in long computations. `close()` waits for every subtask thread to finish, so a subtask that ignores interruption delays the owner.

⚠️ Don't catch `InterruptedException` inside a subtask and carry on as if nothing happened. Either let it propagate or restore the flag with `Thread.currentThread().interrupt()`.

## 5. Timeouts, Nesting and Context Propagation

### Timeouts (replaces `joinUntil`)

```java
Quote bestQuote(List<QuoteProvider> providers) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(
            Joiner.<Quote>anySuccessfulResultOrThrow(),
            cf -> cf.withTimeout(Duration.ofMillis(800)))) {

        providers.forEach(p -> scope.fork(() -> p.quote()));
        return scope.join();

    } catch (StructuredTaskScope.TimeoutException e) {
        return Quote.fallback();   // all remaining subtasks were cancelled
    }
}
```

### Nested scopes form a tree

A subtask can open its own scope. Cancelling the outer scope interrupts the subtask, and that interrupt cancels the inner scope as well — the whole tree shuts down.

```java
Report buildReport(String customerId) throws InterruptedException {
    try (var outer = StructuredTaskScope.open()) {
        var profile = outer.fork(() -> loadProfile(customerId));
        var history = outer.fork(() -> {
            // Inner scope, owned by this subtask's thread
            try (var inner = StructuredTaskScope.open(Joiner.<Order>allSuccessfulOrThrow())) {
                for (String region : REGIONS) {
                    inner.fork(() -> orderArchive.load(customerId, region));
                }
                return inner.join().map(Subtask::get).toList();
            }
        });

        outer.join();
        return new Report(profile.get(), history.get());
    }
}
```

### ScopedValue inheritance

Subtasks automatically see the `ScopedValue` bindings that were in effect when the scope was **opened**. This is the only way bindings cross into other threads automatically. See [Scoped values](6.%20Scoped%20values%20(Java%2025).md).

```java
static final ScopedValue<String> REQUEST_ID = ScopedValue.newInstance();

void handle(Request req) throws Exception {
    ScopedValue.where(REQUEST_ID, req.id()).call(() -> {
        try (var scope = StructuredTaskScope.open()) {
            scope.fork(() -> audit());        // REQUEST_ID.get() works here
            scope.fork(() -> notifyUser());   // ...and here
            scope.join();
        }
        return null;
    });
}
```

⚠️ If you rebind a scoped value *after* opening the scope and then call `fork`, `fork` throws `StructureViolationException`. Bind first, then open the scope.

`ThreadLocal`s are **not** inherited by subtasks (unless they're `InheritableThreadLocal`s, which are copied as usual).

## 6. Real-World Patterns

### Fan-out to downstream services in a Spring controller

```java
@RestController
class CustomerController {

    private final ProfileClient profiles;
    private final OrdersClient orders;
    private final LoyaltyClient loyalty;

    CustomerController(ProfileClient profiles, OrdersClient orders, LoyaltyClient loyalty) {
        this.profiles = profiles;
        this.orders = orders;
        this.loyalty = loyalty;
    }

    @GetMapping("/customers/{id}/overview")
    CustomerOverview overview(@PathVariable String id) throws InterruptedException {
        try (var scope = StructuredTaskScope.open(
                Joiner.<Object>awaitAllSuccessfulOrThrow(),
                cf -> cf.withTimeout(Duration.ofSeconds(2)))) {

            var profile = scope.fork(() -> profiles.get(id));
            var recent  = scope.fork(() -> orders.recent(id, 5));
            var points  = scope.fork(() -> loyalty.points(id));

            scope.join();
            return new CustomerOverview(profile.get(), recent.get(), points.get());
        }
    }
}
```

With `spring.threads.virtual.enabled=true` (Spring Boot 3.2+), the request thread itself is virtual, so blocking in `join()` is cheap. Remember the preview flag: add `--enable-preview` to the compiler arguments and the JVM arguments.

### Hedged requests

Send a request to a replica; if it hasn't answered within a short delay, also send it to a second replica, and take whichever answers first.

```java
Response hedged(Request req) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(Joiner.<Response>anySuccessfulResultOrThrow())) {
        scope.fork(() -> primary.call(req));
        scope.fork(() -> {
            Thread.sleep(50);            // hedge delay; cancelled if primary wins first
            return secondary.call(req);
        });
        return scope.join();
    }
}
```

### Bounded parallelism

A scope doesn't limit concurrency by itself. To protect a downstream system, use a `Semaphore` inside the subtasks:

```java
private final Semaphore permits = new Semaphore(20);

List<Result> processAll(List<Item> items) throws InterruptedException {
    try (var scope = StructuredTaskScope.open(Joiner.<Result>allSuccessfulOrThrow())) {
        for (Item item : items) {
            scope.fork(() -> {
                permits.acquire();
                try {
                    return process(item);
                } finally {
                    permits.release();
                }
            });
        }
        return scope.join().map(Subtask::get).toList();
    }
}
```

For streams of work, `Gatherers.mapConcurrent(maxConcurrency, fn)` (Java 24+) is a final, non-preview alternative.

## 7. vs ExecutorService and CompletableFuture

```java
// ExecutorService: tasks can outlive the method, and cancellation is manual
Dashboard withExecutor(String userId) throws Exception {
    try (ExecutorService executor = Executors.newVirtualThreadPerTaskExecutor()) {
        Future<User>  user  = executor.submit(() -> findUser(userId));
        Future<Order> order = executor.submit(() -> fetchLatestOrder(userId));
        // If user.get() throws, order keeps running until close() waits for it,
        // and nothing interrupts it for you.
        return new Dashboard(user.get(), order.get());
    }
}

// StructuredTaskScope: a failure cancels the sibling immediately
Dashboard withScope(String userId) throws InterruptedException {
    try (var scope = StructuredTaskScope.open()) {
        var user  = scope.fork(() -> findUser(userId));
        var order = scope.fork(() -> fetchLatestOrder(userId));
        scope.join();
        return new Dashboard(user.get(), order.get());
    }
}
```

| | `ExecutorService` | `CompletableFuture` | `StructuredTaskScope` |
|---|---|---|---|
| Task lifetime bound to a code block | No | No | **Yes** |
| Cancel siblings on failure | Manual | Manual (`cancel` doesn't interrupt) | **Automatic** |
| Error handling | `ExecutionException` per future | Callbacks, `CompletionException` | One `join()` outcome |
| Thread model | Any pool | Pool (common pool by default) | Virtual thread per subtask |
| `ScopedValue` inheritance | No | No | **Yes** |
| Status | Final | Final | **Preview** (Java 25) |

**When to use which:**
- **StructuredTaskScope** — request-scoped fan-out/fan-in where all subtasks belong to one operation, and preview APIs are acceptable in your build.
- **ExecutorService** — long-lived background work, queues of jobs, or when you can't enable preview features.
- **CompletableFuture** — non-blocking pipelines that compose callbacks, or existing async APIs that return futures.

### Migrating from the Java 21–24 preview API

| Java 21–24 preview | Java 25 |
|---|---|
| `new StructuredTaskScope.ShutdownOnFailure()` | `StructuredTaskScope.open()` |
| `new StructuredTaskScope.ShutdownOnSuccess<T>()` | `StructuredTaskScope.open(Joiner.anySuccessfulResultOrThrow())` |
| `new StructuredTaskScope<T>()` | `StructuredTaskScope.open(Joiner.awaitAll())` |
| `scope.join(); scope.throwIfFailed();` | `scope.join();` (throws `FailedException`) |
| `scope.result()` | return value of `scope.join()` |
| `scope.joinUntil(deadline)` | `open(joiner, cf -> cf.withTimeout(duration))` |
| `extends StructuredTaskScope<T>` + `handleComplete` | `implements Joiner<T, R>` + `onComplete` |
| `scope.shutdown()` | return `true` from `Joiner.onComplete` / `onFork` |

## Summary

### Quick Reference

```java
// All must succeed (default)
try (var scope = StructuredTaskScope.open()) {
    var a = scope.fork(() -> callA());
    var b = scope.fork(() -> callB());
    scope.join();                         // throws FailedException on failure
    return combine(a.get(), b.get());
}

// First success wins
try (var scope = StructuredTaskScope.open(Joiner.<String>anySuccessfulResultOrThrow())) {
    sources.forEach(s -> scope.fork(() -> s.fetch()));
    return scope.join();
}

// With a timeout
try (var scope = StructuredTaskScope.open(Joiner.awaitAllSuccessfulOrThrow(),
                                          cf -> cf.withTimeout(Duration.ofSeconds(1)))) {
    // ... throws StructuredTaskScope.TimeoutException on expiry
}
```

**Key points:**

- **Preview in Java 25** — needs `--enable-preview`, and the API may change again.
- **Lifetime** — subtasks never outlive the `try` block that forked them.
- **Policy lives in the `Joiner`** — pick a built-in one or implement `onComplete` + `result`.
- **Cancellation = interruption** — write subtasks that respond to interrupts.
- **Context** — `ScopedValue` bindings flow into subtasks; `ThreadLocal`s don't.
