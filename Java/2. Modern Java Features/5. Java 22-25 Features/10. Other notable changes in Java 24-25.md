## 1. Virtual Threads No Longer Pin on `synchronized` (Java 24)

[JEP 491](https://openjdk.org/jeps/491). Before Java 24, a virtual thread that blocked inside a `synchronized` block or method stayed *pinned* to its carrier (platform) thread, which could starve the scheduler. The usual advice was "replace `synchronized` with `ReentrantLock` in code that runs on virtual threads".

From Java 24 on, virtual threads can unmount while holding or waiting for a monitor. **That advice no longer applies** — upgrading the JDK fixes most pinning without code changes. Pinning still happens when a virtual thread blocks inside native code or a foreign function call.

## 2. Startup and Warm-up: Ahead-of-Time Cache (Java 24–25)

Project Leyden's first deliverables, useful for Spring Boot services that need to start fast:

- [JEP 483](https://openjdk.org/jeps/483) (Java 24) — **AOT class loading & linking**: a training run records which classes are loaded and linked; later runs load them from a cache.
- [JEP 514](https://openjdk.org/jeps/514) (Java 25) — **one-step workflow**: `-XX:AOTCacheOutput=app.aot` trains and creates the cache in a single run.
- [JEP 515](https://openjdk.org/jeps/515) (Java 25) — **AOT method profiling**: the cache also stores method profiles, so the JIT warms up sooner.

```bash
# Training run: exercise the app (e.g. run a smoke test), then stop it
java -XX:AOTCacheOutput=app.aot -jar app.jar

# Production runs
java -XX:AOTCache=app.aot -jar app.jar
```

Unlike GraalVM native images, this keeps the normal JVM, so there are no reflection or dynamic-proxy restrictions.

## 3. Memory and Garbage Collection

| Change | Release | Notes |
|---|---|---|
| **Compact object headers** ([JEP 519](https://openjdk.org/jeps/519)) | 25 (product feature; experimental in 24 via [JEP 450](https://openjdk.org/jeps/450)) | Object headers shrink from 12 to 8 bytes on 64-bit JVMs, which cuts heap use for workloads with many small objects. Opt in with `-XX:+UseCompactObjectHeaders`. |
| **Generational Shenandoah** ([JEP 521](https://openjdk.org/jeps/521)) | 25 (product; experimental in 24) | `-XX:+UseShenandoahGC -XX:ShenandoahGCMode=generational` |
| **ZGC non-generational mode removed** ([JEP 490](https://openjdk.org/jeps/490)) | 24 | `-XX:+UseZGC` is always generational; `-XX:-ZGenerational` is obsolete. |

## 4. Security

- **Security Manager permanently disabled** ([JEP 486](https://openjdk.org/jeps/486), Java 24). `-Djava.security.manager=allow` no longer enables it, and `System.setSecurityManager` throws `UnsupportedOperationException`. See [Java Security Manager](../../3.%20Enterprise%20Java/5.%20Java%20Cryptography%20Architecture/4.%20Java%20Security%20Manager%20(deprecated%20but%20important).md).
- **Post-quantum cryptography** (Java 24): ML-KEM key encapsulation ([JEP 496](https://openjdk.org/jeps/496)) and ML-DSA signatures ([JEP 497](https://openjdk.org/jeps/497)).
- **Key Derivation Function API** ([JEP 510](https://openjdk.org/jeps/510), final in Java 25): `javax.crypto.KDF`, with HKDF built in.
- **PEM encodings of keys and certificates** ([JEP 470](https://openjdk.org/jeps/470)): preview in Java 25.

## 5. Integrity by Default: Warnings You May See

- **Restricted JNI** ([JEP 472](https://openjdk.org/jeps/472), Java 24) — loading native libraries through JNI prints a warning unless you pass `--enable-native-access=ALL-UNNAMED` (or a module name). This matches the existing rule for the FFM API.
- **`sun.misc.Unsafe` memory access** ([JEP 498](https://openjdk.org/jeps/498), Java 24) — the first use of `Unsafe`'s memory-access methods prints a warning. Older versions of Netty, Hazelcast, Kryo and similar libraries trigger it; upgrading them usually removes it.

## 6. Observability (Java 25)

JDK Flight Recorder gained:
- CPU-time profiling on Linux ([JEP 509](https://openjdk.org/jeps/509), experimental),
- cooperative sampling for more stable stack traces ([JEP 518](https://openjdk.org/jeps/518)),
- method timing and tracing via bytecode instrumentation ([JEP 520](https://openjdk.org/jeps/520)).
