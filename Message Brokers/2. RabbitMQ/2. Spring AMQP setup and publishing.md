# Spring AMQP Setup and Publishing

> **Applies to:** Spring Boot 3.x (Spring AMQP 3.x) · Java 17+ · **Last updated:** 2026-11-21

## Overview

Spring AMQP gives you `RabbitTemplate` for publishing, `@RabbitListener` for consuming, and `RabbitAdmin` for declaring exchanges, queues and bindings from Spring beans. Spring Boot auto-configures all of it from `spring.rabbitmq.*` properties.

**Key Concept**: By default, `RabbitTemplate.convertAndSend()` returns as soon as the message is written to the socket — the broker hasn't confirmed anything. For messages you can't afford to lose, enable **publisher confirms** and check them.

---

## 1. Setup

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-starter-amqp</artifactId>
</dependency>
```

```yaml
spring:
  rabbitmq:
    host: localhost
    port: 5672
    username: ${RABBITMQ_USERNAME:guest}
    password: ${RABBITMQ_PASSWORD:guest}
    virtual-host: /
    publisher-confirm-type: correlated     # broker confirms each publish
    publisher-returns: true                # unroutable messages are returned to us
    template:
      mandatory: true                      # required for returns to work
```

## 2. Declaring Topology

Exchanges, queues and bindings declared as beans are created by `RabbitAdmin` when the first connection opens (declarations are idempotent: re-declaring with the same arguments is a no-op).

```java
@Configuration
public class RabbitTopologyConfig {

    public static final String ORDERS_EXCHANGE = "orders";
    public static final String INVOICING_QUEUE = "invoicing.order-events";

    @Bean
    TopicExchange ordersExchange() {
        return ExchangeBuilder.topicExchange(ORDERS_EXCHANGE).durable(true).build();
    }

    @Bean
    Queue invoicingQueue() {
        return QueueBuilder.durable(INVOICING_QUEUE)
                .quorum()                                   // replicated quorum queue
                .deadLetterExchange("orders.dlx")
                .deadLetterRoutingKey("invoicing")
                .build();
    }

    @Bean
    Binding invoicingBinding(Queue invoicingQueue, TopicExchange ordersExchange) {
        return BindingBuilder.bind(invoicingQueue).to(ordersExchange).with("order.created.*");
    }
}
```

Several declarations at once:

```java
@Bean
Declarables shippingTopology() {
    Queue queue = QueueBuilder.durable("shipping.order-events").quorum().build();
    TopicExchange exchange = new TopicExchange("orders");
    return new Declarables(queue,
            BindingBuilder.bind(queue).to(exchange).with("order.paid.*"),
            BindingBuilder.bind(queue).to(exchange).with("order.cancelled.*"));
}
```

**Who declares what?** A common convention: the **producer** declares the exchange it publishes to; each **consumer** declares its own queue and bindings. Changing a queue's arguments (e.g. adding a DLX) after it exists fails with `PRECONDITION_FAILED` — use policies (`rabbitmqctl set_policy`) for settings you may change later, or create a new queue.

## 3. Message Conversion

Without configuration, `RabbitTemplate` uses `SimpleMessageConverter` (Java serialization for objects — don't). Register a JSON converter; Spring Boot applies it to the template and to listener containers:

```java
@Bean
MessageConverter jsonMessageConverter(ObjectMapper objectMapper) {
    return new Jackson2JsonMessageConverter(objectMapper);
}
```

The converter adds a `__TypeId__` header with the Java class name. Between services with different packages, map logical names instead:

```java
@Bean
MessageConverter jsonMessageConverter(ObjectMapper objectMapper) {
    Jackson2JsonMessageConverter converter = new Jackson2JsonMessageConverter(objectMapper);
    DefaultJackson2JavaTypeMapper typeMapper = new DefaultJackson2JavaTypeMapper();
    typeMapper.setIdClassMapping(Map.of("orderCreated", OrderCreated.class));
    converter.setJavaTypeMapper(typeMapper);
    return converter;
}
```

Or let the listener's method signature decide the type (the default for `@RabbitListener` with a typed parameter when the header is missing or unknown — set `typeMapper.setTypePrecedence(TypePrecedence.INFERRED)`).

> Spring Boot 4 / Spring AMQP 4 use Jackson 3 and provide `JacksonJsonMessageConverter`; check the migration guide if you upgrade.

## 4. Publishing

```java
@Service
@RequiredArgsConstructor
public class OrderEventPublisher {

    private final RabbitTemplate rabbitTemplate;

    public void orderCreated(Order order) {
        OrderCreated event = OrderCreated.from(order);
        rabbitTemplate.convertAndSend(
                RabbitTopologyConfig.ORDERS_EXCHANGE,
                "order.created." + order.region(),          // e.g. order.created.eu
                event,
                message -> {
                    message.getMessageProperties().setMessageId(event.eventId());   // for consumer dedup
                    message.getMessageProperties().setHeader("event-type", "OrderCreated");
                    return message;
                });
    }
}
```

### Publisher Confirms

With `publisher-confirm-type: correlated`, attach `CorrelationData` and wait for (or react to) the confirm:

```java
public void publishConfirmed(OrderCreated event) {
    CorrelationData correlation = new CorrelationData(event.eventId());

    rabbitTemplate.convertAndSend("orders", "order.created.eu", event, correlation);

    try {
        CorrelationData.Confirm confirm = correlation.getFuture().get(5, TimeUnit.SECONDS);
        if (!confirm.isAck()) {
            throw new EventPublishingException("Broker nacked " + event.eventId() + ": " + confirm.getReason());
        }
        if (correlation.getReturned() != null) {
            throw new EventPublishingException("Unroutable: " + correlation.getReturned().getReplyText());
        }
    } catch (ExecutionException | TimeoutException e) {
        throw new EventPublishingException("No confirm for " + event.eventId(), e);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new EventPublishingException("Interrupted", e);
    }
}
```

Or handle confirms globally and asynchronously:

```java
@Bean
RabbitTemplateCustomizer confirmCallbacks() {
    return template -> {
        template.setConfirmCallback((correlation, ack, cause) -> {
            if (!ack) log.error("Message {} nacked: {}", correlation != null ? correlation.getId() : "?", cause);
        });
        template.setReturnsCallback(returned ->
                log.error("Unroutable message to {} with key {}: {}",
                        returned.getExchange(), returned.getRoutingKey(), returned.getReplyText()));
    };
}
```

| Outcome | Meaning |
|---|---|
| Confirm `ack` | Broker took responsibility (for quorum queues: replicated to a majority) |
| Confirm `nack` | Broker couldn't handle it — retry or fail |
| Return (with `mandatory`) | Exchange had no matching binding — the message would otherwise be silently dropped |
| No confirm (timeout) | Unknown — treat as failure and republish (consumers must deduplicate) |

## 5. Request/Reply

```java
// Client: blocks until a reply arrives or the timeout expires
PriceQuote quote = (PriceQuote) rabbitTemplate.convertSendAndReceive("pricing", "quote.request", new QuoteRequest("p-1", 3));

// Server
@RabbitListener(queues = "pricing.quote-requests")
public PriceQuote quote(QuoteRequest request) {     // return value is sent to the reply-to address
    return pricingService.quote(request);
}
```

Spring uses RabbitMQ's direct reply-to by default. Set `spring.rabbitmq.template.reply-timeout` (default 5 s). For most service-to-service queries, HTTP is simpler — use RPC over RabbitMQ when you already depend on it and want load-levelling.

## 6. Connection Management

```yaml
spring:
  rabbitmq:
    cache:
      channel:
        size: 25                 # cached channels per connection
    connection-timeout: 5s
    requested-heartbeat: 30s
```

- Spring's `CachingConnectionFactory` uses one connection and caches channels.
- Use **separate connections for publishing and consuming** (`rabbitTemplate.setUsePublisherConnection(true)`), so a blocked publisher (memory alarm) doesn't stall consumers that would drain the queues.
- For a cluster, list all nodes: `spring.rabbitmq.addresses: rabbit-1:5672,rabbit-2:5672,rabbit-3:5672`.

## 7. Common Pitfalls

### ⚠️ No confirms, no returns

A typo in the routing key or a missing binding means messages vanish. `mandatory` + returns tells you; confirms tell you the broker stored the message.

### ⚠️ Publishing inside a database transaction

Same problem as with Kafka: a DB rollback after the publish leaves an event for something that didn't happen. Use the outbox pattern — see [Reliability patterns](5.%20Reliability%20patterns.md).

### ⚠️ Java serialization

The default converter serializes `Serializable` objects with Java serialization: brittle across versions and a deserialization security risk. Always configure a JSON (or other explicit) converter.

### ⚠️ Changing queue arguments in code

Redeploying with a changed `x-dead-letter-exchange` on an existing queue fails at startup. Use policies or migrate to a new queue name.

---

## Summary & Best Practices

- ✓ Declare exchanges in producers, queues + bindings in consumers.
- ✓ Use quorum queues and a JSON message converter.
- ✓ Enable publisher confirms and `mandatory` returns for important messages.
- ✓ Set a `messageId` on every message so consumers can deduplicate.
- ✓ Separate publisher and consumer connections.
