# Testing RabbitMQ Applications

> **Applies to:** Spring Boot 3.x (Spring AMQP 3.x) · Java 17+ · **Last updated:** 2026-11-21

## Overview

As with Kafka, split RabbitMQ tests by what they verify:

| Layer | What to verify | Tool |
|---|---|---|
| Business logic | The handler's behaviour | Plain unit tests |
| Wiring | Exchanges, bindings, routing keys, conversion, retries, DLX | Integration test against a real broker (**Testcontainers**) |
| Listener invocation without a broker | That a listener method is called with the right arguments | `@RabbitListenerTest` harness |

**Key Concept**: Routing bugs (wrong routing key, missing binding) are the most common RabbitMQ defects, and only a real broker catches them. Mocks of `RabbitTemplate` can't tell you that a message would have been dropped.

## 1. Unit Testing

```java
class OrderEventsListenerTest {

    private final InvoiceService invoiceService = mock(InvoiceService.class);
    private final OrderEventsListener listener = new OrderEventsListener(invoiceService);

    @Test
    void createsInvoice() {
        OrderCreated event = new OrderCreated("e-1", "o-1", "c-1", new BigDecimal("42.00"));

        listener.onOrderCreated(event);

        verify(invoiceService).createFor(event);
    }
}
```

```java
@Test
void publishesToOrdersExchangeWithRegionKey() {
    RabbitTemplate rabbitTemplate = mock(RabbitTemplate.class);
    OrderEventPublisher publisher = new OrderEventPublisher(rabbitTemplate);

    publisher.orderCreated(order("o-1", "eu"));

    verify(rabbitTemplate).convertAndSend(eq("orders"), eq("order.created.eu"),
            any(OrderCreated.class), any(MessagePostProcessor.class));
}
```

## 2. Integration Tests with Testcontainers

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-testcontainers</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>rabbitmq</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.awaitility</groupId>
    <artifactId>awaitility</artifactId>
    <scope>test</scope>
</dependency>
```

```java
@SpringBootTest
@Testcontainers
class InvoicingFlowIT {

    @Container
    @ServiceConnection                  // configures spring.rabbitmq.* automatically
    static RabbitMQContainer rabbit = new RabbitMQContainer(DockerImageName.parse("rabbitmq:4.0-management"));

    @Autowired RabbitTemplate rabbitTemplate;
    @Autowired InvoiceRepository invoices;

    @Test
    void createsInvoiceWhenOrderIsCreated() {
        rabbitTemplate.convertAndSend("orders", "order.created.eu",
                new OrderCreated("e-1", "o-1", "c-1", new BigDecimal("42.00")));

        await().atMost(Duration.ofSeconds(10))
               .untilAsserted(() -> assertThat(invoices.findByOrderId("o-1")).isPresent());
    }
}
```

This one test verifies the exchange and binding declarations, the routing key pattern, JSON conversion and the listener — everything a mock would miss.

### Testing Routing Explicitly

```java
@Autowired AmqpAdmin amqpAdmin;

@Test
void euOrdersReachInvoicingButNotUsAnalytics() {
    rabbitTemplate.convertAndSend("orders", "order.created.eu", sampleEvent());

    await().untilAsserted(() ->
            assertThat(amqpAdmin.getQueueInfo("invoicing.order-events").getMessageCount()).isZero()); // consumed
    assertThat(amqpAdmin.getQueueInfo("us-analytics.order-events").getMessageCount()).isZero();
}
```

To inspect messages yourself, stop the listener for that test (`RabbitListenerEndpointRegistry`) and use `rabbitTemplate.receiveAndConvert(queue, timeoutMs)`.

## 3. Testing Retries and Dead Lettering

```java
@SpringBootTest(properties = {
        "spring.rabbitmq.listener.simple.retry.initial-interval=10ms",   // keep the test fast
        "spring.rabbitmq.listener.simple.retry.max-attempts=3"
})
@Testcontainers
class InvoicingDeadLetterIT {

    @Container
    @ServiceConnection
    static RabbitMQContainer rabbit = new RabbitMQContainer(DockerImageName.parse("rabbitmq:4.0-management"));

    @Autowired RabbitTemplate rabbitTemplate;
    @MockitoBean InvoiceService invoiceService;          // Spring Boot 3.4+; @MockBean before that

    @Test
    void failingMessageEndsUpInDlq() {
        doThrow(new IllegalStateException("boom")).when(invoiceService).createFor(any());

        rabbitTemplate.convertAndSend("orders", "order.created.eu", sampleEvent());

        Message dead = await().atMost(Duration.ofSeconds(10))
                .until(() -> rabbitTemplate.receive("invoicing.order-events.dlq"), Objects::nonNull);

        assertThat(dead.getMessageProperties().getHeaders())
                .containsKey("x-exception-message");                // from RepublishMessageRecoverer
        verify(invoiceService, times(3)).createFor(any());
    }

    @Test
    void malformedJsonIsDeadLettered() {
        rabbitTemplate.send("orders", "order.created.eu",
                MessageBuilder.withBody("not-json".getBytes(StandardCharsets.UTF_8))
                        .setContentType(MessageProperties.CONTENT_TYPE_JSON)
                        .build());

        Message dead = await().until(() -> rabbitTemplate.receive("invoicing.order-events.dlq"), Objects::nonNull);
        assertThat(new String(dead.getBody(), StandardCharsets.UTF_8)).isEqualTo("not-json");
    }
}
```

## 4. The `@RabbitListenerTest` Harness

`spring-rabbit-test` can wrap listeners in Mockito spies or capture their invocations, for asserting *that* a listener was called and *with what* — still with a real (or test) broker delivering the message:

```xml
<dependency>
    <groupId>org.springframework.amqp</groupId>
    <artifactId>spring-rabbit-test</artifactId>
    <scope>test</scope>
</dependency>
```

```java
@SpringBootTest
@RabbitListenerTest(capture = true)
@Testcontainers
class ListenerHarnessIT {

    @Container @ServiceConnection
    static RabbitMQContainer rabbit = new RabbitMQContainer(DockerImageName.parse("rabbitmq:4.0-management"));

    @Autowired RabbitListenerTestHarness harness;
    @Autowired RabbitTemplate rabbitTemplate;

    @Test
    void listenerReceivesEvent() throws InterruptedException {
        rabbitTemplate.convertAndSend("orders", "order.created.eu", sampleEvent());

        InvocationData data = harness.getNextInvocationDataFor("invoicing", 10, TimeUnit.SECONDS);  // listener id
        assertThat(data).isNotNull();
        assertThat(data.getArguments()[0]).isInstanceOf(OrderCreated.class);
    }
}
```

The listener must have an `id` (`@RabbitListener(id = "invoicing", ...)`).

`spring-rabbit-test` also has `TestRabbitTemplate`, which invokes listeners directly without a broker — useful for very fast tests of request/reply listeners, but it doesn't exercise exchanges and bindings.

## 5. Common Pitfalls

### ⚠️ Only mocking `RabbitTemplate`

A mock accepts any routing key. Typos and missing bindings go unnoticed until production. Have at least one Testcontainers test per flow.

### ⚠️ Leftover messages between tests

Queues persist across tests in a shared container. Purge the queues you use in `@BeforeEach` (`amqpAdmin.purgeQueue(name)`) or use unique IDs and assert on them.

### ⚠️ Slow retry tests

Production backoff settings (seconds) make DLQ tests slow. Override them with test properties.

---

## Summary & Best Practices

- ✓ Unit test handlers and publishers without a broker.
- ✓ Use Testcontainers + `@ServiceConnection` to test routing, conversion, retries and DLQs.
- ✓ Wait with Awaitility; purge queues between tests.
- ✓ Use `@RabbitListenerTest` when you need to assert on listener invocations.
