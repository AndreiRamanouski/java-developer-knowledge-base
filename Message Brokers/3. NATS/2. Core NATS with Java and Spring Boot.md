# Core NATS with Java and Spring Boot

> **Applies to:** NATS Java client (jnats) 2.x · Spring Boot 3.x · Java 17+ · **Last updated:** 2026-11-21

## Overview

The official Java client is **jnats** (`io.nats:jnats`). Unlike Kafka and RabbitMQ, Spring Boot has **no built-in auto-configuration** for NATS, so you create the `Connection` bean yourself — a few lines of configuration. (The NATS project publishes a Spring Boot starter and a Spring Cloud Stream binder; check their maintenance status before depending on them. This page uses the plain client, which works everywhere.)

**Key Concept**: One `Connection` per application is enough. It's thread-safe, reconnects automatically, and multiplexes all subscriptions. Messages are delivered to handlers by a **Dispatcher** thread.

## 1. Setup

```xml
<dependency>
    <groupId>io.nats</groupId>
    <artifactId>jnats</artifactId>
    <version>${jnats.version}</version>   <!-- not managed by Spring Boot -->
</dependency>
```

```yaml
# application.yml
nats:
  servers: nats://localhost:4222
  connection-name: ${spring.application.name}
```

```java
@ConfigurationProperties("nats")
public record NatsProperties(List<String> servers, String connectionName) {}

@Configuration
@EnableConfigurationProperties(NatsProperties.class)
@Slf4j
public class NatsConfig {

    @Bean(destroyMethod = "")            // closed by the lifecycle bean below, after draining
    public Connection natsConnection(NatsProperties props) throws IOException, InterruptedException {
        Options options = Options.builder()
                .servers(props.servers().toArray(String[]::new))
                .connectionName(props.connectionName())
                .maxReconnects(-1)                              // keep trying forever
                .reconnectWait(Duration.ofSeconds(2))
                .connectionTimeout(Duration.ofSeconds(5))
                .connectionListener((conn, event) -> log.info("NATS connection event: {}", event))
                .errorListener(new ErrorListener() {
                    @Override
                    public void slowConsumerDetected(Connection conn, Consumer consumer) {
                        log.warn("NATS slow consumer detected: {}", consumer);
                    }
                    @Override
                    public void exceptionOccurred(Connection conn, Exception exp) {
                        log.error("NATS error", exp);
                    }
                })
                .build();
        return Nats.connect(options);
    }

    @Bean
    public SmartLifecycle natsDrainOnShutdown(Connection connection) {
        return new SmartLifecycle() {
            private volatile boolean running = true;
            @Override public void start() {}
            @Override public boolean isRunning() { return running; }
            @Override public int getPhase() { return Integer.MAX_VALUE - 100; }   // stop late
            @Override public void stop() {
                try {
                    // Stop receiving, finish in-flight handlers, flush outgoing messages, then close
                    connection.drain(Duration.ofSeconds(10)).get(15, TimeUnit.SECONDS);
                } catch (Exception e) {
                    log.warn("NATS drain did not complete cleanly", e);
                } finally {
                    running = false;
                }
            }
        };
    }
}
```

`Consumer` in `slowConsumerDetected` is `io.nats.client.Consumer`, not `java.util.function.Consumer`.

### Serialization

NATS payloads are `byte[]`; you choose the format. JSON with Jackson is the usual choice:

```java
@Component
@RequiredArgsConstructor
public class NatsJson {
    private final ObjectMapper objectMapper;

    public byte[] write(Object value) {
        try { return objectMapper.writeValueAsBytes(value); }
        catch (JsonProcessingException e) { throw new IllegalArgumentException(e); }
    }

    public <T> T read(byte[] data, Class<T> type) {
        try { return objectMapper.readValue(data, type); }
        catch (IOException e) { throw new IllegalArgumentException("Bad payload for " + type.getSimpleName(), e); }
    }
}
```

## 2. Publishing

```java
@Service
@RequiredArgsConstructor
public class OrderEventPublisher {

    private final Connection nats;
    private final NatsJson json;

    public void orderCreated(Order order) {
        Headers headers = new Headers()
                .add("event-type", "OrderCreated")
                .add("event-id", UUID.randomUUID().toString());

        nats.publish("orders.created." + order.region(), headers, json.write(OrderCreated.from(order)));
    }
}
```

`publish` is asynchronous and returns immediately; the client buffers and writes in the background. Core NATS has no publish acknowledgement — if you need confirmation that the message was stored, publish to JetStream instead (see [JetStream](3.%20JetStream%20-%20streams%20and%20consumers.md)). `nats.flush(Duration)` waits until the buffer has reached the server, which is useful in tests and before shutdown.

## 3. Subscribing

### Dispatcher-Based Subscriptions

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class OrderEventsSubscriber {

    private final Connection nats;
    private final NatsJson json;
    private final BillingService billing;
    private Dispatcher dispatcher;

    @PostConstruct
    void subscribe() {
        dispatcher = nats.createDispatcher();

        // Queue group "billing": each message goes to ONE instance of this service
        dispatcher.subscribe("orders.created.*", "billing", msg -> {
            try {
                OrderCreated event = json.read(msg.getData(), OrderCreated.class);
                billing.handle(event);
            } catch (Exception e) {
                // Core NATS has no redelivery: log, count, and decide what to do
                log.error("Failed to handle {} on {}", msg.getHeaders(), msg.getSubject(), e);
            }
        });
    }

    @PreDestroy
    void unsubscribe() {
        if (dispatcher != null) {
            nats.closeDispatcher(dispatcher);
        }
    }
}
```

- A dispatcher delivers its messages **sequentially on one thread**. Long-running handlers delay everything behind them; create separate dispatchers for independent workloads, or hand off to an executor if ordering doesn't matter.
- Without a queue name, every instance receives every message (fan-out). With a queue name, instances share them.
- An exception in a core NATS handler doesn't cause redelivery — the message is gone. Use JetStream when processing must be retried.

### Synchronous Subscriptions

```java
Subscription sub = nats.subscribe("inventory.updates");
Message msg = sub.nextMessage(Duration.ofSeconds(1));   // null on timeout
```

Useful in tests and simple workers; dispatchers are the norm in services.

## 4. Request/Reply

### Responder

```java
@PostConstruct
void serveQuotes() {
    Dispatcher d = nats.createDispatcher();
    d.subscribe("pricing.quote", "pricing", msg -> {
        QuoteRequest request = json.read(msg.getData(), QuoteRequest.class);
        PriceQuote quote = pricingService.quote(request);
        nats.publish(msg.getReplyTo(), json.write(quote));
    });
}
```

### Requester

```java
public PriceQuote quote(QuoteRequest request) {
    try {
        Message reply = nats.request("pricing.quote", json.write(request))
                            .get(2, TimeUnit.SECONDS);
        return json.read(reply.getData(), PriceQuote.class);
    } catch (ExecutionException | CancellationException e) {
        // No responders (nobody subscribed) or the request was cancelled; the exact
        // exception type depends on the jnats version, so treat both cases as "unavailable"
        throw new PricingUnavailableException("No pricing responder available", e);
    } catch (TimeoutException e) {
        throw new PricingUnavailableException("Pricing timed out", e);
    } catch (InterruptedException e) {
        Thread.currentThread().interrupt();
        throw new PricingUnavailableException("Interrupted", e);
    }
}
```

With "no responders" support (enabled by default in recent servers and clients), a request to a subject nobody listens on fails immediately instead of waiting for the full timeout.

### Scatter-Gather

To collect answers from several responders (e.g. "which warehouses have SKU p-1?"), subscribe to your own inbox and publish a request **without** a queue group on the responder side, then collect replies until a deadline:

```java
String inbox = nats.createInbox();
Subscription replies = nats.subscribe(inbox);
nats.publish("inventory.stock-check", inbox, json.write(new StockCheck("p-1")));

List<StockLevel> levels = new ArrayList<>();
Instant deadline = Instant.now().plusMillis(300);
while (Instant.now().isBefore(deadline)) {
    Message m = replies.nextMessage(Duration.between(Instant.now(), deadline));
    if (m == null) break;
    levels.add(json.read(m.getData(), StockLevel.class));
}
replies.unsubscribe();
```

## 5. Observability

- **Connection events** — log them via `connectionListener` (DISCONNECTED, RECONNECTED, CLOSED…).
- **Client statistics** — `nats.getStatistics()` exposes in/out message and byte counts, reconnects and more; register them as Micrometer gauges.
- **Server monitoring** — the HTTP endpoint (`-m 8222`) serves `/varz`, `/connz`, `/subsz`, `/jsz`; the Prometheus NATS exporter scrapes them.
- **Tracing** — there's no built-in Micrometer instrumentation; propagate the W3C `traceparent` header yourself in NATS `Headers` (inject on publish, extract on receive).

## 6. Common Pitfalls

### ⚠️ Creating a connection per request

Connections are long-lived. Create one bean and share it.

### ⚠️ Blocking work inside a dispatcher handler

All subscriptions on a dispatcher share one thread. A 2-second handler caps that dispatcher at 0.5 messages/second and eventually triggers slow-consumer drops.

### ⚠️ Closing instead of draining

`close()` discards in-flight messages. `drain()` stops new deliveries, lets handlers finish and flushes outgoing messages first.

### ⚠️ Treating core NATS as reliable

There's no retry or dead-letter mechanism in core NATS. Anything that must survive failures belongs in JetStream.

## Summary & Best Practices

```java
Connection nats = Nats.connect(options);                              // one per app
nats.publish("orders.created.eu", headers, payload);                  // fire and forget
nats.createDispatcher().subscribe("orders.created.*", "billing", h);  // queue group
nats.request("pricing.quote", payload).get(2, SECONDS);               // request/reply
nats.drain(Duration.ofSeconds(10));                                   // graceful shutdown
```

- ✓ One shared `Connection`, unlimited reconnects, connection and error listeners.
- ✓ Queue groups for horizontally scaled services.
- ✓ Keep handlers fast; separate dispatchers for independent workloads.
- ✓ Drain on shutdown.
- ✓ Use JetStream when messages must not be lost.
