# Testing Kafka Applications

> **Applies to:** Spring Boot 3.x (Spring for Apache Kafka 3.x) · Java 17+ · **Last updated:** 2026-11-21

## Overview

Kafka code has three layers worth testing, each with its own tool:

| Layer | What to verify | Tool |
|---|---|---|
| Business logic | The handler does the right thing with an event | Plain unit tests — call the method directly |
| Wiring | Serialization, topic names, listener config, error handling, DLTs | Integration test with a real broker: **Testcontainers** or **embedded Kafka** |
| Stream topologies | Kafka Streams transformations | `TopologyTestDriver` (see [Kafka Streams](6.%20Kafka%20Streams%20with%20Spring%20Boot.md#8-testing-with-topologytestdriver)) |

**Key Concept**: Kafka is asynchronous. An integration test sends a record and then has to **wait** for the effect. Use Awaitility with a timeout — never `Thread.sleep`.

## 1. Unit Testing Listeners

Keep listeners thin and test the logic without Kafka:

```java
@Component
@RequiredArgsConstructor
public class OrderEventsListener {
    private final BillingService billingService;

    @KafkaListener(topics = "orders")
    public void onOrderEvent(OrderEvent event) {
        billingService.handle(event);
    }
}

class OrderEventsListenerTest {

    private final BillingService billingService = mock(BillingService.class);
    private final OrderEventsListener listener = new OrderEventsListener(billingService);

    @Test
    void delegatesToBilling() {
        OrderEvent event = new OrderEvent("o-1", "c-1", new BigDecimal("10.00"), "p-1");

        listener.onOrderEvent(event);

        verify(billingService).handle(event);
    }
}
```

Producers that wrap `KafkaTemplate` can be tested with a mocked template returning a completed future:

```java
when(kafkaTemplate.send(eq("orders"), eq("o-1"), any()))
        .thenReturn(CompletableFuture.completedFuture(mock(SendResult.class)));
```

## 2. Integration Tests with Testcontainers (Recommended)

A real Kafka broker in Docker, the same version as production:

```xml
<dependency>
    <groupId>org.springframework.boot</groupId>
    <artifactId>spring-boot-testcontainers</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>kafka</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.testcontainers</groupId>
    <artifactId>junit-jupiter</artifactId>
    <scope>test</scope>
</dependency>
<dependency>
    <groupId>org.awaitility</groupId>
    <artifactId>awaitility</artifactId>
    <scope>test</scope>
</dependency>
```

```java
@SpringBootTest
@Testcontainers
class OrderFlowIT {

    @Container
    @ServiceConnection          // sets spring.kafka.bootstrap-servers automatically
    static KafkaContainer kafka = new KafkaContainer(DockerImageName.parse("apache/kafka:3.9.0"));

    @Autowired KafkaTemplate<String, OrderEvent> kafkaTemplate;
    @Autowired InvoiceRepository invoices;

    @Test
    void createsInvoiceForOrder() {
        kafkaTemplate.send("orders", "o-1", new OrderEvent("o-1", "c-1", new BigDecimal("99.90"), "p-1"));

        await().atMost(Duration.ofSeconds(10))
               .untilAsserted(() -> assertThat(invoices.findByOrderId("o-1")).isPresent());
    }
}
```

`KafkaContainer` here is `org.testcontainers.kafka.KafkaContainer` (Testcontainers 1.20+), which runs the official `apache/kafka` image in KRaft mode. The older `org.testcontainers.containers.KafkaContainer` uses Confluent images.

### Sharing One Container

Starting a broker takes a few seconds. Share one per test run with a base class or Spring Boot's `@ImportTestcontainers`/`@TestConfiguration` with a `@Bean @ServiceConnection` container — Spring caches the application context, so the container is reused across test classes with the same configuration.

```java
@TestConfiguration(proxyBeanMethods = false)
public class KafkaTestcontainersConfig {
    @Bean
    @ServiceConnection
    KafkaContainer kafkaContainer() {
        return new KafkaContainer(DockerImageName.parse("apache/kafka:3.9.0"));
    }
}

@SpringBootTest
@Import(KafkaTestcontainersConfig.class)
class PaymentFlowIT { ... }
```

## 3. Embedded Kafka

`spring-kafka-test` can start an in-process broker — no Docker required:

```java
@SpringBootTest(properties = "spring.kafka.bootstrap-servers=${spring.embedded.kafka.brokers}")
@EmbeddedKafka(partitions = 1, topics = { "orders", "orders-dlt" })
class OrderFlowEmbeddedTest {

    @Autowired KafkaTemplate<String, OrderEvent> kafkaTemplate;
    @Autowired InvoiceRepository invoices;

    @Test
    void createsInvoiceForOrder() {
        kafkaTemplate.send("orders", "o-1", new OrderEvent("o-1", "c-1", new BigDecimal("99.90"), "p-1"));

        await().atMost(Duration.ofSeconds(10))
               .untilAsserted(() -> assertThat(invoices.findByOrderId("o-1")).isPresent());
    }
}
```

| | Embedded Kafka | Testcontainers |
|---|---|---|
| Needs Docker | No | Yes |
| Startup | Fast | A few seconds |
| Fidelity | Broker classes on your test classpath; version tied to `spring-kafka-test` | Exact production broker version and config |
| Classpath conflicts | Possible (Scala/broker dependencies in older versions) | None |

Prefer Testcontainers when Docker is available in CI; embedded Kafka is fine for quick wiring tests.

## 4. Consuming Test Output

To assert what the application **produced**, read the output topic with a test consumer:

```java
@Test
void publishesInvoiceEvent() {
    kafkaTemplate.send("orders", "o-1", order("o-1"));

    try (Consumer<String, String> consumer = testConsumer("invoices")) {
        ConsumerRecord<String, String> record =
                KafkaTestUtils.getSingleRecord(consumer, "invoices", Duration.ofSeconds(10));

        assertThat(record.key()).isEqualTo("o-1");
        assertThat(record.value()).contains("\"orderId\":\"o-1\"");
    }
}

private Consumer<String, String> testConsumer(String topic) {
    Map<String, Object> props = KafkaTestUtils.consumerProps(kafka.getBootstrapServers(), "test-" + UUID.randomUUID(), "true");
    props.put(ConsumerConfig.AUTO_OFFSET_RESET_CONFIG, "earliest");
    Consumer<String, String> consumer =
            new DefaultKafkaConsumerFactory<>(props, new StringDeserializer(), new StringDeserializer()).createConsumer();
    consumer.subscribe(List.of(topic));
    return consumer;
}
```

Use a **random group ID** per test so tests don't steal each other's records.

## 5. Testing Error Handling

```java
@Test
void sendsMalformedRecordToDlt() {
    // rawTemplate: a KafkaTemplate<String, byte[]> with ByteArraySerializer, defined in the test.
    // bytesConsumer(...): like testConsumer(...) above, with a ByteArrayDeserializer for values.
    // Raw bytes that aren't valid JSON
    rawTemplate.send("orders", "o-bad", "not-json".getBytes(StandardCharsets.UTF_8));

    try (Consumer<String, byte[]> dlt = bytesConsumer("orders-dlt")) {
        ConsumerRecord<String, byte[]> record = KafkaTestUtils.getSingleRecord(dlt, "orders-dlt", Duration.ofSeconds(15));

        assertThat(new String(record.value(), StandardCharsets.UTF_8)).isEqualTo("not-json");
        assertThat(record.headers().lastHeader(KafkaHeaders.DLT_EXCEPTION_FQCN)).isNotNull();
    }
}
```

Speed up retry tests by overriding the backoff in a test profile (e.g. 3 retries × 10 ms).

## 6. Common Pitfalls

### ⚠️ `Thread.sleep` to wait for consumers

Either too short (flaky) or too long (slow). Use Awaitility.

### ⚠️ Listener not ready when the test sends

With `auto-offset-reset: latest`, a record sent before the consumer has its partitions assigned is skipped. Use `earliest` in tests, or wait for assignment:

```java
@Autowired KafkaListenerEndpointRegistry registry;

@BeforeEach
void waitForAssignment() {
    registry.getListenerContainers().forEach(c ->
            ContainerTestUtils.waitForAssignment(c, 1));   // number of partitions
}
```

### ⚠️ Tests sharing topics and state

Records from one test leak into the next. Use unique keys/IDs per test, or unique topic names, and assert on your own records only.

---

## Summary & Best Practices

- ✓ Unit test handler logic without Kafka.
- ✓ Use Testcontainers with `@ServiceConnection` for integration tests; share the container.
- ✓ Wait with Awaitility; use random consumer group IDs and `earliest` offset reset in tests.
- ✓ Test the unhappy paths: malformed records, retries, DLT routing.
