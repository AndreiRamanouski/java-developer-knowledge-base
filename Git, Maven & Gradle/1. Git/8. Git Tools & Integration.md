### GitKraken

Professional Git client with visual commit graph and team collaboration features.

**Features:**

```
GitKraken Advantages:
─────────────────────

✓ Beautiful visual commit graph
✓ Drag-and-drop branch operations
✓ Built-in merge conflict editor
✓ GitHub/GitLab/Bitbucket integration
✓ Interactive rebase interface
✓ Undo functionality

✓ Cross-platform (Windows, Mac, Linux)

GitKraken Disadvantages:
────────────────────────

✗ Paid (free for students/open source)
✗ Can be resource-intensive
✗ Some advanced features require Pro
```

**Common workflows in GitKraken:**

```
1. Visual Commit Graph
   ───────────────────
   • See entire branch structure at a glance
   • Identify merge points and divergences
   • Understand team workflow visually

   ────────────────────────
   • Drag branch to another to merge
   • Right-click for rebase options

3. Interactive Rebase
   ──────────────────
   • Visual interface for commit reordering
   • Squash, drop, or edit commits

   ───────────────────
   • Built-in 3-way merge editor

   ────────────────────────
```

### When to Use GUI vs CLI

**Decision Matrix:**

```
Use GUI when:
─────────────

✓ Visualizing commit history
  • Understanding branch relationships
  • Exploring project timeline
  • Finding merge points

✓ Resolving merge conflicts
  • 3-way merge visualization
  • Side-by-side comparison
  • Point-and-click resolution

✓ Interactive rebase
  • Reordering commits visually
  • Squashing with drag-and-drop
  • Editing commit messages

✓ Learning Git
  • Understanding concepts visually
  • Seeing immediate feedback
  • Reducing command memorization

✓ Complex branch operations
  • Comparing multiple branches
  • Cherry-picking visually
  • Managing multiple remotes

Use CLI when:
─────────────

✓ Scripting and automation
  • CI/CD pipelines
  • Git hooks
  • Batch operations

✓ Remote server access (SSH)
  • No GUI available
  • Server-side operations
  • Production deployments

✓ Speed and efficiency
  • Faster for experienced users
  • Keyboard-focused workflow
  • No mouse required

✓ Advanced operations
  • Complex git commands
  • Bisect debugging
  • Filter-branch operations

✓ Precise control
  • Exact command parameters
  • Reproducible operations
  • Documentation purposes

Hybrid Approach (Best):
───────────────────────

✓ Use GUI for visualization and conflict resolution
✓ Use CLI for daily commits and common operations
✓ Use IDE integration for code-centric tasks
✓ Learn both to maximize productivity
```

**Example workflows:**

```
Scenario 1: Daily Development
──────────────────────────────
• Edit code in IDE (IntelliJ)
• View changes in IDE Git panel
• Commit using IDE (Cmd+K)
• Push using IDE (Cmd+Shift+K)
Why: Fast, integrated with coding

Scenario 2: Resolving Complex Merge
────────────────────────────────────
• git fetch origin (CLI)
• git merge origin/main (CLI - conflict!)
• Open GitKraken/IntelliJ merge tool
• Resolve conflicts visually
• git add . && git commit (CLI)
Why: Visual conflict resolution is easier

Scenario 3: Understanding History
──────────────────────────────────
• Open SourceTree/GitKraken
• View commit graph
• Explore branches visually
• Find problematic commit
• git show <sha> (CLI for details)
Why: Visual graph shows relationships

Scenario 4: CI/CD Pipeline
───────────────────────────
• git clone repo
• git checkout -b feature/new
• git add . && git commit -m "..."
• git push -u origin feature/new
Why: Automation requires CLI

Scenario 5: Code Review
────────────────────────
• git fetch origin
• git checkout pr-branch
• View changes in IDE
• Test code
• Comment on GitHub web UI
Why: Best tool for each step
```

## 2. Git Aliases

### Creating Shortcuts

**Configuration syntax:**

```bash
# Create alias with git config
git config --global alias.<alias-name> '<git-command>'

# Examples:
git config --global alias.co checkout
git config --global alias.br branch
git config --global alias.ci commit
git config --global alias.st status

# Now use:
git co main        # git checkout main
git br             # git branch
git ci -m "msg"    # git commit -m "msg"
git st             # git status
```

**Editing .gitconfig directly:**

```bash
# Open .gitconfig
vim ~/.gitconfig

# Add aliases section:
[alias]
    co = checkout
    br = branch
    ci = commit
    st = status
    unstage = reset HEAD --
    last = log -1 HEAD
    visual = log --graph --oneline --all
```

### Useful Aliases

**Essential aliases:**

```bash
# ~/.gitconfig

[alias]
    # ─────────────────────────────────────────
    # Basic shortcuts
    # ─────────────────────────────────────────
    
    co = checkout
    br = branch
    ci = commit
    st = status
    
    # ─────────────────────────────────────────
    # Status shortcuts
    # ─────────────────────────────────────────
    
    s = status -sb              # Short status with branch
    
    # ─────────────────────────────────────────
    # Commit shortcuts
    # ─────────────────────────────────────────
    
    cm = commit -m              # Commit with message
    ca = commit -am             # Add all and commit
    amend = commit --amend      # Amend last commit
    amendne = commit --amend --no-edit  # Amend without editing message
    
    # ─────────────────────────────────────────
    # Log variations
    # ─────────────────────────────────────────
    
    lg = log --graph --oneline --decorate --all
    ls = log --pretty=format:"%C(yellow)%h %C(blue)%ad %C(red)%d %C(reset)%s %C(green)[%cn]" --decorate --date=short
    ll = log --pretty=format:"%C(yellow)%h%C(red)%d %C(reset)%s %C(green)[%cn]" --decorate --numstat
    last = log -1 HEAD --stat
    dl = "!git ll -1"           # Show last commit details
    
    # ─────────────────────────────────────────
    # Diff shortcuts
    # ─────────────────────────────────────────
    
    d = diff
    ds = diff --staged
    dc = diff --cached
    
    # ─────────────────────────────────────────
    # Branch operations
    # ─────────────────────────────────────────
    
    branches = branch -a        # Show all branches
    remotes = remote -v         # Show remotes
    current = rev-parse --abbrev-ref HEAD  # Show current branch
    
    # ─────────────────────────────────────────
    # Undo operations
    # ─────────────────────────────────────────
    
    unstage = reset HEAD --     # Unstage files
    undo = reset --soft HEAD~1  # Undo last commit, keep changes
    discard = checkout --       # Discard changes
    
    # ─────────────────────────────────────────
    # Stash shortcuts
    # ─────────────────────────────────────────
    
    stash-all = stash save --include-untracked
    stash-unapply = !git stash show -p | git apply -R
    
    # ─────────────────────────────────────────
    # Advanced operations
    # ─────────────────────────────────────────
    
    # List contributors with commit counts
    contributors = shortlog -sn
    
    # Show files in a commit
    show-files = "!f() { git diff-tree --no-commit-id --name-only -r $1; }; f"
    
    # Delete merged branches
    cleanup = "!git branch --merged | grep -v '\\*\\|main\\|develop' | xargs -n 1 git branch -d"
    
    # Find commits by commit message
    find = "!f() { git log --all --grep=$1; }; f"
    
    # Find commits by source code
    fc = "!f() { git log --pretty=format:'%C(yellow)%h %C(blue)%ad %C(reset)%s%C(green) [%cn]' --decorate --date=short -S$1; }; f"
    
    # Create new branch and switch
    nb = "!f() { git checkout -b $1; }; f"
    
    # Sync with remote
    sync = !git fetch origin && git rebase origin/main
    
    # Quick commit
    quick = "!f() { git add -A && git commit -m \"$1\"; }; f"
    
    # Pretty log with graph
    tree = log --graph --pretty=format:'%C(auto)%h%d %s %C(black)%C(bold)%cr' --all
    
    # Show ignored files
    ignored = !git ls-files -v | grep "^[[:lower:]]"
    
    # Assume unchanged (useful for config files)
    assume = update-index --assume-unchanged
    unassume = update-index --no-assume-unchanged
    assumed = "!git ls-files -v | grep ^h | cut -c 3-"
```

**Usage examples:**

```bash
# Using aliases

# Status
git s
# On main | +1 -0

# Quick commit
git quick "feat: Add user validation"
# Equivalent to: git add -A && git commit -m "feat: Add user validation"

# Pretty log
git lg
# * a1b2c3d (HEAD -> main) feat: Add validation
# * 9a8b7c6 fix: Correct bug
# * 8a7b6c5 docs: Update README

# Find commits
git find "authentication"
# Shows all commits with "authentication" in message

# Sync with remote
git sync
# Fetches and rebases on origin/main

# Show last commit
git last
# commit a1b2c3d...
# Author: John Doe
# Date: Mon Jan 15 2024
#     feat: Add user validation

# Cleanup merged branches
git cleanup
# Deleted branch: feature/old-feature
# Deleted branch: bugfix/old-bug
```

**Complex alias examples:**

```bash
# ~/.gitconfig

[alias]
    # Show commits in current branch not in main
    new = !git log main..HEAD
    
    # Interactive rebase with specific number of commits
    rb = "!f() { git rebase -i HEAD~$1; }; f"
    # Usage: git rb 5  (rebase last 5 commits)
    
    # Publish current branch to remote
    publish = !git push -u origin $(git current)
    
    # Unpublish (delete remote branch)
    unpublish = !git push origin :$(git current)
    
    # Pull with rebase and autostash
    up = pull --rebase --autostash
    
    # Save current work (stash with message and untracked)
    save = !git stash save --include-untracked
    
    # Restore last stash
    restore = stash pop
    
    # Show what you've done today
    today = log --since="yesterday" --author="$(git config user.name)" --oneline
    
    # Show what changed in last commit
    changed = diff --name-only HEAD~1..HEAD
    
    # Checkout pull request (GitHub)
    pr = "!f() { git fetch origin pull/$1/head:pr-$1 && git checkout pr-$1; }; f"
    # Usage: git pr 123  (checkout PR #123)
```

### Actions/CI Integration

**GitHub Actions workflow for Java:**

```yaml
# .github/workflows/ci.yml
name: Java CI/CD

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main ]

jobs:
  build:
    name: Build and Test
    runs-on: ubuntu-latest
    
    steps:
      - uses: actions/checkout@v3
      
      - name: Set up JDK 17
        uses: actions/setup-java@v3
        with:
          java-version: '17'
          distribution: 'temurin'
          cache: maven
      
      - name: Build with Maven
        run: mvn -B clean package
      
      - name: Run tests
        run: mvn test
      
      - name: Generate coverage report
        run: mvn jacoco:report
      
      - name: Upload coverage to Codecov
        uses: codecov/codecov-action@v3
        with:
          files: ./target/site/jacoco/jacoco.xml
      
      - name: SonarQube Scan
        uses: sonarsource/sonarqube-scan-action@master
        env:
          SONAR_TOKEN: ${{ secrets.SONAR_TOKEN }}
          SONAR_HOST_URL: ${{ secrets.SONAR_HOST_URL }}
      
      - name: Build Docker image
        run: docker build -t myapp:${{ github.sha }} .
      
      - name: Save artifacts
        uses: actions/upload-artifact@v3
        with:
          name: jar-file
          path: target/*.jar
```

```yaml
    - main
```

## Summary

### Git GUIs

- ✅ **GitKraken**: Professional, visual, team features
- ✅ **SourceTree**: Free, powerful, Git Flow integration
- ✅ **GitHub Desktop**: Simple, GitHub-focused
- ✅ **IDE Integration**: IntelliJ IDEA, VS Code
- ✅ **When to use**: GUI for visualization, CLI for automation

### Git Aliases

- ✅ **Basic shortcuts**: co, br, ci, st
- ✅ **Log aliases**: lg, ls, ll for pretty logs
- ✅ **Workflow aliases**: quick, sync, cleanup
- ✅ **Advanced aliases**: pr (checkout PR), rb (interactive rebase)

### GitHub/GitLab Features

- ✅ **Issues**: Bug tracking, feature requests, project management
- ✅ **Project Boards**: Kanban-style workflow
- ✅ **Actions/CI**: Automated testing and deployment
- ✅ **GitHub CLI**: gh pr, gh issue, gh workflow commands
- ✅ **Protected Branches**: Enforce code review and quality
- ✅ **CODEOWNERS**: Require specific team reviews
- ✅ **PR Templates**: Standardize pull request process

**Best Practices:**

- Use GUI for complex visualizations and conflict resolution
- Use CLI for automation and daily operations
- Create aliases for frequently used commands
- Set up proper CODEOWNERS for critical code
- Use PR templates to ensure consistency
- Leverage CI/CD for automated quality checks
- Protect important branches with appropriate rules
