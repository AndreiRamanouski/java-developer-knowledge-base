# Redis Pub/Sub Messaging

## Overview

Redis Pub/Sub provides lightweight, fire-and-forget messaging for real-time communication between application components. Publishers send messages to channels without knowledge of subscribers. Subscribers listen to channels and receive messages. Spring Data Redis provides declarative messaging with @RedisListener and programmatic publishing with RedisTemplate. Ideal for event notifications, cache invalidation, and real-time updates.

**Key Concept**: Redis Pub/Sub is fire-and-forget - messages not persisted, missed by offline subscribers. Use for: real-time notifications, cache invalidation, live updates. NOT for: guaranteed delivery, message queuing, persistent messaging (use Kafka/RabbitMQ instead). Configure listeners with MessageListenerAdapter or @RedisListener. Publish with convertAndSend(). Support pattern matching with wildcards (*).

### Configuration with MessageListenerAdapter

**Redis Listener Container:**

```java
@Configuration
@EnableRedisRepositories
public class RedisPubSubConfig {
    
    /**
     * Redis message listener container
     * Manages listener lifecycle and message dispatching
     */
    @Bean
    public RedisMessageListenerContainer redisMessageListenerContainer(
            RedisConnectionFactory connectionFactory,
            MessageListenerAdapter listenerAdapter) {
        
        RedisMessageListenerContainer container = new RedisMessageListenerContainer();
        
        // Set connection factory
        container.setConnectionFactory(connectionFactory);
        
        // Add message listener for specific channel
        container.addMessageListener(
            listenerAdapter,
            new ChannelTopic("orders")
        );
        
        // Add pattern listener (wildcard)
        container.addMessageListener(
            listenerAdapter,
            new PatternTopic("notifications.*")
        );
        
        return container;
    }
    
    /**
     * Message listener adapter
     * Delegates messages to POJO methods
     */
    @Bean
    public MessageListenerAdapter listenerAdapter(MessageReceiver receiver) {
        MessageListenerAdapter adapter = new MessageListenerAdapter(receiver);
        
        // Set method name to call (default: handleMessage)
        adapter.setDefaultListenerMethod("handleMessage");
        
        // Set serializer for message deserialization
        adapter.setSerializer(new GenericJackson2JsonRedisSerializer());
        
        return adapter;
    }
    
    /**
     * Message receiver POJO
     */
    @Bean
    public MessageReceiver messageReceiver() {
        return new MessageReceiver();
    }
}

/**
 * Message receiver - handles incoming messages
 */
@Slf4j
public class MessageReceiver {
    
    /**

    public void handleMessage(String message, String channel) {
```

```java
        log.info("Cache invalidation request - Channel: {}, Key: {}", channel, cacheKey);
        
        // Extract cache name from channel (e.g., "cache.users" -> "users")
        String cacheName = channel.replace("cache.", "");
        
        // Invalidate cache
        Cache cache = cacheManager.getCache(cacheName);
        if (cache != null) {
            if ("*".equals(cacheKey)) {
                cache.clear();
                log.info("Cleared entire cache: {}", cacheName);
            } else {
                cache.evict(cacheKey);
                log.info("Evicted cache entry - Cache: {}, Key: {}", cacheName, cacheKey);
            }
        }
    }
```

```java
        log.info("User {} activity: {}", userId, event.getActivityType());
        
        // Track activity
        // Could publish to analytics system
    }
    
    /**
     * Cache invalidation with pattern
     */
    @RedisListener(patterns = "cache.invalidate.*")
    public void handleCacheInvalidation(CacheInvalidationEvent event, String channel) {
        String cacheType = channel.substring(channel.lastIndexOf('.') + 1);
        
        log.info("Invalidating {} cache: {}", cacheType, event.getKeys());
        
        // Invalidate specified keys
        event.getKeys().forEach(key -> invalidateCache(cacheType, key));
    }

     * Error handling with try-catch
     */
    @RedisListener(topics = "payment.process")

            log.info("Processing payment: {}", event.getPaymentId());

            orderService.processPayment(event);

            // Publish failure event
            publishPaymentFailure(event.getPaymentId(), e.getMessage());
        }
    }

     * Asynchronous processing
     */

        log.info("Sending email asynchronously to: {}", email.getTo());

        notificationService.sendEmail(email);
    }

        // Publish failure event
```

## 3. Publishing Messages with RedisTemplate

### Basic Publishing

**Simple Message Publisher:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class RedisMessagePublisher {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final StringRedisTemplate stringRedisTemplate;
    
    /**
     * Publish string message to channel
     */
    public void publishStringMessage(String channel, String message) {
        stringRedisTemplate.convertAndSend(channel, message);
        log.info("Published message to {}: {}", channel, message);
    }
    
    /**
     * Publish object message (serialized as JSON)
     */
    public void publishObjectMessage(String channel, Object message) {
        redisTemplate.convertAndSend(channel, message);
        log.info("Published object to {}: {}", channel, message.getClass().getSimpleName());
    }
    
    /**
     * Publish to multiple channels
     */
    public void broadcastMessage(List<String> channels, String message) {
        channels.forEach(channel -> 
            stringRedisTemplate.convertAndSend(channel, message)
        );
        
        log.info("Broadcast message to {} channels", channels.size());
    }
    
    /**
     * Publish with metadata
     */
    public void publishWithMetadata(String channel, Object payload, Map<String, String> metadata) {
        MessageWrapper wrapper = new MessageWrapper(payload, metadata);
        redisTemplate.convertAndSend(channel, wrapper);
        
        log.info("Published wrapped message to {}", channel);
    }
}

@Data
@AllArgsConstructor
@NoArgsConstructor
class MessageWrapper {
    private Object payload;
    private Map<String, String> metadata;
}
```

## 4. Channel Patterns and Wildcards

### Pattern Matching

**Wildcard Patterns:**

```java
@Configuration
public class PatternListenerConfig {
    
    @Bean
    public RedisMessageListenerContainer patternListenerContainer(
            RedisConnectionFactory connectionFactory,
            PatternMessageListener listener) {
        
        RedisMessageListenerContainer container = new RedisMessageListenerContainer();
        container.setConnectionFactory(connectionFactory);
        
        // Single asterisk (*) - matches any characters within a single segment
        container.addMessageListener(
            new MessageListenerAdapter(listener, "handleNotification"),
            new PatternTopic("notifications.*")
        );
        // Matches: notifications.email, notifications.sms
        // Does NOT match: notifications.push.urgent
        
        // Multiple patterns
        container.addMessageListener(
            new MessageListenerAdapter(listener, "handleUserEvent"),
            new PatternTopic("user.*.events")
        );
        // Matches: user.123.events, user.456.events
        
        // Complex patterns
        container.addMessageListener(
            new MessageListenerAdapter(listener, "handleCacheEvent"),
            new PatternTopic("cache.*.*")
        );
        // Matches: cache.users.invalidate, cache.products.update
        
        return container;
    }
}
```

```java
@Component
@Slf4j
public class PatternListenerExamples {
    
    /**
     * All notifications (any type)
     * Pattern: notifications.*
     * Matches: notifications.email, notifications.sms, notifications.push
     */
    @RedisListener(patterns = "notifications.*")
    public void handleAllNotifications(String message, String channel) {
        String type = channel.substring(channel.lastIndexOf('.') + 1);
        log.info("Notification [{}]: {}", type, message);
    }
    
    /**
     * User-specific events
     * Pattern: user.*.activity
     * Matches: user.123.activity, user.456.activity
     */
    @RedisListener(patterns = "user.*.activity")
    public void handleUserActivity(UserActivityEvent event, String channel) {
        String userId = extractSegment(channel, 1);
        log.info("User {} activity: {}", userId, event.getActivityType());
    }
    
    /**
     * Order lifecycle events
     * Pattern: order.*
     * Matches: order.created, order.cancelled, order.completed
     */
    @RedisListener(patterns = "order.*")
    public void handleOrderEvents(String message, String channel) {
        String eventType = channel.substring(channel.lastIndexOf('.') + 1);
        
        log.info("Order event [{}]: {}", eventType, message);
        
        switch (eventType) {
            case "created":
                handleOrderCreated(message);
                break;
            case "cancelled":
                handleOrderCancelled(message);
                break;
            case "completed":
                handleOrderCompleted(message);
                break;
        }
    }
    
    /**
     * Cache operations (all types and entities)
     * Pattern: cache.*.*
     * Matches: cache.users.invalidate, cache.products.update
     */
    @RedisListener(patterns = "cache.*.*")
    public void handleCacheOperations(String message, String channel) {
        String[] parts = channel.split("\\.");
        String entity = parts[1];
        String operation = parts[2];
        
        log.info("Cache operation - Entity: {}, Operation: {}, Data: {}", 
            entity, operation, message);
    }
    
    /**
     * Environment-specific events
     * Pattern: events.prod.*
     * Matches: events.prod.alert, events.prod.warning
     */
    @RedisListener(patterns = "events.${spring.profiles.active}.*")
    public void handleEnvironmentEvents(String message, String channel) {
        log.info("Environment event on {}: {}", channel, message);
    }
    
    /**
     * All system events
     * Pattern: system.**
     * Note: Redis doesn't support **, but you can use multiple patterns
     */
    @RedisListener(patterns = {"system.*", "system.*.*", "system.*.*.*"})
    public void handleSystemEvents(String message, String channel) {
        log.info("System event on {}: {}", channel, message);
    }
    
    private String extractSegment(String channel, int index) {
        String[] parts = channel.split("\\.");
```

```java
@Component
@Slf4j
@RequiredArgsConstructor
class CacheInvalidationListener {
    
    private final CacheManager cacheManager;
    
    /**
     * Listen for cache invalidation events
     */
    @RedisListener(patterns = "cache.invalidate.*")
    public void handleCacheInvalidation(CacheInvalidationMessage message, String channel) {
        // Extract cache name
        String cacheName = channel.substring(channel.lastIndexOf('.') + 1);
        
        Cache cache = cacheManager.getCache(cacheName);
        
        if (cache == null) {
            log.warn("Cache not found: {}", cacheName);
            return;
        }
        
        if (message.getOperation() == CacheOperation.CLEAR) {
            cache.clear();
            log.info("Cleared cache: {}", cacheName);
        } else if (message.getOperation() == CacheOperation.EVICT) {
            message.getKeys().forEach(key -> {
                cache.evict(key);
                log.debug("Evicted cache entry - Cache: {}, Key: {}", cacheName, key);
            });
            
            log.info("Evicted {} entries from cache: {}", message.getKeys().size(), cacheName);
        }
    }
}

@NoArgsConstructor

    private String reason;

        user.setLastName(request.getLastName());
```

## Best Practices Summary

### ✅ DO:

1. **Use for real-time** notifications and updates
2. **Implement error handling** in listeners
3. **Use pattern matching** for flexible subscriptions
4. **Keep messages small** (<1MB recommended)
5. **Use JSON serialization** for interoperability
6. **Monitor subscription** count and message rate
7. **Use async processing** for heavy operations
8. **Combine with WebSocket** for browser updates
9. **Document channel naming** conventions
10. **Test listener error** scenarios

### ❌ DON'T:

1. **Don't rely on delivery** guarantees (fire-and-forget)
2. **Don't use for critical** business operations
3. **Don't expect message** persistence
4. **Don't send large** payloads (use references)
5. **Don't block in listeners** (use @Async)
6. **Don't use for event** sourcing (use Kafka)
7. **Don't forget connection** pool configuration
8. **Don't ignore offline** subscribers (will miss messages)
9. **Don't use for queuing** (no consumer groups)
10. **Don't store state** in messages

## Interview Questions

**Q1: What's the difference between Redis Pub/Sub and message queues like Kafka?**

Redis Pub/Sub: Fire-and-forget, no persistence, messages lost if no subscribers, all subscribers receive all messages, sub-millisecond latency, in-memory. Kafka: Persistent, guaranteed delivery, can replay messages, consumer groups (load balancing), ordering within partition, disk-based. Use Redis for: real-time notifications, cache invalidation, live updates where loss acceptable. Use Kafka for: event sourcing, critical processing, guaranteed delivery, stream processing. Redis simpler, faster. Kafka more reliable, complex.

**Q2: How do you handle message loss in Redis Pub/Sub?**

Redis Pub/Sub is fire-and-forget - if no subscribers or subscriber offline, message lost. Strategies: (1) Hybrid approach - persist critical data elsewhere (DB/Kafka), use Redis only for real-time notification. (2) Idempotent operations - design so message loss doesn't break system. (3) Fallback mechanisms - poll database if real-time update missed. (4) Store notifications in database and use Redis only for instant delivery. Example: Order created → save to DB, publish via Redis. User offline? Sees order when logging in from DB.

**Q3: What are channel patterns and when to use them?**

Pattern matching uses wildcards (*) to subscribe to multiple channels. Single asterisk matches one segment: `notifications.*` matches `notifications.email`, `notifications.sms`. Use for: (1) Category-based routing - subscribe to all notifications of any type. (2) User-specific events - `user.*.activity` matches all users. (3) Dynamic subscriptions - don't need to know all channel names. (4) Simplified configuration - one listener for multiple related channels. Extract metadata from channel name in listener. Example: `cache.*.invalidate` handles all cache types.

**Q4: How do you implement cache invalidation across multiple application instances?**

Problem: Cache update on one instance, other instances have stale data. Solution with Redis Pub/Sub: (1) Update database and local cache. (2) Publish invalidation message to Redis channel `cache.invalidate.users`. (3) All instances subscribe to invalidation channel. (4) Each instance receives message, invalidates its local cache. Benefits: Eventual consistency across instances, minimal latency, simple implementation. Pattern: `cache.invalidate.*` for all caches. Include keys to invalidate or "*" for clear all. All instances stay synchronized.

**Q5: When would you choose Redis Pub/Sub over WebSocket?**

Different purposes. WebSocket: Client-server bidirectional communication, maintains persistent connection, server pushes to browsers/mobile. Redis Pub/Sub: Server-to-server communication, decouples application instances, broadcasts within backend. Typical architecture: Redis Pub/Sub for inter-service communication + WebSocket for browser delivery. Flow: Instance A publishes to Redis → All instances (including A) receive → Each instance pushes to connected WebSocket clients. Redis Pub/Sub enables horizontal scaling of WebSocket servers. Don't choose one over other - use together.

Redis Pub/Sub messaging in Spring Boot:

- ✅ **MessageListenerAdapter** - POJO-based listeners, delegation

- ✅ **Use Cases** - Real-time notifications, cache invalidation, live updates

**Key Takeaway**: Redis Pub/Sub provides lightweight, fire-and-forget messaging perfect for real-time notifications, cache invalidation, and live updates where message loss is acceptable. Configure listeners with @RedisListener or MessageListenerAdapter. Publish with redisTemplate.convertAndSend(). Support pattern matching with wildcards for flexible routing. NOT suitable for guaranteed delivery, persistence, or critical operations (use Kafka instead). Typical latency <1ms, throughput 1M+ msg/sec. Combine with WebSocket for browser updates. Use hybrid approach: Kafka for persistence + Redis for real-time. Best for stateless, ephemeral, broadcast-style messaging.
