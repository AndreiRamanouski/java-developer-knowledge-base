# Redis Performance Optimization

## Overview

Redis performance optimization involves reducing network round trips with pipelining, ensuring atomic operations with Lua scripts, tuning connection pools, optimizing memory usage, and avoiding common anti-patterns. Proper optimization can improve throughput by 10-100x and reduce latency from milliseconds to microseconds. Monitor key metrics with Redis INFO and use appropriate data structures for your use case.

**Key Concept**: Redis bottlenecks: network latency (use pipeline/Lua), memory (optimize data structures, set eviction policies), CPU (avoid slow commands like KEYS). Pipeline reduces round trips from N to 1. Lua scripts execute atomically on server. Tune connection pool: max-active=2x cores, max-idle=50% max-active. Monitor: memory usage, hit rate, evicted keys, slow queries. Avoid: KEYS in production, large values in hashes, unbounded collections.

## 1. Pipeline for Batch Operations

### Understanding Pipelining

**Normal vs Pipelined Operations:**

```
┌──────────────────────────────────────────────────────────────┐
│         Normal Operations vs Pipelining                       │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  NORMAL (3 commands, 3 round trips):                         │
│  Client ──┬── SET key1 ──> Redis                            │
│           │               ─┬─> Response                      │
│           │                │                                 │
│           ├── SET key2 ────┼──> Redis                       │
│           │                ├──> Response                     │
│           │                │                                 │
│           └── SET key3 ────┼──> Redis                       │
│                            └──> Response                     │
│                                                               │
│  Time: 3 x (Network RTT + Redis Execution)                  │
│                                                               │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  PIPELINED (3 commands, 1 round trip):                      │
│  Client ──┬─ SET key1 ──┐                                   │
│           ├─ SET key2 ──┤──> Redis                          │
│           └─ SET key3 ──┘                                    │
│                          │                                   │
│                          ├─ Response 1 ──┐                  │
│                          ├─ Response 2 ──┤─> Client         │
│                          └─ Response 3 ──┘                  │
│                                                               │
│  Time: 1 x Network RTT + 3 x Redis Execution                │
│                                                               │
│  Speedup: ~3x for network-bound operations                  │
└──────────────────────────────────────────────────────────────┘

Network RTT typical: 0.5-2ms (local), 50-200ms (cross-region)
Redis execution: <0.1ms per simple command
```

### Basic Pipelining

**RedisTemplate Pipelining:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class RedisPipelineService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final StringRedisTemplate stringRedisTemplate;
    
    /**
     * Execute multiple operations in pipeline
     */
    public List<Object> executePipelined(List<String> keys, List<String> values) {
        long startTime = System.currentTimeMillis();
        
        List<Object> results = stringRedisTemplate.executePipelined(
            new RedisCallback<Object>() {
                @Override
                public Object doInRedis(RedisConnection connection) {
                    StringRedisConnection stringConn = (StringRedisConnection) connection;
                    
                    for (int i = 0; i < keys.size(); i++) {
                        stringConn.set(keys.get(i), values.get(i));
                    }
                    
                    // Return null - pipeline returns list of results
                    return null;
                }
            }
        );
        
        long duration = System.currentTimeMillis() - startTime;
        log.info("Pipelined {} operations in {}ms", keys.size(), duration);
        
        return results;
    }
    
    /**
     * Pipeline with different commands
     */
    public List<Object> executeMultipleCommands() {
        return stringRedisTemplate.executePipelined(
            new RedisCallback<Object>() {
                @Override
                public Object doInRedis(RedisConnection connection) {
                    StringRedisConnection conn = (StringRedisConnection) connection;
                    
                    // SET operations
                    conn.set("user:1", "John");
                    conn.set("user:2", "Jane");
                    
                    // GET operations
                    conn.get("user:1");
                    
                    // INCR operations
                    conn.incr("counter");
                    
                    // Hash operations
                    conn.hSet("user:1:profile", "email", "john@example.com");
                    
                    return null;
                }
            }
        );
    }
    
    /**
     * Batch cache operations
     */
    public void batchSetCache(Map<String, Object> data) {
        redisTemplate.executePipelined(new RedisCallback<Object>() {
            @Override
            public Object doInRedis(RedisConnection connection) {
                RedisSerializer<String> keySerializer = 
                    (RedisSerializer<String>) redisTemplate.getKeySerializer();
                
                RedisSerializer<Object> valueSerializer = 
                    (RedisSerializer<Object>) redisTemplate.getValueSerializer();
                
                data.forEach((key, value) -> {
                    byte[] rawKey = keySerializer.serialize(key);
                    byte[] rawValue = valueSerializer.serialize(value);
                    
                    connection.set(rawKey, rawValue);
                    connection.expire(rawKey, 3600); // 1 hour TTL
                });
                
                return null;
            }
        });
        
        log.info("Batch cached {} items", data.size());
    }
}
```

### Advanced Pipelining Patterns

**Bulk Operations Service:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class BulkOperationsService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final StringRedisTemplate stringRedisTemplate;
    
    /**
     * Bulk GET with pipeline
     */
    public Map<String, String> bulkGet(List<String> keys) {
        List<Object> results = stringRedisTemplate.executePipelined(
            new RedisCallback<Object>() {
                @Override
                public Object doInRedis(RedisConnection connection) {
                    StringRedisConnection conn = (StringRedisConnection) connection;
                    
                    keys.forEach(conn::get);
                    
                    return null;
                }
            }
        );
        
        Map<String, String> resultMap = new HashMap<>();
        for (int i = 0; i < keys.size(); i++) {
            String value = (String) results.get(i);
            if (value != null) {
                resultMap.put(keys.get(i), value);
            }
        }
        
        return resultMap;
    }
    
    /**
     * Bulk increment counters
     */
    public Map<String, Long> bulkIncrement(List<String> counterKeys) {
        List<Object> results = stringRedisTemplate.executePipelined(
            new RedisCallback<Object>() {
                @Override
                public Object doInRedis(RedisConnection connection) {
                    StringRedisConnection conn = (StringRedisConnection) connection;
                    
                    counterKeys.forEach(conn::incr);
                    
                    return null;
                }
            }
        );
        
        Map<String, Long> counterMap = new HashMap<>();
        for (int i = 0; i < counterKeys.size(); i++) {
            counterMap.put(counterKeys.get(i), (Long) results.get(i));
        }
        
        return counterMap;
    }
    
    /**
     * Bulk delete with pipeline
     */
    public void bulkDelete(List<String> keys) {
        // Chunk into batches of 1000 for very large deletes
        int batchSize = 1000;
        
        for (int i = 0; i < keys.size(); i += batchSize) {
            int end = Math.min(i + batchSize, keys.size());
            List<String> batch = keys.subList(i, end);
            
            stringRedisTemplate.executePipelined(
                new RedisCallback<Object>() {
                    @Override
                    public Object doInRedis(RedisConnection connection) {
                        StringRedisConnection conn = (StringRedisConnection) connection;
                        
                        batch.forEach(conn::del);
                        
                        return null;
                    }
                }
            );
        }
        
        log.info("Bulk deleted {} keys", keys.size());
    }
    
    /**
     * Bulk cache invalidation with pipeline
     */
    public void invalidateMultipleCaches(Map<String, List<String>> cacheKeysMap) {
        redisTemplate.executePipelined(new RedisCallback<Object>() {
            @Override
            public Object doInRedis(RedisConnection connection) {
                RedisSerializer<String> serializer = 
                    (RedisSerializer<String>) redisTemplate.getKeySerializer();
                
                cacheKeysMap.forEach((cacheName, keys) -> {
                    keys.forEach(key -> {
                        String fullKey = cacheName + "::" + key;
                        byte[] rawKey = serializer.serialize(fullKey);
                        connection.del(rawKey);
                    });
                });
                
                return null;
            }
        });
    }
    
    /**
     * Batch user data import
     */
    @Transactional
    public void importUsers(List<User> users) {
        long startTime = System.currentTimeMillis();
        
        redisTemplate.executePipelined(new RedisCallback<Object>() {
            @Override
            public Object doInRedis(RedisConnection connection) {
                users.forEach(user -> {
                    String key = "user:" + user.getId();
                    
                    // Store user as hash
                    Map<String, String> userData = Map.of(
                        "id", user.getId().toString(),
                        "username", user.getUsername(),
                        "email", user.getEmail(),
                        "status", user.getStatus()
                    );
                    
                    userData.forEach((field, value) -> {
                        connection.hSet(
                            key.getBytes(),
                            field.getBytes(),
                            value.getBytes()
                        );
                    });
                    
                    // Set expiration
                    connection.expire(key.getBytes(), 3600);
                });
                
                return null;
            }
        });
        
        long duration = System.currentTimeMillis() - startTime;
        log.info("Imported {} users in {}ms ({} users/sec)", 
            users.size(), duration, users.size() * 1000 / duration);
    }
}
```

## 2. Lua Scripts for Atomic Operations

### Why Lua Scripts?

**Lua Benefits:**

```
┌──────────────────────────────────────────────────────────────┐
│              Lua Scripts Advantages                           │
├──────────────────────────────────────────────────────────────┤
│                                                               │
│  ✅ Atomic Execution                                         │
│     - Entire script runs as single unit                      │
│     - No other commands can interleave                       │
│     - No race conditions                                     │
│                                                               │
│  ✅ Server-Side Execution                                    │
│     - Reduces network round trips                            │
│     - Multiple operations in single call                     │
│     - Lower latency                                          │
│                                                               │
│  ✅ Complex Logic                                            │
│     - Conditional operations                                 │
│     - Loops and iterations                                   │
│     - Multiple data structure operations                     │
│                                                               │
│  ✅ Consistency                                              │
│     - Guaranteed execution order                             │
│     - All operations succeed or fail together                │
│                                                               │
│  Example: Rate Limiting                                      │
│  Without Lua (3 round trips, race condition):               │
│    1. GET counter                                            │
│    2. Check if < limit                                       │
│    3. INCR counter                                           │
│                                                               │
│  With Lua (1 round trip, atomic):                           │
│    1. GET + CHECK + INCR in single script                   │
└──────────────────────────────────────────────────────────────┘
```

### Basic Lua Scripts

**Simple Lua Script Examples:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class LuaScriptService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final StringRedisTemplate stringRedisTemplate;
    
    /**
     * Simple increment with maximum value
     */
    public Long incrementWithMax(String key, long increment, long maxValue) {
        String script = 
            "local current = redis.call('GET', KEYS[1]) " +
            "if current then " +
            "  current = tonumber(current) " +
            "else " +
            "  current = 0 " +
            "end " +
            "local newValue = current + tonumber(ARGV[1]) " +
            "if newValue <= tonumber(ARGV[2]) then " +
            "  redis.call('SET', KEYS[1], newValue) " +
            "  return newValue " +
            "else " +
            "  return -1 " +
            "end";
        
        RedisScript<Long> redisScript = RedisScript.of(script, Long.class);
        
        Long result = stringRedisTemplate.execute(
            redisScript,
            Collections.singletonList(key),
            String.valueOf(increment),
            String.valueOf(maxValue)
        );
        
        return result;
    }
    
    /**
     * Get and delete atomically
     */
    public String getAndDelete(String key) {
        String script = 
            "local value = redis.call('GET', KEYS[1]) " +
            "if value then " +
            "  redis.call('DEL', KEYS[1]) " +
            "end " +
            "return value";
        
        RedisScript<String> redisScript = RedisScript.of(script, String.class);
        
        return stringRedisTemplate.execute(
            redisScript,
            Collections.singletonList(key)
        );
    }
    
    /**
     * Set with conditional logic
     */
    public boolean setIfGreater(String key, long value) {
        String script = 
            "local current = redis.call('GET', KEYS[1]) " +
            "local newValue = tonumber(ARGV[1]) " +
            "if not current or tonumber(current) < newValue then " +
            "  redis.call('SET', KEYS[1], newValue) " +
            "  return 1 " +
            "else " +
            "  return 0 " +
            "end";
        
        RedisScript<Long> redisScript = RedisScript.of(script, Long.class);
        
        Long result = stringRedisTemplate.execute(
            redisScript,
            Collections.singletonList(key),
            String.valueOf(value)
        );
        
        return result != null && result == 1;
    }
}
```

### Advanced Lua Scripts

**Production Lua Scripts:**

```java
@Component
@Slf4j
public class AdvancedLuaScripts {
    
    /**
     * Rate limiting with sliding window
     */
    public static class SlidingWindowRateLimiter {
        
        private final StringRedisTemplate redisTemplate;
        private final RedisScript<Long> script;
        
        public SlidingWindowRateLimiter(StringRedisTemplate redisTemplate) {
            this.redisTemplate = redisTemplate;
            
            String scriptText = 
                "local key = KEYS[1] " +
                "local limit = tonumber(ARGV[1]) " +
                "local window = tonumber(ARGV[2]) " +
                "local now = tonumber(ARGV[3]) " +
                "local clearBefore = now - window " +
                "" +
                "redis.call('ZREMRANGEBYSCORE', key, 0, clearBefore) " +
                "local count = redis.call('ZCARD', key) " +
                "" +
                "if count < limit then " +
                "  redis.call('ZADD', key, now, now) " +
                "  redis.call('EXPIRE', key, window) " +
                "  return 1 " +
                "else " +
                "  return 0 " +
                "end";
            
            this.script = RedisScript.of(scriptText, Long.class);
        }
        
        public boolean allowRequest(String userId, int maxRequests, int windowSeconds) {
            String key = "rate_limit:" + userId;
            long now = System.currentTimeMillis();
            
            Long result = redisTemplate.execute(
                script,
                Collections.singletonList(key),
                String.valueOf(maxRequests),
                String.valueOf(windowSeconds * 1000),
                String.valueOf(now)
            );
            
            return result != null && result == 1;
        }
    }
    
    /**
     * Distributed counter with sharding
     */
    public static class ShardedCounter {
        
        private final StringRedisTemplate redisTemplate;
        private final RedisScript<Long> incrScript;
        private final RedisScript<Long> getScript;
        private final int shardCount;
        
        public ShardedCounter(StringRedisTemplate redisTemplate, int shardCount) {
            this.redisTemplate = redisTemplate;
            this.shardCount = shardCount;
            
            // Increment script
            String incrScriptText = 
                "local baseKey = KEYS[1] " +
                "local shardCount = tonumber(ARGV[1]) " +
                "local increment = tonumber(ARGV[2]) " +
                "local shard = math.random(0, shardCount - 1) " +
                "local shardKey = baseKey .. ':' .. shard " +
                "return redis.call('INCRBY', shardKey, increment)";
            
            this.incrScript = RedisScript.of(incrScriptText, Long.class);
            
            // Get total script
            String getScriptText = 
                "local baseKey = KEYS[1] " +
                "local shardCount = tonumber(ARGV[1]) " +
                "local total = 0 " +
                "for i = 0, shardCount - 1 do " +
                "  local shardKey = baseKey .. ':' .. i " +
                "  local value = redis.call('GET', shardKey) " +
                "  if value then " +
                "    total = total + tonumber(value) " +
                "  end " +
                "end " +
                "return total";
            
            this.getScript = RedisScript.of(getScriptText, Long.class);
        }
        
        public Long increment(String counterName, long value) {
            return redisTemplate.execute(
                incrScript,
                Collections.singletonList(counterName),
                String.valueOf(shardCount),
                String.valueOf(value)
            );
        }
        
        public Long getTotal(String counterName) {
            return redisTemplate.execute(
                getScript,
                Collections.singletonList(counterName),
                String.valueOf(shardCount)
            );
        }
    }
    
    /**
     * Leaderboard update with TTL
     */
    public static class LeaderboardManager {
        
        private final StringRedisTemplate redisTemplate;
        private final RedisScript<Long> updateScript;
        
        public LeaderboardManager(StringRedisTemplate redisTemplate) {
            this.redisTemplate = redisTemplate;
            
            String scriptText = 
                "local leaderboard = KEYS[1] " +
                "local userId = ARGV[1] " +
                "local score = tonumber(ARGV[2]) " +
                "local ttl = tonumber(ARGV[3]) " +
                "" +
                "local currentScore = redis.call('ZSCORE', leaderboard, userId) " +
                "if not currentScore or tonumber(currentScore) < score then " +
                "  redis.call('ZADD', leaderboard, score, userId) " +
                "  redis.call('EXPIRE', leaderboard, ttl) " +
                "  return 1 " +
                "else " +
                "  return 0 " +
                "end";
            
            this.updateScript = RedisScript.of(scriptText, Long.class);
        }
        
        public boolean updateScore(String leaderboardName, String userId, 
                                   double score, int ttlSeconds) {
            Long result = redisTemplate.execute(
                updateScript,
                Collections.singletonList(leaderboardName),
                userId,
                String.valueOf(score),
                String.valueOf(ttlSeconds)
            );
            
            return result != null && result == 1;
        }
    }
    
    /**
     * Conditional cache update
     */
    public static class ConditionalCache {
        
        private final RedisTemplate<String, Object> redisTemplate;
        private final RedisScript<Long> updateScript;
        
        public ConditionalCache(RedisTemplate<String, Object> redisTemplate) {
            this.redisTemplate = redisTemplate;
            
            String scriptText = 
                "local key = KEYS[1] " +
                "local newValue = ARGV[1] " +
                "local version = tonumber(ARGV[2]) " +
                "local ttl = tonumber(ARGV[3]) " +
                "" +
                "local currentVersion = redis.call('HGET', key, 'version') " +
                "if not currentVersion or tonumber(currentVersion) < version then " +
                "  redis.call('HSET', key, 'value', newValue) " +
                "  redis.call('HSET', key, 'version', version) " +
                "  redis.call('EXPIRE', key, ttl) " +
                "  return 1 " +
                "else " +
                "  return 0 " +
                "end";
            
            this.updateScript = RedisScript.of(scriptText, Long.class);
        }
        
        public boolean updateIfNewer(String key, Object value, long version, int ttl) {
            RedisSerializer<Object> serializer = 
                (RedisSerializer<Object>) redisTemplate.getValueSerializer();
            
            byte[] serializedValue = serializer.serialize(value);
            String base64Value = Base64.getEncoder()
                .encodeToString(serializedValue);
            
            Long result = redisTemplate.execute(
                updateScript,
                Collections.singletonList(key),
                base64Value,
                String.valueOf(version),
                String.valueOf(ttl)
            );
            
            return result != null && result == 1;
        }
    }
}
```

## 3. Connection Pooling Tuning

### Pool Configuration

**Optimal Pool Settings:**

```yaml
spring:
  data:
    redis:
      host: localhost
      port: 6379
      
      lettuce:
        pool:
          # Maximum number of connections in pool
          # Formula: 2 x number of CPU cores
          # For 8 cores: 16 connections
          max-active: 16
          
          # Maximum idle connections
          # Formula: 50% of max-active
          max-idle: 8
          
          # Minimum idle connections
          # Keep some connections warm
          min-idle: 4
          
          # Maximum wait time for connection
          # Fail fast if pool exhausted
          max-wait: 2000ms
          
          # Test connections on borrow
          test-on-borrow: true
          
          # Test idle connections
          test-while-idle: true
          
          # Eviction interval
          time-between-eviction-runs: 60000ms
        
        # Command timeout
        # Should be higher than typical operation time
        timeout: 2000ms
        
        # Shutdown timeout
        shutdown-timeout: 100ms
```

**Java Configuration:**

```java
@Configuration
public class RedisPoolConfig {
    
    @Value("${redis.pool.max-active:16}")
    private int maxActive;
    
    @Value("${redis.pool.max-idle:8}")
    private int maxIdle;
    
    @Value("${redis.pool.min-idle:4}")
    private int minIdle;
    
    /**
     * Optimized connection pool configuration
     */
    @Bean
    public LettuceConnectionFactory redisConnectionFactory() {
        // Pool configuration
        GenericObjectPoolConfig<Object> poolConfig = new GenericObjectPoolConfig<>();
        
        // Connection limits
        poolConfig.setMaxTotal(maxActive);
        poolConfig.setMaxIdle(maxIdle);
        poolConfig.setMinIdle(minIdle);
        
        // Wait configuration
        poolConfig.setMaxWaitMillis(2000);
        poolConfig.setBlockWhenExhausted(true);
        
        // Validation
        poolConfig.setTestOnBorrow(true);
        poolConfig.setTestOnReturn(false);
        poolConfig.setTestWhileIdle(true);
        
        // Eviction configuration
        poolConfig.setTimeBetweenEvictionRunsMillis(60000);
        poolConfig.setMinEvictableIdleTimeMillis(300000);  // 5 minutes
        poolConfig.setNumTestsPerEvictionRun(3);
        
        // JMX monitoring
        poolConfig.setJmxEnabled(true);
        poolConfig.setJmxNamePrefix("redis-pool");
        
        // Lettuce client configuration
        LettucePoolingClientConfiguration clientConfig = 
            LettucePoolingClientConfiguration.builder()
                .poolConfig(poolConfig)
                .commandTimeout(Duration.ofSeconds(2))
                .shutdownTimeout(Duration.ofMillis(100))
                .build();
        
        // Redis configuration
        RedisStandaloneConfiguration redisConfig = 
            new RedisStandaloneConfiguration("localhost", 6379);
        
        return new LettuceConnectionFactory(redisConfig, clientConfig);
    }
}
```

```java
    /**
     * Monitor pool health
```

## 6. Common Anti-Patterns to Avoid

### Anti-Pattern Examples

**What NOT to Do:**

```java
@Service
@Slf4j
public class RedisAntiPatterns {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final StringRedisTemplate stringRedisTemplate;
    
    public RedisAntiPatterns(
            RedisTemplate<String, Object> redisTemplate,
            StringRedisTemplate stringRedisTemplate) {
        this.redisTemplate = redisTemplate;
        this.stringRedisTemplate = stringRedisTemplate;
    }
    
    /**
     * ❌ ANTI-PATTERN 1: Using KEYS in production
     * Problem: Blocks Redis, O(N) where N = all keys
     */
    public void antiPattern_Keys() {
        // NEVER DO THIS IN PRODUCTION
        Set<String> keys = stringRedisTemplate.keys("user:*");
        
        // With 1 million keys, this can block Redis for seconds
    }
    
    /**
     * ✅ CORRECT: Use SCAN instead
     */
    public void correct_Scan() {
        Set<String> allKeys = new HashSet<>();
        
        stringRedisTemplate.execute((RedisCallback<Object>) connection -> {
            Cursor<byte[]> cursor = connection.scan(
                ScanOptions.scanOptions()
                    .match("user:*")
                    .count(100)
                    .build()
            );
            
            while (cursor.hasNext()) {
                allKeys.add(new String(cursor.next()));
            }
            
            cursor.close();
            return null;
        });
    }
    
    /**
     * ❌ ANTI-PATTERN 2: Large values in single key
     * Problem: Memory fragmentation, slow serialization
     */
    public void antiPattern_LargeValue() {
        // Storing 10MB object in single key
        byte[] largeData = new byte[10 * 1024 * 1024];
        redisTemplate.opsForValue().set("large:data", largeData);
    }
    
    /**
     * ✅ CORRECT: Split large data into chunks
     */
    public void correct_ChunkedData() {
        byte[] largeData = new byte[10 * 1024 * 1024];
        int chunkSize = 1024 * 1024;  // 1MB chunks
        
        for (int i = 0; i < largeData.length; i += chunkSize) {
            int end = Math.min(i + chunkSize, largeData.length);
            byte[] chunk = Arrays.copyOfRange(largeData, i, end);
            
            stringRedisTemplate.opsForValue()
                .set("large:data:chunk:" + (i / chunkSize), 
                     Base64.getEncoder().encodeToString(chunk));
        }
    }
    
    /**
     * ❌ ANTI-PATTERN 3: N+1 queries
     * Problem: Multiple round trips
     */
    public Map<String, User> antiPattern_N_Plus_1(List<Long> userIds) {
        Map<String, User> users = new HashMap<>();
        
        // N queries - very slow
        for (Long id : userIds) {
            User user = (User) redisTemplate.opsForValue().get("user:" + id);
            if (user != null) {
                users.put("user:" + id, user);
            }
        }
        
        return users;
    }
    
    /**
     * ✅ CORRECT: Use pipeline or MGET
     */
    public Map<String, User> correct_BatchGet(List<Long> userIds) {
        List<String> keys = userIds.stream()
            .map(id -> "user:" + id)
            .collect(Collectors.toList());
        
        List<Object> values = redisTemplate.opsForValue().multiGet(keys);
        
        Map<String, User> users = new HashMap<>();
        for (int i = 0; i < keys.size(); i++) {
            if (values.get(i) != null) {
                users.put(keys.get(i), (User) values.get(i));
            }
        }
        
        return users;
    }
    
    /**
     * ❌ ANTI-PATTERN 4: Unbounded collections
     * Problem: Memory leak
     */
    public void antiPattern_UnboundedList(String userId, String activity) {
        // List grows forever - memory leak
        stringRedisTemplate.opsForList().rightPush("activities:" + userId, activity);
    }
    
    /**
     * ✅ CORRECT: Bounded collections with TTL
     */
    public void correct_BoundedList(String userId, String activity) {
        String key = "activities:" + userId;
        
        stringRedisTemplate.opsForList().leftPush(key, activity);
        stringRedisTemplate.opsForList().trim(key, 0, 99);  // Keep only 100
        stringRedisTemplate.expire(key, Duration.ofDays(7));  // TTL
    }
    
    /**
     * ❌ ANTI-PATTERN 5: Not setting TTL
     * Problem: Memory never freed
     */
    public void antiPattern_NoTTL(String key, String value) {
        stringRedisTemplate.opsForValue().set(key, value);
        // Never expires - will stay in Redis forever
    }
    
    /**
     * ✅ CORRECT: Always set appropriate TTL
     */
    public void correct_WithTTL(String key, String value) {
        stringRedisTemplate.opsForValue().set(key, value, Duration.ofHours(1));
    }
    
    /**
     * ❌ ANTI-PATTERN 6: Hot key problem
     * Problem: Single key accessed millions of times
     */
    public void antiPattern_HotKey() {
        // Everyone hits same key - bottleneck
        String config = stringRedisTemplate.opsForValue().get("app:config");
    }
    
    /**
     * ✅ CORRECT: Shard hot keys or cache locally
     */
    public void correct_ShardedKey(String userId) {
        // Shard across multiple keys
        int shard = Math.abs(userId.hashCode() % 10);
        String key = "app:config:" + shard;
        
        String config = stringRedisTemplate.opsForValue().get(key);
    }
    
    /**
     * ❌ ANTI-PATTERN 7: Using Redis as primary database
     * Problem: Data loss if Redis fails
     */
    public void antiPattern_PrimaryDatabase(Order order) {
        // Only storing in Redis - data loss risk
        redisTemplate.opsForValue().set("order:" + order.getId(), order);
    }
    
    /**
     * ✅ CORRECT: Redis as cache, database as source of truth
     */
    @Transactional
    public void correct_CachePattern(Order order) {
        // 1. Save to database (source of truth)
        // orderRepository.save(order);
        
        // 2. Cache in Redis
        redisTemplate.opsForValue().set(
            "order:" + order.getId(),
            order,
            Duration.ofHours(1)
        );
    }
    
    /**
     * ❌ ANTI-PATTERN 8: Ignoring connection errors
     * Problem: Silent failures
     */
    public void antiPattern_NoErrorHandling(String key) {
        stringRedisTemplate.opsForValue().get(key);
        // No error handling - fails silently
    }
    
    /**
     * ✅ CORRECT: Handle connection errors gracefully
     */
    public String correct_ErrorHandling(String key) {
        try {
            return stringRedisTemplate.opsForValue().get(key);
            
        } catch (RedisConnectionFailureException e) {
            log.error("Redis connection failed - falling back to database", e);
            // Fallback to database
            return fetchFromDatabase(key);
            
        } catch (Exception e) {
            log.error("Redis operation failed", e);
            return null;
        }
    }
    
    /**
     * ❌ ANTI-PATTERN 9: Blocking operations in high-traffic code
     * Problem: Slow operations block threads
     */
    public void antiPattern_BlockingOperation() {
        // BLPOP blocks thread - don't use in request handlers
        List<String> result = stringRedisTemplate.opsForList()
            .leftPop("queue", Duration.ofSeconds(30));
    }
    
    /**
     * ✅ CORRECT: Use async for blocking operations
     */
    @Async
    public CompletableFuture<String> correct_AsyncOperation() {
        List<String> result = stringRedisTemplate.opsForList()
            .leftPop("queue", Duration.ofSeconds(30));
        
        return CompletableFuture.completedFuture(
            result != null && !result.isEmpty() ? result.get(0) : null
        );
    }
    
    private String fetchFromDatabase(String key) {
        // Database fallback logic
        return null;
    }
```

### ✅ DO:

1. **Use pipeline** for batch operations (5-100x speedup)
2. **Use Lua scripts** for atomic multi-step operations
3. **Tune connection pool** (max-active = 2x cores)
4. **Set TTL on all keys** - prevent memory leaks
5. **Use SCAN instead of KEYS** - never block Redis
6. **Monitor hit rate** - target >80%
7. **Use appropriate data structures** - optimize memory
8. **Set maxmemory** with eviction policy
9. **Handle connection errors** - implement fallbacks

### ❌ DON'T:

2. **Don't store large values** (>1MB per key)
3. **Don't create unbounded** collections
4. **Don't skip TTL** - always set expiration
5. **Don't use as primary** database (use as cache)

8. **Don't block threads** with BLPOP in handlers
9. **Don't ignore memory** usage (monitor and alert)
10. **Don't forget error** handling (connection failures)

## Interview Questions

**Q1: How does pipelining improve Redis performance?**

Pipelining batches multiple commands into single network round trip. Normal: 3 commands = 3 RTTs (e.g., 3ms total). Pipelined: 3 commands = 1 RTT (1ms total). Speedup: network latency eliminated for N-1 commands. Typical improvement: 5-100x for network-bound operations. Network RTT often dominates (0.5-2ms local, 50-200ms cross-region) vs Redis execution (<0.1ms). Use for: batch SET/GET, bulk deletes, cache warming. Implementation: executePipelined() in Spring. Returns list of results. Critical for high-throughput applications.

**Q2: When should you use Lua scripts instead of pipelining?**

Use Lua for: (1) Atomic operations - entire script runs without interleaving, prevents race conditions. (2) Conditional logic - if/else, loops that depend on Redis data. (3) Complex multi-step operations - read, modify, write. (4) Read-then-write patterns - rate limiting, leaderboards. Use pipeline for: simple batch operations without conditionals. Example: Rate limiting needs Lua (GET counter, check limit, INCR atomically). Batch cache warming uses pipeline (just SETs). Lua = atomicity + server-side logic. Pipeline = batch network optimization.

**Q3: What are optimal connection pool settings?**

Formula: max-active = 2x CPU cores (e.g., 16 for 8 cores), max-idle = 50% of max-active (e.g., 8), min-idle = 25-50% of max-active (e.g., 4). Rationale: max-active prevents pool exhaustion, max-idle keeps warm connections, min-idle ensures baseline availability. Additional settings: max-wait = 2s (fail fast), test-on-borrow = true, test-while-idle = true, eviction interval = 60s. Too small = connection exhaustion, latency spikes. Too large = resource waste, connection overhead. Monitor: pool utilization, wait time, connection errors.

**Q4: How do you optimize Redis memory usage?**

Strategies: (1) Set maxmemory with eviction policy (allkeys-lru for cache). (2) Always set TTL - prevent leaks. (3) Use hashes for objects (vs serialized strings) - smaller. (4) Bound collections - LTRIM lists, limit sorted sets. (5) Avoid large values (>1MB) - chunk if needed. (6) Use integers for counters (not strings). (7) Compress large values (gzip). (8) Monitor evicted_keys - if high, increase memory or lower TTLs. Typical savings: hashes vs strings = 30-50% reduction. Example: user object as hash (200 bytes) vs JSON string (500 bytes).

**Q5: What are the most critical Redis anti-patterns to avoid?**

Top anti-patterns: (1) KEYS in production - blocks Redis, O(N). Use SCAN. (2) N+1 queries - multiple RTTs. Use pipeline/MGET. (3) No TTL - memory leaks. Always set expiration. (4) Unbounded collections - lists/sets grow forever. Use LTRIM, limit size. (5) Large values (>1MB) - memory fragmentation. Chunk data. (6) Hot key - single key bottleneck. Shard or replicate. (7) Redis as primary DB - data loss risk. Use as cache only. (8) Ignoring errors - silent failures. Implement fallbacks. (9) Blocking operations in handlers - thread starvation. Use async.
