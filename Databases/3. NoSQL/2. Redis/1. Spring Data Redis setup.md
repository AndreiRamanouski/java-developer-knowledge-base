# Spring Data Redis Setup

## Overview

Spring Data Redis provides easy integration with Redis, a high-performance in-memory data store used for caching, session management, real-time analytics, and message queuing. Spring Boot's auto-configuration makes Redis integration straightforward while providing flexibility for advanced configurations.

**Key Concept**: Spring Data Redis abstracts Redis operations through RedisTemplate and repositories. Choose Lettuce (default, reactive-ready) over Jedis for better performance and features. Use StringRedisTemplate for string-based caching, RedisTemplate with serializers for complex objects. Configure connection pooling for production environments.

### Auto-Configuration Overview

**What Spring Boot Auto-Configures:**

```java
/**
 * Spring Boot automatically configures:
 * 
 * 1. RedisConnectionFactory (LettuceConnectionFactory by default)
 * 2. RedisTemplate<Object, Object>
 * 3. StringRedisTemplate (RedisTemplate<String, String>)
 * 4. Connection pooling (if commons-pool2 is on classpath)
 * 5. Redis repositories support
 * 
 * You can override these with custom beans.
 */

@Configuration
@ConditionalOnClass(RedisOperations.class)
@EnableConfigurationProperties(RedisProperties.class)
public class RedisAutoConfiguration {
    
    @Bean
    @ConditionalOnMissingBean(name = "redisTemplate")
    public RedisTemplate<Object, Object> redisTemplate(
            RedisConnectionFactory redisConnectionFactory) {
        RedisTemplate<Object, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(redisConnectionFactory);
        return template;
    }
    
    @Bean
    @ConditionalOnMissingBean
    public StringRedisTemplate stringRedisTemplate(
            RedisConnectionFactory redisConnectionFactory) {
        return new StringRedisTemplate(redisConnectionFactory);
    }
}
```

### Lettuce Configuration (Default)

**Using Lettuce Client:**

```java
/**
 * Lettuce is the default Redis client in Spring Boot 2.x+
 * No additional configuration needed for basic usage
 */

@Configuration
public class LettuceRedisConfig {
    
    /**
     * Lettuce with connection pooling
     * Requires commons-pool2 dependency
     */
    @Bean
    public LettuceConnectionFactory lettuceConnectionFactory() {
        // Pool configuration
        GenericObjectPoolConfig<Object> poolConfig = new GenericObjectPoolConfig<>();
        poolConfig.setMaxTotal(20);         // Maximum active connections
        poolConfig.setMaxIdle(10);          // Maximum idle connections
        poolConfig.setMinIdle(5);           // Minimum idle connections
        poolConfig.setMaxWait(Duration.ofSeconds(2));  // Max wait for connection
        poolConfig.setTestOnBorrow(true);   // Test connection when borrowed
        poolConfig.setTestOnReturn(true);   // Test connection when returned
        poolConfig.setTestWhileIdle(true);  // Test idle connections
        
        LettucePoolingClientConfiguration clientConfig = 
            LettucePoolingClientConfiguration.builder()
                .poolConfig(poolConfig)
                .commandTimeout(Duration.ofSeconds(2))
                .shutdownTimeout(Duration.ofMillis(100))
                .build();
        
        // Redis standalone configuration
        RedisStandaloneConfiguration serverConfig = 
            new RedisStandaloneConfiguration();
        serverConfig.setHostName("localhost");
        serverConfig.setPort(6379);
        serverConfig.setPassword("your-password");  // Optional
        serverConfig.setDatabase(0);
        
        return new LettuceConnectionFactory(serverConfig, clientConfig);
    }
    
    /**
     * Lettuce with advanced SSL/TLS configuration
     */
    @Bean
    public LettuceConnectionFactory secureLettuceConnectionFactory() {
        // SSL configuration
        LettuceClientConfiguration clientConfig = 
            LettuceClientConfiguration.builder()
                .useSsl()
                .disablePeerVerification()  // For self-signed certs (dev only)
                .commandTimeout(Duration.ofSeconds(2))
                .build();
        
        RedisStandaloneConfiguration serverConfig = 
            new RedisStandaloneConfiguration("localhost", 6380);
        
        return new LettuceConnectionFactory(serverConfig, clientConfig);
    }
    
    /**
     * Lettuce with custom read/write configuration
     */
    @Bean
    public LettuceConnectionFactory readWriteLettuceFactory() {
        LettuceClientConfiguration clientConfig = 
            LettuceClientConfiguration.builder()
                .readFrom(ReadFrom.REPLICA_PREFERRED)  // Read from replicas
                .commandTimeout(Duration.ofSeconds(2))
                .build();
        
        RedisStandaloneConfiguration serverConfig = 
            new RedisStandaloneConfiguration("localhost", 6379);
        
        return new LettuceConnectionFactory(serverConfig, clientConfig);
    }
}
```

## 3. RedisTemplate Configuration

### Basic RedisTemplate Setup

**Custom RedisTemplate Configuration:**

```java
@Configuration
public class RedisTemplateConfig {
    
    /**
     * Default RedisTemplate with String keys and JSON values
     * Most common configuration for caching objects
     */
    @Bean
    public RedisTemplate<String, Object> redisTemplate(
            RedisConnectionFactory connectionFactory) {
        
        RedisTemplate<String, Object> template = new RedisTemplate<>();
        template.setConnectionFactory(connectionFactory);
        
        // JSON serializer for values
        Jackson2JsonRedisSerializer<Object> jsonSerializer = 
            new Jackson2JsonRedisSerializer<>(Object.class);
        
        // Configure ObjectMapper for JSON serialization
        ObjectMapper objectMapper = new ObjectMapper();
        objectMapper.setVisibility(PropertyAccessor.ALL, JsonAutoDetect.Visibility.ANY);
        objectMapper.activateDefaultTyping(
            objectMapper.getPolymorphicTypeValidator(),
            ObjectMapper.DefaultTyping.NON_FINAL,
            JsonTypeInfo.As.PROPERTY
        );
        jsonSerializer.setObjectMapper(objectMapper);
        
        // String serializer for keys
        StringRedisSerializer stringSerializer = new StringRedisSerializer();
        
        // Configure serializers
        template.setKeySerializer(stringSerializer);           // Key: String
        template.setValueSerializer(jsonSerializer);           // Value: JSON
        template.setHashKeySerializer(stringSerializer);       // Hash key: String
        template.setHashValueSerializer(jsonSerializer);       // Hash value: JSON
        
        template.afterPropertiesSet();
        return template;
    }
    
    /**
     * RedisTemplate for caching domain objects
     */
    @Bean
    public RedisTemplate<String, User> userRedisTemplate(
            RedisConnectionFactory connectionFactory) {
        
        RedisTemplate<String, User> template = new RedisTemplate<>();
        template.setConnectionFactory(connectionFactory);
        
        // JSON serializer for User objects
        Jackson2JsonRedisSerializer<User> serializer = 
            new Jackson2JsonRedisSerializer<>(User.class);
        
        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(serializer);
        template.setHashKeySerializer(new StringRedisSerializer());
        template.setHashValueSerializer(serializer);
        
        template.afterPropertiesSet();
        return template;
    }
    
    /**
     * RedisTemplate with binary serialization (faster but not human-readable)
     */
    @Bean
    public RedisTemplate<String, byte[]> binaryRedisTemplate(
            RedisConnectionFactory connectionFactory) {
        
        RedisTemplate<String, byte[]> template = new RedisTemplate<>();
        template.setConnectionFactory(connectionFactory);
        
        template.setKeySerializer(new StringRedisSerializer());
        template.setValueSerializer(new ByteArrayRedisSerializer());
        
        template.afterPropertiesSet();
        return template;
    }
}
```

### RedisTemplate Operations

**Using RedisTemplate:**

```java
@Service
@RequiredArgsConstructor
public class RedisService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * Value Operations (String data type)
     */
    public void valueOperations() {
        ValueOperations<String, Object> ops = redisTemplate.opsForValue();
        
        // Set value
        ops.set("user:1", new User("John", "john@example.com"));
        
        // Set with expiration
        ops.set("session:abc", "data", Duration.ofMinutes(30));
        
        // Set if absent (like setnx)
        Boolean set = ops.setIfAbsent("lock:resource", "locked", Duration.ofSeconds(10));
        
        // Get value
        User user = (User) ops.get("user:1");
        
        // Increment
        Long counter = ops.increment("page:views", 1);
        
        // Multi-get
        List<Object> values = ops.multiGet(Arrays.asList("key1", "key2", "key3"));
    }
    
    /**
     * Hash Operations (Hash data type)
     */
    public void hashOperations() {
        HashOperations<String, String, Object> ops = redisTemplate.opsForHash();
        
        // Put field
        ops.put("user:1", "name", "John");
        ops.put("user:1", "email", "john@example.com");
        
        // Put all
        Map<String, Object> userData = Map.of(
            "name", "John",
            "email", "john@example.com",
            "age", 30
        );
        ops.putAll("user:1", userData);
        
        // Get field
        Object name = ops.get("user:1", "name");
        
        // Get all
        Map<String, Object> allData = ops.entries("user:1");
        
        // Increment hash field
        Long age = ops.increment("user:1", "age", 1);
        
        // Check field exists
        Boolean exists = ops.hasKey("user:1", "email");
        
        // Delete field
        ops.delete("user:1", "tempField");
    }
    
    /**
     * List Operations (List data type)
     */
    public void listOperations() {
        ListOperations<String, Object> ops = redisTemplate.opsForList();
        
        // Push to right (append)
        ops.rightPush("queue:tasks", "task1");
        ops.rightPush("queue:tasks", "task2");
        
        // Push to left (prepend)
        ops.leftPush("queue:tasks", "urgent-task");
        
        // Pop from left (dequeue)
        Object task = ops.leftPop("queue:tasks");
        
        // Pop from right
        Object lastTask = ops.rightPop("queue:tasks");
        
        // Get range
        List<Object> tasks = ops.range("queue:tasks", 0, -1);  // All items
        
        // Get by index
        Object firstTask = ops.index("queue:tasks", 0);
        
        // List size
        Long size = ops.size("queue:tasks");
        
        // Trim list
        ops.trim("queue:tasks", 0, 99);  // Keep first 100 items
    }
    
    /**
     * Set Operations (Set data type)
     */
    public void setOperations() {
        SetOperations<String, Object> ops = redisTemplate.opsForSet();
        
        // Add members
        ops.add("tags", "java", "spring", "redis");
        
        // Get all members
        Set<Object> members = ops.members("tags");
        
        // Check membership
        Boolean isMember = ops.isMember("tags", "java");
        
        // Remove member
        ops.remove("tags", "redis");
        
        // Pop random member
        Object randomTag = ops.pop("tags");
        
        // Set size
        Long size = ops.size("tags");
        
        // Set operations
        Set<Object> union = ops.union("set1", "set2");
        Set<Object> intersect = ops.intersect("set1", "set2");
        Set<Object> diff = ops.difference("set1", "set2");
    }
    
    /**
     * Sorted Set Operations (ZSet data type)
     */
    public void sortedSetOperations() {
        ZSetOperations<String, Object> ops = redisTemplate.opsForZSet();
        
        // Add with score
        ops.add("leaderboard", "player1", 100);
        ops.add("leaderboard", "player2", 150);
        ops.add("leaderboard", "player3", 120);
        
        // Get range by rank (ascending)
        Set<Object> topPlayers = ops.range("leaderboard", 0, 2);  // Top 3
        
        // Get range by rank (descending)
        Set<Object> bottomPlayers = ops.reverseRange("leaderboard", 0, 2);
        
        // Get range by score
        Set<Object> midRange = ops.rangeByScore("leaderboard", 100, 150);
        
        // Get score
        Double score = ops.score("leaderboard", "player1");
        
        // Increment score
        Double newScore = ops.incrementScore("leaderboard", "player1", 10);
        
        // Get rank
        Long rank = ops.rank("leaderboard", "player1");  // 0-indexed
        Long reverseRank = ops.reverseRank("leaderboard", "player1");
        
        // Remove member
        ops.remove("leaderboard", "player2");
        
        // Count
        Long count = ops.count("leaderboard", 100, 150);
    }
    
    /**
     * Key Operations
     */
    public void keyOperations() {
        // Delete key
        redisTemplate.delete("key");
        
        // Delete multiple keys
        redisTemplate.delete(Arrays.asList("key1", "key2", "key3"));
        
        // Check key exists
        Boolean exists = redisTemplate.hasKey("key");
        
        // Set expiration
        redisTemplate.expire("key", Duration.ofMinutes(30));
        
        // Set expiration at specific time
        redisTemplate.expireAt("key", Instant.now().plus(1, ChronoUnit.HOURS));
        
        // Get TTL
        Long ttl = redisTemplate.getExpire("key", TimeUnit.SECONDS);
        
        // Persist (remove expiration)
        redisTemplate.persist("key");
        
        // Rename key
        redisTemplate.rename("oldKey", "newKey");
        
        // Get keys matching pattern
        Set<String> keys = redisTemplate.keys("user:*");
    }
}
```

```java
@Configuration
public class RedisPoolConfig {
    
    @Value("${spring.data.redis.host}")
    private String host;
    
    @Value("${spring.data.redis.port}")
    private int port;
    
    @Value("${spring.data.redis.password:}")
    private String password;

     * Production-ready Lettuce pool configuration
     */
    @Bean
    public LettuceConnectionFactory redisConnectionFactory() {
        // Pool configuration
        GenericObjectPoolConfig<Object> poolConfig = createPoolConfig();
        
        // Client configuration with pooling
        LettucePoolingClientConfiguration clientConfig = 
            LettucePoolingClientConfiguration.builder()
                .poolConfig(poolConfig)
                .commandTimeout(Duration.ofSeconds(3))
                .shutdownTimeout(Duration.ofMillis(200))
                .build();

            new RedisStandaloneConfiguration(host, port);
        
        if (password != null && !password.isEmpty()) {
            serverConfig.setPassword(password);
        }
        
        return new LettuceConnectionFactory(serverConfig, clientConfig);
    }

     * Create optimized pool configuration
     */

        GenericObjectPoolConfig<Object> config = new GenericObjectPoolConfig<>();
        
        // Pool size
        config.setMaxTotal(16);    // Max connections in pool
        config.setMaxIdle(8);      // Max idle connections
        config.setMinIdle(4);      // Min idle connections (kept warm)

        config.setBlockWhenExhausted(true);  // Block when pool exhausted

        config.setTimeBetweenEvictionRuns(Duration.ofMinutes(1));
        config.setMinEvictableIdleTime(Duration.ofMinutes(5));

        config.setSoftMinEvictableIdleTime(Duration.ofMinutes(3));

        config.setTestOnBorrow(true);    // Test before use

        config.setLifo(true);
```

1. **Use Lettuce** (default) - better performance and features

### ❌ DON'T:

2. **Don't skip connection pooling** in production

4. **Don't forget timeout configuration** - can hang indefinitely

7. **Don't ignore pool monitoring** - critical for debugging
8. **Don't hardcode credentials** - use environment variables
9. **Don't skip SSL/TLS** for production deployments

## Interview Questions

**Q1: What's the difference between Lettuce and Jedis Redis clients?**

Lettuce (default since Spring Boot 2.0): Thread-safe, uses Netty (NIO), supports reactive/async operations, single connection reusable. Jedis: Not thread-safe (requires pooling), blocking I/O, simpler API, more mature. Use Lettuce for: modern apps, reactive programming, better performance. Use Jedis only for: legacy systems, specific Jedis features. Lettuce is recommended for all new applications.

**Q2: When should you use StringRedisTemplate vs RedisTemplate?**

StringRedisTemplate: For string-only operations (keys and values both strings), human-readable in Redis CLI, counters, session IDs, configuration values. RedisTemplate<String, Object>: For complex objects, automatic JSON serialization, domain object caching, type-safe operations. StringRedisTemplate is actually RedisTemplate<String, String>. Choose based on data: strings → StringRedisTemplate, objects → RedisTemplate with JSON serializer.

**Q3: Why is connection pooling important for Redis?**

Connection pooling: (1) Reuses connections (avoids creation overhead), (2) Limits concurrent connections, (3) Provides health monitoring. For Lettuce: Optional but recommended for high-throughput (Lettuce connections are thread-safe). For Jedis: REQUIRED (Jedis connections not thread-safe). Configure with commons-pool2: max-active (max connections), max-idle (kept warm), min-idle (pre-created), max-wait (timeout). Typical production: max-active=16-32, max-idle=8-16.

**Q4: What's the difference between Redis Sentinel and Redis Cluster?**

Sentinel: High availability with automatic failover. Architecture: 1 master + N replicas + 3+ sentinels. Use for: datasets <100GB, read scaling sufficient, simpler setup. Provides automatic failover but single master (write bottleneck). Cluster: Horizontal scaling with sharding. Architecture: 3+ masters + replicas, hash slots for sharding. Use for: datasets >100GB, high write throughput, distributed writes. Provides both scaling and failover but more complex.

**Q5: How do you configure Redis serialization in Spring Boot?**

Configure RedisTemplate with serializers: (1) StringRedisSerializer for keys (human-readable), (2) GenericJackson2JsonRedisSerializer for values (JSON with type info), (3) Configure ObjectMapper for JSON settings. Avoid default JdkSerializationRedisSerializer (not human-readable, large size). Recommended: `template.setKeySerializer(new StringRedisSerializer()); template.setValueSerializer(new GenericJackson2JsonRedisSerializer());` This gives readable keys and compact JSON values.

## Summary

Spring Data Redis setup essentials:

- ✅ **Dependencies** - spring-boot-starter-data-redis includes Lettuce
- ✅ **Lettuce vs Jedis** - Use Lettuce (thread-safe, reactive, better performance)
- ✅ **RedisTemplate** - Configure JSON serializers for production
- ✅ **StringRedisTemplate** - Use for simple string caching
- ✅ **Connection Pooling** - Essential for production (commons-pool2)
- ✅ **Sentinel/Cluster** - Sentinel for HA, Cluster for scaling

**Key Takeaway**: Spring Boot auto-configures Redis with sensible defaults. Use Lettuce (default) with connection pooling for production. Configure JSON serialization instead of default JDK serialization. StringRedisTemplate for simple caching, RedisTemplate<String, Object> for complex objects. Use Sentinel for high availability with automatic failover, Cluster for horizontal scaling with sharding. Always set timeouts and monitor pool health.
