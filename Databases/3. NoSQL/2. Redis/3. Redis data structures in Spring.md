# Redis Data Structures in Spring

## Overview

Redis provides five core data structures that enable efficient solutions for various use cases. Spring Data Redis exposes these through RedisTemplate operations methods. Understanding which data structure to use is crucial for optimal performance and correct semantics. Each structure has specific strengths and ideal use cases.

**Key Concept**: Strings for simple key-value caching, Lists for queues and timelines, Sets for unique collections and relationships, Sorted Sets for rankings and leaderboards, Hashes for objects with multiple fields. Choose based on access patterns: random access → Hashes, ordering → Lists/Sorted Sets, uniqueness → Sets, simple storage → Strings.

## 1. Strings - opsForValue()

### Overview and Use Cases

**String Data Structure:**

```
Redis Strings are binary-safe sequences of bytes (up to 512MB)
Can store: text, numbers, serialized objects, binary data

Use Cases:
✅ Simple key-value caching
✅ Session data
✅ Counters and metrics
✅ Rate limiting
✅ Distributed locks
✅ Feature flags
✅ Serialized objects (JSON)
```

### Basic String Operations

**ValueOperations Interface:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class StringOperationsService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    private final StringRedisTemplate stringRedisTemplate;
    
    /**
     * SET and GET operations
     */
    public void basicOperations() {
        ValueOperations<String, Object> ops = redisTemplate.opsForValue();
        
        // Set value
        ops.set("user:1:name", "John Doe");
        
        // Set with expiration
        ops.set("session:abc", "active", Duration.ofMinutes(30));
        
        // Get value
        String name = (String) ops.get("user:1:name");
        
        // Set if absent (SETNX)
        Boolean wasSet = ops.setIfAbsent("lock:resource", "locked");
        
        // Set if present
        Boolean wasUpdated = ops.setIfPresent("user:1:name", "Jane Doe");
        
        // Get and set atomically
        String oldValue = (String) ops.getAndSet("counter", "0");
        
        // Multi-set
        Map<String, Object> values = Map.of(
            "user:1:name", "John",
            "user:1:email", "john@example.com",
            "user:1:age", 30
        );
        ops.multiSet(values);
        
        // Multi-get
        List<String> keys = List.of("user:1:name", "user:1:email", "user:1:age");
        List<Object> results = ops.multiGet(keys);
        
        // Delete
        redisTemplate.delete("user:1:name");
    }
    
    /**
     * Counter operations (INCR/DECR)
     */
    public void counterOperations() {
        ValueOperations<String, Object> ops = redisTemplate.opsForValue();
        
        // Increment by 1
        Long views = ops.increment("page:views");
        
        // Increment by amount
        Long score = ops.increment("user:1:score", 10);
        
        // Decrement
        Long remaining = ops.decrement("inventory:item:1");
        
        // Decrement by amount
        Long stock = ops.decrement("inventory:item:1", 5);
        
        // Increment double
        Double rating = ops.increment("product:1:rating", 0.5);
    }
    
    /**
     * Bit operations
     */
    public void bitOperations() {
        ValueOperations<String, Object> ops = redisTemplate.opsForValue();
        
        // Set bit
        ops.setBit("user:online:2024-01-15", 123, true);  // User 123 online
        
        // Get bit
        Boolean isOnline = ops.getBit("user:online:2024-01-15", 123);
        
        // Append
        Integer length = ops.append("log:file", "New log entry\n");
        
        // Get range (substring)
        String substring = ops.get("log:file", 0, 100);
        
        // Set range
        ops.set("message", "Hello", 6);  // Overwrites from position 6
    }
}
```

### Real-World String Use Cases

**Practical Examples:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class StringUseCases {
    
    private final StringRedisTemplate stringRedisTemplate;
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * 1. Session Management
     */
    public void saveSession(String sessionId, SessionData sessionData) {
        String key = "session:" + sessionId;
        
        // Store serialized session
        redisTemplate.opsForValue().set(
            key,
            sessionData,
            Duration.ofMinutes(30)
        );
    }
    
    public SessionData getSession(String sessionId) {
        String key = "session:" + sessionId;
        return (SessionData) redisTemplate.opsForValue().get(key);
    }
    
    /**
     * 2. Rate Limiting (Token Bucket)
     */
    public boolean checkRateLimit(String userId, int maxRequests) {
        String key = "rate:limit:" + userId;
        
        // Increment counter
        Long requests = stringRedisTemplate.opsForValue().increment(key);
        
        if (requests == 1) {
            // First request - set expiration
            stringRedisTemplate.expire(key, Duration.ofMinutes(1));
        }
        
        return requests <= maxRequests;
    }
    
    /**
     * 3. Distributed Lock
     */
    public boolean acquireLock(String resourceId, String lockValue, Duration timeout) {
        String key = "lock:" + resourceId;
        
        Boolean acquired = stringRedisTemplate.opsForValue()
            .setIfAbsent(key, lockValue, timeout);
        
        return Boolean.TRUE.equals(acquired);
    }
    
    public void releaseLock(String resourceId, String lockValue) {
        String key = "lock:" + resourceId;
        String currentValue = stringRedisTemplate.opsForValue().get(key);
        
        if (lockValue.equals(currentValue)) {
            stringRedisTemplate.delete(key);
        }
    }
    
    /**
     * 4. Page View Counter
     */
    public void incrementPageViews(String pageId) {
        String key = "page:views:" + pageId;
        stringRedisTemplate.opsForValue().increment(key);
    }
    
    public Long getPageViews(String pageId) {
        String key = "page:views:" + pageId;
        String value = stringRedisTemplate.opsForValue().get(key);
        return value != null ? Long.parseLong(value) : 0L;
    }
    
    /**
     * 5. Feature Flags
     */
    public void setFeatureFlag(String feature, boolean enabled) {
        String key = "feature:" + feature;
        stringRedisTemplate.opsForValue().set(key, String.valueOf(enabled));
    }
    
    public boolean isFeatureEnabled(String feature) {
        String key = "feature:" + feature;
        String value = stringRedisTemplate.opsForValue().get(key);
        return "true".equalsIgnoreCase(value);
    }
    
    /**
     * 6. User Presence (Last Seen)
     */
    public void updateUserPresence(String userId) {
        String key = "user:lastseen:" + userId;
        stringRedisTemplate.opsForValue().set(
            key,
            String.valueOf(System.currentTimeMillis()),
            Duration.ofDays(7)
        );
    }
    
    public Long getUserLastSeen(String userId) {
        String key = "user:lastseen:" + userId;
        String value = stringRedisTemplate.opsForValue().get(key);
        return value != null ? Long.parseLong(value) : null;
    }
    
    /**
     * 7. Cache with TTL
     */
    public void cacheData(String key, Object data, Duration ttl) {
        redisTemplate.opsForValue().set(key, data, ttl);
    }
    
    public Object getCachedData(String key) {
        return redisTemplate.opsForValue().get(key);
    }
}
```

## 2. Lists - opsForList()

### Overview and Use Cases

**List Data Structure:**

```
Redis Lists are linked lists of strings
Insertion/deletion at head/tail: O(1)
Access by index: O(N)

Use Cases:
✅ Message queues
✅ Activity feeds / timelines
✅ Recently viewed items
✅ Task queues
✅ Notifications
✅ Chat messages
✅ Undo/redo stacks
```

### Basic List Operations

**ListOperations Interface:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class ListOperationsService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * Push and Pop operations
     */
    public void basicListOperations() {
        ListOperations<String, Object> ops = redisTemplate.opsForList();
        
        // Left push (prepend) - returns list length
        Long length = ops.leftPush("queue", "task1");
        
        // Right push (append)
        ops.rightPush("queue", "task2");
        
        // Push multiple values
        ops.leftPushAll("queue", "task3", "task4", "task5");
        ops.rightPushAll("queue", "task6", "task7");
        
        // Push if list exists
        ops.leftPushIfPresent("queue", "task0");
        ops.rightPushIfPresent("queue", "task8");
        
        // Push before/after pivot value
        ops.leftPush("queue", "task1", "task0.5");  // Insert before task1
        
        // Left pop (remove and return first element)
        Object first = ops.leftPop("queue");
        
        // Right pop (remove and return last element)
        Object last = ops.rightPop("queue");
        
        // Blocking pop (waits if empty)
        Object item = ops.leftPop("queue", Duration.ofSeconds(5));
        
        // List length
        Long size = ops.size("queue");
    }
    
    /**
     * Range and index operations
     */
    public void rangeOperations() {
        ListOperations<String, Object> ops = redisTemplate.opsForList();
        
        // Get range (0-based index, inclusive)
        List<Object> all = ops.range("queue", 0, -1);  // All items
        List<Object> first10 = ops.range("queue", 0, 9);  // First 10
        
        // Get element by index
        Object element = ops.index("queue", 0);  // First element
        Object lastElement = ops.index("queue", -1);  // Last element
        
        // Set element by index
        ops.set("queue", 0, "updated-task");
        
        // Trim list (keep only range)
        ops.trim("queue", 0, 99);  // Keep first 100 items
        
        // Remove elements
        Long removed = ops.remove("queue", 0, "task1");  // Remove all "task1"
        ops.remove("queue", 1, "task2");  // Remove first occurrence
        ops.remove("queue", -2, "task3");  // Remove last 2 occurrences
    }
    
    /**
     * Blocking operations (for queues)
     */
    public void blockingOperations() {
        ListOperations<String, Object> ops = redisTemplate.opsForList();
        
        // Blocking left pop
        Object item = ops.leftPop("queue", Duration.ofSeconds(10));
        
        // Blocking right pop
        item = ops.rightPop("queue", Duration.ofSeconds(10));
        
        // Right pop from source, left push to destination (atomically)
        Object moved = ops.rightPopAndLeftPush("source", "destination");
        
        // Blocking version
        moved = ops.rightPopAndLeftPush(
            "source",
            "destination",
            Duration.ofSeconds(5)
        );
    }
}
```

### Real-World List Use Cases

**Practical Examples:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class ListUseCases {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * 1. Message Queue (FIFO)
     */
    public void enqueueMessage(String queueName, Message message) {
        redisTemplate.opsForList().rightPush(queueName, message);
        log.info("Enqueued message to {}", queueName);
    }
    
    public Message dequeueMessage(String queueName) {
        // Blocking dequeue with 5 second timeout
        Object message = redisTemplate.opsForList()
            .leftPop(queueName, Duration.ofSeconds(5));
        
        return (Message) message;
    }
    
    public long getQueueSize(String queueName) {
        Long size = redisTemplate.opsForList().size(queueName);
        return size != null ? size : 0;
    }
    
    /**
     * 2. Recent Activity Feed
     */
    public void addActivity(String userId, Activity activity) {
        String key = "feed:" + userId;
        
        // Add to front of list
        redisTemplate.opsForList().leftPush(key, activity);
        
        // Keep only recent 100 activities
        redisTemplate.opsForList().trim(key, 0, 99);
    }
    
    public List<Activity> getRecentActivities(String userId, int limit) {
        String key = "feed:" + userId;
        
        List<Object> activities = redisTemplate.opsForList()
            .range(key, 0, limit - 1);
        
        return activities.stream()
            .map(obj -> (Activity) obj)
            .collect(Collectors.toList());
    }
    
    /**
     * 3. Recently Viewed Products
     */
    public void addRecentlyViewed(String userId, String productId) {
        String key = "recent:views:" + userId;
        
        // Remove if already exists
        redisTemplate.opsForList().remove(key, 0, productId);
        
        // Add to front
        redisTemplate.opsForList().leftPush(key, productId);
        
        // Keep only 20 most recent
        redisTemplate.opsForList().trim(key, 0, 19);
        
        // Set expiration
        redisTemplate.expire(key, Duration.ofDays(30));
    }
    
    public List<String> getRecentlyViewed(String userId) {
        String key = "recent:views:" + userId;
        
        List<Object> products = redisTemplate.opsForList().range(key, 0, -1);
        
        return products.stream()
            .map(Object::toString)
            .collect(Collectors.toList());
    }
    
    /**
     * 4. Task Queue with Priority
     */
    public void addHighPriorityTask(Task task) {
        // Add to front for high priority
        redisTemplate.opsForList().leftPush("tasks", task);
    }
    
    public void addLowPriorityTask(Task task) {
        // Add to end for low priority
        redisTemplate.opsForList().rightPush("tasks", task);
    }
    
    public Task getNextTask() {
        // Always pop from front
        return (Task) redisTemplate.opsForList().leftPop("tasks");
    }
    
    /**
     * 5. Notification Queue
     */
    public void sendNotification(String userId, Notification notification) {
        String key = "notifications:" + userId;
        
        redisTemplate.opsForList().rightPush(key, notification);
        
        // Keep only last 50 notifications
        redisTemplate.opsForList().trim(key, -50, -1);
    }
    
    public List<Notification> getNotifications(String userId, int limit) {
        String key = "notifications:" + userId;
        
        List<Object> notifications = redisTemplate.opsForList()
            .range(key, 0, limit - 1);
        
        return notifications.stream()
            .map(obj -> (Notification) obj)
            .collect(Collectors.toList());
    }
    
    public void clearNotifications(String userId) {
        String key = "notifications:" + userId;
        redisTemplate.delete(key);
    }
    
    /**
     * 6. Chat Messages
     */
    public void addMessage(String chatId, ChatMessage message) {
        String key = "chat:" + chatId;
        
        redisTemplate.opsForList().rightPush(key, message);
        
        // Keep messages for 7 days
        redisTemplate.expire(key, Duration.ofDays(7));
    }
    
    public List<ChatMessage> getMessages(String chatId, int page, int size) {
        String key = "chat:" + chatId;
        
        int start = page * size;
        int end = start + size - 1;
        
        List<Object> messages = redisTemplate.opsForList().range(key, start, end);
        
        return messages.stream()
            .map(obj -> (ChatMessage) obj)
            .collect(Collectors.toList());
    }
}
```

## 3. Sets - opsForSet()

### Overview and Use Cases

**Set Data Structure:**

```
Redis Sets are unordered collections of unique strings
Add/Remove/Check membership: O(1)
Set operations (union, intersection, difference): O(N)

Use Cases:
✅ Tags and categories
✅ User relationships (followers/following)
✅ Unique visitors tracking
✅ Voting systems
✅ Access control lists
✅ Social graphs
✅ Lottery/random selection
```

### Basic Set Operations

**SetOperations Interface:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class SetOperationsService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * Basic set operations
     */
    public void basicSetOperations() {
        SetOperations<String, Object> ops = redisTemplate.opsForSet();
        
        // Add members
        Long added = ops.add("tags", "java", "spring", "redis");
        
        // Remove members
        Long removed = ops.remove("tags", "redis");
        
        // Check membership
        Boolean isMember = ops.isMember("tags", "java");
        
        // Get all members
        Set<Object> members = ops.members("tags");
        
        // Get random member (don't remove)
        Object random = ops.randomMember("tags");
        
        // Get multiple random members
        List<Object> randomMembers = ops.randomMembers("tags", 3);
        
        // Get distinct random members
        Set<Object> distinctRandom = ops.distinctRandomMembers("tags", 2);
        
        // Pop random member (remove and return)
        Object popped = ops.pop("tags");
        
        // Pop multiple
        List<Object> poppedList = ops.pop("tags", 2);
        
        // Set size
        Long size = ops.size("tags");
        
        // Move member between sets
        Boolean moved = ops.move("sourceSet", "value", "destinationSet");
    }
    
    /**
     * Set operations (union, intersection, difference)
     */
    public void setOperations() {
        SetOperations<String, Object> ops = redisTemplate.opsForSet();
        
        // Union (all elements from both sets)
        Set<Object> union = ops.union("set1", "set2");
        Set<Object> multiUnion = ops.union("set1", List.of("set2", "set3"));
        
        // Union and store result
        Long unionSize = ops.unionAndStore("set1", "set2", "unionResult");
        
        // Intersection (common elements)
        Set<Object> intersect = ops.intersect("set1", "set2");
        Set<Object> multiIntersect = ops.intersect("set1", List.of("set2", "set3"));
        
        // Intersection and store
        ops.intersectAndStore("set1", "set2", "intersectResult");
        
        // Difference (elements in set1 but not in set2)
        Set<Object> diff = ops.difference("set1", "set2");
        Set<Object> multiDiff = ops.difference("set1", List.of("set2", "set3"));
        
        // Difference and store
        ops.differenceAndStore("set1", "set2", "diffResult");
    }
    
    /**
     * Scan operation (for large sets)
     */
    public void scanSet() {
        SetOperations<String, Object> ops = redisTemplate.opsForSet();
        
        // Scan with cursor (better for large sets)
        Cursor<Object> cursor = ops.scan("largeSet", 
            ScanOptions.scanOptions().match("user:*").count(100).build());
        
        while (cursor.hasNext()) {
            Object member = cursor.next();
            // Process member
        }
        
        cursor.close();
    }
}
```

## 4. Sorted Sets - opsForZSet()

### Overview and Use Cases

**Sorted Set Data Structure:**

```
Redis Sorted Sets are sets where each member has a score
Members unique, scores can repeat
Sorted by score (ascending)
Add/Remove: O(log(N))
Range queries: O(log(N)+M)

Use Cases:
✅ Leaderboards and rankings
✅ Priority queues
✅ Time-series data
✅ Auto-complete
✅ Rate limiting (sliding window)
✅ Top-N queries
✅ Scheduled tasks
```

### Basic Sorted Set Operations

**ZSetOperations Interface:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class SortedSetOperationsService {
    
    private final RedisTemplate<String, Object> redisTemplate;
    
    /**
     * Basic sorted set operations
     */
    public void basicSortedSetOperations() {
        ZSetOperations<String, Object> ops = redisTemplate.opsForZSet();
        
        // Add with score
        Boolean added = ops.add("leaderboard", "player1", 100.0);
        
        // Add multiple
        Set<ZSetOperations.TypedTuple<Object>> tuples = Set.of(
            ZSetOperations.TypedTuple.of("player2", 150.0),
```

## 5. Hashes - opsForHash()

### Overview and Use Cases

**Hash Data Structure:**

```
Redis Hashes are maps of field-value pairs
Like a mini Redis database inside a key
Field operations: O(1)
Good for objects with multiple attributes

Use Cases:
✅ User profiles
✅ Product details
✅ Session data
✅ Configuration settings
✅ Shopping cart items
✅ Real-time analytics
✅ Object caching
```

```java
    public void basicHashOperations() {

        ops.put("user:1", "name", "John Doe");
        ops.put("user:1", "email", "john@example.com");

            "name", "John Doe",
            "email", "john@example.com",

        );
```

## Best Practices Summary

### ✅ DO:

1. **Choose based on access patterns** - not data type
2. **Use Hashes for objects** with multiple fields
3. **Use Sorted Sets for rankings** and time-series
4. **Use Lists for queues** and chronological data
5. **Use Sets for uniqueness** and relationships
6. **Use Strings for simple** key-value caching
7. **Set appropriate TTLs** for all data
8. **Use SCAN for large** collections, not KEYS
9. **Consider memory usage** for data structure choice
10. **Batch operations** when possible (MGET, MSET)

### ❌ DON'T:

1. **Don't use Lists** for random access (O(N))
2. **Don't fetch entire** large collections (use pagination)
3. **Don't use KEYS** in production (use SCAN)
4. **Don't store large values** in Strings (use Hashes)
5. **Don't ignore** data structure overhead
6. **Don't use Sets** when order matters (use Sorted Sets)
7. **Don't forget to cleanup** old data
8. **Don't serialize unnecessarily** - use native structures
9. **Don't mix concerns** in single key
10. **Don't over-engineer** - start simple

## Interview Questions

**Q1: When should you use a Hash instead of multiple Strings?**

Use Hash when: (1) Object has 5+ fields, (2) Need to update individual fields, (3) Want memory efficiency (25 bytes/field vs 50+ bytes/key), (4) Need to fetch specific fields. Use Strings when: (1) < 5 fields, (2) Always access entire object, (3) Need simplicity. Example: User profile with name, email, age → Hash saves memory and allows partial updates like `HSET user:1 email new@email.com`.

**Q2: What's the difference between List and Sorted Set for time-series data?**

List: Chronological order by insertion, O(1) push/pop at ends, O(N) range queries, simple. Sorted Set: Sorted by timestamp (score), O(log N) insertions, O(log N + M) range queries, can query by time range, easy cleanup of old data. Use List for: simple timelines, FIFO queues. Use Sorted Set for: time-based queries, scheduled tasks, cleanup by time range. Sorted Set better for complex time queries but slightly more overhead.

**Q3: How do you choose between Set and List?**

Set: Unordered, unique members, O(1) add/remove/check, set operations (union/intersect). Use for: tags, followers, unique visitors, voting. List: Ordered, duplicates allowed, O(1) at ends O(N) in middle, queue operations. Use for: message queues, activity feeds, recent items, chat history. Key decision: Need uniqueness? → Set. Need order? → List or Sorted Set. Need both? → Sorted Set.

**Q4: What are the performance implications of different data structures?**

String GET/SET: O(1), best for simple cache. List push/pop: O(1) at ends, O(N) for index access - avoid LINDEX on large lists. Set add/remove/check: O(1), set operations O(N). Sorted Set: O(log N) for most operations, best for ranked data. Hash field ops: O(1), efficient for objects. Memory: Hash most efficient for multi-field objects (25 bytes/field vs 50+/key). Consider sharding for large collections.

**Q5: How do you implement a leaderboard system?**

Use Sorted Set - ideal for leaderboards. Score represents ranking metric. Operations: `ZADD leaderboard userId score` to add/update, `ZINCRBY leaderboard userId 10` to increment, `ZREVRANGE leaderboard 0 9 WITHSCORES` for top 10, `ZREVRANK leaderboard userId` for user's rank. Efficient: O(log N) updates, O(log N + M) range queries. Can have multiple leaderboards (daily, weekly, all-time) and use ZUNIONSTORE for combined rankings.

## Summary

Redis data structures in Spring Boot:

- ✅ **Strings** - Simple caching, counters, locks (opsForValue)
- ✅ **Lists** - Queues, timelines, recent items (opsForList)
- ✅ **Sets** - Unique items, tags, relationships (opsForSet)
- ✅ **Sorted Sets** - Leaderboards, rankings, time-series (opsForZSet)
- ✅ **Hashes** - Objects with fields, carts, profiles (opsForHash)
- ✅ **Selection** - Choose based on access patterns and operations needed

**Key Takeaway**: Each Redis data structure has specific strengths. Use Strings for simple key-value, Lists for ordered collections and queues, Sets for unique members and relationships, Sorted Sets for rankings and time-based data, Hashes for objects with multiple fields. Choose based on access patterns: random access → Hash, ordering → List/Sorted Set, uniqueness → Set, simple → String. Consider performance: String/Hash O(1), List O(1) at ends, Set O(1) membership, Sorted Set O(log N). Memory efficiency: Hash best for multi-field objects (25 bytes/field vs 50+ bytes/string).
