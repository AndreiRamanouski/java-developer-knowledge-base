# Transactions in MongoDB

## Overview

MongoDB supports multi-document ACID transactions starting from version 4.0 (replica sets) and 4.2 (sharded clusters). Transactions provide atomicity across multiple documents and collections, ensuring data consistency in complex operations. However, transactions have performance costs and should be used judiciously.

**Key Concept**: Use transactions when you need atomicity across multiple documents or collections. For single-document operations, MongoDB's atomic document updates are sufficient and faster. Transactions require replica sets and add latency - design your schema to minimize transaction needs.

---

## 1. Multi-Document ACID Transactions

### ACID Properties in MongoDB

**Understanding ACID:**

```
A - Atomicity: All operations succeed or all fail
C - Consistency: Database moves from one valid state to another
I - Isolation: Concurrent transactions don't interfere
D - Durability: Committed data persists after system failure

MongoDB provides these guarantees for:
- Single document operations (always ACID)
- Multi-document transactions (MongoDB 4.0+)
```

### Basic Transaction Usage

**Programmatic Transaction Management:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class BankingService {
    
    private final MongoTemplate mongoTemplate;
    private final AccountRepository accountRepository;
    private final TransactionRepository transactionRepository;
    
    /**
     * Transfer money between accounts using transaction
     */
    public Transaction transferMoney(
            String fromAccountId, 
            String toAccountId, 
            BigDecimal amount) {
        
        // Create transaction record
        Transaction transaction = new Transaction();
        transaction.setFromAccountId(fromAccountId);
        transaction.setToAccountId(toAccountId);
        transaction.setAmount(amount);
        transaction.setStatus("PENDING");
        transaction.setType("TRANSFER");
        transaction.setCreatedAt(LocalDateTime.now());
        
        // Start MongoDB session for transaction
        ClientSession session = mongoTemplate.getMongoDatabaseFactory()
            .getSession(ClientSessionOptions.builder()
                .causallyConsistent(true)
                .build());
        
        try {
            // Start transaction
            session.startTransaction(
                TransactionOptions.builder()
                    .readConcern(ReadConcern.SNAPSHOT)
                    .writeConcern(WriteConcern.MAJORITY)
                    .readPreference(ReadPreference.primary())
                    .build()
            );
            
            // Save transaction record
            transaction = mongoTemplate.save(transaction, session);
            
            // Debit from source account
            Account fromAccount = mongoTemplate.findById(
                fromAccountId, Account.class, session
            );
            
            if (fromAccount == null) {
                throw new AccountNotFoundException(fromAccountId);
            }
            
            if (fromAccount.getBalance().compareTo(amount) < 0) {
                throw new InsufficientFundsException(
                    fromAccountId, fromAccount.getBalance(), amount
                );
            }
            
            fromAccount.setBalance(fromAccount.getBalance().subtract(amount));
            fromAccount.setLastModified(LocalDateTime.now());
            mongoTemplate.save(fromAccount, session);
            
            // Credit to destination account
            Account toAccount = mongoTemplate.findById(
                toAccountId, Account.class, session
            );
            
            if (toAccount == null) {
                throw new AccountNotFoundException(toAccountId);
            }
            
            toAccount.setBalance(toAccount.getBalance().add(amount));
            toAccount.setLastModified(LocalDateTime.now());
            mongoTemplate.save(toAccount, session);
            
            // Update transaction status
            transaction.setStatus("COMPLETED");
            transaction.setCompletedAt(LocalDateTime.now());
            mongoTemplate.save(transaction, session);
            
            // Commit transaction
            session.commitTransaction();
            
            log.info("Transfer completed: {} from {} to {}", 
                amount, fromAccountId, toAccountId);
            
            return transaction;
            
        } catch (Exception e) {
            // Abort transaction on any error
            session.abortTransaction();
            
            log.error("Transfer failed: {}", e.getMessage(), e);
            
            // Update transaction with error
            transaction.setStatus("FAILED");
            transaction.setErrorMessage(e.getMessage());
            mongoTemplate.save(transaction);
            
            throw new TransferFailedException(
                "Transfer failed: " + e.getMessage(), e
            );
            
        } finally {
            session.close();
        }
    }
}

// Custom exceptions
class AccountNotFoundException extends RuntimeException {
    public AccountNotFoundException(String accountId) {
        super("Account not found: " + accountId);
    }
}

class InsufficientFundsException extends RuntimeException {
    public InsufficientFundsException(
            String accountId, BigDecimal balance, BigDecimal required) {
        super(String.format(
            "Insufficient funds in account %s: balance=%s, required=%s",
            accountId, balance, required
        ));
    }
}

class TransferFailedException extends RuntimeException {
    public TransferFailedException(String message, Throwable cause) {
        super(message, cause);
    }
}
```

## 2. @Transactional with MongoDB

### Spring Transaction Configuration

**Enable Transactions:**

```java
@Configuration
@EnableMongoRepositories(basePackages = "com.example.repository")
@EnableTransactionManagement
public class MongoTransactionConfig extends AbstractMongoClientConfiguration {
    
    @Value("${spring.data.mongodb.database}")
    private String database;
    
    @Value("${spring.data.mongodb.uri}")
    private String uri;
    
    @Override
    protected String getDatabaseName() {
        return database;
    }
    
    @Override
    public MongoClient mongoClient() {
        ConnectionString connectionString = new ConnectionString(uri);
        
        MongoClientSettings settings = MongoClientSettings.builder()
            .applyConnectionString(connectionString)
            .readConcern(ReadConcern.SNAPSHOT)
            .writeConcern(WriteConcern.MAJORITY)
            .build();
        
        return MongoClients.create(settings);
    }
    
    /**
     * Transaction manager bean
     */
    @Bean
    public MongoTransactionManager transactionManager(MongoDatabaseFactory dbFactory) {
        TransactionOptions transactionOptions = TransactionOptions.builder()
            .readConcern(ReadConcern.SNAPSHOT)
            .writeConcern(WriteConcern.MAJORITY)
            .readPreference(ReadPreference.primary())
            .build();
        
        return new MongoTransactionManager(dbFactory, transactionOptions);
    }
}
```

### Using @Transactional Annotation

**Declarative Transaction Management:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class OrderService {
    
    private final OrderRepository orderRepository;
    private final InventoryRepository inventoryRepository;
    private final PaymentRepository paymentRepository;
    private final NotificationService notificationService;
    
    /**
     * Create order with transaction
     * All operations succeed or all fail
     */
    @Transactional
    public Order createOrder(OrderRequest request) {
        log.info("Creating order for user: {}", request.getUserId());
        
        // 1. Create order
        Order order = new Order();
        order.setUserId(request.getUserId());
        order.setItems(request.getItems());
        order.setTotalAmount(calculateTotal(request.getItems()));
        order.setStatus("PENDING");
        order.setCreatedAt(LocalDateTime.now());
        
        order = orderRepository.save(order);
        
        // 2. Reserve inventory for each item
        for (OrderItem item : request.getItems()) {
            Inventory inventory = inventoryRepository
                .findByProductId(item.getProductId())
                .orElseThrow(() -> new ProductNotFoundException(item.getProductId()));
            
            if (inventory.getQuantity() < item.getQuantity()) {
                throw new InsufficientInventoryException(
                    item.getProductId(), 
                    inventory.getQuantity(), 
                    item.getQuantity()
                );
            }
            
            // Reduce inventory
            inventory.setQuantity(inventory.getQuantity() - item.getQuantity());
            inventory.setReserved(inventory.getReserved() + item.getQuantity());
            inventoryRepository.save(inventory);
        }
        
        // 3. Process payment
        Payment payment = new Payment();
        payment.setOrderId(order.getId());
        payment.setAmount(order.getTotalAmount());
        payment.setStatus("PENDING");
        payment.setCreatedAt(LocalDateTime.now());
        
        payment = paymentRepository.save(payment);
        
        // Simulate payment processing
        if (!processPayment(payment)) {
            throw new PaymentFailedException(payment.getId());
        }
        
        payment.setStatus("COMPLETED");
        payment.setCompletedAt(LocalDateTime.now());
        paymentRepository.save(payment);
        
        // 4. Update order status
        order.setStatus("CONFIRMED");
        order.setPaymentId(payment.getId());
        order = orderRepository.save(order);
        
        log.info("Order created successfully: {}", order.getId());
        
        // Note: Notification is sent after transaction commits
        // (in @TransactionalEventListener or @AfterCommit)
        
        return order;
    }
    
    /**
     * Cancel order with transaction
     */
    @Transactional
    public void cancelOrder(String orderId) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new OrderNotFoundException(orderId));
        
        if (!"PENDING".equals(order.getStatus()) && 
            !"CONFIRMED".equals(order.getStatus())) {
            throw new OrderCannotBeCancelledException(orderId, order.getStatus());
        }
        
        // Restore inventory
        for (OrderItem item : order.getItems()) {
            Inventory inventory = inventoryRepository
                .findByProductId(item.getProductId())
                .orElseThrow(() -> new ProductNotFoundException(item.getProductId()));
            
            inventory.setQuantity(inventory.getQuantity() + item.getQuantity());
            inventory.setReserved(inventory.getReserved() - item.getQuantity());
            inventoryRepository.save(inventory);
        }
        
        // Refund payment if exists
        if (order.getPaymentId() != null) {
            Payment payment = paymentRepository.findById(order.getPaymentId())
                .orElse(null);
            
            if (payment != null && "COMPLETED".equals(payment.getStatus())) {
                payment.setStatus("REFUNDED");
                payment.setRefundedAt(LocalDateTime.now());
                paymentRepository.save(payment);
            }
        }
        
        // Update order status
        order.setStatus("CANCELLED");
        order.setCancelledAt(LocalDateTime.now());
        orderRepository.save(order);
        
        log.info("Order cancelled: {}", orderId);
    }
    
    /**
     * Transaction with custom isolation
     */
    @Transactional(
        isolation = Isolation.READ_COMMITTED,
        propagation = Propagation.REQUIRED,
        timeout = 30,  // 30 seconds
        rollbackFor = Exception.class
    )
    public void updateOrderWithCustomSettings(String orderId, String newStatus) {
        Order order = orderRepository.findById(orderId)
            .orElseThrow(() -> new OrderNotFoundException(orderId));
        
        order.setStatus(newStatus);
        order.setLastModified(LocalDateTime.now());
        
        orderRepository.save(order);
    }
    
    /**
     * Read-only transaction (optimization)
     */
    @Transactional(readOnly = true)
    public OrderSummary getOrderSummary(String userId) {
        List<Order> orders = orderRepository.findByUserId(userId);
        
        BigDecimal totalSpent = orders.stream()
            .map(Order::getTotalAmount)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
        
        return new OrderSummary(userId, orders.size(), totalSpent);
    }
    
    private BigDecimal calculateTotal(List<OrderItem> items) {
        return items.stream()
            .map(item -> item.getPrice().multiply(
                BigDecimal.valueOf(item.getQuantity())
            ))
            .reduce(BigDecimal.ZERO, BigDecimal::add);
    }
    
    private boolean processPayment(Payment payment) {
        // Simulate payment processing
        // In real application, call payment gateway API
        return true;
    }
}

@Data
class OrderRequest {
    private String userId;
    private List<OrderItem> items;
}

@Data
class OrderSummary {
    private String userId;
    private int totalOrders;
    private BigDecimal totalSpent;
    
    public OrderSummary(String userId, int totalOrders, BigDecimal totalSpent) {
        this.userId = userId;
        this.totalOrders = totalOrders;
        this.totalSpent = totalSpent;
    }
}
```

### Transaction Propagation

**Understanding Propagation Behavior:**

```java
@Service
@RequiredArgsConstructor
public class TransactionPropagationExamples {
    
    private final OrderRepository orderRepository;
    private final AuditLogRepository auditLogRepository;
    
    /**
     * REQUIRED (default): Use existing transaction or create new
     */
    @Transactional(propagation = Propagation.REQUIRED)
    public void requiredExample() {
        // Uses existing transaction if available
        // Creates new transaction if none exists
    }
    
    /**
     * REQUIRES_NEW: Always create new transaction
     * Suspends existing transaction if present
     */
    @Transactional(propagation = Propagation.REQUIRES_NEW)
    public void auditLog(String message) {
        // This runs in separate transaction
        // Commits independently even if outer transaction fails
        
        AuditLog log = new AuditLog();
        log.setMessage(message);
        log.setTimestamp(LocalDateTime.now());
        
        auditLogRepository.save(log);
    }
    
    /**
     * NESTED: Nested transaction within existing transaction
     */
    @Transactional(propagation = Propagation.NESTED)
    public void nestedExample() {
        // Creates nested transaction (savepoint)
        // Can rollback nested without affecting outer transaction
    }
    
    /**
     * MANDATORY: Must run within existing transaction
     * Throws exception if no transaction exists
     */
    @Transactional(propagation = Propagation.MANDATORY)
    public void mandatoryExample() {
        // Must be called from within a transaction
        // Throws exception otherwise
    }
    
    /**
     * SUPPORTS: Use transaction if exists, else non-transactional
     */
    @Transactional(propagation = Propagation.SUPPORTS)
    public void supportsExample() {
        // Flexible - works with or without transaction
    }
    
    /**
     * NOT_SUPPORTED: Always run without transaction
     * Suspends existing transaction if present
     */
    @Transactional(propagation = Propagation.NOT_SUPPORTED)
    public void notSupportedExample() {
        // Never runs in transaction
        // Suspends transaction if exists
    }
    
    /**
     * NEVER: Must NOT run within transaction
     * Throws exception if transaction exists
     */
    @Transactional(propagation = Propagation.NEVER)
    public void neverExample() {
        // Must be called without transaction
        // Throws exception if transaction exists
    }
    
    /**
     * Example: Audit log that commits independently
     */
    @Transactional
    public void processOrderWithAudit(Order order) {
        try {
            // Main transaction
            orderRepository.save(order);
            
            // Audit in separate transaction (always commits)
            auditLog("Order created: " + order.getId());
            
            // If this fails, audit log still persists
            if (order.getTotalAmount().compareTo(BigDecimal.ZERO) <= 0) {
                throw new InvalidOrderException("Invalid amount");
            }
            
        } catch (Exception e) {
            // Main transaction rolls back
            // But audit log persists (separate transaction)
            throw e;
        }
    }
}
```

## 3. Replica Set Requirement

### Understanding Replica Set Requirement

**Why Replica Sets?**

```
MongoDB transactions require replica sets because:

1. Consensus Protocol: Replica set members vote on transactions
2. Write Concern Majority: Ensures data replication
3. Oplog: Transaction operations logged for replication
4. Failover: Transaction state maintained during failover

Standalone MongoDB: ❌ Transactions NOT supported
Replica Set: ✅ Transactions supported
Sharded Cluster: ✅ Transactions supported (MongoDB 4.2+)
```

```java
@Component
@RequiredArgsConstructor
@Slf4j
public class MongoReplicaSetValidator {
    
    private final MongoClient mongoClient;
    
    @PostConstruct
    public void validateReplicaSet() {
        try {
            Document isMaster = mongoClient.getDatabase("admin")
                .runCommand(new Document("isMaster", 1));
            
            if (!isMaster.containsKey("setName")) {
                log.warn("⚠️ MongoDB is running in standalone mode");
                log.warn("⚠️ Transactions are NOT supported");
                log.warn("⚠️ Please configure a replica set for production");
            } else {

                log.info("✓ MongoDB replica set detected: {}", setName);
                log.info("✓ Transactions are supported");
                
                // Get replica set members
                List<Document> hosts = isMaster.getList("hosts", Document.class);
                log.info("✓ Replica set members: {}", hosts);
            }
            
        } catch (Exception e) {
            log.error("Failed to check replica set status", e);
        }
    }

     * Check if transactions are supported
     */
    public boolean transactionsSupported() {
        try {
            Document isMaster = mongoClient.getDatabase("admin")
                .runCommand(new Document("isMaster", 1));
            
            return isMaster.containsKey("setName");
            
        } catch (Exception e) {
            return false;
        }
    }
```

## 4. Read Concerns and Write Concerns

### Read Concerns

**Understanding Read Concern Levels:**

```java
public enum ReadConcernLevel {
    
    /**
     * LOCAL (default)
     * - Returns most recent data
     * - May not be durable (not yet replicated)
     * - Fastest, but may read uncommitted data
     */
    LOCAL,
    
    /**
     * AVAILABLE
     * - Similar to LOCAL
     * - Returns most recent data
     * - No guarantee of durability
     */
    AVAILABLE,
    
    /**
     * MAJORITY
     * - Returns data acknowledged by majority
     * - Data is durable (won't rollback)
     * - Slower than LOCAL, but safer
     */
    MAJORITY,
    
    /**
     * LINEARIZABLE
     * - Strongest consistency
     * - Reflects all prior majority writes
     * - Must use primary read preference
     * - Slowest, only for critical reads
     */
    LINEARIZABLE,
    
    /**
     * SNAPSHOT
     * - Used in transactions
     * - Point-in-time consistent view
     * - Reads from snapshot at transaction start
     */
    SNAPSHOT
}
```

**Configuring Read Concern:**

```java
@Service
@RequiredArgsConstructor
public class ReadConcernExamples {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * Default read concern (LOCAL)
     */
    public User getUserLocal(String userId) {
        Query query = new Query(Criteria.where("_id").is(userId));
        
        // Uses default LOCAL read concern
        return mongoTemplate.findOne(query, User.class);
    }
    
    /**
     * MAJORITY read concern
     * Guaranteed durable data
     */
    public User getUserMajority(String userId) {
        Query query = new Query(Criteria.where("_id").is(userId));
        
        query.withReadConcern(ReadConcern.MAJORITY);
        
        return mongoTemplate.findOne(query, User.class);
    }
    
    /**
     * LINEARIZABLE read concern
     * Strongest consistency for critical operations
     */
    public Account getAccountBalanceLinearizable(String accountId) {
        Query query = new Query(Criteria.where("_id").is(accountId));
        
        query.withReadConcern(ReadConcern.LINEARIZABLE)
             .withReadPreference(ReadPreference.primary());
        
        return mongoTemplate.findOne(query, Account.class);
    }
    
    /**
     * Transaction with SNAPSHOT read concern
     */
    @Transactional
    public OrderSummary getConsistentOrderData(String orderId) {
        // All reads in transaction use SNAPSHOT read concern
        // Ensures consistent view of data
        
        Order order = mongoTemplate.findById(orderId, Order.class);
        Payment payment = mongoTemplate.findById(order.getPaymentId(), Payment.class);
        
        return new OrderSummary(order, payment);
    }
}
```

### Write Concerns

**Understanding Write Concern Levels:**

```java
public class WriteConcernExamples {
    
    /**
     * W=0: UNACKNOWLEDGED
     * - Fire and forget
     * - No acknowledgment
     * - Fastest, no guarantee
     */
    public static final WriteConcern UNACKNOWLEDGED = WriteConcern.UNACKNOWLEDGED;
    
    /**
     * W=1: ACKNOWLEDGED (default)
     * - Acknowledged by primary
     * - Balances performance and safety
     */
    public static final WriteConcern ACKNOWLEDGED = WriteConcern.ACKNOWLEDGED;
    
    /**
     * W="majority": MAJORITY
     * - Acknowledged by majority of replica set
     * - Ensures data durability
     * - Recommended for critical data
     */
    public static final WriteConcern MAJORITY = WriteConcern.MAJORITY;
    
    /**
     * W=N: Custom write concern
     * - Wait for N replicas
     * - Custom durability level
     */
    public static WriteConcern custom(int replicas) {
        return new WriteConcern(replicas);
    }
    
    /**
     * With journal=true
     * - Wait for journal commit
     * - Ensures durability on disk
     */
    public static final WriteConcern JOURNALED = WriteConcern.ACKNOWLEDGED
        .withJournal(true);
    
    /**
     * With timeout
     * - Wait up to N milliseconds
     * - Fail if not acknowledged in time
     */
    public static WriteConcern withTimeout(int timeoutMs) {
        return WriteConcern.MAJORITY
            .withWTimeout(timeoutMs, TimeUnit.MILLISECONDS);
    }
}
```

**Using Write Concerns:**

```java
@Service
@RequiredArgsConstructor
public class WriteConcernService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * Fast write (unacknowledged)
     * Use for logs, metrics
     */
    public void logEvent(Event event) {
        mongoTemplate.setWriteConcern(WriteConcern.UNACKNOWLEDGED);
        mongoTemplate.save(event);
    }
    
    /**
     * Standard write (acknowledged by primary)
     */
    public User createUser(User user) {
        mongoTemplate.setWriteConcern(WriteConcern.ACKNOWLEDGED);
        return mongoTemplate.save(user);
    }
    
    /**
     * Critical write (majority acknowledgment)
     */
    public Order createOrder(Order order) {
        WriteConcern writeConcern = WriteConcern.MAJORITY
            .withWTimeout(5000, TimeUnit.MILLISECONDS)
            .withJournal(true);
        
        mongoTemplate.setWriteConcern(writeConcern);
        
        try {
            return mongoTemplate.save(order);
        } catch (MongoWriteConcernException e) {
            throw new OrderPersistenceException(
                "Failed to persist order with required durability", e
            );
        }
    }
    
    /**
     * Transaction with custom write concern
     */
    @Transactional
    public void transferWithCustomConcern(
            String fromAccount, String toAccount, BigDecimal amount) {
        
        // Transaction uses configured write concern
        // Set in MongoTransactionManager
        
        Account from = mongoTemplate.findById(fromAccount, Account.class);
```

```java
public class TransactionErrorTypes {
    
    /**
     * TransientTransactionError
     * - Temporary failure (network issue, primary election)
     * - Safe to retry entire transaction
     */
    public static boolean isTransientError(Exception e) {
        return e.getMessage() != null && 
               e.getMessage().contains("TransientTransactionError");
    }
    
    /**
     * UnknownTransactionCommitResult
     * - Commit status unknown
     * - May have committed or not
     * - Safe to retry commit only
     */
    public static boolean isUnknownCommitResult(Exception e) {
        return e.getMessage() != null && 
               e.getMessage().contains("UnknownTransactionCommitResult");
    }
    
    /**
     * WriteConflict
     * - Concurrent modification
     * - Retry with backoff
     */
    public static boolean isWriteConflict(Exception e) {
        return e instanceof MongoCommandException &&
               ((MongoCommandException) e).getErrorCode() == 112;
    }
    
    /**
     * TransactionTooLarge
     * - Transaction exceeded size limit
     * - Break into smaller transactions
     */
    public static boolean isTransactionTooLarge(Exception e) {
        return e.getMessage() != null &&
               e.getMessage().contains("Transaction exceeded size limit");
    }
}
```

### Retry Logic

**Automatic Retry with Exponential Backoff:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class ResilientTransactionService {
    
    private final MongoTemplate mongoTemplate;
    private static final int MAX_RETRIES = 3;
    private static final long INITIAL_BACKOFF_MS = 100;
    
    /**
     * Execute transaction with automatic retry
     */
    public <T> T executeWithRetry(TransactionCallback<T> callback) {
        int attempt = 0;
        long backoffMs = INITIAL_BACKOFF_MS;
        
        while (attempt < MAX_RETRIES) {
            try {
                return executeInTransaction(callback);
                
            } catch (Exception e) {
                attempt++;
                
                if (isRetryable(e) && attempt < MAX_RETRIES) {
                    log.warn("Transaction failed (attempt {}/{}): {}. Retrying...", 
                        attempt, MAX_RETRIES, e.getMessage());
                    
                    // Exponential backoff
                    sleep(backoffMs);
                    backoffMs *= 2;
                    
                } else {
                    log.error("Transaction failed after {} attempts", attempt);
                    throw new TransactionFailedException(
                        "Transaction failed after retries", e
                    );
                }
            }
        }
        
        throw new TransactionFailedException(
            "Transaction failed after maximum retries"
        );
    }
    
    /**
     * Execute callback in transaction
     */
    private <T> T executeInTransaction(TransactionCallback<T> callback) {
        ClientSession session = mongoTemplate.getMongoDatabaseFactory()
            .getSession(ClientSessionOptions.builder()
                .causallyConsistent(true)
                .build());
        
        try {
            session.startTransaction(
                TransactionOptions.builder()
                    .readConcern(ReadConcern.SNAPSHOT)
                    .writeConcern(WriteConcern.MAJORITY)
                    .build()
            );
            
            T result = callback.doInTransaction(session);
            
            commitWithRetry(session);
            
            return result;
            
        } catch (Exception e) {
            session.abortTransaction();
            throw e;
            
        } finally {
            session.close();
        }
    }
    
    /**
     * Commit with retry for UnknownTransactionCommitResult
     */
    private void commitWithRetry(ClientSession session) {
        int attempt = 0;
        
        while (attempt < MAX_RETRIES) {
            try {
                session.commitTransaction();
                return;
                
            } catch (MongoException e) {
                if (e.getErrorLabels().contains("UnknownTransactionCommitResult") &&
                    attempt < MAX_RETRIES - 1) {
                    
                    log.warn("Commit result unknown, retrying...");
                    attempt++;
                    sleep(100);
                    
                } else {
                    throw e;
                }
            }
        }
    }
    
    /**
     * Check if error is retryable
     */
    private boolean isRetryable(Exception e) {
        if (!(e instanceof MongoException)) {
            return false;
        }
        
        MongoException mongoEx = (MongoException) e;
        
        // TransientTransactionError label
        if (mongoEx.getErrorLabels().contains("TransientTransactionError")) {
            return true;
        }
        
        // Write conflict
        if (mongoEx instanceof MongoCommandException) {
            int errorCode = ((MongoCommandException) mongoEx).getErrorCode();
            return errorCode == 112;  // WriteConflict
        }
        
        return false;
    }
    
    private void sleep(long milliseconds) {
        try {
            Thread.sleep(milliseconds);
        } catch (InterruptedException e) {
            Thread.currentThread().interrupt();
        }
    }
}

@FunctionalInterface
interface TransactionCallback<T> {
    T doInTransaction(ClientSession session);
}

// Usage example
@Service
@RequiredArgsConstructor
public class OrderServiceWithRetry {
    
    private final ResilientTransactionService transactionService;
    private final OrderRepository orderRepository;
    private final InventoryRepository inventoryRepository;
    
    public Order createOrderWithRetry(OrderRequest request) {
        return transactionService.executeWithRetry(session -> {
            // Create order
            Order order = new Order();
            order.setUserId(request.getUserId());
            order.setItems(request.getItems());
            order = mongoTemplate.save(order, session);
            
            // Update inventory
            for (OrderItem item : request.getItems()) {
                Inventory inventory = inventoryRepository
                    .findByProductId(item.getProductId(), session)
                    .orElseThrow();
                
                inventory.setQuantity(
                    inventory.getQuantity() - item.getQuantity()
                );
                
                inventoryRepository.save(inventory, session);
            }
            
            return order;
        });
    }
}
```

### Circuit Breaker Pattern

**Prevent Cascading Failures:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class TransactionCircuitBreakerService {
    
    private final AtomicInteger failureCount = new AtomicInteger(0);
    private final AtomicLong lastFailureTime = new AtomicLong(0);
    
    private static final int FAILURE_THRESHOLD = 5;
    private static final long RESET_TIMEOUT_MS = 60000;  // 1 minute
    
    private enum State {
        CLOSED,   // Normal operation
        OPEN,     // Failing, reject requests
        HALF_OPEN // Testing if recovered
    }
    
    private volatile State state = State.CLOSED;
    
    /**
     * Execute transaction with circuit breaker
     */
    public <T> T executeWithCircuitBreaker(Supplier<T> operation) {
        if (state == State.OPEN) {
            if (shouldAttemptReset()) {
                state = State.HALF_OPEN;
                log.info("Circuit breaker: HALF_OPEN, attempting reset");
            } else {
                throw new CircuitBreakerOpenException(
                    "Circuit breaker is OPEN, rejecting transaction"
                );
            }
        }
        
        try {
            T result = operation.get();
            
            // Success - reset circuit breaker
            if (state == State.HALF_OPEN) {
                state = State.CLOSED;
                failureCount.set(0);
                log.info("Circuit breaker: CLOSED, system recovered");
            }
            
            return result;
            
        } catch (Exception e) {
            handleFailure();
            throw e;
        }
    }
    
    private void handleFailure() {
        int failures = failureCount.incrementAndGet();
        lastFailureTime.set(System.currentTimeMillis());
        
        if (failures >= FAILURE_THRESHOLD) {
            state = State.OPEN;
            log.error("Circuit breaker: OPEN after {} failures", failures);
        }
    }
    
    private boolean shouldAttemptReset() {
        long timeSinceLastFailure = 
            System.currentTimeMillis() - lastFailureTime.get();
        
        return timeSinceLastFailure >= RESET_TIMEOUT_MS;
    }
}

class CircuitBreakerOpenException extends RuntimeException {
    public CircuitBreakerOpenException(String message) {
        super(message);
    }
}
```

### Transaction Performance Impact

**Understanding Performance Costs:**

```
Transaction Overhead:
1. Network round trips: Begin, commit/abort
2. Oplog writes: All operations logged
3. Lock acquisition: Prevents conflicts
4. Snapshot creation: Point-in-time view
5. Write concern majority: Wait for replication

Performance Impact:
- Latency: +5-50ms per transaction
- Throughput: 50-70% of non-transactional
- Resource usage: More memory, CPU, I/O

When to Use:
✅ Multi-document atomicity required
✅ Complex business logic with rollback
✅ Financial transactions
✅ Inventory management

When to Avoid:
❌ Single document updates (already atomic)
❌ High-throughput operations
❌ Long-running operations (>60s limit)
❌ Large batch operations
```

```java
@Component

public class TransactionMetricsCollector {
    
    private final MeterRegistry meterRegistry;
    
    /**
     * Track transaction duration

    public <T> T trackTransaction(
            String transactionName, 
            Supplier<T> operation) {
        
        Timer.Sample sample = Timer.start(meterRegistry);
        
        try {
            T result = operation.get();

                .tag("status", "success")

                .increment();

        } catch (Exception e) {
            sample.stop(Timer.builder("mongodb.transaction.duration")
                .tag("transaction", transactionName)
                .tag("status", "error")
                .register(meterRegistry));
            
            Counter.builder("mongodb.transaction.count")
                .tag("transaction", transactionName)
                .tag("status", "error")
                .register(meterRegistry)
                .increment();
            
            throw e;
        }
    }
}
```

## Interview Questions

**Q1: When should you use MongoDB transactions?**

Use transactions when you need atomicity across multiple documents or collections (order + inventory + payment). Single-document updates are already atomic and don't need transactions. Avoid for: high-throughput operations, single-document updates, long-running operations (>60s), external API calls. Transactions add 5-50ms latency and require replica sets.

**Q2: What are the requirements for MongoDB transactions?**

Transactions require: (1) MongoDB 4.0+ for replica sets, 4.2+ for sharded clusters, (2) Replica set configuration (minimum 3 nodes recommended), (3) WiredTiger storage engine (default). Standalone MongoDB does NOT support transactions. Use `rs.status()` to verify replica set is active.

**Q3: Explain read concern and write concern in MongoDB transactions.**

Read concern controls consistency of reads: LOCAL (default, fastest), MAJORITY (durable data), SNAPSHOT (transaction consistency), LINEARIZABLE (strongest, slowest). Write concern controls acknowledgment: W=1 (primary only), MAJORITY (replicated to majority), custom (W=N replicas). Use MAJORITY/MAJORITY for critical data, SNAPSHOT in transactions.

**Q4: How do you handle transaction errors in MongoDB?**

Implement retry logic for transient errors (TransientTransactionError label). Use exponential backoff (100ms, 200ms, 400ms). Retry commit for UnknownTransactionCommitResult. Handle WriteConflict (error code 112) with retry. Maximum 3 retries recommended. Use circuit breaker pattern to prevent cascading failures in high-error scenarios.

**Q5: What are the performance implications of MongoDB transactions?**

Transactions add: (1) Latency +5-50ms per transaction, (2) Throughput reduction 30-50%, (3) Resource usage (memory, CPU, locks), (4) Network overhead (begin/commit round trips), (5) Oplog writes for all operations. Optimize by: preparing data outside transaction, using bulk operations, keeping transactions short (<1s), minimizing operations, avoiding external calls.
