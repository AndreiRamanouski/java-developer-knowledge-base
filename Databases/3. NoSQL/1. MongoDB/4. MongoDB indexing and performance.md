# MongoDB Indexing and Performance

## Overview

Indexes are critical for MongoDB query performance. Without proper indexes, MongoDB performs collection scans examining every document. With the right indexes, queries execute in milliseconds instead of seconds. Understanding index types, query optimization, and monitoring is essential for production applications.

**Key Concept**: Indexes improve read performance but slow down writes. Design indexes based on your query patterns - index fields you query frequently, in the order you query them. Monitor index usage and remove unused indexes to optimize write performance.

## 1. Creating Indexes with Annotations

### @Indexed Annotation

**Single Field Indexes:**

```java
@Document(collection = "users")
@Data
public class User {
    
    @Id
    private String id;
    
    // Simple index
    @Indexed
    private String email;
    
    // Unique index
    @Indexed(unique = true)
    private String username;
    
    // Sparse index (only index documents that have this field)
    @Indexed(sparse = true)
    private String phoneNumber;
    
    // TTL index (auto-delete documents after duration)
    @Indexed(expireAfterSeconds = 2592000)  // 30 days
    private LocalDateTime createdAt;
    
    // Descending index
    @Indexed(direction = IndexDirection.DESCENDING)
    private LocalDateTime lastLoginAt;
    
    // Partial index (with filter)
    @Indexed(
        partialFilter = "{ 'status': 'ACTIVE' }",
        name = "active_users_email_idx"
    )
    private String businessEmail;
    
    // Background index creation (non-blocking)
    @Indexed(background = true)
    private String department;
    
    private String firstName;
    private String lastName;
    private Integer age;
    private String status;
}
```

### Programmatic Index Creation

**Using MongoTemplate:**

```java
@Configuration
public class MongoIndexConfiguration {
    
    @Autowired
    private MongoTemplate mongoTemplate;
    
    @PostConstruct
    public void createIndexes() {
        createUserIndexes();
        createOrderIndexes();
        createProductIndexes();
    }
    
    private void createUserIndexes() {
        IndexOperations indexOps = mongoTemplate.indexOps(User.class);
        
        // Simple ascending index
        Index emailIndex = new Index()
            .on("email", Sort.Direction.ASC)
            .unique()
            .named("email_unique_idx");
        indexOps.ensureIndex(emailIndex);
        
        // Compound index
        Index nameIndex = new Index()
            .on("lastName", Sort.Direction.ASC)
            .on("firstName", Sort.Direction.ASC)
            .named("name_idx");
        indexOps.ensureIndex(nameIndex);
        
        // Partial index
        Index activeUserIndex = new Index()
            .on("status", Sort.Direction.ASC)
            .on("createdAt", Sort.Direction.DESC)
            .partial(PartialIndexFilter.of(
                Criteria.where("status").is("ACTIVE")
            ))
            .named("active_user_idx");
        indexOps.ensureIndex(activeUserIndex);
        
        // TTL index
        Index ttlIndex = new Index()
            .on("createdAt", Sort.Direction.ASC)
            .expire(Duration.ofDays(90))
            .named("user_ttl_idx");
        indexOps.ensureIndex(ttlIndex);
        
        // Text index
        TextIndexDefinition textIndex = new TextIndexDefinition.TextIndexDefinitionBuilder()
            .onField("firstName", 2.0f)
            .onField("lastName", 2.0f)
            .onField("email", 1.0f)
            .named("user_text_idx")
            .build();
        indexOps.ensureIndex(textIndex);
    }
    
    private void createOrderIndexes() {
        IndexOperations indexOps = mongoTemplate.indexOps(Order.class);
        
        // Compound index for common query pattern
        Index userOrderIndex = new Index()
            .on("userId", Sort.Direction.ASC)
            .on("orderDate", Sort.Direction.DESC)
            .named("user_order_date_idx");
        indexOps.ensureIndex(userOrderIndex);
        
        // Index for status filtering
        Index statusIndex = new Index()
            .on("status", Sort.Direction.ASC)
            .on("totalAmount", Sort.Direction.DESC)
            .named("status_amount_idx");
        indexOps.ensureIndex(statusIndex);
    }
    
    private void createProductIndexes() {
        IndexOperations indexOps = mongoTemplate.indexOps(Product.class);
        
        // Unique SKU index
        Index skuIndex = new Index()
            .on("sku", Sort.Direction.ASC)
            .unique()
            .named("sku_unique_idx");
        indexOps.ensureIndex(skuIndex);
        
        // Category and price index
        Index categoryPriceIndex = new Index()
            .on("category", Sort.Direction.ASC)
            .on("price", Sort.Direction.DESC)
            .named("category_price_idx");
        indexOps.ensureIndex(categoryPriceIndex);
    }
}
```

### Index Management Service

**Manage Indexes Programmatically:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class IndexManagementService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * List all indexes for a collection
     */
    public List<IndexInfo> listIndexes(Class<?> entityClass) {
        IndexOperations indexOps = mongoTemplate.indexOps(entityClass);
        return indexOps.getIndexInfo();
    }
    
    /**
     * Create index if not exists
     */
    public void ensureIndex(Class<?> entityClass, Index index) {
        IndexOperations indexOps = mongoTemplate.indexOps(entityClass);
        
        String indexName = indexOps.ensureIndex(index);
        log.info("Ensured index {} on {}", indexName, entityClass.getSimpleName());
    }
    
    /**
     * Drop index by name
     */
    public void dropIndex(Class<?> entityClass, String indexName) {
        IndexOperations indexOps = mongoTemplate.indexOps(entityClass);
        indexOps.dropIndex(indexName);
        
        log.info("Dropped index {} from {}", indexName, entityClass.getSimpleName());
    }
    
    /**
     * Drop all indexes except _id
     */
    public void dropAllIndexes(Class<?> entityClass) {
        IndexOperations indexOps = mongoTemplate.indexOps(entityClass);
        indexOps.dropAllIndexes();
        
        log.info("Dropped all indexes from {}", entityClass.getSimpleName());
    }
    
    /**
     * Rebuild all indexes
     */
    public void rebuildIndexes(Class<?> entityClass) {
        IndexOperations indexOps = mongoTemplate.indexOps(entityClass);
        
        // Get existing index definitions
        List<IndexInfo> existingIndexes = indexOps.getIndexInfo();
        
        // Drop and recreate (except _id)
        existingIndexes.stream()
            .filter(idx -> !idx.getName().equals("_id_"))
            .forEach(idx -> {
                indexOps.dropIndex(idx.getName());
                log.info("Dropped index {} for rebuild", idx.getName());
            });
        
        // Recreate indexes from annotations
        mongoTemplate.indexOps(entityClass).ensureIndex(new Index());
        
        log.info("Rebuilt indexes for {}", entityClass.getSimpleName());
    }
    
    /**
     * Check if index exists
     */
    public boolean indexExists(Class<?> entityClass, String indexName) {
        IndexOperations indexOps = mongoTemplate.indexOps(entityClass);
        
        return indexOps.getIndexInfo().stream()
            .anyMatch(idx -> idx.getName().equals(indexName));
    }
    
    /**
     * Get index statistics
     */
    public Map<String, Object> getIndexStats(Class<?> entityClass) {
        String collectionName = mongoTemplate.getCollectionName(entityClass);
        
        Document command = new Document("collStats", collectionName)
            .append("indexDetails", true);
        
        Document stats = mongoTemplate.getDb().runCommand(command);
        
        return Map.of(
            "collection", collectionName,
            "indexCount", stats.get("nindexes"),
            "totalIndexSize", stats.get("totalIndexSize"),
            "indexSizes", stats.get("indexSizes")
        );
    }
}
```

### Compound Indexes

**Multi-Field Indexes:**

```java
@Document(collection = "orders")
@CompoundIndexes({
    // Order matters! This index supports:
    // 1. Queries on userId only
    // 2. Queries on userId + status
    // 3. Queries on userId + status + orderDate
    // But NOT queries on status only or orderDate only
    @CompoundIndex(
        name = "user_status_date_idx",
        def = "{'userId': 1, 'status': 1, 'orderDate': -1}"
    )
})
@Data
public class Order {
    
    @Id
    private String id;
    
    private String userId;
    private String status;
    private LocalDateTime orderDate;
    private BigDecimal totalAmount;
}

@Service
@RequiredArgsConstructor
public class OrderQueryService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * Uses compound index (userId only)
     */
    public List<Order> getUserOrders(String userId) {
        Query query = new Query(Criteria.where("userId").is(userId));
        return mongoTemplate.find(query, Order.class);
    }
    
    /**
     * Uses compound index (userId + status)
     */
    public List<Order> getUserOrdersByStatus(String userId, String status) {
        Query query = new Query(
            Criteria.where("userId").is(userId)
                .and("status").is(status)
        );
        return mongoTemplate.find(query, Order.class);
    }
    
    /**
     * Uses compound index fully (userId + status + orderDate)
     */
    public List<Order> getUserOrdersByStatusAndDate(
            String userId, String status, LocalDateTime date) {
        
        Query query = new Query(
            Criteria.where("userId").is(userId)
                .and("status").is(status)
                .and("orderDate").gte(date)
        );
        return mongoTemplate.find(query, Order.class);
    }
    
    /**
     * Does NOT use compound index efficiently
     * (queries on status without userId)
     */
    public List<Order> getOrdersByStatus(String status) {
        Query query = new Query(Criteria.where("status").is(status));
        return mongoTemplate.find(query, Order.class);
        // Consider creating separate index on status
    }
}
```

**Compound Index Best Practices:**

```java
/**
 * ESR Rule: Equality, Sort, Range
 * 
 * Index field order:
 * 1. Equality matches (=, in)
 * 2. Sort fields
 * 3. Range queries (>, <, between)
 */

@Document(collection = "analytics_events")
@CompoundIndexes({
    // Good: Following ESR rule
    @CompoundIndex(
        name = "esr_example_idx",
        def = "{'userId': 1, 'createdAt': -1, 'value': 1}"
        // userId = equality
        // createdAt = sort
        // value = range
    ),
    
    // Common query pattern
    @CompoundIndex(
        name = "user_type_time_idx",
        def = "{'userId': 1, 'eventType': 1, 'timestamp': -1}"
    )
})
@Data
public class AnalyticsEvent {
    @Id
    private String id;
    
    private String userId;
    private String eventType;
    private LocalDateTime timestamp;
    private Double value;
}
```

**Multikey Index Limitations:**

```java
@Document(collection = "products")
@CompoundIndexes({
    // ❌ Cannot create compound multikey index on multiple arrays
    // This will FAIL if both colors and sizes are arrays

        name = "invalid_multikey_idx",
        def = "{'colors': 1, 'sizes': 1}"  // Both arrays - not allowed
    ),
    
    // ✅ Can create compound index with one array and other fields
    @CompoundIndex(
        name = "valid_multikey_idx",
        def = "{'category': 1, 'tags': 1}"  // Only tags is array - OK
    )

@Data

    @Id
    private String id;
    
    private String category;
    private List<String> tags;  // Array

    private List<String> sizes;  // Array
```

### Programmatic explain() in Spring

**Execute explain() Programmatically:**

```java
@Service
@RequiredArgsConstructor
@Slf4j
public class QueryAnalysisService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * Analyze query execution
     */
    public QueryExplanation explainQuery(Query query, Class<?> entityClass) {
        // Get explain plan
        Document explainResult = mongoTemplate.executeCommand(
            new Document("explain", new Document()
                .append("find", mongoTemplate.getCollectionName(entityClass))
                .append("filter", query.getQueryObject())
            )
        );
        
        return parseExplainResult(explainResult);
    }
    
    /**
     * Check if query uses index
     */
    public boolean usesIndex(Query query, Class<?> entityClass) {
        QueryExplanation explanation = explainQuery(query, entityClass);
        return !explanation.getStage().equals("COLLSCAN");
    }
    
    /**
     * Analyze query performance
     */
    public QueryPerformanceMetrics analyzePerformance(
            Query query, Class<?> entityClass) {
        
        long startTime = System.currentTimeMillis();
        
        List<?> results = mongoTemplate.find(query, entityClass);
        
        long endTime = System.currentTimeMillis();
        long executionTime = endTime - startTime;
        
        QueryExplanation explanation = explainQuery(query, entityClass);
        
        return QueryPerformanceMetrics.builder()
            .executionTimeMs(executionTime)
            .documentsReturned(results.size())
            .documentsExamined(explanation.getDocsExamined())
            .keysExamined(explanation.getKeysExamined())
            .usedIndex(explanation.getIndexUsed())
            .stage(explanation.getStage())
            .efficient(isQueryEfficient(explanation))
            .build();
    }
    
    private boolean isQueryEfficient(QueryExplanation explanation) {
        // Query is efficient if:
        // 1. Uses an index (not COLLSCAN)
        // 2. Examines reasonable number of documents
        // 3. Keys examined ≈ documents returned
        
        if (explanation.getStage().equals("COLLSCAN")) {
            return false;  // Collection scan is inefficient
        }
        
        long docsExamined = explanation.getDocsExamined();
        long docsReturned = explanation.getDocsReturned();
        
        if (docsExamined == 0) {
            return true;  // No documents examined
        }
        
        // Efficiency ratio: how many documents we had to examine
        // to get the results
        double ratio = (double) docsReturned / docsExamined;
        
        return ratio >= 0.5;  // At least 50% efficiency
    }
    
    private QueryExplanation parseExplainResult(Document explainResult) {
        Document executionStats = explainResult.get("executionStats", Document.class);
        Document executionStages = executionStats.get("executionStages", Document.class);
        
        String stage = executionStages.getString("stage");
        String indexUsed = null;
        
        // Check for index scan
        if (stage.equals("FETCH")) {
            Document inputStage = executionStages.get("inputStage", Document.class);
            if (inputStage != null && inputStage.getString("stage").equals("IXSCAN")) {
                indexUsed = inputStage.getString("indexName");
                stage = "IXSCAN";
            }
        } else if (stage.equals("IXSCAN")) {
            indexUsed = executionStages.getString("indexName");
        }
        
        return QueryExplanation.builder()
            .stage(stage)
            .indexUsed(indexUsed)
            .executionTimeMs(executionStats.getInteger("executionTimeMillis"))
            .docsReturned(executionStats.getInteger("nReturned"))
            .docsExamined(executionStats.getInteger("totalDocsExamined"))
            .keysExamined(executionStats.getInteger("totalKeysExamined"))
            .build();
    }
}

@Data
@Builder
class QueryExplanation {
    private String stage;  // IXSCAN, COLLSCAN, FETCH, etc.
    private String indexUsed;
    private Integer executionTimeMs;
    private Integer docsReturned;
    private Integer docsExamined;
    private Integer keysExamined;
}

@Data
@Builder
class QueryPerformanceMetrics {
    private Long executionTimeMs;
    private Integer documentsReturned;
    private Integer documentsExamined;
    private Integer keysExamined;
    private String usedIndex;
    private String stage;
    private Boolean efficient;
    
    @Override
    public String toString() {
        return String.format(
            "Performance: %dms | Stage: %s | Index: %s | Docs: %d/%d | Keys: %d | Efficient: %s",
            executionTimeMs, stage, usedIndex, 
            documentsReturned, documentsExamined, keysExamined, efficient
        );
    }
}
```

## 4. Covered Queries

### Understanding Covered Queries

**What is a Covered Query?**

```
A covered query is one where:
1. All queried fields are in the index
2. All returned fields are in the index
3. MongoDB can satisfy the query entirely from the index
4. No need to examine actual documents

Result: Extremely fast queries (index only, no disk I/O)
```

**Example:**

```java
@Document(collection = "users")
@CompoundIndexes({
    @CompoundIndex(
        name = "email_status_idx",
        def = "{'email': 1, 'status': 1}"
    )
})
@Data
public class User {
    @Id
    private String id;
    
    private String email;
    private String status;
    private String firstName;
    private String lastName;
}

@Service
@RequiredArgsConstructor
public class CoveredQueryService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * ✅ Covered query - uses index only
     */
    public List<String> getActiveUserEmails() {
        Query query = new Query(Criteria.where("status").is("ACTIVE"));
        
        // Include only fields in the index
        query.fields()
            .include("email")
            .include("status")
            .exclude("_id");  // Must exclude _id for covered query
        
        List<User> users = mongoTemplate.find(query, User.class);
        
        return users.stream()
            .map(User::getEmail)
            .collect(Collectors.toList());
    }
    
    /**
     * ❌ Not covered - includes firstName (not in index)
     */
    public List<User> getActiveUsersWithName() {
        Query query = new Query(Criteria.where("status").is("ACTIVE"));
        
        // Includes field not in index
        query.fields()
            .include("email")
            .include("status")
            .include("firstName");  // Not in index!
        
        return mongoTemplate.find(query, User.class);
    }
    
    /**
     * ❌ Not covered - doesn't exclude _id
     */
    public List<String> getUserEmailsNotCovered() {
        Query query = new Query(Criteria.where("status").is("ACTIVE"));
        
        // Didn't exclude _id
        query.fields()
            .include("email")
            .include("status");
            // Missing: .exclude("_id")
        
        List<User> users = mongoTemplate.find(query, User.class);
        return users.stream().map(User::getEmail).collect(Collectors.toList());
    }
}
```

### Creating Indexes for Covered Queries

**Optimal Index Design:**

```java
@Document(collection = "orders")
@CompoundIndexes({
    // Index for covered query
    @CompoundIndex(
        name = "user_status_amount_idx",
        def = "{'userId': 1, 'status': 1, 'totalAmount': 1}"
    )
})
@Data
public class Order {
    @Id
    private String id;
    
    private String userId;
    private String status;
    private BigDecimal totalAmount;
    private LocalDateTime orderDate;
}

@Service
@RequiredArgsConstructor
public class OrderCoveredQueryService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * Covered query for order totals
     */
    public BigDecimal getUserTotalSpending(String userId) {
        Query query = new Query(
            Criteria.where("userId").is(userId)
                .and("status").is("COMPLETED")
        );
        
        // Project only indexed fields
        query.fields()
            .include("totalAmount")
            .exclude("_id");
        
        List<Order> orders = mongoTemplate.find(query, Order.class);
        
        return orders.stream()
            .map(Order::getTotalAmount)
            .reduce(BigDecimal.ZERO, BigDecimal::add);
    }
    
    /**
     * Verify query is covered
     */
    public boolean verifyCoveredQuery(Query query) {
        Document explainResult = mongoTemplate.executeCommand(
            new Document("explain", new Document()
                .append("find", "orders")
                .append("filter", query.getQueryObject())
                .append("projection", query.getFieldsObject())
            )
        );
        
        Document executionStats = explainResult.get("executionStats", Document.class);
        
        // If totalDocsExamined = 0, query is covered
        return executionStats.getInteger("totalDocsExamined") == 0;
    }
}
```

## 5. Index Intersection

### Understanding Index Intersection

**What is Index Intersection?**

```
MongoDB can use multiple indexes for a single query by:
1. Using first index to get candidate documents
2. Using second index to get more candidates
3. Intersecting the results
4. Returning only documents in both sets

Note: Usually compound index is better, but intersection
can help when you have existing single-field indexes
```

**Example:**

```java
@Document(collection = "products")
@Data
public class Product {
    @Id
    private String id;
    
    // Two separate indexes
    @Indexed
    private String category;
    
    @Indexed
    private String brand;
    
    private String name;
    private BigDecimal price;
}

@Service
@RequiredArgsConstructor
public class ProductIndexIntersectionService {
    
    private final MongoTemplate mongoTemplate;
    
    /**
     * Query that can use index intersection
     */
    public List<Product> findProductsByCategoryAndBrand(
            String category, String brand) {
        
        Query query = new Query(
            Criteria.where("category").is(category)
                .and("brand").is(brand)
        );
        
        // MongoDB may use:
        // 1. Index on category → get matching products
        // 2. Index on brand → get matching products
        // 3. Intersect both sets
        
        return mongoTemplate.find(query, Product.class);
    }
    
    /**
     * Check if query uses index intersection
     */
    public boolean usesIndexIntersection(Query query) {
        Document explainResult = mongoTemplate.executeCommand(
            new Document("explain", new Document()
                .append("find", "products")
                .append("filter", query.getQueryObject())
            )
        );
        
        Document executionStats = explainResult.get("executionStats", Document.class);
        Document executionStages = executionStats.get("executionStages", Document.class);
        
        // Check if stage is AND_SORTED or AND_HASH
        String stage = executionStages.getString("stage");
        
        return stage.startsWith("AND_");
    }
}
```

**When to Use Compound Index vs Index Intersection:**

```java
/**
 * Scenario 1: Frequent combined queries
 * Solution: Create compound index (better performance)
 */
@CompoundIndex(
    name = "category_brand_idx",
    def = "{'category': 1, 'brand': 1}"
)

/**
 * Scenario 2: Sometimes query by category, sometimes by brand
 * Solution: Keep separate indexes and let MongoDB intersect when needed
 */
@Indexed
private String category;

@Indexed
private String brand;

/**
 * Scenario 3: Multiple query patterns
 * Solution: Create multiple compound indexes
 */
@CompoundIndexes({
    @CompoundIndex(def = "{'category': 1, 'price': 1}"),
    @CompoundIndex(def = "{'brand': 1, 'price': 1}"),
    @CompoundIndex(def = "{'category': 1, 'brand': 1}")
})
```

### Query Performance Monitoring

**Monitor Slow Queries:**

```java
@Aspect
@Component
@Slf4j
public class MongoQueryMonitoringAspect {
    
    private final MeterRegistry meterRegistry;
    private final long slowQueryThresholdMs = 1000;  // 1 second
    
    public MongoQueryMonitoringAspect(MeterRegistry meterRegistry) {
        this.meterRegistry = meterRegistry;
    }
    
    @Around("execution(* org.springframework.data.mongodb.repository.MongoRepository+.*(..))")
    public Object monitorRepositoryQuery(ProceedingJoinPoint joinPoint) throws Throwable {
        String methodName = joinPoint.getSignature().getName();
        String className = joinPoint.getSignature().getDeclaringTypeName();
        
        Timer.Sample sample = Timer.start(meterRegistry);
        
        try {
            Object result = joinPoint.proceed();
            
            sample.stop(Timer.builder("mongodb.query.duration")
                .tag("method", methodName)
                .tag("class", className)
                .tag("status", "success")
                .register(meterRegistry));
            
            return result;
            
        } catch (Exception e) {
            sample.stop(Timer.builder("mongodb.query.duration")
                .tag("method", methodName)
                .tag("class", className)
                .tag("status", "error")
                .register(meterRegistry));
            
            throw e;
        }
    }
    
    @Around("execution(* org.springframework.data.mongodb.core.MongoTemplate.*(..))")
    public Object monitorTemplateQuery(ProceedingJoinPoint joinPoint) throws Throwable {
        String methodName = joinPoint.getSignature().getName();
        
        long startTime = System.currentTimeMillis();
        
        try {
            Object result = joinPoint.proceed();
            
            long duration = System.currentTimeMillis() - startTime;
            
            // Log slow queries
            if (duration > slowQueryThresholdMs) {
                log.warn("Slow query detected: {} took {}ms", methodName, duration);
                
                Counter.builder("mongodb.slow.queries")
                    .tag("method", methodName)
                    .register(meterRegistry)
                    .increment();
            }
            
            return result;
            
        } catch (Exception e) {
            Counter.builder("mongodb.query.errors")
                .tag("method", methodName)
                .register(meterRegistry)
                .increment();
            
            throw e;
        }
    }
}
```

## Best Practices Summary

### ✅ DO:

1. **Index frequently queried fields** - email, status, userId
2. **Use compound indexes** for multi-field queries (follow ESR rule)
3. **Create unique indexes** for fields like email, username
4. **Use partial indexes** to reduce index size (status='ACTIVE')
5. **Monitor query performance** with explain() regularly
6. **Create covered queries** when possible (index-only)
7. **Use TTL indexes** for temporary data (sessions, logs)
8. **Index embedded document fields** with dot notation
9. **Test with realistic data** - performance differs at scale
10. **Monitor index usage** - drop unused indexes

### ❌ DON'T:

1. **Don't over-index** - each index slows writes
2. **Don't index low-cardinality fields** (true/false) as single index
3. **Don't forget to exclude _id** in covered queries
4. **Don't create redundant indexes** - {a,b} covers {a}
5. **Don't index everything** - target actual query patterns
6. **Don't ignore index order** in compound indexes
7. **Don't skip monitoring** - watch for slow queries
8. **Don't use indexes on small collections** (< 1000 docs)
9. **Don't create duplicate indexes** - check existing first
10. **Don't ignore explain()** results - optimize based on data

### Index Design Guidelines:

**Cardinality:**

```
High cardinality (good for indexing):
- Email addresses (unique per user)
- Phone numbers
- Order IDs
- SKUs

Low cardinality (poor for single-field index):
- Boolean fields (true/false)
- Status with few values (ACTIVE, INACTIVE)
- Gender (M, F, Other)

Use compound indexes for low-cardinality fields
```

**ESR Rule for Compound Indexes:**

```
Order fields in index:
1. Equality matches (=, in)
2. Sort fields
3. Range queries (>, <, between)

Example: Query users where status='ACTIVE', sort by createdAt, age > 18
Index: {'status': 1, 'createdAt': -1, 'age': 1}
```

## Interview Questions

**Q1: What is the ESR rule for compound index design?**

ESR = Equality, Sort, Range. Order compound index fields as: (1) Equality matches (=, in) first, (2) Sort fields second, (3) Range queries (>, <, between) last. Example: for query `status='ACTIVE' ORDER BY date WHERE age>18`, index should be `{'status':1, 'date':-1, 'age':1}`. This maximizes index efficiency.

**Q2: What is a covered query and why is it important?**

Covered query satisfies entire query from index without examining documents - all queried and returned fields must be in index. Extremely fast (index-only, no disk I/O). Requires: (1) query fields in index, (2) projection includes only index fields, (3) `_id` excluded. Example: index `{email:1, status:1}` covers query `{status:'ACTIVE'}` projecting only `{email:1, status:1, _id:0}`.

**Q3: How do you analyze query performance in MongoDB?**

Use `explain("executionStats")` to analyze: (1) executionTimeMillis - query duration, (2) totalDocsExamined vs nReturned - efficiency ratio, (3) stage - IXSCAN (good) vs COLLSCAN (bad), (4) indexName - which index used, (5) totalKeysExamined - index efficiency. Efficient query: uses index, examines few docs, ratio close to 1.0.

**Q4: What's the difference between single-field and compound indexes?**

Single-field indexes on one field (email), support queries on that field only. Compound indexes on multiple fields ({userId:1, date:-1}), support queries on: (1) first field only, (2) first + second fields, (3) all fields (prefix matching). Order matters! Cannot support queries on second field alone. Choose compound for common multi-field query patterns.

**Q5: How do you monitor MongoDB performance in production?**

Use Spring Boot Actuator with custom health indicators and metrics. Monitor: (1) Connection pool usage (current/available), (2) Query performance (execution time, slow queries), (3) Index usage (explain() results), (4) Collection stats (document count, sizes), (5) Operation counters (insert/query/update/delete). Set alerts for slow queries (>1s), connection pool exhaustion, high document examination ratios.
