# Testing Flyway Migrations

## Overview

Comprehensive testing of database migrations prevents production failures, ensures data integrity, and validates performance under realistic conditions. Flyway migrations must be tested as rigorously as application code.

**Key Concept**: Database migrations are code that modifies critical infrastructure. Test migrations with the same rigor as application code - unit tests for basic functionality, integration tests with real databases, and performance tests with production-like data volumes.

**Basic Integration Test:**

```java
@SpringBootTest
@ActiveProfiles("test")
class FlywayMigrationTest {
    
    @Autowired
    private DataSource dataSource;
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    @Test
    void shouldApplyAllMigrations() {
        // Given - Flyway has run via auto-configuration
        
        // When - Check that migrations were applied
        List<String> tables = getTableNames();
        
        // Then - Verify expected tables exist
        assertThat(tables).contains(
            "USERS",
            "ORDERS",
            "PRODUCTS",
            "FLYWAY_SCHEMA_HISTORY"
        );
    }
    
    @Test
    void shouldCreateUsersTableWithCorrectSchema() {
        // When
        Map<String, String> columns = getTableColumns("USERS");
        
        // Then
        assertThat(columns)
            .containsEntry("USER_ID", "BIGINT")
            .containsEntry("USERNAME", "VARCHAR")
            .containsEntry("EMAIL", "VARCHAR")
            .containsEntry("CREATED_AT", "TIMESTAMP");
    }
    
    @Test
    void shouldCreateIndexesOnUsersTable() {
        // When
        List<String> indexes = getTableIndexes("USERS");
        
        // Then
        assertThat(indexes).contains(
            "IDX_USERS_EMAIL",
            "IDX_USERS_USERNAME"
        );
    }
    
    @Test
    void shouldEnforceForeignKeyConstraints() {
        // Given
        jdbcTemplate.update(
            "INSERT INTO users (user_id, username, email) VALUES (1, 'testuser', 'test@example.com')"
        );
        
        // When - Insert order with valid user_id
        jdbcTemplate.update(
            "INSERT INTO orders (order_id, user_id, total_amount) VALUES (1, 1, 100.00)"
        );
        
        // Then - Should succeed
        Integer count = jdbcTemplate.queryForObject(
            "SELECT COUNT(*) FROM orders", Integer.class
        );
        assertThat(count).isEqualTo(1);
        
        // When - Try to insert order with invalid user_id
        // Then - Should fail with constraint violation
        assertThatThrownBy(() -> 
            jdbcTemplate.update(
                "INSERT INTO orders (order_id, user_id, total_amount) VALUES (2, 999, 200.00)"
            )
        ).isInstanceOf(DataIntegrityViolationException.class);
    }
    
    @Test
    void shouldApplyMigrationsInCorrectOrder() {
        // Query Flyway history
        List<Map<String, Object>> history = jdbcTemplate.queryForList(
            "SELECT installed_rank, version, description FROM flyway_schema_history ORDER BY installed_rank"
        );
        
        // Verify migration order
        assertThat(history).hasSize(4);
        assertThat(history.get(0).get("VERSION")).isEqualTo("1");
        assertThat(history.get(1).get("VERSION")).isEqualTo("2");
        assertThat(history.get(2).get("VERSION")).isEqualTo("3");
        assertThat(history.get(3).get("VERSION")).isEqualTo("4");
    }
    
    private List<String> getTableNames() {
        return jdbcTemplate.queryForList(
            "SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA = 'PUBLIC'",
            String.class
        );
    }
    
    private Map<String, String> getTableColumns(String tableName) {
        String sql = """
            SELECT COLUMN_NAME, TYPE_NAME
            FROM INFORMATION_SCHEMA.COLUMNS
            WHERE TABLE_NAME = ?
            """;
        
        return jdbcTemplate.query(sql, rs -> {
            Map<String, String> columns = new HashMap<>();
            while (rs.next()) {
                columns.put(
                    rs.getString("COLUMN_NAME"),
                    rs.getString("TYPE_NAME")
                );
            }
            return columns;
        }, tableName);
    }
    
    private List<String> getTableIndexes(String tableName) {
        return jdbcTemplate.queryForList(
            "SELECT INDEX_NAME FROM INFORMATION_SCHEMA.INDEXES WHERE TABLE_NAME = ?",
            String.class,
            tableName
        );
    }
}
```

### Testing Individual Migrations

**Isolated Migration Test:**

```java
@SpringBootTest
@ActiveProfiles("test")
@DirtiesContext(classMode = DirtiesContext.ClassMode.AFTER_EACH_TEST_METHOD)
class IndividualMigrationTest {
    
    @Autowired
    private DataSource dataSource;
    
    private Flyway flyway;
    
    @BeforeEach
    void setUp() {
        flyway = Flyway.configure()
            .dataSource(dataSource)
            .locations("classpath:db/migration")
            .cleanDisabled(false)
            .load();
        
        // Clean database before each test
        flyway.clean();
    }
    
    @Test
    void testV1_CreateUsersTable() {
        // When - Apply only first migration
        flyway.migrate(MigrateConfig.builder()
            .target(new MigrationVersion("1"))
            .build());
        
        // Then - Verify users table exists
        JdbcTemplate jdbcTemplate = new JdbcTemplate(dataSource);
        
        List<String> tables = jdbcTemplate.queryForList(
            "SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA = 'PUBLIC'",
            String.class
        );
        
        assertThat(tables).contains("USERS");
        assertThat(tables).doesNotContain("ORDERS");  // Not created yet
    }
    
    @Test
    void testV2_CreateOrdersTable() {
        // Given - Apply migrations up to V1
        flyway.migrate(MigrateConfig.builder()
            .target(new MigrationVersion("1"))
            .build());
        
        // When - Apply V2
        flyway.migrate(MigrateConfig.builder()
            .target(new MigrationVersion("2"))
            .build());
        
        // Then - Verify orders table exists
        JdbcTemplate jdbcTemplate = new JdbcTemplate(dataSource);
        
        List<String> tables = jdbcTemplate.queryForList(
            "SELECT TABLE_NAME FROM INFORMATION_SCHEMA.TABLES WHERE TABLE_SCHEMA = 'PUBLIC'",
            String.class
        );
        
        assertThat(tables).contains("USERS", "ORDERS");
    }
    
    @Test
    void testV3_DataMigration() {
        // Given - Apply migrations up to V2
        flyway.migrate(MigrateConfig.builder()
            .target(new MigrationVersion("2"))
            .build());
        
        // Insert test data in old format
        JdbcTemplate jdbcTemplate = new JdbcTemplate(dataSource);
        jdbcTemplate.update(
            "INSERT INTO users (user_id, first_name, last_name) VALUES (1, 'John', 'Doe')"
        );
        
        // When - Apply V3 (data migration)
        flyway.migrate(MigrateConfig.builder()
            .target(new MigrationVersion("3"))
            .build());
        
        // Then - Verify data was migrated correctly
        String fullName = jdbcTemplate.queryForObject(
            "SELECT full_name FROM users WHERE user_id = 1",
            String.class
        );
        
        assertThat(fullName).isEqualTo("John Doe");
    }
}
```

### H2 Compatibility Issues

**Problem: H2 vs PostgreSQL Differences**

```java
// H2 may not support all PostgreSQL features
// Example: SKIP LOCKED not supported in older H2 versions

// ❌ Migration that fails on H2
-- V4__batch_update.sql
UPDATE users SET status = 'ACTIVE'
WHERE user_id IN (
    SELECT user_id FROM users LIMIT 1000 FOR UPDATE SKIP LOCKED
);

// ✅ H2-compatible alternative for testing
UPDATE users SET status = 'ACTIVE'
WHERE user_id IN (
    SELECT user_id FROM users LIMIT 1000
);
```

```java
@SpringBootTest
@ActiveProfiles("test")
abstract class MultiDatabaseMigrationTest {
    
    @Autowired
    protected DataSource dataSource;
    
    @Autowired

        assertThat(tables)
            .as("Tables for " + getDatabaseType())
            .contains(normalizeTableName("users"));
        
        System.out.println("✓ " + getDatabaseType() + " migrations applied successfully");
    }
    
    @Test
    void shouldCreateCorrectSchema() {
        Map<String, String> userColumns = getTableColumns("users");
        
        assertThat(userColumns)
            .as("User table columns for " + getDatabaseType())
            .containsKey(normalizeColumnName("user_id"))
            .containsKey(normalizeColumnName("username"))
            .containsKey(normalizeColumnName("email"));
        
        System.out.println("✓ " + getDatabaseType() + " schema correct");
    }
    
    protected abstract List<String> getTables();
    
    protected abstract Map<String, String> getTableColumns(String tableName);
    
    protected String normalizeTableName(String tableName) {
        return getDatabaseType().equals("PostgreSQL") ? 
            tableName.toLowerCase() : tableName.toUpperCase();
    }
    
    protected String normalizeColumnName(String columnName) {
        return getDatabaseType().equals("PostgreSQL") ? 
            columnName.toLowerCase() : columnName.toUpperCase();
    }
}
```

## 3. Testing Migration Ordering

### Sequential Order Verification

```java
@SpringBootTest
@Testcontainers
class MigrationOrderingTest {
    
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15-alpine");
    
    @DynamicPropertySource
    static void registerProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
        registry.add("spring.flyway.enabled", () -> true);
    }
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    @Test
    void shouldApplyMigrationsInCorrectOrder() {
        // Query migration history
        List<MigrationRecord> history = jdbcTemplate.query(
            "SELECT installed_rank, version, description, type FROM flyway_schema_history ORDER BY installed_rank",
            (rs, rowNum) -> new MigrationRecord(
                rs.getInt("installed_rank"),
                rs.getString("version"),
                rs.getString("description"),
                rs.getString("type")
            )
        );
        
        // Verify sequential ordering
        assertThat(history).isNotEmpty();
        
        for (int i = 0; i < history.size(); i++) {
            MigrationRecord record = history.get(i);
            assertThat(record.installedRank()).isEqualTo(i + 1);
        }
        
        // Verify version ordering
        for (int i = 0; i < history.size() - 1; i++) {
            String currentVersion = history.get(i).version();
            String nextVersion = history.get(i + 1).version();
            
            if (currentVersion != null && nextVersion != null) {
                assertThat(compareVersions(currentVersion, nextVersion))
                    .as("Version %s should be less than %s", currentVersion, nextVersion)
                    .isLessThan(0);
            }
        }
    }
    
    @Test
    void shouldNotHaveGapsInMigrationHistory() {
        List<Integer> ranks = jdbcTemplate.queryForList(
            "SELECT installed_rank FROM flyway_schema_history ORDER BY installed_rank",
            Integer.class
        );
        
        // Verify no gaps in ranking
        for (int i = 0; i < ranks.size(); i++) {
            assertThat(ranks.get(i)).isEqualTo(i + 1);
        }
    }
    
    @Test
    void shouldRespectDependencies() {
        // Verify dependent migrations applied after dependencies
        
        // Get migration ranks
        Integer usersMigrationRank = jdbcTemplate.queryForObject(
            "SELECT installed_rank FROM flyway_schema_history WHERE description LIKE '%users%'",
            Integer.class
        );
        
        Integer ordersMigrationRank = jdbcTemplate.queryForObject(
            "SELECT installed_rank FROM flyway_schema_history WHERE description LIKE '%orders%'",
            Integer.class
        );
        
        // Orders table depends on users table (foreign key)
        assertThat(ordersMigrationRank)
            .as("Orders migration should come after users migration")
            .isGreaterThan(usersMigrationRank);
    }
    
    private int compareVersions(String v1, String v2) {
        String[] parts1 = v1.split("\\.");
        String[] parts2 = v2.split("\\.");
        
        int maxLength = Math.max(parts1.length, parts2.length);
        
        for (int i = 0; i < maxLength; i++) {
            int num1 = i < parts1.length ? Integer.parseInt(parts1[i]) : 0;
            int num2 = i < parts2.length ? Integer.parseInt(parts2[i]) : 0;
            
            if (num1 != num2) {
                return Integer.compare(num1, num2);
            }
        }
        
        return 0;
    }
    
    record MigrationRecord(int installedRank, String version, String description, String type) {}
}
```

### Out-of-Order Migration Testing

```java
@SpringBootTest
@Testcontainers
class OutOfOrderMigrationTest {
    
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15-alpine");
    
    @DynamicPropertySource
    static void registerProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
        registry.add("spring.flyway.enabled", () -> false);  // Manual control
        registry.add("spring.flyway.out-of-order", () -> true);  // Enable out-of-order
    }
    
    @Autowired
    private DataSource dataSource;
    
    @Test
    void shouldDetectOutOfOrderMigrations() {
        // Simulate scenario:
        // V1, V2, V3, V5 already applied
        // Now V4 is added (out of order)
        
        Flyway flyway = Flyway.configure()
            .dataSource(dataSource)
            .locations("classpath:db/migration")
            .outOfOrder(true)
            .load();
        
        // Apply migrations
        MigrateResult result = flyway.migrate();
        
        // Check if out-of-order migrations were detected and applied
        JdbcTemplate jdbcTemplate = new JdbcTemplate(dataSource);
        
        List<OutOfOrderMigration> outOfOrder = jdbcTemplate.query(
            """
            SELECT 
                h1.version,
                h1.installed_rank,
                MAX(h2.version) as executed_after_version
            FROM flyway_schema_history h1
            JOIN flyway_schema_history h2 
                ON h2.installed_rank < h1.installed_rank
                AND h2.version > h1.version
            WHERE h1.version IS NOT NULL
            GROUP BY h1.version, h1.installed_rank
            ORDER BY h1.installed_rank
            """,
            (rs, rowNum) -> new OutOfOrderMigration(
                rs.getString("version"),
                rs.getInt("installed_rank"),
                rs.getString("executed_after_version")
            )
        );
        
        if (!outOfOrder.isEmpty()) {
            System.out.println("Out-of-order migrations detected:");
            outOfOrder.forEach(m -> 
                System.out.printf("  Version %s executed after version %s%n",
                    m.version(), m.executedAfterVersion())
            );
        }
    }
    
    record OutOfOrderMigration(String version, int installedRank, String executedAfterVersion) {}
}
```

## 4. Validating Migration Success

### Comprehensive Validation Tests

```java
@SpringBootTest
@Testcontainers
class MigrationValidationTest {
    
    @Container
    static PostgreSQLContainer<?> postgres = new PostgreSQLContainer<>("postgres:15-alpine");
    
    @DynamicPropertySource
    static void registerProperties(DynamicPropertyRegistry registry) {
        registry.add("spring.datasource.url", postgres::getJdbcUrl);
        registry.add("spring.datasource.username", postgres::getUsername);
        registry.add("spring.datasource.password", postgres::getPassword);
    }
    
    @Autowired
    private DataSource dataSource;
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    @Test
    void shouldHaveNoFailedMigrations() {
        List<Map<String, Object>> failed = jdbcTemplate.queryForList(
            "SELECT * FROM flyway_schema_history WHERE success = false"
        );
        
        assertThat(failed)
            .as("Should have no failed migrations")
            .isEmpty();
    }
    
    @Test
    void shouldHaveConsistentChecksums() {
        // Validate checksums haven't changed
        Flyway flyway = Flyway.configure()
            .dataSource(dataSource)
            .locations("classpath:db/migration")
            .load();
        
        // This will throw exception if checksums don't match
        assertThatCode(() -> flyway.validate())
            .as("Checksums should be consistent")
            .doesNotThrowAnyException();
    }
    
    @Test
    void shouldHaveAllExpectedTables() {
        List<String> tables = jdbcTemplate.queryForList(
            "SELECT tablename FROM pg_tables WHERE schemaname = 'public'",
            String.class
        );
        
        assertThat(tables).contains(
            "users",
            "orders",
            "products",
            "order_items",
            "flyway_schema_history"
        );
    }
    
    @Test
    void shouldHaveAllExpectedIndexes() {
        Map<String, List<String>> tableIndexes = new HashMap<>();
        
        jdbcTemplate.query(
            "SELECT tablename, indexname FROM pg_indexes WHERE schemaname = 'public'",
            rs -> {
                String table = rs.getString("tablename");
                String index = rs.getString("indexname");
                tableIndexes.computeIfAbsent(table, k -> new ArrayList<>()).add(index);
            }
        );
        
        // Verify users table indexes
        assertThat(tableIndexes.get("users"))
            .as("Users table should have expected indexes")
            .containsAnyOf("idx_users_email", "idx_users_username");
        
        // Verify orders table indexes
        assertThat(tableIndexes.get("orders"))
            .as("Orders table should have expected indexes")
            .containsAnyOf("idx_orders_user_id", "idx_orders_order_date");
    }
    
    @Test
    void shouldHaveAllExpectedConstraints() {
        List<ConstraintInfo> constraints = jdbcTemplate.query(
            """
            SELECT
                tc.table_name,
                tc.constraint_name,
                tc.constraint_type
            FROM information_schema.table_constraints tc
            WHERE tc.table_schema = 'public'
            ORDER BY tc.table_name, tc.constraint_type
            """,
            (rs, rowNum) -> new ConstraintInfo(
                rs.getString("table_name"),
                rs.getString("constraint_name"),
                rs.getString("constraint_type")
            )
        );
        
        // Verify primary keys
        assertThat(constraints)
            .filteredOn(c -> c.constraintType().equals("PRIMARY KEY"))
            .extracting(ConstraintInfo::tableName)
            .contains("users", "orders", "products");
        
        // Verify foreign keys
        assertThat(constraints)
            .filteredOn(c -> c.constraintType().equals("FOREIGN KEY"))
            .isNotEmpty();
    }
    
    @Test
    void shouldHaveCorrectColumnTypes() {
        Map<String, String> userColumns = getColumnTypes("users");
        
        assertThat(userColumns)
            .containsEntry("user_id", "bigint")
            .containsEntry("username", "character varying")
            .containsEntry("email", "character varying")
            .containsEntry("created_at", "timestamp without time zone");
    }
    
    @Test
    void shouldHaveCorrectDefaultValues() {
        List<ColumnDefault> defaults = jdbcTemplate.query(
            """
            SELECT
                table_name,
                column_name,
                column_default
            FROM information_schema.columns
            WHERE table_schema = 'public'
              AND column_default IS NOT NULL
            """,
            (rs, rowNum) -> new ColumnDefault(
                rs.getString("table_name"),
                rs.getString("column_name"),
                rs.getString("column_default")
            )
        );
        
        // Verify created_at has CURRENT_TIMESTAMP
        assertThat(defaults)
            .filteredOn(d -> d.columnName().equals("created_at"))
            .allMatch(d -> d.columnDefault().contains("CURRENT_TIMESTAMP"));
    }
    
    private Map<String, String> getColumnTypes(String tableName) {
        return jdbcTemplate.query(
            """
            SELECT column_name, data_type
            FROM information_schema.columns
            WHERE table_name = ?
            """,
            rs -> {
                Map<String, String> columns = new HashMap<>();
                while (rs.next()) {
                    columns.put(rs.getString("column_name"), rs.getString("data_type"));
                }
                return columns;
            },
            tableName
        );
    }
    
    record ConstraintInfo(String tableName, String constraintName, String constraintType) {}
    record ColumnDefault(String tableName, String columnName, String columnDefault) {}
}
```

## Best Practices Summary

### ✅ DO:

1. **Use Testcontainers** for production-like testing
2. **Test on target database** (don't rely only on H2)
3. **Validate migration order** and dependencies
4. **Test rollback procedures** when possible
5. **Measure performance** with realistic data volumes
6. **Automate tests** in CI/CD pipeline
7. **Test schema validation** (constraints, indexes)
8. **Test data integrity** after migrations
9. **Use matrix testing** for multiple databases
10. **Generate migration reports** in CI/CD

### ❌ DON'T:

1. **Don't test only with H2** if production uses PostgreSQL/MySQL
2. **Don't skip performance testing** for large migrations
3. **Don't ignore checksum validation** errors
4. **Don't test with empty databases** (use realistic data)
5. **Don't skip integration tests** (unit tests aren't enough)
6. **Don't ignore CI/CD failures** - they prevent production issues
7. **Don't test migrations individually** without full sequence
8. **Don't skip validation tests** (constraints, indexes, etc.)
9. **Don't forget multi-database testing** if supporting multiple DBs
10. **Don't deploy untested migrations** to production

## Interview Questions

**Q1: Why use Testcontainers instead of H2 for testing Flyway migrations?**

Testcontainers provides real database instances (PostgreSQL, MySQL) that match production behavior exactly. H2 has different SQL dialects, features, and constraints than production databases. Real databases catch issues with database-specific syntax, stored procedures, and subtle behavioral differences that H2 misses.

**Q2: How do you test that migrations are applied in the correct order?**

Query `flyway_schema_history` table and verify: (1) `installed_rank` is sequential without gaps, (2) version numbers increase monotonically, (3) dependent migrations come after their dependencies. Also verify schema state matches expected state after each migration sequence.

**Q3: What metrics should you measure when performance testing migrations?**

Measure: (1) total migration time, (2) per-migration execution time, (3) throughput for data migrations (rows/second), (4) index creation time on large tables, (5) lock acquisition time. Set performance budgets and fail builds if exceeded. Test with production-like data volumes.

**Q4: How do you integrate Flyway testing into CI/CD pipelines?**

Use matrix builds to test against multiple database versions, validate migration syntax and naming, run integration tests with Testcontainers, measure performance, generate migration reports, check for dangerous operations (DROP, TRUNCATE), and fail builds if any validation fails. Archive test results and reports.

**Q5: What should you validate after migrations complete?**

Validate: (1) all expected tables exist, (2) all expected indexes created, (3) foreign key constraints present, (4) column types correct, (5) default values set properly, (6) no failed migrations in history, (7) checksums consistent, (8) data integrity maintained, (9) no orphaned records.
