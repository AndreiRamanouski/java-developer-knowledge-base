# Flyway Migration Patterns

## Overview

Flyway supports multiple migration patterns to handle various database versioning scenarios. From simple SQL scripts to complex Java-based migrations, understanding these patterns enables effective database evolution across all project phases.

**Key Concept**: Choose the right migration pattern for your needs - SQL for standard DDL/DML, Java for complex business logic, baselines for existing databases, and callbacks for cross-cutting concerns like auditing and notifications.

---

## 1. SQL-Based Migrations (Most Common)

### Basic SQL Migration Structure

SQL migrations are the most common and recommended approach for Flyway.

**V1__create_users_table.sql:**

```sql
-- Description: Create users table for authentication
-- Author: john.doe
-- Date: 2024-06-01

-- Create users table
CREATE TABLE users (
    user_id BIGSERIAL PRIMARY KEY,
    username VARCHAR(50) NOT NULL UNIQUE,
    email VARCHAR(100) NOT NULL UNIQUE,
    password_hash VARCHAR(255) NOT NULL,
    first_name VARCHAR(50),
    last_name VARCHAR(50),
    is_active BOOLEAN DEFAULT TRUE,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);

-- Create indexes for performance
CREATE INDEX idx_users_email ON users(email);
CREATE INDEX idx_users_username ON users(username);
CREATE INDEX idx_users_active ON users(is_active) WHERE is_active = TRUE;

-- Create trigger for updated_at
CREATE OR REPLACE FUNCTION update_updated_at_column()
RETURNS TRIGGER AS $$
BEGIN
    NEW.updated_at = CURRENT_TIMESTAMP;
    RETURN NEW;
END;
$$ LANGUAGE plpgsql;

CREATE TRIGGER users_updated_at
    BEFORE UPDATE ON users
    FOR EACH ROW
    EXECUTE FUNCTION update_updated_at_column();
```

### Complex SQL Patterns

**V2__create_orders_with_partitioning.sql:**

```sql
-- Multi-statement migration with partitioning

-- Create orders table with partitioning
CREATE TABLE orders (
    order_id BIGSERIAL,
    user_id BIGINT NOT NULL,
    order_number VARCHAR(50) NOT NULL,
    order_date DATE NOT NULL DEFAULT CURRENT_DATE,
    total_amount DECIMAL(10, 2) NOT NULL,
    status VARCHAR(20) NOT NULL DEFAULT 'PENDING',
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    PRIMARY KEY (order_id, order_date),
    CONSTRAINT fk_orders_user FOREIGN KEY (user_id) 
        REFERENCES users(user_id) ON DELETE CASCADE
) PARTITION BY RANGE (order_date);

-- Create partitions for 2024
CREATE TABLE orders_2024_q1 PARTITION OF orders
    FOR VALUES FROM ('2024-01-01') TO ('2024-04-01');

CREATE TABLE orders_2024_q2 PARTITION OF orders
    FOR VALUES FROM ('2024-04-01') TO ('2024-07-01');

CREATE TABLE orders_2024_q3 PARTITION OF orders
    FOR VALUES FROM ('2024-07-01') TO ('2024-10-01');

CREATE TABLE orders_2024_q4 PARTITION OF orders
    FOR VALUES FROM ('2024-10-01') TO ('2025-01-01');

-- Create indexes on partitioned table
CREATE INDEX idx_orders_user_id ON orders(user_id);
CREATE INDEX idx_orders_order_date ON orders(order_date);
CREATE INDEX idx_orders_status ON orders(status);
CREATE INDEX idx_orders_number ON orders(order_number);

-- Create sequence for order numbers
CREATE SEQUENCE order_number_seq START WITH 1000;

-- Create function to generate order numbers
CREATE OR REPLACE FUNCTION generate_order_number()
RETURNS VARCHAR AS $$
DECLARE
    next_val BIGINT;
    order_num VARCHAR(50);
BEGIN
    next_val := nextval('order_number_seq');
    order_num := 'ORD-' || TO_CHAR(CURRENT_DATE, 'YYYYMMDD') || '-' || LPAD(next_val::TEXT, 6, '0');
    RETURN order_num;
END;
$$ LANGUAGE plpgsql;
```

### Data Migration Patterns

**V3__migrate_legacy_user_data.sql:**

```sql
-- Data migration with transformation

-- Create temporary staging table
CREATE TEMP TABLE legacy_users_staging (
    old_id INTEGER,
    old_username VARCHAR(100),
    old_email VARCHAR(100),
    old_first_name VARCHAR(100),
    old_last_name VARCHAR(100),
    old_status VARCHAR(20)
);

-- Copy data from legacy table (if it exists)
DO $$
BEGIN
    IF EXISTS (SELECT 1 FROM information_schema.tables WHERE table_name = 'legacy_users') THEN
        INSERT INTO legacy_users_staging
        SELECT id, username, email, first_name, last_name, status
        FROM legacy_users;
    END IF;
END $$;

-- Transform and migrate data
INSERT INTO users (username, email, first_name, last_name, is_active)
SELECT 
    LOWER(TRIM(old_username)),
    LOWER(TRIM(old_email)),
    INITCAP(TRIM(old_first_name)),
    INITCAP(TRIM(old_last_name)),
    CASE 
        WHEN old_status = 'ACTIVE' THEN TRUE
        WHEN old_status = 'INACTIVE' THEN FALSE
        ELSE TRUE
    END
FROM legacy_users_staging
WHERE old_email IS NOT NULL
  AND old_username IS NOT NULL
ON CONFLICT (email) DO NOTHING;

-- Log migration statistics
DO $$
DECLARE
    migrated_count INTEGER;
    skipped_count INTEGER;
BEGIN
    SELECT COUNT(*) INTO migrated_count FROM users WHERE created_at >= CURRENT_TIMESTAMP - INTERVAL '1 minute';
    SELECT COUNT(*) INTO skipped_count FROM legacy_users_staging WHERE old_email IS NULL OR old_username IS NULL;
    
    RAISE NOTICE 'Migrated % users', migrated_count;
    RAISE NOTICE 'Skipped % invalid records', skipped_count;
END $$;

-- Drop legacy table (optional, uncomment if needed)
-- DROP TABLE IF EXISTS legacy_users;
```

### Conditional SQL

**V4__conditional_schema_changes.sql:**

```sql
-- Conditional DDL based on existing schema

-- Add column only if it doesn't exist
DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM information_schema.columns 
        WHERE table_name = 'users' AND column_name = 'phone_number'
    ) THEN
        ALTER TABLE users ADD COLUMN phone_number VARCHAR(20);
        RAISE NOTICE 'Added phone_number column';
    ELSE
        RAISE NOTICE 'phone_number column already exists';
    END IF;
END $$;

-- Create index only if it doesn't exist
DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM pg_indexes 
        WHERE tablename = 'users' AND indexname = 'idx_users_phone'
    ) THEN
        CREATE INDEX idx_users_phone ON users(phone_number);
        RAISE NOTICE 'Created idx_users_phone index';
    END IF;
END $$;

-- Add constraint only if it doesn't exist
DO $$
BEGIN
    IF NOT EXISTS (
        SELECT 1 FROM pg_constraint 
        WHERE conname = 'chk_users_phone_format'
    ) THEN
        ALTER TABLE users 
        ADD CONSTRAINT chk_users_phone_format 
        CHECK (phone_number ~ '^\+?[1-9]\d{1,14}$');
        RAISE NOTICE 'Added phone_format constraint';
    END IF;
END $$;
```

### Transaction Control

**By default, each migration runs in a transaction:**

```sql
-- V5__transactional_migration.sql
-- Entire file runs in one transaction

BEGIN;  -- Optional, Flyway handles this

INSERT INTO users (username, email) VALUES ('user1', 'user1@example.com');
INSERT INTO orders (user_id, order_number, total_amount) 
    VALUES (1, 'ORD-001', 100.00);

-- If any statement fails, entire migration rolls back

COMMIT;  -- Optional, Flyway handles this
```

**Disable transaction for specific migrations:**

```yaml
# application.yml
spring:
  flyway:
    # This doesn't work per-file
    # Use executeInTransaction in Java-based migrations instead
```

**For PostgreSQL - statements that can't run in transaction:**

```sql
-- V6__create_index_concurrently.sql

-- These statements cannot run in a transaction block
-- Split into separate migration or use Java-based migration

-- Option 1: Put in separate file
CREATE INDEX CONCURRENTLY idx_users_full_name 
ON users((first_name || ' ' || last_name));
```

## 2. Java-Based Migrations for Complex Logic

### Creating Java Migrations

Java migrations provide programmatic control for complex scenarios.

**Basic Java Migration:**

```java
package db.migration;

import org.flywaydb.core.api.migration.BaseJavaMigration;
import org.flywaydb.core.api.migration.Context;
import java.sql.PreparedStatement;
import java.sql.ResultSet;
import java.sql.Statement;

/**
 * Naming convention: V{version}__{description}.java
 * Must be in classpath:db/migration package
 */
public class V7__Encrypt_User_Passwords extends BaseJavaMigration {
    
    @Override
    public void migrate(Context context) throws Exception {
        // Get connection from context
        try (Statement select = context.getConnection().createStatement()) {
            // Read users with plain text passwords
            ResultSet users = select.executeQuery(
                "SELECT user_id, password FROM users WHERE password_hash IS NULL"
            );
            
            // Prepare update statement
            try (PreparedStatement update = context.getConnection().prepareStatement(
                "UPDATE users SET password_hash = ? WHERE user_id = ?"
            )) {
                int count = 0;
                while (users.next()) {
                    long userId = users.getLong("user_id");
                    String plainPassword = users.getString("password");
                    
                    // Encrypt password using BCrypt
                    String hashedPassword = hashPassword(plainPassword);
                    
                    update.setString(1, hashedPassword);
                    update.setLong(2, userId);
                    update.addBatch();
                    
                    count++;
                    
                    // Execute batch every 1000 records
                    if (count % 1000 == 0) {
                        update.executeBatch();
                        System.out.println("Encrypted " + count + " passwords...");
                    }
                }
                
                // Execute remaining batch
                update.executeBatch();
                System.out.println("Total passwords encrypted: " + count);
            }
        }
    }
    
    private String hashPassword(String plainPassword) {
        // Use BCrypt or other hashing algorithm
        // For example purposes, simplified
        return "hashed_" + plainPassword;
    }
}
```

### Complex Data Transformation

```java
package db.migration;

import org.flywaydb.core.api.migration.BaseJavaMigration;
import org.flywaydb.core.api.migration.Context;
import java.sql.*;
import java.util.HashMap;
import java.util.Map;

public class V8__Migrate_Order_Data_With_Validation extends BaseJavaMigration {
    
    @Override
    public void migrate(Context context) throws Exception {
        Connection conn = context.getConnection();
        
        // Track migration statistics
        Map<String, Integer> stats = new HashMap<>();
        stats.put("migrated", 0);
        stats.put("skipped", 0);
        stats.put("errors", 0);
        
        // Create staging table
        try (Statement stmt = conn.createStatement()) {
            stmt.execute("""
                CREATE TEMP TABLE order_migration_log (
                    old_order_id BIGINT,
                    new_order_id BIGINT,
                    status VARCHAR(20),
                    error_message TEXT,
                    migrated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
                )
            """);
        }
        
        // Read orders from legacy table
        try (Statement select = conn.createStatement();
             ResultSet rs = select.executeQuery(
                 "SELECT * FROM legacy_orders ORDER BY order_id"
             )) {
            
            PreparedStatement insertOrder = conn.prepareStatement(
                "INSERT INTO orders (user_id, order_number, order_date, total_amount, status) " +
                "VALUES (?, ?, ?, ?, ?) RETURNING order_id",
                Statement.RETURN_GENERATED_KEYS
            );
            
            PreparedStatement logMigration = conn.prepareStatement(
                "INSERT INTO order_migration_log (old_order_id, new_order_id, status, error_message) " +
                "VALUES (?, ?, ?, ?)"
            );
            
            while (rs.next()) {
                long oldOrderId = rs.getLong("order_id");
                
                try {
                    // Validate data
                    if (!isValidOrder(rs)) {
                        logMigration.setLong(1, oldOrderId);
                        logMigration.setNull(2, Types.BIGINT);
                        logMigration.setString(3, "SKIPPED");
                        logMigration.setString(4, "Invalid data");
                        logMigration.executeUpdate();
                        
                        stats.put("skipped", stats.get("skipped") + 1);
                        continue;
                    }
                    
                    // Transform and insert
                    insertOrder.setLong(1, rs.getLong("customer_id"));
                    insertOrder.setString(2, generateOrderNumber(oldOrderId));
                    insertOrder.setDate(3, rs.getDate("order_date"));
                    insertOrder.setBigDecimal(4, rs.getBigDecimal("total"));
                    insertOrder.setString(5, mapStatus(rs.getString("status")));
                    
                    ResultSet generatedKeys = insertOrder.executeQuery();
                    if (generatedKeys.next()) {
                        long newOrderId = generatedKeys.getLong(1);
                        
                        // Log success
                        logMigration.setLong(1, oldOrderId);
                        logMigration.setLong(2, newOrderId);
                        logMigration.setString(3, "SUCCESS");
                        logMigration.setNull(4, Types.VARCHAR);
                        logMigration.executeUpdate();
                        
                        stats.put("migrated", stats.get("migrated") + 1);
                    }
                    
                } catch (SQLException e) {
                    // Log error
                    logMigration.setLong(1, oldOrderId);
                    logMigration.setNull(2, Types.BIGINT);
                    logMigration.setString(3, "ERROR");
                    logMigration.setString(4, e.getMessage());
                    logMigration.executeUpdate();
                    
                    stats.put("errors", stats.get("errors") + 1);
                }
            }
        }
        
        // Print migration summary
        System.out.println("Migration Summary:");
        System.out.println("  Migrated: " + stats.get("migrated"));
        System.out.println("  Skipped: " + stats.get("skipped"));
        System.out.println("  Errors: " + stats.get("errors"));
        
        // Optionally fail if too many errors
        if (stats.get("errors") > stats.get("migrated") * 0.1) {
            throw new Exception("Migration failed: Too many errors (> 10%)");
        }
    }
    
    private boolean isValidOrder(ResultSet rs) throws SQLException {
        return rs.getDate("order_date") != null &&
               rs.getBigDecimal("total") != null &&
               rs.getBigDecimal("total").compareTo(BigDecimal.ZERO) > 0;
    }
    
    private String generateOrderNumber(long oldOrderId) {
        return "ORD-" + String.format("%08d", oldOrderId);
    }
    
    private String mapStatus(String oldStatus) {
        return switch (oldStatus.toUpperCase()) {
            case "NEW", "PENDING" -> "PENDING";
            case "COMPLETE", "DONE" -> "COMPLETED";
            case "CANCELLED", "CANCELED" -> "CANCELLED";
            default -> "PENDING";
        };
    }
}
```

### External Service Integration

```java
package db.migration;

import org.flywaydb.core.api.migration.BaseJavaMigration;
import org.flywaydb.core.api.migration.Context;
import org.springframework.web.client.RestTemplate;
import com.fasterxml.jackson.databind.ObjectMapper;
import java.sql.*;
import java.util.List;

public class V9__Sync_Users_With_External_System extends BaseJavaMigration {
    
    private final RestTemplate restTemplate = new RestTemplate();
    private final ObjectMapper objectMapper = new ObjectMapper();
    
    @Override
    public void migrate(Context context) throws Exception {
        // Fetch users from external API
        String apiUrl = System.getenv("EXTERNAL_API_URL");
        if (apiUrl == null) {
            System.out.println("EXTERNAL_API_URL not set, skipping sync");
            return;
        }
        
        String response = restTemplate.getForObject(
            apiUrl + "/api/users",
            String.class
        );
        
        List<ExternalUser> externalUsers = objectMapper.readValue(
            response,
            objectMapper.getTypeFactory()
                .constructCollectionType(List.class, ExternalUser.class)
        );
        
        // Upsert users into database
        try (PreparedStatement upsert = context.getConnection().prepareStatement(
            """
            INSERT INTO users (external_id, username, email, first_name, last_name)
            VALUES (?, ?, ?, ?, ?)
            ON CONFLICT (external_id) 
            DO UPDATE SET
                username = EXCLUDED.username,
                email = EXCLUDED.email,
                first_name = EXCLUDED.first_name,
                last_name = EXCLUDED.last_name,
                updated_at = CURRENT_TIMESTAMP
            """
        )) {
            for (ExternalUser user : externalUsers) {
                upsert.setString(1, user.getId());
                upsert.setString(2, user.getUsername());
                upsert.setString(3, user.getEmail());
                upsert.setString(4, user.getFirstName());
                upsert.setString(5, user.getLastName());
                upsert.addBatch();
            }
            
            int[] results = upsert.executeBatch();
            System.out.println("Synced " + results.length + " users from external system");
        }
    }
    
    static class ExternalUser {
        private String id;
        private String username;
        private String email;
        private String firstName;
        private String lastName;
        
        // Getters and setters
        public String getId() { return id; }
        public void setId(String id) { this.id = id; }
        public String getUsername() { return username; }
        public void setUsername(String username) { this.username = username; }
        public String getEmail() { return email; }
        public void setEmail(String email) { this.email = email; }
        public String getFirstName() { return firstName; }
        public void setFirstName(String firstName) { this.firstName = firstName; }
        public String getLastName() { return lastName; }
        public void setLastName(String lastName) { this.lastName = lastName; }
    }
}
```

```java
package db.migration;

import org.flywaydb.core.api.migration.BaseJavaMigration;

import org.springframework.jdbc.core.JdbcTemplate;
import org.springframework.jdbc.datasource.SingleConnectionDataSource;
import org.springframework.stereotype.Component;

@Component
public class V10__Spring_Aware_Migration extends BaseJavaMigration {
    
    @Override
    public void migrate(Context context) throws Exception {
        // Create JdbcTemplate from Flyway connection
        JdbcTemplate jdbcTemplate = new JdbcTemplate(
            new SingleConnectionDataSource(context.getConnection(), true)
        );
        
        // Use Spring's JdbcTemplate for cleaner code
        List<Map<String, Object>> users = jdbcTemplate.queryForList(
            "SELECT user_id, email FROM users WHERE is_active = TRUE"
        );
        
        for (Map<String, Object> user : users) {
            Long userId = (Long) user.get("user_id");
            String email = (String) user.get("email");
            
            // Process each user
            jdbcTemplate.update(
                "INSERT INTO user_preferences (user_id, email_notifications) VALUES (?, ?)",
                userId,
                true
            );
        }
        
        System.out.println("Created preferences for " + users.size() + " users");
    }
}
```

## 3. Baseline Migrations for Existing Databases

### Understanding Baseline

Baseline allows Flyway to work with existing databases that already have schema.

**Scenario:**

```
You have a production database with existing schema
You want to start using Flyway for future changes
You don't want Flyway to try creating existing tables
```

### Baseline Configuration

**application.yml:**

```yaml
spring:
  flyway:
    enabled: true
    baseline-on-migrate: true
    baseline-version: 1.0
    baseline-description: "Production baseline - existing schema"
```

**What Happens:**

```
1. Flyway checks if flyway_schema_history exists
2. If table doesn't exist, Flyway creates it
3. Flyway inserts baseline record:
   - version: 1.0
   - type: BASELINE
   - description: "Production baseline - existing schema"
4. Migrations with version <= 1.0 are IGNORED
5. Migrations with version > 1.0 are EXECUTED
```

### Baseline Workflow

**Step 1: Take Database Snapshot**

```bash
# Generate SQL dump of current production schema
pg_dump -h localhost -U postgres -d proddb --schema-only > baseline_schema.sql
```

**Step 2: Create Baseline Migration (Optional)**

```sql
-- V1.0__baseline.sql
-- This file documents existing schema but won't be executed on prod

-- Existing users table (for reference)
-- CREATE TABLE users (
--     user_id BIGSERIAL PRIMARY KEY,
--     username VARCHAR(50) NOT NULL,
--     email VARCHAR(100) NOT NULL
-- );

-- Existing orders table (for reference)
-- CREATE TABLE orders (
--     order_id BIGSERIAL PRIMARY KEY,
--     user_id BIGINT NOT NULL,
--     total_amount DECIMAL(10,2)
-- );
```

**Step 3: Configure Baseline**

```yaml
spring:
  flyway:
    baseline-on-migrate: true
    baseline-version: 1.0
```

**Step 4: Create New Migrations**

```sql
-- V1.1__add_phone_to_users.sql
-- This WILL execute (version > baseline)
ALTER TABLE users ADD COLUMN phone_number VARCHAR(20);

-- V1.2__create_user_preferences.sql
-- This WILL execute (version > baseline)
CREATE TABLE user_preferences (
    preference_id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    theme VARCHAR(50) DEFAULT 'light',
    CONSTRAINT fk_preferences_user FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);
```

### Manual Baseline Command

**Using Flyway CLI:**

```bash
# Baseline existing database
flyway -url=jdbc:postgresql://localhost:5432/proddb \
       -user=produser \
       -password=prodpass \
       baseline \
       -baselineVersion=1.0 \
       -baselineDescription="Production baseline"
```

**Programmatically:**

```java
@Configuration
public class FlywayBaselineConfig {
    
    @Bean
    public Flyway flyway(DataSource dataSource) {
        Flyway flyway = Flyway.configure()
            .dataSource(dataSource)
            .baselineVersion("1.0")
            .baselineDescription("Production baseline")
            .load();
        
        // Check if schema history exists
        if (!hasSchemaHistory(dataSource)) {
            // Baseline the database
            flyway.baseline();
            System.out.println("Database baselined at version 1.0");
        }
        
        // Run migrations
        flyway.migrate();
        
        return flyway;
    }
    
    private boolean hasSchemaHistory(DataSource dataSource) {
        try (Connection conn = dataSource.getConnection();
             Statement stmt = conn.createStatement();
             ResultSet rs = stmt.executeQuery(
                 "SELECT 1 FROM flyway_schema_history LIMIT 1"
             )) {
            return rs.next();
        } catch (SQLException e) {
            return false;
        }
    }
}
```

## 4. Migration File Organization

### Basic Organization

**Simple Project:**

```
src/main/resources/
└── db/
    └── migration/
        ├── V1__create_users.sql
        ├── V2__create_orders.sql
        ├── V3__create_products.sql
        └── R__create_views.sql
```

### Organized by Version

**Medium Project:**

```
src/main/resources/
└── db/
    └── migration/
        ├── v1.0/
        │   ├── V1.0.0__baseline.sql
        │   ├── V1.0.1__create_users.sql
        │   └── V1.0.2__create_orders.sql
        ├── v1.1/
        │   ├── V1.1.0__add_products.sql
        │   └── V1.1.1__add_user_preferences.sql
        ├── v2.0/

        │   └── V2.0.1__migrate_data.sql
        └── repeatable/
            ├── R__create_views.sql
            └── R__create_procedures.sql
```

**Configuration:**

```yaml
spring:
  flyway:
```

```java
package com.example.flyway.callbacks;

import org.flywaydb.core.api.callback.Callback;
import org.flywaydb.core.api.callback.Context;

        return event == Event.BEFORE_MIGRATE ||
               event == Event.AFTER_MIGRATE ||
               event == Event.AFTER_MIGRATE_ERROR;

            System.err.println("=== Migration Failed ===");
            logMigrationFailure(context);
        }
    }
    
    @Override
    public String getCallbackName() {
        return "MigrationAuditCallback";
    }
    
    private void logMigrationStart(Context context) {
        try (var stmt = context.getConnection().createStatement()) {
            stmt.execute(
                "INSERT INTO migration_audit_log (event_type, details) " +
                "VALUES ('MIGRATION_START', 'Migration process started')"
            );
        } catch (Exception e) {
            System.err.println("Failed to log migration start: " + e.getMessage());
        }
    }
    
    private void logMigrationSuccess(Context context) {
        try (var stmt = context.getConnection().createStatement()) {
            stmt.execute(
                "INSERT INTO migration_audit_log (event_type, details) " +

            );
        } catch (Exception e) {
            System.err.println("Failed to log migration success: " + e.getMessage());
        }
    }
    
    private void logMigrationFailure(Context context) {
```

### Advanced Callback with Notifications

```java
package com.example.flyway.callbacks;

import org.flywaydb.core.api.callback.Callback;
import org.flywaydb.core.api.callback.Context;
import org.flywaydb.core.api.callback.Event;
import org.springframework.beans.factory.annotation.Autowired;
import org.springframework.stereotype.Component;
import java.sql.ResultSet;
import java.sql.Statement;

@Component
public class MigrationNotificationCallback implements Callback {
    
    @Autowired
    private NotificationService notificationService;
    
    @Autowired
    private MetricsService metricsService;
    
    private long migrationStartTime;
    
    @Override
    public boolean supports(Event event, Context context) {
        return event == Event.BEFORE_MIGRATE ||
               event == Event.AFTER_EACH_MIGRATE ||
               event == Event.AFTER_MIGRATE ||
               event == Event.AFTER_MIGRATE_ERROR;
    }
    
    @Override
    public boolean canHandleInTransaction(Event event, Context context) {
        return true;
    }
    
    @Override
    public void handle(Event event, Context context) {
        switch (event) {
            case BEFORE_MIGRATE -> handleBeforeMigrate(context);
            case AFTER_EACH_MIGRATE -> handleAfterEachMigrate(context);
            case AFTER_MIGRATE -> handleAfterMigrate(context);
            case AFTER_MIGRATE_ERROR -> handleAfterMigrateError(context);
        }
    }
    
    private void handleBeforeMigrate(Context context) {
        migrationStartTime = System.currentTimeMillis();
        
        String environment = System.getenv("ENVIRONMENT");
        
        // Send notification
        notificationService.sendInfo(
            "Database Migration Started",
            String.format("Flyway migration started in %s environment", environment)
        );
        
        // Record metric
        metricsService.recordMigrationStart();
    }
    
    private void handleAfterEachMigrate(Context context) {
        try {
            // Get latest migration info
            String query = """
                SELECT version, description, execution_time
                FROM flyway_schema_history
                ORDER BY installed_rank DESC
                LIMIT 1
                """;
            
            try (Statement stmt = context.getConnection().createStatement();
                 ResultSet rs = stmt.executeQuery(query)) {
                
                if (rs.next()) {
                    String version = rs.getString("version");
                    String description = rs.getString("description");
                    int executionTime = rs.getInt("execution_time");
                    
                    System.out.printf("✓ Migrated to version %s (%s) in %dms%n",
                        version, description, executionTime);
                    
                    // Record per-migration metric
                    metricsService.recordMigrationStep(version, executionTime);
                }
            }
        } catch (Exception e) {
            System.err.println("Error logging migration: " + e.getMessage());
        }
    }
    
    private void handleAfterMigrate(Context context) {
        long duration = System.currentTimeMillis() - migrationStartTime;
        
        try {
            // Get migration statistics
            MigrationStats stats = getMigrationStats(context);
            
            // Send success notification
            notificationService.sendSuccess(
                "Database Migration Completed",
                String.format(
                    "Migration completed successfully in %dms. " +
                    "Applied %d migrations. New version: %s",
                    duration,
                    stats.getAppliedCount(),
                    stats.getCurrentVersion()
                )
            );
            
            // Record metrics
            metricsService.recordMigrationSuccess(duration);
            
        } catch (Exception e) {
            System.err.println("Error in after migrate callback: " + e.getMessage());
        }
    }
    
    private void handleAfterMigrateError(Context context) {
        long duration = System.currentTimeMillis() - migrationStartTime;
        
        // Send failure notification
        notificationService.sendError(
            "Database Migration Failed",
            String.format(
                "Migration failed after %dms. Check logs for details.",
                duration
            )
        );
        
        // Record failure metric
        metricsService.recordMigrationFailure(duration);
    }
    
    private MigrationStats getMigrationStats(Context context) throws Exception {
        String query = """
            SELECT 
                COUNT(*) as total_count,
                MAX(version) as current_version
            FROM flyway_schema_history
            WHERE success = true
              AND installed_on >= CURRENT_TIMESTAMP - INTERVAL '1 hour'
            """;
        
        try (Statement stmt = context.getConnection().createStatement();
             ResultSet rs = stmt.executeQuery(query)) {
            
            if (rs.next()) {
                return new MigrationStats(
                    rs.getInt("total_count"),
                    rs.getString("current_version")
                );
            }
        }
        
        return new MigrationStats(0, "unknown");
    }
    
    @Override
    public String getCallbackName() {
        return "MigrationNotificationCallback";
    }
    
    private record MigrationStats(int appliedCount, String currentVersion) {}
}
```

## 6. Out-of-Order Migrations

### Understanding Out-of-Order

**Problem Scenario:**

```
Developer A creates: V5__feature_a.sql
Developer B creates: V4__feature_b.sql (lower version)

Main branch has: V1, V2, V3, V5
Developer B merges V4

Flyway sees:
  V1 ✓ executed
  V2 ✓ executed
  V3 ✓ executed
  V4 ✗ NOT executed (but version < current version 5)
  V5 ✓ executed

By default: Flyway IGNORES V4 (version < current)
```

### Enabling Out-of-Order

**Configuration:**

```yaml
spring:
  flyway:
    out-of-order: true  # Allow execution of out-of-order migrations
```

**With out-of-order enabled:**

```
Flyway will execute V4 even though V5 was already executed
V4 is marked as executed in flyway_schema_history
```

### Use Cases for Out-of-Order

**Parallel Development:**

```
Team A (Feature Branch 1):
  - Creates V10__add_user_preferences.sql
  - Merges to main

Team B (Feature Branch 2):
  - Creates V9__add_product_categories.sql
  - Merges to main after Team A

With out-of-order: V9 executes even though V10 already ran
Without out-of-order: V9 is ignored
```

**Hotfix Scenarios:**

```
Production version: V50
Hotfix branch creates: V49__urgent_fix.sql

With out-of-order: V49 executes
Without out-of-order: V49 ignored (fails migration)
```

### Configuration Example

```java
@Configuration
public class FlywayConfig {
    
    @Bean
    public Flyway flyway(DataSource dataSource) {
        return Flyway.configure()
            .dataSource(dataSource)
            .locations("classpath:db/migration")
            .outOfOrder(true)  // Enable out-of-order migrations
            .validateOnMigrate(true)
            .load();
    }
}
```

### Out-of-Order Detection

**Schema History Example:**

```sql
SELECT installed_rank, version, description, installed_on
FROM flyway_schema_history
ORDER BY installed_rank;

installed_rank | version | description              | installed_on
---------------|---------|--------------------------|---------------------
1              | 1       | create users             | 2024-06-01 10:00:00
2              | 2       | create orders            | 2024-06-01 10:00:01
3              | 3       | create products          | 2024-06-01 10:00:02
4              | 5       | add user preferences     | 2024-06-01 10:00:03
5              | 4       | add product categories   | 2024-06-01 10:00:04  ← Out of order!
```

### Risks of Out-of-Order

**⚠️ Dependency Issues:**

```sql
-- V5__add_user_preferences.sql (executed first)
CREATE TABLE user_preferences (
    preference_id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    theme VARCHAR(50),
    language VARCHAR(10),
    CONSTRAINT fk_preferences_user FOREIGN KEY (user_id)
        REFERENCES users(user_id)
);

-- V4__modify_users_table.sql (executed later, out of order)
-- This might conflict with V5 if it modifies users table
ALTER TABLE users DROP COLUMN user_id;  -- BREAKS V5's FK!
```

### Best Practices for Out-of-Order

**Use Timestamp Versioning:**

```
Instead of:
  V1, V2, V3, V4, V5

Use:
  V20240601100000__create_users.sql
  V20240601110000__create_orders.sql
  V20240601120000__create_products.sql

Benefits:
  - No version conflicts
  - Natural chronological order
  - Merge conflicts less likely
```

**Version Number Ranges:**

```
Team A uses: V1000-V1999
Team B uses: V2000-V2999
Hotfixes use: V100-V199
Infrastructure uses: V10-V99

Reduces need for out-of-order
```

### Monitoring Out-of-Order Migrations

```java
@Component
public class OutOfOrderMigrationDetector implements Callback {
    
    @Override
    public boolean supports(Event event, Context context) {
        return event == Event.AFTER_MIGRATE;
    }
    
    @Override
    public boolean canHandleInTransaction(Event event, Context context) {
        return true;
    }
    
    @Override
    public void handle(Event event, Context context) {
        try {
            List<OutOfOrderMigration> outOfOrder = detectOutOfOrder(context);
            
            if (!outOfOrder.isEmpty()) {
                System.out.println("⚠️  OUT-OF-ORDER MIGRATIONS DETECTED:");
                for (OutOfOrderMigration migration : outOfOrder) {
                    System.out.printf("  - Version %s executed after version %s%n",
                        migration.version(), migration.executedAfter());
                }
            }
        } catch (Exception e) {
            System.err.println("Error detecting out-of-order: " + e.getMessage());
        }
    }
    
    private List<OutOfOrderMigration> detectOutOfOrder(Context context) throws Exception {
        String query = """
            SELECT 
                h1.version as version,
                h1.installed_rank as rank,
                MAX(h2.version) as executed_after
            FROM flyway_schema_history h1
            JOIN flyway_schema_history h2 
                ON h2.installed_rank < h1.installed_rank
                AND h2.version > h1.version
            WHERE h1.version IS NOT NULL
            GROUP BY h1.version, h1.installed_rank
            ORDER BY h1.installed_rank
            """;
        
        List<OutOfOrderMigration> result = new ArrayList<>();
        
        try (Statement stmt = context.getConnection().createStatement();
             ResultSet rs = stmt.executeQuery(query)) {
            
            while (rs.next()) {
                result.add(new OutOfOrderMigration(
                    rs.getString("version"),
                    rs.getString("executed_after")
                ));
            }
        }
        
        return result;
    }
    
    @Override
    public String getCallbackName() {
        return "OutOfOrderMigrationDetector";
    }
    
    private record OutOfOrderMigration(String version, String executedAfter) {}
}
```

## Best Practices Summary

### ✅ DO:

1. **Use SQL migrations** for standard DDL/DML
2. **Use Java migrations** for complex business logic
3. **Baseline existing databases** before first migration
4. **Organize migrations** logically (by version, module, or type)
5. **Use callbacks** for auditing and notifications
6. **Enable out-of-order** only when necessary
7. **Use timestamp versioning** to avoid conflicts
8. **Document baseline** schema for reference
9. **Test migrations** before production
10. **Keep migrations** small and focused

### ❌ DON'T:

1. **Don't mix unrelated changes** in one migration
2. **Don't use Java migrations** for simple DDL
3. **Don't skip baseline** for existing databases
4. **Don't over-organize** (too many subdirectories)
5. **Don't abuse callbacks** (keep them lightweight)
6. **Don't enable out-of-order** without understanding risks
7. **Don't use sequential versions** in parallel development
8. **Don't modify baseline** after it's set
9. **Don't forget to test** Java migrations thoroughly
10. **Don't skip documentation** in migration files

## Interview Questions

**Q1: When should you use Java-based migrations instead of SQL?**

Use Java migrations for complex business logic, data transformations requiring validation, external service integration, or operations that need programmatic control (batching, error handling). Use SQL for straightforward DDL/DML operations.

**Q2: How do you handle an existing production database with Flyway?**

Use baseline: configure `baseline-on-migrate: true` and set `baseline-version` to a version (e.g., 1.0). Flyway will mark all migrations ≤ baseline as executed without running them. New migrations > baseline version will execute normally.

**Q3: What are Flyway callbacks and when would you use them?**

Callbacks are hooks that execute at specific lifecycle points (beforeMigrate, afterMigrate, etc.). Use them for cross-cutting concerns like auditing, notifications, performance logging, or environment setup/cleanup. They can be SQL files or Java classes.

**Q4: What are the risks of enabling out-of-order migrations?**

Out-of-order migrations can create dependency issues if a later migration depends on an earlier one that wasn't yet executed. It can also make the migration history harder to understand. Only enable when absolutely necessary and use timestamp versioning to minimize conflicts.

**Q5: How do you organize migrations for a large project with multiple teams?**

Use organized directory structure (by module/version), timestamp-based versioning to avoid conflicts, version number ranges per team (Team A: V1000-1999, Team B: V2000-2999), and separate locations for common vs. environment-specific migrations.

Flyway migration patterns enable flexible database evolution:

- ✅ **SQL migrations** for standard schema changes
- ✅ **Java migrations** for complex transformations
- ✅ **Baseline** for existing databases
- ✅ **Organized structure** for maintainability
- ✅ **Callbacks** for cross-cutting concerns
