# Advanced Liquibase Features

## Overview

Liquibase provides advanced features beyond basic schema management, including custom Java changes, sophisticated data migrations, database-specific optimizations, and reverse engineering capabilities. Mastering these features enables complex migration scenarios and database-agnostic solutions.

**Key Concept**: While basic Liquibase changes handle most scenarios, advanced features enable complex data transformations, database-specific optimizations, and integration with existing databases.

---

## 1. Custom Change Classes in Java

Custom change classes allow you to write complex migration logic in Java when declarative changelogs aren't sufficient.

### Creating a Custom Change Class

**Basic Custom Change:**

```java
package com.example.liquibase.changes;

import liquibase.change.custom.CustomTaskChange;
import liquibase.database.Database;
import liquibase.exception.CustomChangeException;
import liquibase.exception.SetupException;
import liquibase.exception.ValidationErrors;
import liquibase.resource.ResourceAccessor;
import lombok.Setter;

@Setter
public class EncryptUserPasswordsChange implements CustomTaskChange {
    
    private String tableName = "users";
    private String passwordColumnName = "password";
    private String encryptedPasswordColumnName = "password_hash";
    
    @Override
    public void execute(Database database) throws CustomChangeException {
        try {
            // Get connection
            Connection connection = database.getConnection()
                .getUnderlyingConnection();
            
            // Read plain text passwords
            String selectSql = String.format(
                "SELECT user_id, %s FROM %s WHERE %s IS NOT NULL",
                passwordColumnName, tableName, passwordColumnName
            );
            
            PreparedStatement selectStmt = connection.prepareStatement(selectSql);
            ResultSet rs = selectStmt.executeQuery();
            
            // Prepare update statement
            String updateSql = String.format(
                "UPDATE %s SET %s = ? WHERE user_id = ?",
                tableName, encryptedPasswordColumnName
            );
            PreparedStatement updateStmt = connection.prepareStatement(updateSql);
            
            int count = 0;
            while (rs.next()) {
                long userId = rs.getLong("user_id");
                String plainPassword = rs.getString(passwordColumnName);
                
                // Encrypt password
                String hashedPassword = BCrypt.hashpw(plainPassword, BCrypt.gensalt());
                
                updateStmt.setString(1, hashedPassword);
                updateStmt.setLong(2, userId);
                updateStmt.executeUpdate();
                
                count++;
            }
            
            rs.close();
            selectStmt.close();
            updateStmt.close();
            
            System.out.println("Encrypted " + count + " passwords");
            
        } catch (Exception e) {
            throw new CustomChangeException("Failed to encrypt passwords", e);
        }
    }
    
    @Override
    public String getConfirmationMessage() {
        return "User passwords have been encrypted";
    }
    
    @Override
    public void setUp() throws SetupException {
        // Setup logic (optional)
    }
    
    @Override
    public void setFileOpener(ResourceAccessor resourceAccessor) {
        // Not used in this example
    }
    
    @Override
    public ValidationErrors validate(Database database) {
        ValidationErrors errors = new ValidationErrors();
        
        if (tableName == null || tableName.isEmpty()) {
            errors.addError("tableName is required");
        }
        
        if (passwordColumnName == null || passwordColumnName.isEmpty()) {
            errors.addError("passwordColumnName is required");
        }
        
        if (encryptedPasswordColumnName == null || encryptedPasswordColumnName.isEmpty()) {
            errors.addError("encryptedPasswordColumnName is required");
        }
        
        return errors;
    }
}
```

### Advanced Custom Change with Rollback

```java
package com.example.liquibase.changes;

import liquibase.change.custom.CustomTaskChange;
import liquibase.change.custom.CustomTaskRollback;
import liquibase.database.Database;
import liquibase.exception.CustomChangeException;
import liquibase.exception.RollbackImpossibleException;
import liquibase.exception.ValidationErrors;
import liquibase.resource.ResourceAccessor;
import lombok.Setter;
import lombok.extern.slf4j.Slf4j;

@Slf4j
@Setter
public class MigrateUserDataChange implements CustomTaskChange, CustomTaskRollback {
    
    private String sourceTable = "old_users";
    private String targetTable = "new_users";
    private int batchSize = 1000;
    
    @Override
    public void execute(Database database) throws CustomChangeException {
        try {
            Connection connection = database.getConnection()
                .getUnderlyingConnection();
            
            // Count total records
            String countSql = "SELECT COUNT(*) FROM " + sourceTable;
            PreparedStatement countStmt = connection.prepareStatement(countSql);
            ResultSet countRs = countStmt.executeQuery();
            countRs.next();
            int totalRecords = countRs.getInt(1);
            countRs.close();
            countStmt.close();
            
            log.info("Migrating {} records from {} to {}", 
                totalRecords, sourceTable, targetTable);
            
            // Batch migration
            String selectSql = String.format(
                "SELECT user_id, username, email, first_name, last_name, " +
                "created_at FROM %s ORDER BY user_id", 
                sourceTable
            );
            
            String insertSql = String.format(
                "INSERT INTO %s (user_id, username, email, full_name, " +
                "created_date) VALUES (?, ?, ?, ?, ?)",
                targetTable
            );
            
            PreparedStatement selectStmt = connection.prepareStatement(selectSql);
            PreparedStatement insertStmt = connection.prepareStatement(insertSql);
            
            ResultSet rs = selectStmt.executeQuery();
            
            int count = 0;
            int batchCount = 0;
            
            while (rs.next()) {
                long userId = rs.getLong("user_id");
                String username = rs.getString("username");
                String email = rs.getString("email");
                String firstName = rs.getString("first_name");
                String lastName = rs.getString("last_name");
                Timestamp createdAt = rs.getTimestamp("created_at");
                
                // Transform data
                String fullName = (firstName + " " + lastName).trim();
                
                insertStmt.setLong(1, userId);
                insertStmt.setString(2, username);
                insertStmt.setString(3, email);
                insertStmt.setString(4, fullName);
                insertStmt.setTimestamp(5, createdAt);
                insertStmt.addBatch();
                
                batchCount++;
                count++;
                
                // Execute batch
                if (batchCount >= batchSize) {
                    insertStmt.executeBatch();
                    connection.commit();
                    batchCount = 0;
                    log.info("Migrated {} of {} records", count, totalRecords);
                }
            }
            
            // Execute remaining batch
            if (batchCount > 0) {
                insertStmt.executeBatch();
                connection.commit();
            }
            
            rs.close();
            selectStmt.close();
            insertStmt.close();
            
            log.info("Migration completed: {} records migrated", count);
            
        } catch (Exception e) {
            throw new CustomChangeException("Failed to migrate user data", e);
        }
    }
    
    @Override
    public void rollback(Database database) throws CustomChangeException, 
                                                     RollbackImpossibleException {
        try {
            Connection connection = database.getConnection()
                .getUnderlyingConnection();
            
            // Delete migrated data
            String deleteSql = "DELETE FROM " + targetTable;
            PreparedStatement deleteStmt = connection.prepareStatement(deleteSql);
            int deleted = deleteStmt.executeUpdate();
            connection.commit();
            deleteStmt.close();
            
            log.info("Rollback completed: {} records deleted from {}", 
                deleted, targetTable);
            
        } catch (Exception e) {
            throw new CustomChangeException("Failed to rollback migration", e);
        }
    }
    
    @Override
    public String getConfirmationMessage() {
        return String.format("Migrated data from %s to %s", sourceTable, targetTable);
    }
    
    @Override
    public void setUp() throws SetupException {
        // Setup if needed
    }
    
    @Override
    public void setFileOpener(ResourceAccessor resourceAccessor) {
        // Not used
    }
    
    @Override
    public ValidationErrors validate(Database database) {
        ValidationErrors errors = new ValidationErrors();
        
        if (batchSize <= 0) {
            errors.addError("batchSize must be greater than 0");
        }
        
        return errors;
    }
}
```

### Custom Change with External Services

```java
package com.example.liquibase.changes;

import liquibase.change.custom.CustomTaskChange;
import liquibase.database.Database;
import liquibase.exception.CustomChangeException;
import org.springframework.web.client.RestTemplate;
import lombok.Setter;

@Setter
public class SyncWithExternalSystemChange implements CustomTaskChange {
    
    private String apiEndpoint;
    private String apiKey;
    private String tableName = "users";
    
    @Override
    public void execute(Database database) throws CustomChangeException {
        try {
            Connection connection = database.getConnection()
                .getUnderlyingConnection();
            
            // Fetch data from external system
            RestTemplate restTemplate = new RestTemplate();
            HttpHeaders headers = new HttpHeaders();
            headers.set("Authorization", "Bearer " + apiKey);
            
            HttpEntity<String> entity = new HttpEntity<>(headers);
            ResponseEntity<ExternalUser[]> response = restTemplate.exchange(
                apiEndpoint,
                HttpMethod.GET,
                entity,
                ExternalUser[].class
            );
            
            ExternalUser[] externalUsers = response.getBody();
            
            if (externalUsers == null || externalUsers.length == 0) {
                return;
            }
            
            // Insert/update in database
            String upsertSql = String.format(
                "MERGE INTO %s t " +
                "USING (SELECT ? as external_id, ? as email, ? as name FROM DUAL) s " +
                "ON (t.external_id = s.external_id) " +
                "WHEN MATCHED THEN " +
                "  UPDATE SET t.email = s.email, t.name = s.name " +
                "WHEN NOT MATCHED THEN " +
                "  INSERT (external_id, email, name) " +
                "  VALUES (s.external_id, s.email, s.name)",
                tableName
            );
            
            PreparedStatement stmt = connection.prepareStatement(upsertSql);
            
            for (ExternalUser user : externalUsers) {
                stmt.setString(1, user.getId());
                stmt.setString(2, user.getEmail());
                stmt.setString(3, user.getName());
                stmt.executeUpdate();
            }
            
            connection.commit();
            stmt.close();
            
        } catch (Exception e) {
            throw new CustomChangeException("Failed to sync with external system", e);
        }
    }
    
    @Override
    public String getConfirmationMessage() {
        return "Synced data with external system";
    }
    
    @Override
    public ValidationErrors validate(Database database) {
        ValidationErrors errors = new ValidationErrors();
        
        if (apiEndpoint == null || apiEndpoint.isEmpty()) {
            errors.addError("apiEndpoint is required");
        }
        
        if (apiKey == null || apiKey.isEmpty()) {
            errors.addError("apiKey is required");
        }
        
        return errors;
    }
    
    // Other required methods...
}

@Data
class ExternalUser {
    private String id;
    private String email;
    private String name;
}
```

### Custom SQL Generator

For more control over generated SQL:

```java
package com.example.liquibase.generators;

import liquibase.database.Database;
import liquibase.database.core.OracleDatabase;
import liquibase.sql.Sql;
import liquibase.sql.UnparsedSql;
import liquibase.sqlgenerator.SqlGeneratorChain;
import liquibase.sqlgenerator.core.CreateTableGenerator;
import liquibase.statement.core.CreateTableStatement;

public class CustomCreateTableGenerator extends CreateTableGenerator {
    
    @Override
    public int getPriority() {
        return PRIORITY_DATABASE + 1; // Higher priority than default
    }
    
    @Override
    public boolean supports(CreateTableStatement statement, Database database) {
        return database instanceof OracleDatabase;
    }
    
    @Override
    public Sql[] generateSql(CreateTableStatement statement, 
                            Database database, 
                            SqlGeneratorChain sqlGeneratorChain) {
        
        // Call default generator
        Sql[] defaultSql = super.generateSql(statement, database, sqlGeneratorChain);
        
        // Add custom optimizations for Oracle
        String tableName = statement.getTableName();
        String additionalSql = String.format(
            "ALTER TABLE %s STORAGE (INITIAL 10M NEXT 10M PCTINCREASE 0)",
            database.escapeTableName(
                statement.getCatalogName(),
                statement.getSchemaName(),
                tableName
            )
        );
        
        Sql[] result = new Sql[defaultSql.length + 1];
        System.arraycopy(defaultSql, 0, result, 0, defaultSql.length);
        result[defaultSql.length] = new UnparsedSql(additionalSql);
        
        return result;
    }
}
```

```yaml
      author: john.doe
      changes:
```

```yaml
            sql: |
              -- Load and transform data from staging table
              INSERT INTO users (user_id, username, email, full_name)
              SELECT 
                s.id,
                LOWER(s.login_name),
                LOWER(s.email_address),
                s.first_name || ' ' || s.last_name
              FROM staging_users s
              WHERE NOT EXISTS (
                SELECT 1 FROM users u 
                WHERE u.email = LOWER(s.email_address)
              );
              
              -- Update statistics
              UPDATE migration_stats 
              SET users_migrated = (SELECT COUNT(*) FROM users),
                  migration_date = CURRENT_TIMESTAMP
              WHERE migration_id = 'v1.0';
```

## 4. SQL vs Abstracted Changes

### When to Use Abstracted Changes (createTable, addColumn)

**Advantages:**

- ✅ Database-independent
- ✅ Automatic rollback generation
- ✅ Validated by Liquibase
- ✅ Better documentation

**Example:**

```yaml
databaseChangeLog:
```

### When to Use SQL

**Advantages:**

- ✅ Database-specific optimizations
- ✅ Complex DDL not supported by Liquibase
- ✅ Stored procedures, triggers, views
- ✅ Performance tuning

**Example:**

```yaml
databaseChangeLog:
  # ✅ Good: Database-specific optimization
  - changeSet:
      id: 002-create-optimized-table-oracle
      author: john.doe
      dbms: oracle
      changes:
        - sql:
            sql: |
              CREATE TABLE orders (
                order_id NUMBER(19) PRIMARY KEY,
                customer_id NUMBER(19) NOT NULL,
                order_date DATE NOT NULL,
                total_amount NUMBER(10,2)
              )
              TABLESPACE orders_data
              STORAGE (
                INITIAL 100M
                NEXT 100M
                PCTINCREASE 0
              )
              PARTITION BY RANGE (order_date)
              INTERVAL (NUMTOYMINTERVAL(1, 'MONTH'))
              (
                PARTITION orders_initial 
                VALUES LESS THAN (DATE '2024-01-01')
              );
              
              CREATE INDEX idx_orders_customer 
              ON orders(customer_id) 
              LOCAL;
      rollback:
        - sql:
            sql: DROP TABLE orders;
```

```yaml
    author: john.doe

    changes:
```

```yaml
          viewName: v_user_summary

              u.user_id,
              u.username,
              u.email,
              COUNT(o.order_id) as total_orders,

- changeSet:
    id: 005-create-complex-view
    author: john.doe
    runOnChange: true
    changes:
      - sql:
          sql: |
            CREATE OR REPLACE VIEW v_user_analytics AS
            WITH user_stats AS (
              SELECT 
                user_id,
                COUNT(DISTINCT order_id) as order_count,
                SUM(total_amount) as total_revenue,
                MAX(order_date) as last_order_date
              FROM orders
              GROUP BY user_id
            )
            SELECT 
              u.user_id,
              u.username,
              u.email,
              COALESCE(s.order_count, 0) as order_count,
              COALESCE(s.total_revenue, 0) as total_revenue,
              s.last_order_date,
              CASE 
                WHEN s.last_order_date > SYSDATE - 30 THEN 'ACTIVE'
                WHEN s.last_order_date > SYSDATE - 90 THEN 'DORMANT'
                ELSE 'INACTIVE'
              END as user_status
            FROM users u
            LEFT JOIN user_stats s ON u.user_id = s.user_id;
```

### Reverse Engineering Workflow

**1. Generate initial baseline:**

```bash
# Generate from production database
mvn liquibase:generateChangeLog \
  -Dliquibase.url=jdbc:oracle:thin:@prod:1521:PROD \
  -Dliquibase.outputChangeLogFile=db/changelog/baseline/db.changelog-baseline.yaml
```

**2. Clean up and organize:**

```bash
# Split into logical files
db/changelog/baseline/
├── db.changelog-baseline.yaml (master)
├── 001-tables.yaml
├── 002-indexes.yaml
├── 003-sequences.yaml
├── 004-foreign-keys.yaml
└── 005-views.yaml
```

**3. Create master changelog:**

```yaml
# db/changelog/db.changelog-master.yaml
databaseChangeLog:
  # Baseline from existing database
  - include:
      file: db/changelog/baseline/db.changelog-baseline.yaml
      context: baseline
  
  # Mark as baseline (don't execute on existing prod)
  - changeSet:
      id: baseline-tag
      author: system
      context: baseline
      changes:
        - tagDatabase:
            tag: baseline
  
  # New migrations go here
  - includeAll:
      path: db/changelog/migrations/
      relativeToChangelogFile: true
```

**4. Mark baseline as executed (for existing databases):**

```bash
# Mark baseline changesets as already executed
liquibase \
  --changeLogFile=db/changelog/baseline/db.changelog-baseline.yaml \
  --contexts=baseline \
  changelogSync
```

7. **Don't use loadData** for volatile application data

## Interview Questions

**Q1: When would you create a custom change class instead of using SQL?**

Create custom changes when you need complex business logic, interaction with external systems, conditional processing based on data, or sophisticated error handling that SQL can't easily provide. Examples: encrypting passwords, calling APIs, complex data transformations.

**Q2: What's the difference between loadData and loadUpdateData?**

`loadData` performs INSERT only (fails if record exists). `loadUpdateData` performs UPSERT (INSERT if not exists, UPDATE if exists), using the primaryKey attribute to identify existing records.

**Q3: Why might you choose SQL over abstracted Liquibase changes?**

Use SQL for: (1) database-specific optimizations (partitioning, compression), (2) features not supported by Liquibase (complex stored procedures), (3) performance tuning, (4) when you're committed to a specific database and don't need portability.

**Q4: How do you baseline an existing production database?**

Generate changelog from production using `generateChangeLog`, clean up and organize the output, mark it with a "baseline" context, then use `changelogSync` to mark all baseline changesets as executed without running them. Future migrations go after the baseline.

**Q5: What are the risks of using auto-generated changelogs?**

Generated changelogs may include: (1) unnecessary objects (temp tables, system objects), (2) poor naming (auto-generated IDs), (3) missing comments/documentation, (4) wrong column types, (5) missing logical grouping. Always review and clean up before use.
