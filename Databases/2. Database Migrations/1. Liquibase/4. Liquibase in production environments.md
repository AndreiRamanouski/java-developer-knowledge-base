# Liquibase in Production Environments

## Overview

Running Liquibase in production requires careful planning, robust rollback strategies, and proper handling of edge cases. Production deployments demand zero-downtime strategies, cluster coordination, and comprehensive auditing to ensure data integrity and system availability.

**Key Concept**: Production database migrations are high-risk operations. Success requires pre-deployment validation, automated rollback capabilities, comprehensive testing, and monitoring throughout the deployment process.

---

## 1. Zero-Downtime Deployment Strategies

### The Expand-Contract Pattern

The expand-contract (also called parallel change) pattern enables zero-downtime schema changes.

**Phase 1: Expand (Add new, keep old)**

```yaml
# Release 1: Add new column, keep old column
databaseChangeLog:
  - changeSet:
      id: 001-add-full-name-column
      author: john.doe
      comment: Phase 1 - Expand - Add new full_name column
      changes:
        # Add new column (nullable initially)
        - addColumn:
            tableName: users
            columns:
              - column:
                  name: full_name
                  type: VARCHAR(200)
                  # Initially nullable for existing rows
        
        # Create trigger to sync old -> new
        - sql:
            dbms: oracle
            sql: |
              CREATE OR REPLACE TRIGGER sync_full_name
              BEFORE INSERT OR UPDATE ON users
              FOR EACH ROW
              BEGIN
                IF :NEW.full_name IS NULL THEN
                  :NEW.full_name := :NEW.first_name || ' ' || :NEW.last_name;
                END IF;
              END;
      rollback:
        - sql:
            sql: DROP TRIGGER sync_full_name
        - dropColumn:
            tableName: users
            columnName: full_name

  - changeSet:
      id: 002-backfill-full-name
      author: john.doe
      comment: Phase 1 - Backfill existing data
      changes:
        - sql:
            sql: |
              -- Backfill in batches to avoid locks
              UPDATE users
              SET full_name = first_name || ' ' || last_name
              WHERE full_name IS NULL
              AND ROWNUM <= 10000;
              
              COMMIT;
        # Run multiple times if needed for large tables
```

**Application Code (supports both schemas):**

```java
@Entity
@Table(name = "users")
public class User {
    @Id
    private Long userId;
    
    // Old columns (still used)
    @Column(name = "first_name")
    private String firstName;
    
    @Column(name = "last_name")
    private String lastName;
    
    // New column (Phase 1: read-only, Phase 2: read-write)
    @Column(name = "full_name")
    private String fullName;
    
    // Application writes to both old and new during transition
    public void setName(String first, String last) {
        this.firstName = first;
        this.lastName = last;
        this.fullName = first + " " + last;
    }
}
```

**Phase 2: Contract (Remove old)**

```yaml
# Release 2: After all applications updated
databaseChangeLog:
  - changeSet:
      id: 003-drop-old-name-columns
      author: john.doe
      comment: Phase 2 - Contract - Remove old columns
      preConditions:
        - onFail: HALT
        # Ensure all applications are using new column
        - sqlCheck:
            expectedResult: 0
            sql: |
              -- Check no recent writes to old columns
              SELECT COUNT(*) 
              FROM user_audit_log 
              WHERE column_name IN ('first_name', 'last_name')
              AND change_date > SYSDATE - 7
      changes:
        # Drop trigger (no longer needed)
        - sql:
            sql: DROP TRIGGER sync_full_name
        
        # Drop old columns
        - dropColumn:
            tableName: users
            columnName: first_name
        - dropColumn:
            tableName: users
            columnName: last_name
      rollback:
        # Cannot easily rollback - data loss
        - empty
```

### Blue-Green Deployment

Deploy to new environment, switch traffic after validation.

**Database Strategy:**

```yaml
# Shared database approach
databaseChangeLog:
  # Changes must be backward compatible
  - changeSet:
      id: 004-add-new-feature-column
      author: john.doe
      comment: Add column for new feature (nullable for old version)
      changes:
        - addColumn:
            tableName: products
            columns:
              - column:
                  name: rating
                  type: DECIMAL(3,2)
                  # Nullable so old version doesn't break
                  defaultValue: null
```

**Deployment Flow:**

```
1. Blue environment (current production)
2. Apply backward-compatible migrations to shared database
3. Deploy Green environment (new version)
4. Validate Green environment
5. Switch traffic to Green
6. Keep Blue for quick rollback
7. After validation period, decommission Blue
8. Apply contract changes (remove old columns)
```

### Rolling Deployment

Gradually update application instances.

**Requirements:**

```yaml
databaseChangeLog:
  # All changes must be backward compatible
  - changeSet:
      id: 005-add-status-column
      author: john.doe
      changes:
        - addColumn:
            tableName: orders
            columns:
              - column:
                  name: new_status
                  type: VARCHAR(50)
                  # Default ensures old app instances work
                  defaultValue: 'PENDING'
```

**Application Compatibility:**

```java
@Entity
@Table(name = "orders")
public class Order {
    // Old instances use old_status
    @Column(name = "old_status")
    private String oldStatus;
    
    // New instances use new_status
    @Column(name = "new_status")
    private String newStatus;
    
    // Getter handles both (for migration period)
    public String getStatus() {
        return newStatus != null ? newStatus : oldStatus;
    }
}
```

Safest approach for zero-downtime.

**Safe Operations:**

```yaml
      changes:
        - createTable:
            tableName: audit_log

      author: john.doe
      changes:
        - addColumn:
            tableName: users
            columns:
              - column:
                  name: metadata
                  type: CLOB
  
  # ✅ Safe: Add index
  - changeSet:
      id: 008-add-performance-index
      author: john.doe
      changes:
        - createIndex:
            indexName: idx_users_email
            tableName: users
            columns:
              - column:
                  name: email
  
  # ⚠️ Risky: Drop column (needs expand-contract)
  - changeSet:
      id: 009-drop-deprecated-column
      author: john.doe
      comment: Only after all apps updated
      preConditions:
        - sqlCheck:
            expectedResult: 0
            sql: SELECT COUNT(*) FROM app_versions WHERE version < '2.0'
      changes:
        - dropColumn:
            tableName: users
            columnName: deprecated_field
```

```java
        // Apply all migrations
        liquibase.update(new Contexts("test"));

        // Verify database state at v1.0
        assertTrue(tableExists("users"));
        assertFalse(tableExists("orders")); // Added after v1.0

    @Test
    void testRollbackToDate() throws Exception {
        // Apply migrations
        liquibase.update(new Contexts("test"));
        
        // Rollback to specific date

            LocalDate.of(2024, 6, 1)
                .atStartOfDay(ZoneId.systemDefault())
                .toInstant()
        );

        // Verify state as of that date

    }

        boolean exists = rs.next();
        rs.close();
        return exists;

        DatabaseMetaData metaData = dataSource.getConnection().getMetaData();
        ResultSet rs = metaData.getColumns(null, null, tableName.toUpperCase(),

        boolean exists = rs.next();
        rs.close();
        return exists;
    }
```

```bash
  --url=$DB_URL \
  --username=$DB_USER \
  --password=$DB_PASS \

# 7. Verify migration

# Run verification queries
# Check application health

# 8. If verification fails, rollback

  echo "Migration verification failed! Rolling back..."

    --changeLogFile=$CHANGELOG_FILE \
```

### Rollback Decision Tree

```java
/**
 * Rollback Decision Framework
 */
public class RollbackDecisionService {
    
    public enum RollbackStrategy {
        AUTOMATIC_ROLLBACK,
        MANUAL_ROLLBACK,
        FORWARD_FIX,
        NO_ACTION
    }
    
    public RollbackStrategy determineStrategy(MigrationFailure failure) {
        // 1. Data corruption detected
        if (failure.isDataCorruption()) {
            return RollbackStrategy.AUTOMATIC_ROLLBACK;
        }
        
        // 2. Partial migration (some changesets failed)
        if (failure.isPartialMigration()) {
            // Check if failed changeset has rollback
            if (failure.hasRollback()) {
                return RollbackStrategy.AUTOMATIC_ROLLBACK;
            } else {
                return RollbackStrategy.MANUAL_ROLLBACK;
            }
        }
        
        // 3. Application incompatibility
        if (failure.isApplicationError()) {
            // Check if schema change is reversible
            if (failure.isReversible() && !failure.hasDataLoss()) {
                return RollbackStrategy.AUTOMATIC_ROLLBACK;
            } else {
                return RollbackStrategy.FORWARD_FIX;
            }
        }
        
        // 4. Performance degradation
        if (failure.isPerformanceIssue()) {
            // Can often be fixed forward
            return RollbackStrategy.FORWARD_FIX;
        }
        
        // 5. Lock timeout or resource exhaustion
        if (failure.isResourceIssue()) {
            return RollbackStrategy.NO_ACTION; // Retry later
        }
        
        return RollbackStrategy.MANUAL_ROLLBACK;
    }
}
```

## 3. Handling Failed Migrations

### Failure Detection and Recovery

**Custom Liquibase Listener:**

```java
@Component
public class ProductionLiquibaseListener implements ChangeSetListener {
    
    private static final Logger log = LoggerFactory.getLogger(ProductionLiquibaseListener.class);
    
    @Autowired
    private NotificationService notificationService;
    
    @Autowired
    private MetricsService metricsService;
    
    @Override
    public void willRun(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                       Database database, ChangeSet.RunStatus runStatus) {
        log.info("Executing changeset: {}", changeSet.getId());
        metricsService.recordMigrationStart(changeSet.getId());
    }
    
    @Override
    public void ran(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                   Database database, ChangeExecListener execListener) {
        log.info("Successfully executed: {}", changeSet.getId());
        metricsService.recordMigrationSuccess(changeSet.getId());
    }
    
    @Override
    public void rolledBack(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                          Database database) {
        log.warn("Rolled back changeset: {}", changeSet.getId());
        metricsService.recordMigrationRollback(changeSet.getId());
        
        // Alert operations team
        notificationService.sendAlert(
            "Database Migration Rolled Back",
            "Changeset " + changeSet.getId() + " was rolled back"
        );
    }
    
    @Override
    public void runFailed(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                         Database database, Exception exception) {
        log.error("Migration failed for changeset: {}", changeSet.getId(), exception);
        metricsService.recordMigrationFailure(changeSet.getId());
        
        // Critical alert
        notificationService.sendCriticalAlert(
            "Database Migration Failed",
            String.format("Changeset %s failed: %s", 
                changeSet.getId(), exception.getMessage())
        );
        
        // Attempt automatic remediation
        try {
            handleFailure(changeSet, database, exception);
        } catch (Exception e) {
            log.error("Automatic remediation failed", e);
        }
    }
    
    private void handleFailure(ChangeSet changeSet, Database database, 
                              Exception exception) throws Exception {
        // 1. Mark changeset as failed
        markAsFailed(changeSet, exception);
        
        // 2. Check if rollback is possible
        if (hasRollback(changeSet)) {
            log.info("Attempting automatic rollback...");
            rollback(changeSet, database);
        } else {
            log.warn("No rollback defined for changeset: {}", changeSet.getId());
            // Manual intervention required
        }
    }
    
    private void markAsFailed(ChangeSet changeSet, Exception exception) {
        // Update custom tracking table
        // Store error details for analysis
    }
    
    private boolean hasRollback(ChangeSet changeSet) {
        return changeSet.getRollback() != null && 
               !changeSet.getRollback().getChanges().isEmpty();
    }
    
    private void rollback(ChangeSet changeSet, Database database) throws Exception {
        // Execute rollback logic
        changeSet.rollback(database);
    }
}
```

### Failed Migration Recovery

**Handling FAILED State:**

```java
@Service
public class MigrationRecoveryService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    /**
     * Find failed changesets
     */
    public List<FailedChangeSet> getFailedChangeSets() {
        String sql = """
            SELECT id, author, filename, dateexecuted, exectype, md5sum, description
            FROM DATABASECHANGELOG
            WHERE exectype = 'FAILED'
            ORDER BY dateexecuted DESC
            """;
        
        @SuppressWarnings("unchecked")
        List<Object[]> results = entityManager.createNativeQuery(sql).getResultList();
        
        return results.stream()
            .map(row -> new FailedChangeSet(
                (String) row[0],  // id
                (String) row[1],  // author
                (String) row[2],  // filename
                ((Timestamp) row[3]).toInstant(),  // dateexecuted
                (String) row[4],  // exectype
                (String) row[5],  // md5sum
                (String) row[6]   // description
            ))
            .collect(Collectors.toList());
    }
    
    /**
     * Clear failed status to retry
     */
    @Transactional
    public void clearFailedStatus(String changeSetId, String author, String filename) {
        String sql = """
            DELETE FROM DATABASECHANGELOG
            WHERE id = :id 
            AND author = :author 
            AND filename = :filename
            AND exectype = 'FAILED'
            """;
        
        int deleted = entityManager.createNativeQuery(sql)
            .setParameter("id", changeSetId)
            .setParameter("author", author)
            .setParameter("filename", filename)
            .executeUpdate();
        
        if (deleted > 0) {
            log.info("Cleared failed status for changeset: {}", changeSetId);
        }
    }
    
    /**
     * Force mark changeset as successful (use with caution!)
     */
    @Transactional
    public void forceMarkAsSuccessful(String changeSetId, String author, String filename) {
        String sql = """
            UPDATE DATABASECHANGELOG
            SET exectype = 'EXECUTED'
            WHERE id = :id 
            AND author = :author 
            AND filename = :filename
            """;
        
        int updated = entityManager.createNativeQuery(sql)
            .setParameter("id", changeSetId)
            .setParameter("author", author)
            .setParameter("filename", filename)
            .executeUpdate();
        
        if (updated > 0) {
            log.warn("Force marked changeset as successful: {}", changeSetId);
        }
    }
}
```

### Retry Logic for Transient Failures

**Retry Configuration:**

```java
@Configuration
public class LiquibaseRetryConfiguration {
    
    @Bean
    public SpringLiquibase liquibase(DataSource dataSource) {
        RetryableSpringLiquibase liquibase = new RetryableSpringLiquibase();
        liquibase.setDataSource(dataSource);
        liquibase.setChangeLog("classpath:db/changelog/db.changelog-master.yaml");
        liquibase.setMaxRetries(3);
        liquibase.setRetryDelaySeconds(10);
        return liquibase;
    }
}

public class RetryableSpringLiquibase extends SpringLiquibase {
    
    private int maxRetries = 3;
    private int retryDelaySeconds = 10;
    
    @Override
    public void afterPropertiesSet() throws LiquibaseException {
        int attempts = 0;
        LiquibaseException lastException = null;
        
        while (attempts < maxRetries) {
            try {
                super.afterPropertiesSet();
                return; // Success
            } catch (LiquibaseException e) {
                lastException = e;
                attempts++;
                
                if (isRetryable(e) && attempts < maxRetries) {
                    log.warn("Migration attempt {} failed, retrying in {}s...", 
                        attempts, retryDelaySeconds);
                    
                    try {
                        Thread.sleep(retryDelaySeconds * 1000);
                    } catch (InterruptedException ie) {
                        Thread.currentThread().interrupt();
                        throw e;
                    }
                } else {
                    throw e;
                }
            }
        }
        
        throw lastException;
    }
    
    private boolean isRetryable(LiquibaseException e) {
        String message = e.getMessage().toLowerCase();
        
        // Retry on transient errors
        return message.contains("timeout") ||
               message.contains("deadlock") ||
               message.contains("lock") ||
               message.contains("connection") ||
               message.contains("network");
    }
    
    // Getters and setters
}
```

## 4. Running Liquibase in Clustered Environments

### The Lock Problem

In clustered environments, multiple application instances might try to run migrations simultaneously.

**Problem Scenario:**

```
Time    Instance 1              Instance 2              Instance 3
----    ----------              ----------              ----------
T0      Startup                 Startup                 Startup
T1      Acquire lock            Wait for lock           Wait for lock
T2      Run migration 001       Waiting...              Waiting...
T3      Run migration 002       Waiting...              Waiting...
T4      Release lock            Acquire lock            Wait for lock
T5      Complete                Run migration 001 ❌     Waiting...
                                (Already executed!)
```

### Liquibase Lock Mechanism

**DATABASECHANGELOGLOCK Table:**

```sql
CREATE TABLE DATABASECHANGELOGLOCK (
    ID NUMBER NOT NULL,
    LOCKED NUMBER(1) NOT NULL,
    LOCKGRANTED TIMESTAMP,
    LOCKEDBY VARCHAR2(255),
    CONSTRAINT PK_DATABASECHANGELOGLOCK PRIMARY KEY (ID)
);

-- Always has exactly one row with ID = 1
INSERT INTO DATABASECHANGELOGLOCK (ID, LOCKED) VALUES (1, 0);
```

**Lock Acquisition Flow:**

```
1. Application tries to run migrations
2. Liquibase executes: UPDATE DATABASECHANGELOGLOCK SET locked=1, lockgranted=NOW(), lockedby='hostname' WHERE id=1 AND locked=0
3. If update count = 1: Lock acquired, proceed
4. If update count = 0: Lock held by another instance, wait or fail
5. After migrations: UPDATE DATABASECHANGELOGLOCK SET locked=0 WHERE id=1
```

### Cluster Configuration

**Leader Election Approach:**

```java
@Configuration
public class ClusteredLiquibaseConfiguration {
    
    @Bean
    @ConditionalOnProperty(name = "liquibase.cluster.enabled", havingValue = "true")
    public SpringLiquibase liquibase(
            DataSource dataSource,
            @Value("${spring.application.name}") String appName,
            @Value("${POD_NAME:localhost}") String podName) {
        
        ClusteredSpringLiquibase liquibase = new ClusteredSpringLiquibase();
        liquibase.setDataSource(dataSource);
        liquibase.setChangeLog("classpath:db/changelog/db.changelog-master.yaml");
        liquibase.setInstanceIdentifier(appName + "-" + podName);
        liquibase.setLockWaitTimeMinutes(30); // Wait up to 30 minutes
        liquibase.setLockPollIntervalSeconds(10); // Check every 10 seconds
        
        return liquibase;
    }
}

public class ClusteredSpringLiquibase extends SpringLiquibase {
    
    private String instanceIdentifier;
    private int lockWaitTimeMinutes = 30;
    private int lockPollIntervalSeconds = 10;
    
    @Override
    public void afterPropertiesSet() throws LiquibaseException {
        log.info("Instance {} attempting to acquire migration lock", instanceIdentifier);
        
        long startTime = System.currentTimeMillis();
        long maxWaitMillis = lockWaitTimeMinutes * 60 * 1000;
        
        while (true) {
            try {
                super.afterPropertiesSet();
                log.info("Instance {} successfully completed migrations", instanceIdentifier);
                return;
            } catch (LockException e) {
                long elapsed = System.currentTimeMillis() - startTime;
                
                if (elapsed >= maxWaitMillis) {
                    log.error("Instance {} timeout waiting for migration lock after {} minutes",
                        instanceIdentifier, lockWaitTimeMinutes);
                    throw e;
                }
                
                log.info("Instance {} waiting for migration lock... ({}/{} minutes)",
                    instanceIdentifier, elapsed / 60000, lockWaitTimeMinutes);
                
                try {
                    Thread.sleep(lockPollIntervalSeconds * 1000);
                } catch (InterruptedException ie) {
                    Thread.currentThread().interrupt();
                    throw e;
                }
            }
        }
    }
    
    // Getters and setters
}
```

**Custom Lock Service:**

```java
@Component
public class TimeoutAwareLockService extends StandardLockService {
    
    private static final int LOCK_TIMEOUT_MINUTES = 30;
    private static final int POLL_INTERVAL_SECONDS = 10;
    
    @Override
    public void waitForLock() throws LockException {
        long startTime = System.currentTimeMillis();
        long maxWaitMillis = LOCK_TIMEOUT_MINUTES * 60 * 1000;
        
        while (!hasChangeLogLock) {
            if (System.currentTimeMillis() - startTime >= maxWaitMillis) {
                // Timeout exceeded
                LockInfo lockInfo = getCurrentLock();
                throw new LockException(
                    String.format(
                        "Timeout after %d minutes waiting for lock. " +
                        "Lock currently held by: %s (acquired at: %s)",
                        LOCK_TIMEOUT_MINUTES,
                        lockInfo.getLockedBy(),
                        lockInfo.getLockGranted()
                    )
                );
            }
            
            // Check lock status
            boolean acquired = acquireLock();
            
            if (acquired) {
                log.info("Successfully acquired migration lock");
                return;
            }
            
            // Wait before retrying
            try {
                Thread.sleep(POLL_INTERVAL_SECONDS * 1000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
                throw new LockException("Interrupted while waiting for lock", e);
            }
        }
    }
    
    private LockInfo getCurrentLock() {
        // Query DATABASECHANGELOGLOCK table
        try {
            String sql = "SELECT locked, lockgranted, lockedby FROM DATABASECHANGELOGLOCK WHERE id = 1";
            // Execute query and return lock info
        } catch (Exception e) {
            return new LockInfo(false, null, "unknown");
        }
    }
}

@Data
@AllArgsConstructor
class LockInfo {
    private boolean locked;
    private Instant lockGranted;
    private String lockedBy;
}
```

**Audit Listener:**

```java
@Component
public class LiquibaseAuditListener implements ChangeSetListener {
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    @Value("${spring.application.name}")
    private String applicationName;
    
    @Value("${spring.profiles.active}")
    private String environment;
    
    private Map<String, Long> changeSetStartTimes = new ConcurrentHashMap<>();
    
    @Override
    public void willRun(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                       Database database, ChangeSet.RunStatus runStatus) {
        changeSetStartTimes.put(changeSet.getId(), System.currentTimeMillis());
    }
    
    @Override
    public void ran(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                   Database database, ChangeExecListener execListener) {
        long startTime = changeSetStartTimes.getOrDefault(changeSet.getId(), 0L);
        long executionTime = System.currentTimeMillis() - startTime;
        
        recordExecution(changeSet, executionTime, "SUCCESS", null);
        
        changeSetStartTimes.remove(changeSet.getId());
    }
    
    @Override
    public void runFailed(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                         Database database, Exception exception) {
        long startTime = changeSetStartTimes.getOrDefault(changeSet.getId(), 0L);
        long executionTime = System.currentTimeMillis() - startTime;
        
        recordExecution(changeSet, executionTime, "FAILED", exception.getMessage());
        
        changeSetStartTimes.remove(changeSet.getId());
    }
    
    @Override
    public void rolledBack(ChangeSet changeSet, DatabaseChangeLog changeLog, 
                          Database database) {
        String sql = """
            UPDATE liquibase_audit
            SET rollback_executed = 1
            WHERE changeset_id = ?
            AND author = ?
            AND filename = ?
            ORDER BY executed_at DESC
            FETCH FIRST 1 ROWS ONLY
            """;
        
        jdbcTemplate.update(sql, 
            changeSet.getId(), 
            changeSet.getAuthor(), 
            changeSet.getFilePath());
    }
    
    private void recordExecution(ChangeSet changeSet, long executionTime, 
                                 String status, String errorMessage) {
        String sql = """
            INSERT INTO liquibase_audit (
                audit_id, changeset_id, author, filename, execution_time_ms,
                executed_by, execution_status, error_message, environment,
                application_version
            ) VALUES (
                liquibase_audit_seq.NEXTVAL, ?, ?, ?, ?, ?, ?, ?, ?, ?
            )
            """;
        
        String executedBy = System.getProperty("user.name");
        String appVersion = getApplicationVersion();
        
        jdbcTemplate.update(sql,
            changeSet.getId(),
            changeSet.getAuthor(),
            changeSet.getFilePath(),
            executionTime,
            executedBy,
            status,
            errorMessage,
            environment,
            appVersion
        );
    }
    
    private String getApplicationVersion() {
        // Get from manifest, git commit, or build info
        return "1.0.0";
    }
}
```

```java
@Service
public class LiquibaseAuditService {

    public List<AuditRecord> getTodaysMigrations() {

            WHERE TRUNC(executed_at) = TRUNC(SYSDATE)

        return jdbcTemplate.query(sql, this::mapAuditRecord);
    }
    
    /**
     * Get failed migrations
     */
    public List<AuditRecord> getFailedMigrations(int days) {
        String sql = """
            SELECT * FROM liquibase_audit
            WHERE execution_status = 'FAILED'
            AND executed_at >= SYSDATE - ?
            ORDER BY executed_at DESC
            """;
        
        return jdbcTemplate.query(sql, this::mapAuditRecord, days);
    }
    
    /**
     * Get migration history for specific changeset
     */
    public List<AuditRecord> getChangeSetHistory(String changeSetId) {
        String sql = """
            SELECT * FROM liquibase_audit
            WHERE changeset_id = ?
            ORDER BY executed_at DESC
            """;
        
        return jdbcTemplate.query(sql, this::mapAuditRecord, changeSetId);
    }
    
    /**
     * Get performance statistics
     */
    public MigrationStats getMigrationStats(LocalDate startDate, LocalDate endDate) {
        String sql = """
            SELECT 
                COUNT(*) as total_migrations,
                SUM(CASE WHEN execution_status = 'SUCCESS' THEN 1 ELSE 0 END) as successful,
                SUM(CASE WHEN execution_status = 'FAILED' THEN 1 ELSE 0 END) as failed,
                AVG(execution_time_ms) as avg_execution_time,
                MAX(execution_time_ms) as max_execution_time,
                SUM(CASE WHEN rollback_executed = 1 THEN 1 ELSE 0 END) as rollbacks
            FROM liquibase_audit
            WHERE executed_at >= ? AND executed_at < ?
            """;
        
        return jdbcTemplate.queryForObject(sql, (rs, rowNum) -> 
            new MigrationStats(
                rs.getInt("total_migrations"),
                rs.getInt("successful"),
                rs.getInt("failed"),
                rs.getLong("avg_execution_time"),
                rs.getLong("max_execution_time"),
                rs.getInt("rollbacks")
            ),
            Timestamp.valueOf(startDate.atStartOfDay()),
            Timestamp.valueOf(endDate.plusDays(1).atStartOfDay())
        );
    }

     * Get slowest migrations

            WHERE execution_status = 'SUCCESS'

            """;

            rs.getInt("rollback_executed") == 1,

            rs.getString("application_version")
        );
    }
```

## Best Practices Summary

### ✅ DO:

1. **Use expand-contract** for zero-downtime migrations
2. **Test rollbacks** before every production deployment
3. **Configure lock timeouts** for clustered environments
4. **Use init containers** in Kubernetes for migrations
5. **Audit all migrations** with custom tracking
6. **Monitor migration performance** and optimize slow changes
7. **Have emergency procedures** for lock release
8. **Validate migrations** in staging first
9. **Use leader election** or single-instance migrations
10. **Document rollback procedures** for each deployment

### ❌ DON'T:

1. **Don't run migrations** on all pods simultaneously
2. **Don't skip rollback testing** even for "simple" changes
3. **Don't wait indefinitely** for locks (set timeouts)
4. **Don't force-release locks** without investigation
5. **Don't ignore failed migrations** - investigate and fix
6. **Don't modify executed changesets** (create new ones)
7. **Don't deploy breaking changes** without expand-contract
8. **Don't skip backup** before production migrations
9. **Don't run large migrations** during peak hours
10. **Don't forget to** test with production-like data volumes

## Interview Questions

**Q1: How do you achieve zero-downtime database migrations?**

Use the expand-contract pattern: (1) Expand - add new schema elements while keeping old ones, (2) Deploy application version supporting both, (3) Contract - remove old schema elements after all apps updated. Also use online DDL operations and database-specific features like Oracle's ONLINE keyword.

**Q2: What happens when a migration fails halfway through in a cluster?**

Liquibase marks the changeset as FAILED in DATABASECHANGELOG and releases the lock. Other instances won't re-attempt the failed changeset. Manual intervention is required: investigate the failure, fix the issue, clear the FAILED status, and retry the migration.

**Q3: How do you prevent multiple instances from running migrations simultaneously?**

Liquibase uses DATABASECHANGELOGLOCK table with a row-level lock. Only one instance can acquire the lock at a time. Configure appropriate timeouts and use Kubernetes init containers or leader election to ensure only one instance attempts migrations.

**Q4: What's your rollback strategy for a production deployment?**

Before deployment: generate rollback SQL, review it, backup database. During deployment: monitor for failures, have automatic rollback for transient errors. Post-deployment: keep previous version deployed for quick rollback if issues detected. For data migrations, prefer forward fixes over rollback when possible.

**Q5: How do you track and audit database changes in production?**

Implement custom ChangeSetListener to record all migrations in an audit table, including execution time, environment, application version, success/failure status, and rollback events. Expose audit endpoints for compliance reporting and performance monitoring. Integrate with monitoring systems for alerts on failures.
