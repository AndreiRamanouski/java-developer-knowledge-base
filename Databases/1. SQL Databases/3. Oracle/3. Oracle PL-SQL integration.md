# Spring Boot Oracle PL/SQL Integration

## Overview

Oracle PL/SQL integration allows Spring Boot applications to leverage powerful database-side logic through stored procedures, functions, and packages. This is essential when working with legacy Oracle databases or when complex business logic must reside in the database layer.

**Key Concept**: While Spring Data JPA encourages database-agnostic code, real-world Oracle systems often require calling stored procedures for performance, security, or legacy integration reasons.

---

## 1. Calling Stored Procedures with @Procedure

### Basic Stored Procedure Call

The simplest way to call Oracle stored procedures is using Spring Data JPA's `@Procedure` annotation.

**Oracle Stored Procedure:**

```sql
-- Create a simple procedure
CREATE OR REPLACE PROCEDURE update_employee_salary(
    p_employee_id IN NUMBER,
    p_new_salary IN NUMBER
) AS
BEGIN
    UPDATE employees 
    SET salary = p_new_salary,
        last_modified = SYSDATE
    WHERE employee_id = p_employee_id;
    
    COMMIT;
END;
/
```

**Spring Repository:**

```java
@Repository
public interface EmployeeRepository extends JpaRepository<Employee, Long> {
    
    // Method 1: @Procedure with procedure name
    @Procedure(name = "update_employee_salary")
    void updateEmployeeSalary(Long employeeId, BigDecimal newSalary);
    
    // Method 2: @Procedure with value attribute
    @Procedure(value = "update_employee_salary")
    void updateSalary(Long employeeId, BigDecimal newSalary);
    
    // Method 3: @Procedure with procedureName
    @Procedure(procedureName = "update_employee_salary")
    void changeSalary(Long employeeId, BigDecimal newSalary);
}
```

**Service Usage:**

```java
@Service
@Transactional
public class EmployeeService {
    
    @Autowired
    private EmployeeRepository employeeRepository;
    
    public void giveRaise(Long employeeId, BigDecimal raiseAmount) {
        Employee employee = employeeRepository.findById(employeeId)
            .orElseThrow(() -> new EntityNotFoundException("Employee not found"));
        
        BigDecimal newSalary = employee.getSalary().add(raiseAmount);
        
        // Call stored procedure
        employeeRepository.updateEmployeeSalary(employeeId, newSalary);
        
        log.info("Updated salary for employee {} to {}", employeeId, newSalary);
    }
}
```

### Stored Procedure with Return Value

**Oracle Function:**

```sql
CREATE OR REPLACE FUNCTION calculate_bonus(
    p_employee_id IN NUMBER,
    p_performance_rating IN NUMBER
) RETURN NUMBER AS
    v_salary NUMBER;
    v_bonus NUMBER;
BEGIN
    SELECT salary INTO v_salary
    FROM employees
    WHERE employee_id = p_employee_id;
    
    v_bonus := v_salary * p_performance_rating / 100;
    
    RETURN v_bonus;
END;
/
```

**Spring Repository:**

```java
@Repository
public interface EmployeeRepository extends JpaRepository<Employee, Long> {
    
    // Call function that returns a value
    @Query(value = "SELECT calculate_bonus(:employeeId, :rating) FROM DUAL", 
           nativeQuery = true)
    BigDecimal calculateBonus(@Param("employeeId") Long employeeId, 
                             @Param("rating") Integer rating);
}
```

### Using @NamedStoredProcedureQuery

For more control, use `@NamedStoredProcedureQuery` on the entity:

**Entity with Named Procedure:**

```java
@Entity
@Table(name = "employees")

            @StoredProcedureParameter(mode = ParameterMode.IN, 
                                     name = "p_employee_id", 
                                     type = Long.class),
            @StoredProcedureParameter(mode = ParameterMode.IN, 
                                     name = "p_new_salary", 
                                     type = BigDecimal.class)
        }
    ),
    @NamedStoredProcedureQuery(
        name = "Employee.calculateBonus",
        procedureName = "calculate_bonus",
        parameters = {
            @StoredProcedureParameter(mode = ParameterMode.IN, 
                                     name = "p_employee_id", 
                                     type = Long.class),
            @StoredProcedureParameter(mode = ParameterMode.IN, 
                                     name = "p_performance_rating", 
                                     type = Integer.class),
            @StoredProcedureParameter(mode = ParameterMode.OUT, 
                                     name = "return_value", 
                                     type = BigDecimal.class)
        }
    )
})
public class Employee {

    private String firstName;
    private String lastName;
    private BigDecimal salary;
    private LocalDateTime lastModified;
    
    // Getters and setters
}
```

## 2. StoredProcedureQuery for Complex Procedures

For complex scenarios with multiple OUT parameters or dynamic procedure calls, use `StoredProcedureQuery`:

### Procedure with Multiple OUT Parameters

**Oracle Procedure:**

```sql
CREATE OR REPLACE PROCEDURE get_employee_stats(
    p_department_id IN NUMBER,
    p_total_count OUT NUMBER,
    p_avg_salary OUT NUMBER,
    p_max_salary OUT NUMBER,
    p_min_salary OUT NUMBER
) AS
BEGIN
    SELECT 
        COUNT(*),
        AVG(salary),
        MAX(salary),
        MIN(salary)
    INTO 
        p_total_count,
        p_avg_salary,
        p_max_salary,
        p_min_salary
    FROM employees
    WHERE department_id = p_department_id;
END;
/
```

**Spring Service:**

```java
@Service
public class EmployeeStatisticsService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    public DepartmentStats getDepartmentStatistics(Long departmentId) {
        StoredProcedureQuery query = entityManager
            .createStoredProcedureQuery("get_employee_stats");
        
        // Register parameters
        query.registerStoredProcedureParameter("p_department_id", 
                                               Long.class, 
                                               ParameterMode.IN);
        query.registerStoredProcedureParameter("p_total_count", 
                                               Integer.class, 
                                               ParameterMode.OUT);
        query.registerStoredProcedureParameter("p_avg_salary", 
                                               BigDecimal.class, 
                                               ParameterMode.OUT);
        query.registerStoredProcedureParameter("p_max_salary", 
                                               BigDecimal.class, 
                                               ParameterMode.OUT);
        query.registerStoredProcedureParameter("p_min_salary", 
                                               BigDecimal.class, 
                                               ParameterMode.OUT);
        
        // Set IN parameter
        query.setParameter("p_department_id", departmentId);
        
        // Execute
        query.execute();
        
        // Get OUT parameters
        Integer totalCount = (Integer) query.getOutputParameterValue("p_total_count");
        BigDecimal avgSalary = (BigDecimal) query.getOutputParameterValue("p_avg_salary");
        BigDecimal maxSalary = (BigDecimal) query.getOutputParameterValue("p_max_salary");
        BigDecimal minSalary = (BigDecimal) query.getOutputParameterValue("p_min_salary");
        
        return new DepartmentStats(totalCount, avgSalary, maxSalary, minSalary);
    }
}

// DTO for results
@Data
@AllArgsConstructor
public class DepartmentStats {
    private Integer totalCount;
    private BigDecimal avgSalary;
    private BigDecimal maxSalary;
    private BigDecimal minSalary;
}
```

### Procedure with INOUT Parameters

**Oracle Procedure:**

```sql
CREATE OR REPLACE PROCEDURE adjust_salary(
    p_employee_id IN NUMBER,
    p_adjustment_pct INOUT NUMBER  -- INOUT parameter
) AS
    v_current_salary NUMBER;
    v_new_salary NUMBER;
BEGIN
    SELECT salary INTO v_current_salary
    FROM employees
    WHERE employee_id = p_employee_id;
    
    -- Cap adjustment at 20%
    IF p_adjustment_pct > 20 THEN
        p_adjustment_pct := 20;
    END IF;
    
    v_new_salary := v_current_salary * (1 + p_adjustment_pct / 100);
    
    UPDATE employees
    SET salary = v_new_salary
    WHERE employee_id = p_employee_id;
    
    -- Return actual adjustment percentage
    p_adjustment_pct := ((v_new_salary - v_current_salary) / v_current_salary) * 100;
END;
/
```

**Spring Service:**

```java
@Service
public class SalaryAdjustmentService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    @Transactional
    public BigDecimal adjustSalary(Long employeeId, BigDecimal requestedPct) {
        StoredProcedureQuery query = entityManager
            .createStoredProcedureQuery("adjust_salary");
        
        query.registerStoredProcedureParameter("p_employee_id", 
                                               Long.class, 
                                               ParameterMode.IN);
        query.registerStoredProcedureParameter("p_adjustment_pct", 
                                               BigDecimal.class, 
                                               ParameterMode.INOUT);
        
        query.setParameter("p_employee_id", employeeId);
        query.setParameter("p_adjustment_pct", requestedPct);
        
        query.execute();
        
        // Get actual adjustment percentage (may be capped)
        BigDecimal actualPct = (BigDecimal) query.getOutputParameterValue("p_adjustment_pct");
        
        log.info("Requested {}% adjustment, actual: {}%", requestedPct, actualPct);
        
        return actualPct;
    }
}
```

## 3. REF CURSOR Handling

REF CURSOR is Oracle's way of returning result sets from stored procedures.

### Basic REF CURSOR

**Oracle Procedure:**

```sql
CREATE OR REPLACE PROCEDURE get_employees_by_dept(
    p_department_id IN NUMBER,
    p_cursor OUT SYS_REFCURSOR
) AS
BEGIN
    OPEN p_cursor FOR
        SELECT employee_id, first_name, last_name, salary
        FROM employees
        WHERE department_id = p_department_id
        ORDER BY last_name;
END;
/
```

**Spring Service:**

```java
@Service
public class EmployeeQueryService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    public List<EmployeeDTO> getEmployeesByDepartment(Long departmentId) {
        StoredProcedureQuery query = entityManager
            .createStoredProcedureQuery("get_employees_by_dept");
        
        query.registerStoredProcedureParameter("p_department_id", 
                                               Long.class, 
                                               ParameterMode.IN);
        query.registerStoredProcedureParameter("p_cursor", 
                                               Class.class, 
                                               ParameterMode.REF_CURSOR);
        
        query.setParameter("p_department_id", departmentId);
        
        query.execute();
        
        // Get result list from REF CURSOR
        List<Object[]> results = query.getResultList();
        
        return results.stream()
            .map(row -> new EmployeeDTO(
                ((Number) row[0]).longValue(),  // employee_id
                (String) row[1],                  // first_name
                (String) row[2],                  // last_name
                (BigDecimal) row[3]              // salary
            ))
            .collect(Collectors.toList());
    }
}

@Data
@AllArgsConstructor
public class EmployeeDTO {
    private Long employeeId;
    private String firstName;
    private String lastName;
    private BigDecimal salary;
}
```

### Multiple REF CURSORS

**Oracle Procedure:**

```sql
CREATE OR REPLACE PROCEDURE get_dept_summary(
    p_department_id IN NUMBER,
    p_employees_cursor OUT SYS_REFCURSOR,
    p_projects_cursor OUT SYS_REFCURSOR
) AS
BEGIN
    -- First cursor: employees
    OPEN p_employees_cursor FOR
        SELECT employee_id, first_name, last_name, salary
        FROM employees
        WHERE department_id = p_department_id;
    
    -- Second cursor: projects
    OPEN p_projects_cursor FOR
        SELECT project_id, project_name, start_date, end_date
        FROM projects
        WHERE department_id = p_department_id;
END;
/
```

**Spring Service:**

```java
@Service
public class DepartmentSummaryService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    public DepartmentSummary getDepartmentSummary(Long departmentId) {
        StoredProcedureQuery query = entityManager
            .createStoredProcedureQuery("get_dept_summary");
        
        query.registerStoredProcedureParameter("p_department_id", 
                                               Long.class, 
                                               ParameterMode.IN);
        query.registerStoredProcedureParameter("p_employees_cursor", 
                                               Class.class, 
                                               ParameterMode.REF_CURSOR);
        query.registerStoredProcedureParameter("p_projects_cursor", 
                                               Class.class, 
                                               ParameterMode.REF_CURSOR);
        
        query.setParameter("p_department_id", departmentId);
        query.execute();
        
        // Get first result set (employees)
        List<Object[]> employeeResults = query.getResultList();
        List<EmployeeDTO> employees = employeeResults.stream()
            .map(row -> new EmployeeDTO(
                ((Number) row[0]).longValue(),
                (String) row[1],
                (String) row[2],
                (BigDecimal) row[3]
            ))
            .collect(Collectors.toList());
        
        // Get second result set (projects)
        boolean hasMoreResults = query.hasMoreResults();
        List<Object[]> projectResults = hasMoreResults ? query.getResultList() : List.of();
        List<ProjectDTO> projects = projectResults.stream()
            .map(row -> new ProjectDTO(
                ((Number) row[0]).longValue(),
                (String) row[1],
                ((Date) row[2]).toLocalDate(),
                ((Date) row[3]).toLocalDate()
            ))
            .collect(Collectors.toList());
        
        return new DepartmentSummary(employees, projects);
    }
}
```

## 4. Package Procedures in Spring Data JPA

Oracle packages group related procedures and functions together.

### Oracle Package

**Package Specification:**

```sql
CREATE OR REPLACE PACKAGE employee_pkg AS
    -- Procedures
    PROCEDURE hire_employee(
        p_first_name IN VARCHAR2,
        p_last_name IN VARCHAR2,
        p_email IN VARCHAR2,
        p_salary IN NUMBER,
        p_department_id IN NUMBER,
        p_employee_id OUT NUMBER
    );
    
    PROCEDURE terminate_employee(
        p_employee_id IN NUMBER,
        p_termination_date IN DATE,
        p_reason IN VARCHAR2
    );
    
    -- Functions
    FUNCTION is_eligible_for_bonus(
        p_employee_id IN NUMBER
    ) RETURN NUMBER;
    
    FUNCTION get_years_of_service(
        p_employee_id IN NUMBER
    ) RETURN NUMBER;
END employee_pkg;
/

-- Package Body
CREATE OR REPLACE PACKAGE BODY employee_pkg AS
    
    PROCEDURE hire_employee(
        p_first_name IN VARCHAR2,
        p_last_name IN VARCHAR2,
        p_email IN VARCHAR2,
        p_salary IN NUMBER,
        p_department_id IN NUMBER,
        p_employee_id OUT NUMBER
    ) AS
    BEGIN
        INSERT INTO employees (
            employee_id, first_name, last_name, email, 
            salary, department_id, hire_date
        ) VALUES (
            employee_seq.NEXTVAL, p_first_name, p_last_name, 
            p_email, p_salary, p_department_id, SYSDATE
        ) RETURNING employee_id INTO p_employee_id;
        
        COMMIT;
    END hire_employee;
    
    PROCEDURE terminate_employee(
        p_employee_id IN NUMBER,
        p_termination_date IN DATE,
        p_reason IN VARCHAR2
    ) AS
    BEGIN
        UPDATE employees
        SET termination_date = p_termination_date,
            termination_reason = p_reason,
            status = 'TERMINATED'
        WHERE employee_id = p_employee_id;
        
        COMMIT;
    END terminate_employee;
    
    FUNCTION is_eligible_for_bonus(
        p_employee_id IN NUMBER
    ) RETURN NUMBER AS
        v_years_service NUMBER;
        v_performance_rating NUMBER;
    BEGIN
        SELECT 
            FLOOR(MONTHS_BETWEEN(SYSDATE, hire_date) / 12),
            performance_rating
        INTO v_years_service, v_performance_rating
        FROM employees
        WHERE employee_id = p_employee_id;
        
        IF v_years_service >= 1 AND v_performance_rating >= 3 THEN
            RETURN 1;  -- Eligible
        ELSE
            RETURN 0;  -- Not eligible
        END IF;
    END is_eligible_for_bonus;
    
    FUNCTION get_years_of_service(
        p_employee_id IN NUMBER
    ) RETURN NUMBER AS
        v_years NUMBER;
    BEGIN
        SELECT FLOOR(MONTHS_BETWEEN(SYSDATE, hire_date) / 12)
        INTO v_years
        FROM employees
        WHERE employee_id = p_employee_id;
        
        RETURN v_years;
    END get_years_of_service;
    
END employee_pkg;
/
```

## 5. Exception Handling (Oracle Error Codes)

Oracle errors must be properly handled in Spring applications.

### Oracle Exception Handling

**Oracle Procedure with Custom Exceptions:**

```sql
CREATE OR REPLACE PROCEDURE process_order(
    p_order_id IN NUMBER,
    p_customer_id IN NUMBER
) AS
    -- Custom exceptions
    insufficient_inventory EXCEPTION;
    invalid_customer EXCEPTION;
    
    PRAGMA EXCEPTION_INIT(insufficient_inventory, -20001);
    PRAGMA EXCEPTION_INIT(invalid_customer, -20002);
    
    v_customer_count NUMBER;
    v_inventory_count NUMBER;
BEGIN
    -- Validate customer
    SELECT COUNT(*) INTO v_customer_count
    FROM customers
    WHERE customer_id = p_customer_id AND status = 'ACTIVE';
    
    IF v_customer_count = 0 THEN
        RAISE_APPLICATION_ERROR(-20002, 'Invalid or inactive customer');
    END IF;
    
    -- Check inventory
    SELECT COUNT(*) INTO v_inventory_count
    FROM order_items oi
    JOIN inventory i ON oi.product_id = i.product_id
    WHERE oi.order_id = p_order_id
      AND i.quantity >= oi.quantity;
    
    IF v_inventory_count = 0 THEN
        RAISE_APPLICATION_ERROR(-20001, 'Insufficient inventory for order');
    END IF;
    
    -- Process order
    UPDATE orders
    SET status = 'PROCESSED',
        processed_date = SYSDATE
    WHERE order_id = p_order_id;
    
    COMMIT;
    
EXCEPTION
    WHEN insufficient_inventory THEN
        ROLLBACK;
        RAISE;
    WHEN invalid_customer THEN
        ROLLBACK;
        RAISE;
    WHEN OTHERS THEN
        ROLLBACK;
        RAISE_APPLICATION_ERROR(-20999, 'Unexpected error: ' || SQLERRM);
END;
/
```

### Spring Exception Handling

**Custom Exception Classes:**

```java
// Base Oracle exception
@ResponseStatus(HttpStatus.INTERNAL_SERVER_ERROR)
public class OracleStoredProcedureException extends RuntimeException {
    private final int oracleErrorCode;
    
    public OracleStoredProcedureException(int errorCode, String message) {
        super(message);
        this.oracleErrorCode = errorCode;
    }
    
    public int getOracleErrorCode() {
        return oracleErrorCode;
    }
}

// Specific exceptions
@ResponseStatus(HttpStatus.BAD_REQUEST)
public class InsufficientInventoryException extends OracleStoredProcedureException {
    public InsufficientInventoryException(String message) {
        super(20001, message);
    }
}

@ResponseStatus(HttpStatus.BAD_REQUEST)
public class InvalidCustomerException extends OracleStoredProcedureException {
    public InvalidCustomerException(String message) {
        super(20002, message);
    }
}
```

**Service with Exception Handling:**

```java
@Service
public class OrderProcessingService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    @Transactional
    public void processOrder(Long orderId, Long customerId) {
        try {
            StoredProcedureQuery query = entityManager
                .createStoredProcedureQuery("process_order");
            
            query.registerStoredProcedureParameter("p_order_id", 
                                                   Long.class, 
                                                   ParameterMode.IN);
            query.registerStoredProcedureParameter("p_customer_id", 
                                                   Long.class, 
                                                   ParameterMode.IN);
            
            query.setParameter("p_order_id", orderId);
            query.setParameter("p_customer_id", customerId);
            
            query.execute();
            
            log.info("Order {} processed successfully", orderId);
            
        } catch (Exception e) {
            handleOracleException(e);
        }
    }
    
    private void handleOracleException(Exception e) {
        Throwable cause = e.getCause();
        
        // Check for SQLException
        while (cause != null) {
            if (cause instanceof SQLException) {
                SQLException sqlEx = (SQLException) cause;
                int errorCode = sqlEx.getErrorCode();
                String message = sqlEx.getMessage();
                
                log.error("Oracle error code: {}, message: {}", errorCode, message);
                
                // Map Oracle error codes to business exceptions
                switch (errorCode) {
                    case 20001:
                        throw new InsufficientInventoryException(
                            extractErrorMessage(message));
                    case 20002:
                        throw new InvalidCustomerException(
                            extractErrorMessage(message));
                    case 20999:
                        throw new OracleStoredProcedureException(
                            errorCode, 
                            "Unexpected database error: " + extractErrorMessage(message));
                    default:
                        throw new OracleStoredProcedureException(
                            errorCode, 
                            "Database error: " + message);
                }
            }
            cause = cause.getCause();
        }
        
        // If not SQLException, rethrow
        throw new RuntimeException("Unexpected error processing order", e);
    }
    
    private String extractErrorMessage(String oracleMessage) {
        // Oracle error format: "ORA-20001: Insufficient inventory for order"
        // Extract the part after the error code
        if (oracleMessage != null && oracleMessage.contains(":")) {
            return oracleMessage.substring(oracleMessage.indexOf(":") + 1).trim();
        }
        return oracleMessage;
    }
}
```

```java
@RestControllerAdvice
public class OracleExceptionHandler {

        );

        );
        return ResponseEntity.status(HttpStatus.BAD_REQUEST).body(error);

            ex.getMessage(),
            ex.getOracleErrorCode()
        );
```

## Best Practices

### 1. **Use Named Parameters**

```java
// ✅ Good: Named parameters
query.registerStoredProcedureParameter("p_employee_id", Long.class, ParameterMode.IN);
query.setParameter("p_employee_id", employeeId);

// ❌ Bad: Positional parameters (harder to maintain)
query.registerStoredProcedureParameter(1, Long.class, ParameterMode.IN);
query.setParameter(1, employeeId);
```

### 2. **Always Handle Exceptions**

```java
// ✅ Good: Specific exception handling
try {
    query.execute();
} catch (Exception e) {
    handleOracleException(e);
}

// ❌ Bad: Swallowing exceptions
try {
    query.execute();
} catch (Exception e) {
    log.error("Error", e);
}
```

### 3. **Use Transactions Appropriately**

```java
// ✅ Good: Transaction management
@Transactional
public void processOrder(Long orderId) {
    orderRepository.save(order);
    // Procedure participates in Spring transaction
    orderRepository.callProcedure(orderId);
}

// ❌ Bad: Procedure commits independently
// (may cause partial commits)
```

## Common Pitfalls

### ❌ Pitfall 1: Ignoring Oracle Error Codes

```java
// Bad: Generic error handling
catch (Exception e) {
    throw new RuntimeException("Database error");
}

// Good: Map Oracle errors to business exceptions
catch (SQLException e) {
    if (e.getErrorCode() == 20001) {
        throw new InsufficientInventoryException(e.getMessage());
    }
}
```

### ❌ Pitfall 2: Not Handling REF CURSOR Properly

```java
// Bad: Assuming single result set
List results = query.getResultList();

// Good: Check for multiple result sets
List results1 = query.getResultList();
if (query.hasMoreResults()) {
    List results2 = query.getResultList();
}
```

### ❌ Pitfall 3: Mixing Spring and Oracle Transactions

```java
// Bad: Oracle commits, Spring rolls back (data inconsistency)
CREATE PROCEDURE my_proc AS
BEGIN
    UPDATE ...;
    COMMIT;  -- ❌ Commits independently of Spring
END;

// Good: Let Spring manage transactions
CREATE PROCEDURE my_proc AS
BEGIN
    UPDATE ...;
    -- No COMMIT - Spring manages it
END;
```

## Interview Questions

**Q1: How do you call an Oracle stored procedure that returns multiple REF CURSORs?**

Use `StoredProcedureQuery` with multiple `REF_CURSOR` parameters, then call `getResultList()` followed by `hasMoreResults()` to iterate through result sets.

**Q2: What's the difference between `@Procedure` and `StoredProcedureQuery`?**

- `@Procedure`: Declarative, simpler for basic procedures with IN parameters
- `StoredProcedureQuery`: Programmatic, required for OUT/INOUT parameters, REF CURSORs, complex scenarios

**Q3: How do you handle Oracle custom exceptions (RAISE_APPLICATION_ERROR) in Spring?**

Extract the `SQLException`, check `getErrorCode()`, map Oracle error codes to business exceptions, and handle with `@RestControllerAdvice`.

**Q4: How do you test stored procedures in Spring Boot?**

Use Testcontainers with Oracle container, create procedures in `@BeforeEach`, verify outputs and side effects, test exception scenarios.

**Q5: What are the transaction implications of calling Oracle procedures from Spring?**

Oracle procedures can commit independently, breaking Spring transaction management. Best practice: avoid COMMIT in procedures, let Spring manage transactions.
