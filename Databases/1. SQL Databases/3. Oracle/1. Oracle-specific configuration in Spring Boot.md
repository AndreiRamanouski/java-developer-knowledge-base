# Oracle with Spring Boot - Configuration Guide

## Deep Dive Interview Guide

This guide covers Oracle-specific configuration for production Spring Boot applications, including dialect selection, connection formats, Wallet integration, RAC setup, connection pooling, and Oracle data types.

**Interview Tip**: Oracle configuration questions test understanding of enterprise database features, high availability, security, performance optimization, and Oracle-specific capabilities.

## Q1: Oracle-specific Configuration in Spring Boot

**Short Answer**: Use org.hibernate.dialect.Oracle12cDialect for Oracle 12c+, Oracle10gDialect for 10g/11g. Connection URL: EZConnect (jdbc:oracle:thin:@//host:1521/service) or TNS (jdbc:oracle:thin:@tnsname). Oracle Wallet stores credentials securely (no plaintext passwords). RAC provides HA with failover (FAILOVER=ON, LOAD_BALANCE=ON). UCP is Oracle-native (advanced features), HikariCP is faster/lighter. Oracle types: NUMBER→BigDecimal, VARCHAR2→String, CLOB→String(@Lob), BLOB→byte[](https://claude.ai/chat/@Lob).

## 1. Oracle Dialect Selection

### Available Oracle Dialects

```java

org.hibernate.dialect.Oracle10gDialect

// Oracle 12c+ (modern, recommended)
org.hibernate.dialect.Oracle12cDialect

// Oracle 19c+ (latest)
// Uses Oracle12cDialect (no separate 19c dialect yet)

// Dialect selection in Spring Boot
spring:
  jpa:
    properties:
      hibernate:
        dialect: org.hibernate.dialect.Oracle12cDialect
```

### Dialect Feature Comparison

```
Dialect          Oracle Version    Key Features
--------------------------------------------------------------------------------
Oracle8iDialect  8i, 9i           Basic SQL, limited features
Oracle9iDialect  9i               ANSI joins, basic analytics
Oracle10gDialect 10g, 11g         Sequences, MERGE, ROWNUM
Oracle12cDialect 12c, 18c, 19c+   Identity columns, OFFSET/FETCH, 
                                  better pagination, JSON support

Recommendations:
- Oracle 12c+: Use Oracle12cDialect
- Oracle 10g/11g: Use Oracle10gDialect
- Don't use 8i/9i dialects (deprecated)
```

### Dialect-Specific Features

```java
// === Oracle 12c+ Identity Columns ===

@Entity
@Table(name = "users")
public class User {
    
    // Oracle 12c+ IDENTITY column (auto-generated)
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    @Column(name = "id")
    private Long id;
    
    // Generated DDL (Oracle 12c+):
    // CREATE TABLE users (
    //     id NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    //     ...
    // )
}

// === Oracle 10g/11g Sequences ===

@Entity
@Table(name = "users")
public class User {
    
    // Oracle 10g/11g requires sequence
    @Id
    @GeneratedValue(strategy = GenerationType.SEQUENCE, generator = "user_seq")
    @SequenceGenerator(
        name = "user_seq",
        sequenceName = "USER_SEQ",
        allocationSize = 1
    )
    @Column(name = "id")
    private Long id;
    
    // Generated DDL (Oracle 10g/11g):
    // CREATE SEQUENCE USER_SEQ START WITH 1 INCREMENT BY 1;
    // CREATE TABLE users (
    //     id NUMBER PRIMARY KEY,
    //     ...
    // )
}

// === Pagination Differences ===

// Oracle 12c+ (OFFSET/FETCH)
@Query("SELECT u FROM User u ORDER BY u.id")
Page<User> findAll(Pageable pageable);
// Generated SQL (Oracle 12c+):
// SELECT * FROM users ORDER BY id OFFSET 20 ROWS FETCH NEXT 10 ROWS ONLY

// Oracle 10g/11g (ROWNUM - less efficient)
// Generated SQL (Oracle 10g/11g):
// SELECT * FROM (
//     SELECT row_.*, ROWNUM rownum_ FROM (
//         SELECT * FROM users ORDER BY id
//     ) row_ WHERE ROWNUM <= 30
// ) WHERE rownum_ > 20
```

### Custom Dialect Configuration

```java
// Custom Oracle dialect with additional features

import org.hibernate.dialect.Oracle12cDialect;
import org.hibernate.dialect.function.StandardSQLFunction;
import org.hibernate.type.StandardBasicTypes;

public class CustomOracleDialect extends Oracle12cDialect {
    
    public CustomOracleDialect() {
        super();
        
        // Register Oracle-specific functions
        registerFunction("listagg", 
            new StandardSQLFunction("listagg", StandardBasicTypes.STRING));
        
        registerFunction("nvl", 
            new StandardSQLFunction("nvl"));
        
        registerFunction("decode", 
            new StandardSQLFunction("decode"));
        
        // Custom column definitions
        registerColumnType(Types.VARCHAR, "VARCHAR2($l)");
        registerColumnType(Types.CLOB, "CLOB");
    }
    
    @Override
    public boolean supportsSequences() {
        return true;
    }
    
    @Override
    public String getSequenceNextValString(String sequenceName) {
        return "SELECT " + sequenceName + ".NEXTVAL FROM DUAL";
    }
}
```

## 2. Connection URL Format (TNS vs EZConnect)

### EZConnect Format (Simple, Recommended)

```yaml
# EZConnect: No tnsnames.ora required

# Basic format
spring:
  datasource:
    url: jdbc:oracle:thin:@//hostname:port/service_name
    # Example: jdbc:oracle:thin:@//localhost:1521/ORCL

# With IP address
spring:
  datasource:
    url: jdbc:oracle:thin:@//192.168.1.100:1521/ORCL

# Multiple addresses (load balancing)
spring:
  datasource:
    url: jdbc:oracle:thin:@(DESCRIPTION=(LOAD_BALANCE=ON)(ADDRESS=(PROTOCOL=TCP)(HOST=host1)(PORT=1521))(ADDRESS=(PROTOCOL=TCP)(HOST=host2)(PORT=1521))(CONNECT_DATA=(SERVICE_NAME=ORCL)))

# With SSL
spring:
  datasource:
    url: jdbc:oracle:thin:@(DESCRIPTION=(ADDRESS=(PROTOCOL=tcps)(HOST=hostname)(PORT=2484))(CONNECT_DATA=(SERVICE_NAME=ORCL)))

# Query parameters
spring:
  datasource:
    url: jdbc:oracle:thin:@//localhost:1521/ORCL?oracle.net.disableOob=true&oracle.jdbc.ReadTimeout=60000
```

### TNS Format (Uses tnsnames.ora)

```yaml
# TNS: Requires tnsnames.ora file

# tnsnames.ora location:
# - Linux: $ORACLE_HOME/network/admin/tnsnames.ora
# - Windows: %ORACLE_HOME%\network\admin\tnsnames.ora

# tnsnames.ora content:
# PROD_DB =
#   (DESCRIPTION =
#     (ADDRESS = (PROTOCOL = TCP)(HOST = prod-db.example.com)(PORT = 1521))
#     (CONNECT_DATA =
#       (SERVICE_NAME = PROD)
#     )
#   )

# Spring Boot configuration
spring:
  datasource:
    url: jdbc:oracle:thin:@PROD_DB
    # Uses TNS name "PROD_DB" from tnsnames.ora

# Specify TNS_ADMIN environment variable
# export TNS_ADMIN=/path/to/oracle/network/admin

# Or in Spring Boot
spring:
  datasource:
    url: jdbc:oracle:thin:@PROD_DB
    hikari:
      data-source-properties:
        oracle.net.tns_admin: /path/to/oracle/network/admin
```

### Connection URL Comparison

```java
@Configuration
public class OracleConnectionExamples {
    
    // === EZConnect: Simple hostname:port/service ===
    public DataSource ezConnectSimple() {
        HikariDataSource ds = new HikariDataSource();
        ds.setJdbcUrl("jdbc:oracle:thin:@//localhost:1521/ORCL");
        ds.setUsername("myuser");
        ds.setPassword("mypassword");
        return ds;
    }
    
    // === EZConnect: With connection properties ===
    public DataSource ezConnectWithProperties() {
        HikariDataSource ds = new HikariDataSource();
        ds.setJdbcUrl("jdbc:oracle:thin:@//localhost:1521/ORCL" +
                     "?oracle.net.disableOob=true" +  // Disable out-of-band breaks
                     "&oracle.jdbc.ReadTimeout=60000" +  // Read timeout 60s
                     "&oracle.net.CONNECT_TIMEOUT=10000");  // Connect timeout 10s
        ds.setUsername("myuser");
        ds.setPassword("mypassword");
        return ds;
    }
    
    // === TNS: Using tnsnames.ora ===
    public DataSource tnsConnect() {
        HikariDataSource ds = new HikariDataSource();
        ds.setJdbcUrl("jdbc:oracle:thin:@PROD_DB");  // TNS name
        ds.setUsername("myuser");
        ds.setPassword("mypassword");
        
        // Set TNS_ADMIN location
        System.setProperty("oracle.net.tns_admin", "/path/to/tns/admin");
        
        return ds;
    }
    
    // === Long format: Full connection descriptor ===
    public DataSource longFormatConnect() {
        String url = "jdbc:oracle:thin:@" +
            "(DESCRIPTION=" +
                "(ADDRESS=(PROTOCOL=TCP)(HOST=prod-db.example.com)(PORT=1521))" +
                "(CONNECT_DATA=(SERVICE_NAME=PROD))" +
            ")";
        
        HikariDataSource ds = new HikariDataSource();
        ds.setJdbcUrl(url);
        ds.setUsername("myuser");
        ds.setPassword("mypassword");
        return ds;
    }
}
```

### URL Format Best Practices

```
Scenario                     Recommended Format
--------------------------------------------------------------------------------
Development (local)          EZConnect: jdbc:oracle:thin:@//localhost:1521/ORCL
Production (single host)     EZConnect: jdbc:oracle:thin:@//host:1521/service
Production (RAC/HA)          Long format with multiple addresses
Container/Cloud              EZConnect with env variables
Complex failover             TNS (tnsnames.ora)

EZConnect Pros:
✅ No tnsnames.ora file needed
✅ Simple, easy to configure
✅ Good for development/containers
✅ URL is self-contained

TNS Pros:
✅ Centralized configuration
✅ Complex failover scenarios
✅ Multiple connection options in one place
✅ Legacy application compatibility
```

## 3. Oracle Wallet Integration

### Understanding Oracle Wallet

```
Oracle Wallet: Secure credential storage
- Stores usernames/passwords encrypted
- No plaintext credentials in config files
- Supports SSL/TLS certificates
- Auto-login wallets (no password needed)

Benefits:
✅ Security: Credentials encrypted at rest
✅ Compliance: No passwords in source code
✅ Rotation: Easy credential rotation
✅ Centralized: One wallet for multiple DBs
```

### Creating Oracle Wallet

```bash

# Create Oracle Wallet using orapki

# 1. Create wallet directory
mkdir -p /opt/oracle/wallet
cd /opt/oracle/wallet

# 2. Create wallet (requires Oracle Instant Client)

# Copyright (c) 2004, 2019, Oracle and/or its affiliates.
# Enter password: [enter password]
# Enter password again: [confirm password]

mkstore -wrl . -createCredential PROD_DB myuser mypassword

# Output:

# Copyright (c) 2004, 2019, Oracle and/or its affiliates.
# Your secret/Password is missing in the command line

# Re-enter your secret/Password: [confirm]

# 4. List credentials

# 5. Set permissions
```

### Java Configuration with Wallet

```java
@Configuration
public class OracleWalletConfig {
    
    @Value("${oracle.wallet.location:/opt/oracle/wallet}")
    private String walletLocation;
    
    @Bean
    public DataSource dataSource() {
        HikariDataSource dataSource = new HikariDataSource();
        
        // Connection URL (no credentials)
        dataSource.setJdbcUrl("jdbc:oracle:thin:/@PROD_DB");
        
        // Set wallet location
        Properties props = new Properties();
        props.setProperty("oracle.net.wallet_location", 
            "(SOURCE=(METHOD=FILE)(METHOD_DATA=(DIRECTORY=" + walletLocation + ")))");
        props.setProperty("oracle.net.tns_admin", walletLocation);
        
        // Apply properties
        dataSource.setDataSourceProperties(props);
        
        return dataSource;
    }
}

// Using OracleDataSource directly
@Configuration
public class OracleDataSourceConfig {
    
    @Bean
    public DataSource oracleDataSource() throws SQLException {
        OracleDataSource ods = new OracleDataSource();
        
        // Set URL (references TNS name)
        ods.setURL("jdbc:oracle:thin:/@PROD_DB");
        
        // Set wallet properties
        Properties props = new Properties();
        props.setProperty("oracle.net.wallet_location", 
            "(SOURCE=(METHOD=FILE)(METHOD_DATA=(DIRECTORY=/opt/oracle/wallet)))");
        
        ods.setConnectionProperties(props);
        
        return ods;
    }
}
```

## 4. RAC (Real Application Clusters) Configuration

### Understanding Oracle RAC

```
Oracle RAC: Multiple database instances accessing single database
- High Availability: Automatic failover if instance fails
- Load Balancing: Distribute connections across instances
- Scalability: Add instances to increase capacity

Architecture:
- Shared Storage: All instances access same data files
- Interconnect: High-speed network between instances
- VIP: Virtual IP for each instance
- SCAN: Single Client Access Name (single entry point)

Benefits:
✅ Zero downtime for instance failures
✅ Rolling patches (patch one instance at a time)
✅ Horizontal scalability
✅ Load distribution
```

### RAC Failover Configuration

```java
@Configuration
public class RacFailoverConfig {
    
    @Bean
    public DataSource racDataSource() {
        HikariDataSource ds = new HikariDataSource();
        
        // RAC SCAN URL
        ds.setJdbcUrl("jdbc:oracle:thin:@//scan.example.com:1521/PROD");
        ds.setUsername("myuser");
        ds.setPassword("mypassword");
        
        // Connection properties for RAC
        Properties props = new Properties();
        
        // Fast Connection Failover (FCF)
        props.setProperty("oracle.jdbc.fanEnabled", "true");
        
        // Connection timeout
        props.setProperty("oracle.net.CONNECT_TIMEOUT", "10000");  // 10 seconds
        
        // Read timeout
        props.setProperty("oracle.jdbc.ReadTimeout", "60000");  // 60 seconds
        
        // Retry count
        props.setProperty("oracle.net.ns.SQLnetDef.TCP_CONNTIMEOUT_STR", "10000");
        
        ds.setDataSourceProperties(props);
        
        // Connection pool settings for RAC
        ds.setMaximumPoolSize(20);  // Larger pool for HA
        ds.setMinimumIdle(5);
        ds.setConnectionTimeout(30000);  // 30 seconds
        ds.setIdleTimeout(600000);  // 10 minutes
        ds.setMaxLifetime(1800000);  // 30 minutes
        
        // Validate connections
        ds.setConnectionTestQuery("SELECT 1 FROM DUAL");
        
        return ds;
    }
}
```

### Failover Types

```sql
-- === Failover Types ===

-- TYPE = SELECT (connection-level failover)
-- - Fails over if connection breaks
-- - SELECT statements can resume
-- - DML transactions are rolled back

FAILOVER_MODE = (TYPE=SELECT)(METHOD=BASIC)

-- TYPE = SESSION (session-level failover)
-- - Creates new session on failover
-- - All active transactions are lost
-- - Application must retry

FAILOVER_MODE = (TYPE=SESSION)(METHOD=BASIC)

-- METHOD = BASIC
-- - Establishes connection to backup on failover
-- - Fast but uses resources

-- METHOD = PRECONNECT
-- - Pre-establishes backup connection
-- - Instant failover but uses more resources

FAILOVER_MODE = (TYPE=SELECT)(METHOD=PRECONNECT)


-- === Load Balancing ===

-- LOAD_BALANCE = ON
-- - Distributes new connections across instances
-- - Round-robin by default

-- Connection-time load balancing
(LOAD_BALANCE=ON)

-- Runtime load balancing (requires services)
-- Configured at database level:
-- DBMS_SERVICE.MODIFY_SERVICE(
--   service_name => 'PROD',
--   goal => DBMS_SERVICE.GOAL_THROUGHPUT,
--   clb_goal => DBMS_SERVICE.CLB_GOAL_SHORT
-- );
```

### Testing RAC Failover

```java
@Service
public class RacFailoverTestService {
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    // Test connection failover
    public void testFailover() {
        try {
            // 1. Get current instance
            String instance1 = getCurrentInstance();
            log.info("Connected to instance: {}", instance1);
            
            // 2. Simulate instance failure (on DBA side)
            log.info("Simulate instance shutdown...");
            
            // 3. Execute query after failover
            Thread.sleep(5000);  // Wait for failover
            String instance2 = getCurrentInstance();
            log.info("After failover, connected to: {}", instance2);
            
            if (!instance1.equals(instance2)) {
                log.info("Failover successful! {} -> {}", instance1, instance2);
            }
            
        } catch (Exception e) {
            log.error("Failover test failed", e);
        }
    }
    
    private String getCurrentInstance() {
        return jdbcTemplate.queryForObject(
            "SELECT SYS_CONTEXT('USERENV', 'INSTANCE_NAME') FROM DUAL",
            String.class
        );
    }
    
    // Test load balancing
    public void testLoadBalancing() {
        Map<String, Integer> instanceCounts = new HashMap<>();
        
        // Create 100 connections and check distribution
        for (int i = 0; i < 100; i++) {
            try (Connection conn = jdbcTemplate.getDataSource().getConnection()) {
                Statement stmt = conn.createStatement();
                ResultSet rs = stmt.executeQuery(
                    "SELECT SYS_CONTEXT('USERENV', 'INSTANCE_NAME') FROM DUAL"
                );
                
                if (rs.next()) {
                    String instance = rs.getString(1);
                    instanceCounts.merge(instance, 1, Integer::sum);
                }
            } catch (SQLException e) {
                log.error("Failed to get instance", e);
            }
        }
        
        log.info("Load balancing distribution:");
        instanceCounts.forEach((instance, count) -> 
            log.info("  Instance {}: {} connections ({}%)", 
                instance, count, count)
        );
        
        // Expected: ~33% per instance for 3-node RAC
    }
}
```

### RAC Monitoring

```java
@Service
public class RacMonitoringService {
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    @Autowired
    private MeterRegistry meterRegistry;
    
    @Scheduled(fixedDelay = 30000)  // Every 30 seconds
    public void monitorRacInstances() {
        try {
            // Query GV$ views (Global Views across all instances)
            String sql = """
                SELECT 
                    inst_id,
                    instance_name,
                    host_name,
                    status,
                    startup_time,
                    (SELECT COUNT(*) FROM gv$session WHERE inst_id = i.inst_id) as session_count
                FROM gv$instance i
                ORDER BY inst_id
                """;
            
            List<Map<String, Object>> instances = jdbcTemplate.queryForList(sql);
            
            for (Map<String, Object> instance : instances) {
                int instId = ((Number) instance.get("inst_id")).intValue();
                String status = (String) instance.get("status");
                int sessionCount = ((Number) instance.get("session_count")).intValue();
                
                // Record metrics
                meterRegistry.gauge("oracle.rac.instance.status",
                    Tags.of("instance_id", String.valueOf(instId)),
                    "OPEN".equals(status) ? 1 : 0
                );
                
                meterRegistry.gauge("oracle.rac.instance.sessions",
                    Tags.of("instance_id", String.valueOf(instId)),
                    sessionCount
                );
                
                log.debug("Instance {}: Status={}, Sessions={}", 
                    instId, status, sessionCount);
            }
            
        } catch (Exception e) {
            log.error("Failed to monitor RAC instances", e);
        }
    }
    
    // Check service availability
    @Scheduled(fixedDelay = 60000)
    public void monitorServices() {
        try {
```

### Connection Pool Comparison

```
Performance            Fastest               Fast
Memory footprint       Smallest              Larger
Oracle features        Basic                 Advanced (FCF, RAC, etc.)
```

```java
// CLOB: Character Large Object (up to 128TB)

@Entity
public class Document {

    private Long id;
    
    // CLOB - for large text
    @Lob
    @Column(columnDefinition = "CLOB")
    private String content;
    // DDL: content CLOB

// Using CLOB programmatically
@Service
public class DocumentService {
    
    @PersistenceContext
    private EntityManager entityManager;
    
    @Transactional
    public void saveLargeText(Long id, String largeText) {
        // For very large text, use streaming
        Document doc = new Document();
        doc.setId(id);
        
        // Hibernate handles CLOB automatically
        doc.setContent(largeText);
        
        entityManager.persist(doc);
    }
    
    // Reading CLOB with JDBC
    public String readClob(Long id) throws SQLException, IOException {
        String sql = "SELECT content FROM documents WHERE id = ?";
        
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            
            ps.setLong(1, id);
            ResultSet rs = ps.executeQuery();
            
            if (rs.next()) {
                Clob clob = rs.getClob("content");
                return clob.getSubString(1, (int) clob.length());
            }
        }
        
        return null;
    }
    
    // Writing BLOB with streaming
    @Transactional
    public void saveFile(Long id, InputStream fileStream) throws Exception {
        String sql = "UPDATE documents SET file_data = ? WHERE id = ?";
        
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql)) {
            
            // Stream large file
            ps.setBlob(1, fileStream);
            ps.setLong(2, id);
            ps.executeUpdate();
        }
    }
}
```

## Best Practices Summary

```
✅ DO:
- Use Oracle12cDialect for Oracle 12c+
- Use EZConnect for simple scenarios
- Use Wallet for credential security
- Configure RAC with SCAN for HA
- Use UCP for RAC/advanced Oracle features
- Use HikariCP for non-RAC simplicity
- Map NUMBER to BigDecimal for precision
- Use VARCHAR2 (not VARCHAR)
- Use CLOB for large text (>4000 chars)
- Test failover scenarios in RAC

❌ DON'T:
- Use deprecated dialects (Oracle8i, Oracle9i)
- Store passwords in plaintext config
- Forget LOAD_BALANCE and FAILOVER for RAC
- Use CHAR instead of VARCHAR2 (wastes space)
- Use Float/Double for money (use BigDecimal)
- Forget to set oracle.jdbc.fanEnabled for RAC
- Mix connection pools (pick one: Hikari or UCP)
- Use VARCHAR (Oracle-deprecated, use VARCHAR2)
```
