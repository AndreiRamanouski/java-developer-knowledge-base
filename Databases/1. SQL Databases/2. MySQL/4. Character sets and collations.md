# MySQL Character Sets and Collations with Spring Boot

## Deep Dive Interview Guide

This guide covers MySQL character sets and collations for production Spring Boot applications, including utf8mb4 configuration, emoji support, migration strategies, and performance implications.

**Interview Tip**: Character set questions test understanding of internationalization (i18n), data integrity, database internals, and production migration strategies.

---

## Q4: Character Sets and Collations

**Short Answer**: utf8mb4 supports full Unicode (4 bytes, emojis), utf8 supports only 3 bytes (no emojis). Collations: utf8mb4_general_ci (fast, case-insensitive), utf8mb4_unicode_ci (accurate, case-insensitive), utf8mb4_bin (case-sensitive), utf8mb4_0900_ai_ci (MySQL 8.0, accent-insensitive). Configure in Spring Boot: jdbc:mysql://localhost/db?characterEncoding=UTF-8. Migration: ALTER TABLE...CONVERT TO CHARACTER SET utf8mb4. Performance: utf8mb4_general_ci 10-15% faster than utf8mb4_unicode_ci. Sorting behavior depends on collation: _ci ignores case, _bin preserves case.

## 1. utf8mb4 vs utf8 (Emoji Support)

### Understanding Character Sets

```
Character Set Comparison:

ascii:       1 byte  - Only English characters (A-Z, 0-9)
latin1:      1 byte  - Western European characters
utf8:        1-3 bytes - Most Unicode, but NO EMOJIS (BMP only)
utf8mb4:     1-4 bytes - FULL Unicode including emojis ✅

Why utf8 can't store emojis:
- Emojis are 4-byte characters (e.g., 😀 = U+1F600)
- MySQL's "utf8" is actually UTF-8 with 3-byte limit
- utf8mb4 = "UTF-8 Multi-Byte 4" (full UTF-8)

MySQL 8.0+ default: utf8mb4
MySQL 5.7 default: latin1 (legacy)
```

### Creating Tables with utf8mb4

```sql
-- === utf8 (Old, Limited) ===
CREATE TABLE users_utf8 (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    bio TEXT
) CHARACTER SET utf8 COLLATE utf8_general_ci;

-- Try to insert emoji
INSERT INTO users_utf8 (name, bio) 
VALUES ('John', 'I love coding 😀');
-- ERROR: Incorrect string value: '\xF0\x9F\x98\x80' for column 'bio'

-- === utf8mb4 (Modern, Full Unicode) ===
CREATE TABLE users_utf8mb4 (
    id BIGINT AUTO_INCREMENT PRIMARY KEY,
    name VARCHAR(100),
    bio TEXT
) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- Insert emoji - works!
INSERT INTO users_utf8mb4 (name, bio) 
VALUES ('John', 'I love coding 😀');
-- SUCCESS

-- Check current character set
SHOW VARIABLES LIKE 'character_set_%';
SHOW VARIABLES LIKE 'collation%';

-- Database-level default
ALTER DATABASE mydb CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

-- Server-level default (my.cnf)
[mysqld]
character-set-server = utf8mb4
collation-server = utf8mb4_unicode_ci
```

### Storage Size Comparison

```sql
-- Storage size differences

-- Latin1 (1 byte per character)
CREATE TABLE test_latin1 (
    id INT PRIMARY KEY,
    text VARCHAR(100)
) CHARACTER SET latin1;

INSERT INTO test_latin1 VALUES (1, 'Hello World');
-- Storage: 11 bytes

-- utf8 (1-3 bytes per character)
CREATE TABLE test_utf8 (
    id INT PRIMARY KEY,
    text VARCHAR(100)
) CHARACTER SET utf8;

INSERT INTO test_utf8 VALUES (1, 'Hello World');  -- ASCII: 11 bytes
INSERT INTO test_utf8 VALUES (2, '中文测试');      -- Chinese: 12 bytes (4 chars × 3)

-- utf8mb4 (1-4 bytes per character)
CREATE TABLE test_utf8mb4 (
    id INT PRIMARY KEY,
    text VARCHAR(100)
) CHARACTER SET utf8mb4;

INSERT INTO test_utf8mb4 VALUES (1, 'Hello World');  -- ASCII: 11 bytes
INSERT INTO test_utf8mb4 VALUES (2, '中文测试');      -- Chinese: 12 bytes (4 chars × 3)
INSERT INTO test_utf8mb4 VALUES (3, 'Emoji 😀');     -- Emoji: 10 bytes (6 ASCII + 4 emoji)

-- VARCHAR(100) maximum storage:
-- latin1:   100 bytes
-- utf8:     300 bytes (100 chars × 3)
-- utf8mb4:  400 bytes (100 chars × 4)

-- Index key length limits:
-- InnoDB max key length: 3072 bytes (MySQL 5.7+)
-- VARCHAR(191) × 4 bytes = 764 bytes (safe for utf8mb4 indexes)
-- VARCHAR(255) × 4 bytes = 1020 bytes (exceeds limit if multiple columns)
```

## 2. Case-Sensitive vs Case-Insensitive Collations

### Common Collations

```sql
-- === utf8mb4_general_ci (Fast, Case-Insensitive) ===
-- ci = Case Insensitive
-- Fast but less accurate for some languages

CREATE TABLE users_general (
    id BIGINT PRIMARY KEY,
    email VARCHAR(255)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

INSERT INTO users_general VALUES (1, 'john@example.com');

-- Case-insensitive comparison
SELECT * FROM users_general WHERE email = 'JOHN@EXAMPLE.COM';
-- Returns: john@example.com (matches!)

SELECT * FROM users_general WHERE email = 'John@Example.Com';
-- Returns: john@example.com (matches!)


-- === utf8mb4_unicode_ci (Accurate, Case-Insensitive) ===
-- More accurate sorting for international characters
-- Slower but better for non-English languages

CREATE TABLE users_unicode (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;

INSERT INTO users_unicode VALUES (1, 'Müller');
INSERT INTO users_unicode VALUES (2, 'Mueller');

-- Both match "mueller"
SELECT * FROM users_unicode WHERE name = 'mueller';
-- Returns: Müller, Mueller (both match!)


-- === utf8mb4_bin (Binary, Case-Sensitive) ===
-- Binary comparison (byte-by-byte)
-- Case-sensitive, accent-sensitive

CREATE TABLE users_bin (
    id BIGINT PRIMARY KEY,
    username VARCHAR(50)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;

INSERT INTO users_bin VALUES (1, 'JohnDoe');

-- Case-sensitive
SELECT * FROM users_bin WHERE username = 'JohnDoe';
-- Returns: JohnDoe ✅

SELECT * FROM users_bin WHERE username = 'johndoe';
-- Returns: nothing ❌ (case mismatch)

SELECT * FROM users_bin WHERE username = 'JOHNDOE';
-- Returns: nothing ❌ (case mismatch)


-- === utf8mb4_0900_ai_ci (MySQL 8.0, Accent-Insensitive) ===
-- ai = Accent Insensitive
-- ci = Case Insensitive
-- Most advanced collation in MySQL 8.0

CREATE TABLE users_0900 (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;

INSERT INTO users_0900 VALUES (1, 'José');
INSERT INTO users_0900 VALUES (2, 'Jose');
INSERT INTO users_0900 VALUES (3, 'JOSE');

-- All match (accent-insensitive + case-insensitive)
SELECT * FROM users_0900 WHERE name = 'jose';
-- Returns: José, Jose, JOSE (all match!)
```

### Collation Comparison Matrix

```
Collation              Case    Accent   Speed    Accuracy   MySQL Version
--------------------------------------------------------------------------------
utf8mb4_general_ci     Ignore  Ignore   Fast     Good       5.5+
utf8mb4_unicode_ci     Ignore  Ignore   Slow     Better     5.5+
utf8mb4_bin            Keep    Keep     Fast     Exact      5.5+
utf8mb4_0900_ai_ci     Ignore  Ignore   Fast     Best       8.0+
utf8mb4_0900_as_ci     Ignore  Keep     Fast     Best       8.0+
utf8mb4_0900_as_cs     Keep    Keep     Fast     Best       8.0+

Recommendations:
- Email addresses: utf8mb4_general_ci (case-insensitive)
- Usernames: utf8mb4_bin (case-sensitive, unique)
- Names: utf8mb4_unicode_ci (proper sorting)
- Passwords: Never store plaintext! (hash them)
- Content: utf8mb4_unicode_ci or utf8mb4_0900_ai_ci
```

### JPA Entity with Different Collations

```java
@Entity
@Table(name = "users")
public class User {
    
    @Id
    @GeneratedValue(strategy = GenerationType.IDENTITY)
    private Long id;
    
    // Case-sensitive username (unique)
    @Column(
        unique = true, 
        length = 50,
        columnDefinition = "VARCHAR(50) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin"
    )
    private String username;  // 'JohnDoe' != 'johndoe'
    
    // Case-insensitive email
    @Column(
        unique = true,
        length = 255,
        columnDefinition = "VARCHAR(255) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci"
    )
    private String email;  // 'john@example.com' == 'JOHN@EXAMPLE.COM'
    
    // Unicode collation for proper name sorting
    @Column(
        length = 100,
        columnDefinition = "VARCHAR(100) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci"
    )
    private String fullName;  // Proper sorting: Müller, Mueller
    
    // Binary for exact matching
    @Column(
        length = 64,
        columnDefinition = "VARCHAR(64) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin"
    )
    private String apiKey;  // Exact match required
}
```

### Testing Case Sensitivity

```java
@SpringBootTest
public class CollationTest {
    
    @Autowired
    private UserRepository userRepository;
    
    @Test
    public void testCaseSensitiveUsername() {
        // Create user with mixed case username
        User user1 = new User();
        user1.setUsername("JohnDoe");
        user1.setEmail("john@example.com");
        userRepository.save(user1);
        
        // Try to create another user with different case
        User user2 = new User();
        user2.setUsername("johndoe");  // Different case
        user2.setEmail("john2@example.com");
        userRepository.save(user2);  // ✅ SUCCESS (different username)
        
        // Find by exact case
        Optional<User> found1 = userRepository.findByUsername("JohnDoe");
        assertThat(found1).isPresent();
        
        Optional<User> found2 = userRepository.findByUsername("johndoe");
        assertThat(found2).isPresent();
        assertThat(found2.get().getId()).isNotEqualTo(found1.get().getId());
    }
    
    @Test
    public void testCaseInsensitiveEmail() {
        User user = new User();
        user.setUsername("john1");
        user.setEmail("john@example.com");
        userRepository.save(user);
        
        // Try different cases
        Optional<User> found1 = userRepository.findByEmail("john@example.com");
        Optional<User> found2 = userRepository.findByEmail("JOHN@EXAMPLE.COM");
        Optional<User> found3 = userRepository.findByEmail("John@Example.Com");
        
        // All should find the same user
        assertThat(found1).isPresent();
        assertThat(found2).isPresent();
        assertThat(found3).isPresent();
        assertThat(found1.get().getId()).isEqualTo(found2.get().getId());
        assertThat(found2.get().getId()).isEqualTo(found3.get().getId());
    }
    
    @Test
    public void testUniquenessWithCollation() {
        // Case-insensitive email - should fail on duplicate
        User user1 = new User();
        user1.setUsername("user1");
        user1.setEmail("test@example.com");
        userRepository.save(user1);
        
        User user2 = new User();
        user2.setUsername("user2");
        user2.setEmail("TEST@EXAMPLE.COM");  // Different case
        
        // Should fail (case-insensitive unique constraint)
        assertThrows(DataIntegrityViolationException.class, () -> {
            userRepository.save(user2);
        });
    }
}
```

### Custom Collation in Queries

```sql
-- Override collation in query

-- Table with case-insensitive collation
CREATE TABLE users (
    username VARCHAR(50) COLLATE utf8mb4_general_ci
);

INSERT INTO users VALUES ('JohnDoe');

-- Normal query (uses table collation - case-insensitive)
SELECT * FROM users WHERE username = 'johndoe';
-- Returns: JohnDoe ✅

-- Force case-sensitive comparison
SELECT * FROM users WHERE username = 'johndoe' COLLATE utf8mb4_bin;
-- Returns: nothing ❌ (case mismatch)

-- Force case-insensitive comparison on binary column
CREATE TABLE api_keys (
    key_value VARCHAR(64) COLLATE utf8mb4_bin
);

INSERT INTO api_keys VALUES ('AbC123');

SELECT * FROM api_keys WHERE key_value = 'abc123' COLLATE utf8mb4_general_ci;
-- Returns: AbC123 ✅ (forced case-insensitive)
```

### Verifying Character Set Configuration

```java
@Service
public class CharacterSetVerificationService {
    
    @Autowired
    private JdbcTemplate jdbcTemplate;
    
    @PostConstruct
    public void verifyCharacterSet() {
        // Check connection character set
        Map<String, String> charsets = new HashMap<>();
        
        String sql = """
            SELECT 
                @@character_set_client,
                @@character_set_connection,
                @@character_set_results,
                @@collation_connection
            """;
        
        jdbcTemplate.query(sql, rs -> {
            charsets.put("client", rs.getString(1));
            charsets.put("connection", rs.getString(2));
            charsets.put("results", rs.getString(3));
            charsets.put("collation", rs.getString(4));
        });
        
        log.info("Character Set Configuration:");
        log.info("  character_set_client: {}", charsets.get("client"));
        log.info("  character_set_connection: {}", charsets.get("connection"));
        log.info("  character_set_results: {}", charsets.get("results"));
        log.info("  collation_connection: {}", charsets.get("collation"));
        
        // Verify utf8mb4
        if (!"utf8mb4".equals(charsets.get("client")) ||
            !"utf8mb4".equals(charsets.get("connection"))) {
            log.warn("WARNING: Not using utf8mb4! Emojis will not work!");
        }
    }
    
    public void verifyTableCharset(String tableName) {
        String sql = """
            SELECT 
                CCSA.CHARACTER_SET_NAME,
                CCSA.COLLATION_NAME
            FROM information_schema.TABLES T,
                 information_schema.COLLATION_CHARACTER_SET_APPLICABILITY CCSA
            WHERE CCSA.collation_name = T.table_collation
              AND T.table_schema = DATABASE()
              AND T.table_name = ?
            """;
        
        jdbcTemplate.query(sql, rs -> {
            String charset = rs.getString(1);
            String collation = rs.getString(2);
            log.info("Table '{}': charset={}, collation={}", 
                    tableName, charset, collation);
        }, tableName);
    }
    
    public void verifyColumnCharset(String tableName, String columnName) {
        String sql = """
            SELECT 
                CHARACTER_SET_NAME,
                COLLATION_NAME
            FROM information_schema.COLUMNS
            WHERE TABLE_SCHEMA = DATABASE()
              AND TABLE_NAME = ?
              AND COLUMN_NAME = ?
            """;
        
        jdbcTemplate.query(sql, rs -> {
            String charset = rs.getString(1);
            String collation = rs.getString(2);
            log.info("Column '{}.{}': charset={}, collation={}", 
                    tableName, columnName, charset, collation);
        }, tableName, columnName);
    }
}
```

## 4. Migration from latin1 to utf8mb4

### Pre-Migration Assessment

```sql
-- Check current database charset
SELECT 
    DEFAULT_CHARACTER_SET_NAME,
    DEFAULT_COLLATION_NAME
FROM information_schema.SCHEMATA
WHERE SCHEMA_NAME = 'mydb';

-- Check all tables
SELECT 
    TABLE_NAME,
    TABLE_COLLATION,
    CCSA.CHARACTER_SET_NAME
FROM information_schema.TABLES T
LEFT JOIN information_schema.COLLATION_CHARACTER_SET_APPLICABILITY CCSA
    ON CCSA.COLLATION_NAME = T.TABLE_COLLATION
WHERE TABLE_SCHEMA = 'mydb'
ORDER BY TABLE_NAME;

-- Check all columns
SELECT 
    TABLE_NAME,
    COLUMN_NAME,
    CHARACTER_SET_NAME,
    COLLATION_NAME,
    COLUMN_TYPE
FROM information_schema.COLUMNS
WHERE TABLE_SCHEMA = 'mydb'
  AND CHARACTER_SET_NAME IS NOT NULL
ORDER BY TABLE_NAME, ORDINAL_POSITION;

-- Estimate migration impact
SELECT 
    TABLE_NAME,
    ROUND(((DATA_LENGTH + INDEX_LENGTH) / 1024 / 1024), 2) AS 'Size (MB)',
    TABLE_ROWS
FROM information_schema.TABLES
WHERE TABLE_SCHEMA = 'mydb'
ORDER BY (DATA_LENGTH + INDEX_LENGTH) DESC;
```

### Zero-Downtime Migration Strategy

```sql
-- === Phase 1: Alter Database Default (Quick) ===
-- This only affects NEW tables, not existing ones

ALTER DATABASE mydb 
CHARACTER SET = utf8mb4 
COLLATE = utf8mb4_unicode_ci;

-- === Phase 2: Alter Tables (Can be slow) ===
-- CONVERT TO will:
-- 1. Change table default charset
-- 2. Convert all character columns
-- 3. Rebuild indexes
-- WARNING: This locks the table!

-- For small tables (< 1M rows):
ALTER TABLE users 
CONVERT TO CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

-- For large tables (> 1M rows), use batched approach:
-- Create new table with utf8mb4
CREATE TABLE users_utf8mb4 LIKE users;

ALTER TABLE users_utf8mb4 
CONVERT TO CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

-- Copy data in batches (use pt-online-schema-change or gh-ost)
-- This avoids locking the table

-- === Phase 3: Specific Column Migration ===
-- If you only need specific columns to support emojis

-- Change only the 'bio' column
ALTER TABLE users 
MODIFY COLUMN bio TEXT 
CHARACTER SET utf8mb4 
COLLATE utf8mb4_unicode_ci;

-- Multiple columns at once
ALTER TABLE users 
MODIFY COLUMN name VARCHAR(100) CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci,
MODIFY COLUMN bio TEXT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci,
MODIFY COLUMN description TEXT CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

### Using pt-online-schema-change (Percona Toolkit)

```bash
  --alter "CONVERT TO CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci" \

# 5. Atomic rename: users -> users_old, users_new -> users
# 6. Drops triggers and old table

# Copied 1000000 rows (10%)
# Copied 2000000 rows (19%)
# ...
# Copied 10485633 rows (100%)
```

```java
    // Migrate in batches to avoid long locks
    public void migrateTableInBatches(String tableName) {
        log.info("Starting migration of table: {}", tableName);
        
        // 1. Create new table with utf8mb4
        String createSql = String.format("""
            CREATE TABLE %s_utf8mb4 LIKE %s
            """, tableName, tableName);
        jdbcTemplate.execute(createSql);
        
        // 2. Alter new table to utf8mb4
        String alterSql = String.format("""
            ALTER TABLE %s_utf8mb4 
            CONVERT TO CHARACTER SET utf8mb4 
            COLLATE utf8mb4_unicode_ci
            """, tableName);
        jdbcTemplate.execute(alterSql);
        
        // 3. Copy data in batches
        long totalRows = jdbcTemplate.queryForObject(
            String.format("SELECT COUNT(*) FROM %s", tableName),
            Long.class
        );
        
        int batchSize = 10000;
        long offset = 0;
        
        while (offset < totalRows) {
            String copySql = String.format("""
                INSERT INTO %s_utf8mb4 
                SELECT * FROM %s 
                LIMIT %d OFFSET %d
                """, tableName, tableName, batchSize, offset);
            
            int copied = jdbcTemplate.update(copySql);
            offset += copied;
            
            log.info("Copied {}/{} rows ({}%)", 
                    offset, totalRows, (offset * 100 / totalRows));
            
            // Sleep to avoid overloading database
            try {
                Thread.sleep(100);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
        }
        
        // 4. Verify row counts match
        long oldCount = jdbcTemplate.queryForObject(
            String.format("SELECT COUNT(*) FROM %s", tableName),
            Long.class
        );
        long newCount = jdbcTemplate.queryForObject(
            String.format("SELECT COUNT(*) FROM %s_utf8mb4", tableName),
            Long.class
        );
        
        if (oldCount != newCount) {
            throw new RuntimeException(
                String.format("Row count mismatch: old=%d, new=%d", oldCount, newCount)
            );
        }
        
        log.info("Migration verification successful");
        
        // 5. Atomic swap (to be done manually during maintenance)
        log.info("Ready to swap tables. Execute manually:");
        log.info("RENAME TABLE {} TO {}_old, {}_utf8mb4 TO {}",
                tableName, tableName, tableName, tableName);
    }
    
    // Check if migration is needed
    public boolean needsMigration(String tableName) {
        String sql = """
            SELECT CCSA.CHARACTER_SET_NAME
            FROM information_schema.TABLES T,
                 information_schema.COLLATION_CHARACTER_SET_APPLICABILITY CCSA
            WHERE CCSA.collation_name = T.table_collation
              AND T.table_schema = DATABASE()
              AND T.table_name = ?
            """;
        
        String charset = jdbcTemplate.queryForObject(sql, String.class, tableName);
        return !"utf8mb4".equals(charset);
    }
    
    // Generate migration report
    public MigrationReport generateReport() {
        String sql = """
            SELECT 
                TABLE_NAME,
                CCSA.CHARACTER_SET_NAME,
                CCSA.COLLATION_NAME,
                ROUND((DATA_LENGTH + INDEX_LENGTH) / 1024 / 1024, 2) AS size_mb,
                TABLE_ROWS
            FROM information_schema.TABLES T
            LEFT JOIN information_schema.COLLATION_CHARACTER_SET_APPLICABILITY CCSA
                ON CCSA.COLLATION_NAME = T.TABLE_COLLATION
            WHERE T.TABLE_SCHEMA = DATABASE()
              AND T.TABLE_TYPE = 'BASE TABLE'
            ORDER BY (DATA_LENGTH + INDEX_LENGTH) DESC
            """;
        
        List<TableInfo> tables = jdbcTemplate.query(sql, (rs, rowNum) -> {
            TableInfo info = new TableInfo();
            info.setTableName(rs.getString("TABLE_NAME"));
            info.setCharset(rs.getString("CHARACTER_SET_NAME"));
            info.setCollation(rs.getString("COLLATION_NAME"));
            info.setSizeMb(rs.getDouble("size_mb"));
            info.setRowCount(rs.getLong("TABLE_ROWS"));
            info.setNeedsMigration(!"utf8mb4".equals(info.getCharset()));
            return info;
        });
        
        MigrationReport report = new MigrationReport();
        report.setTables(tables);
        report.setTotalTables(tables.size());
        report.setTablesNeedingMigration(
            tables.stream().filter(TableInfo::isNeedsMigration).count()
        );
        
        return report;
    }
}

@Data
class TableInfo {
    private String tableName;
    private String charset;
    private String collation;
    private double sizeMb;
    private long rowCount;
    private boolean needsMigration;
}

@Data
class MigrationReport {
    private List<TableInfo> tables;
    private long totalTables;
    private long tablesNeedingMigration;
}
```

### Index Length Adjustments

```sql
-- Problem: utf8mb4 uses 4 bytes per character
-- VARCHAR(255) × 4 = 1020 bytes (exceeds 767 byte limit in MySQL 5.6)

-- Before migration (latin1):
CREATE TABLE users (
    email VARCHAR(255) PRIMARY KEY
) CHARACTER SET latin1;
-- email index: 255 bytes ✅

-- After migration (utf8mb4):
ALTER TABLE users CONVERT TO CHARACTER SET utf8mb4;
-- ERROR: Specified key was too long; max key length is 767 bytes
-- email index: 255 × 4 = 1020 bytes ❌

-- Solution 1: Reduce VARCHAR length
ALTER TABLE users MODIFY COLUMN email VARCHAR(191);
-- 191 × 4 = 764 bytes ✅

-- Solution 2: Use index prefix
CREATE INDEX idx_email ON users (email(191));
-- Only index first 191 characters

-- Solution 3: Enable large index (MySQL 5.7+)
-- In my.cnf:
# innodb_large_prefix = 1
# innodb_file_format = Barracuda
# innodb_file_per_table = 1

-- Then you can use VARCHAR(255):
CREATE TABLE users (
    email VARCHAR(255)
) CHARACTER SET utf8mb4
ROW_FORMAT=DYNAMIC;  -- Required for large indexes
```

## 6. Sorting and Comparison Behavior

### Case-Insensitive Sorting

```sql
-- Sample data
CREATE TABLE employees (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;

INSERT INTO employees VALUES 
(1, 'alice'),
(2, 'Alice'),
(3, 'ALICE'),
(4, 'Bob'),
(5, 'bob');

-- Sort with utf8mb4_general_ci
SELECT * FROM employees ORDER BY name;
-- Result:
-- alice
-- Alice    -- All "Alice" grouped together
-- ALICE
-- Bob      -- All "Bob" grouped together
-- bob

-- Within same name, order is arbitrary (insertion order-ish)


-- Sort with utf8mb4_bin (case-sensitive)
CREATE TABLE employees_bin (
    id BIGINT PRIMARY KEY,
    name VARCHAR(100)
) CHARACTER SET utf8mb4 COLLATE utf8mb4_bin;

INSERT INTO employees_bin SELECT * FROM employees;

SELECT * FROM employees_bin ORDER BY name;
-- Result (ASCII order):
-- ALICE    -- Uppercase first
-- Alice
-- Bob
-- alice    -- Lowercase after uppercase
-- bob
```

## Best Practices Summary

```
✅ DO:
- Use utf8mb4 for all new projects (full Unicode support)
- Use utf8mb4_unicode_ci for international names/content
- Use utf8mb4_bin for case-sensitive fields (usernames, API keys)
- Use utf8mb4_general_ci for performance-critical fields
- Limit VARCHAR to 191 chars for indexed columns (MySQL 5.6)
- Set connection charset in datasource configuration
- Test emoji support before production deployment
- Plan migration carefully for large databases

❌ DON'T:
- Use utf8 (3-byte limit, no emojis)
- Forget to set connection charset (leads to corruption)
- Ignore index length limits when migrating
- Mix collations without understanding implications
- Assume all "utf8" means full Unicode (MySQL gotcha!)
- Migrate large tables without batching strategy
- Skip verification after migration
- Use utf8mb4_bin for everything (breaks search functionality)
```
