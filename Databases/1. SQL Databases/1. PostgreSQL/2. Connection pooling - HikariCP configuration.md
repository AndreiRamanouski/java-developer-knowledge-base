## Q2: Connection pooling - HikariCP configuration

**Short Answer**: HikariCP is the default and fastest connection pool in Spring Boot, offering superior performance through bytecode-level optimizations. Configure pool size based on `connections = ((core_count * 2) + effective_spindle_count)`, monitor with JMX/Actuator, and detect leaks with `leakDetectionThreshold`. Troubleshoot exhaustion by analyzing connection metrics and slow queries.

```java
        config.addDataSourceProperty("prepStmtCacheSize", "250");
        config.addDataSourceProperty("prepStmtCacheSqlLimit", "2048");
        
        return new HikariDataSource(config);
    }
```

## 2. Optimal Pool Sizing Formula

**Formula: `connections = ((core_count * 2) + effective_spindle_count)`**

### Understanding the Formula

```java
// PostgreSQL recommended formula (from HikariCP docs)
// connections = ((core_count * 2) + effective_spindle_count)

// Example calculation for typical server:
// CPU cores: 8
// HDDs: 2 (or 0 for SSD)
// connections = ((8 * 2) + 2) = 18

// For SSD-based systems:
// connections = ((8 * 2) + 1) = 17 (spindle count treated as 1)

@Configuration
public class DynamicPoolSizeConfig {
    
    @Bean
    public DataSource dataSource() {
        HikariConfig config = new HikariConfig();
        
        // Calculate optimal pool size
        int coreCount = Runtime.getRuntime().availableProcessors();
        int effectiveSpindleCount = 2; // HDDs (or 1 for SSD)
        int optimalPoolSize = (coreCount * 2) + effectiveSpindleCount;
        
        log.info("Calculated optimal pool size: {} (cores: {}, spindles: {})",
                 optimalPoolSize, coreCount, effectiveSpindleCount);
        
        config.setMaximumPoolSize(optimalPoolSize);
        config.setMinimumIdle(Math.max(2, optimalPoolSize / 4)); // 25% of max
        
        // Rest of configuration...
        return new HikariDataSource(config);
    }
}
```

### Why This Formula Works

```
Database connections are primarily I/O bound, not CPU bound.

The formula balances:
1. CPU parallelism: core_count * 2
   - Accounts for hyper-threading
   - Allows context switching during I/O waits

2. Disk I/O parallelism: effective_spindle_count
   - Traditional HDDs: count physical spindles
   - SSDs: treated as 1 (much faster, less bottleneck)

Why NOT more connections?
- Database has limited resources (memory, locks, CPU)
- Each connection consumes ~10MB RAM
- More connections = more context switching
- Diminishing returns after optimal point
```

### Testing Your Optimal Size

```java
@Service
public class ConnectionPoolTuningService {
    
    @Autowired
    private HikariDataSource dataSource;
    
    @Autowired
    private MeterRegistry meterRegistry;
    
    public PoolPerformanceMetrics testPoolSize(int poolSize, int concurrentRequests) {
        // Temporarily adjust pool size
        int originalSize = dataSource.getMaximumPoolSize();
        dataSource.setMaximumPoolSize(poolSize);
        
        try {
            ExecutorService executor = Executors.newFixedThreadPool(concurrentRequests);
            
            long startTime = System.currentTimeMillis();
            List<CompletableFuture<Long>> futures = new ArrayList<>();
            
            // Simulate concurrent requests
            for (int i = 0; i < concurrentRequests; i++) {
                CompletableFuture<Long> future = CompletableFuture.supplyAsync(() -> {
                    try (Connection conn = dataSource.getConnection()) {
                        PreparedStatement ps = conn.prepareStatement(
                            "SELECT pg_sleep(0.1)"); // Simulate 100ms query
                        ps.execute();
                        return System.currentTimeMillis();
                    } catch (SQLException e) {
                        throw new RuntimeException(e);
                    }
                }, executor);
                futures.add(future);
            }
            
            // Wait for all to complete
            CompletableFuture.allOf(futures.toArray(new CompletableFuture[0])).join();
            
            long endTime = System.currentTimeMillis();
            long totalTime = endTime - startTime;
            
            // Collect metrics
            return new PoolPerformanceMetrics(
                poolSize,
                concurrentRequests,
                totalTime,
                dataSource.getHikariPoolMXBean().getActiveConnections(),
                dataSource.getHikariPoolMXBean().getTotalConnections(),
                dataSource.getHikariPoolMXBean().getThreadsAwaitingConnection()
            );
            
        } finally {
            // Restore original size
            dataSource.setMaximumPoolSize(originalSize);
        }
    }
    
    public int findOptimalPoolSize() {
        List<PoolPerformanceMetrics> results = new ArrayList<>();
        
        // Test different pool sizes
        for (int poolSize = 5; poolSize <= 50; poolSize += 5) {
            PoolPerformanceMetrics metrics = testPoolSize(poolSize, 100);
            results.add(metrics);
            
            log.info("Pool size: {}, Total time: {}ms, Avg wait: {}ms",
                     poolSize, metrics.getTotalTime(), 
                     metrics.getAverageWaitTime());
        }
        
        // Find the size with best performance
        return results.stream()
            .min(Comparator.comparingLong(PoolPerformanceMetrics::getTotalTime))
            .map(PoolPerformanceMetrics::getPoolSize)
            .orElse(10);
    }
}

@Data
class PoolPerformanceMetrics {
    private final int poolSize;
    private final int concurrentRequests;
    private final long totalTime;
    private final int activeConnections;
    private final int totalConnections;
    private final int waitingThreads;
    
    public long getAverageWaitTime() {
        return totalTime / concurrentRequests;
    }
}
```

### Common Mistakes

```java
// ❌ MISTAKE 1: Pool too large
spring.datasource.hikari.maximum-pool-size = 200
// Problems:
// - Database overwhelmed (200 connections!)
// - Memory waste (200 * 10MB = 2GB)
// - Context switching overhead
// - Connection thrashing

// ❌ MISTAKE 2: Pool too small
spring.datasource.hikari.maximum-pool-size = 2
// Problems:
// - Thread starvation
// - Request timeouts
// - Poor concurrency
// - High connection wait times

// ❌ MISTAKE 3: minimum-idle = maximum-pool-size
spring.datasource.hikari.minimum-idle = 50
spring.datasource.hikari.maximum-pool-size = 50
// Problems:
// - No dynamic scaling
// - Waste connections during low traffic
// - Slower startup (must create all 50)

// ✅ CORRECT: Balanced approach
spring.datasource.hikari.maximum-pool-size = 17 // Formula-based
spring.datasource.hikari.minimum-idle = 5        // 25-30% of max
// Benefits:
// - Scales dynamically
// - Optimal performance
// - Resource efficient
```

## 3. Connection Leak Detection

**What is a Connection Leak?** A connection leak occurs when application code borrows a connection from the pool but never returns it, eventually exhausting the pool.

### Enabling Leak Detection

```yaml
# application.yml
spring:
  datasource:
    hikari:
      leak-detection-threshold: 60000  # 60 seconds
      # If connection held longer than this, log warning with stack trace
```

```java
@Configuration
public class HikariLeakDetectionConfig {
    
    @Bean
    public DataSource dataSource() {
        HikariConfig config = new HikariConfig();
        
        // Enable leak detection (production)
        config.setLeakDetectionThreshold(60000); // 60 seconds
        
        // For development: more aggressive
        if (isDevelopment()) {
            config.setLeakDetectionThreshold(30000); // 30 seconds
        }
        
        // Rest of configuration...
        return new HikariDataSource(config);
    }
}
```

### Leak Detection in Action

```java
// ❌ LEAK: Connection not closed
@Service
public class LeakyService {
    
    @Autowired
    private DataSource dataSource;
    
    public void leakyMethod() {
        try {
            Connection conn = dataSource.getConnection();
            // Use connection
            PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
            ResultSet rs = ps.executeQuery();
            // Process results...
            
            // BUG: Never close connection!
            // HikariCP will detect this after leakDetectionThreshold
            
        } catch (SQLException e) {
            throw new RuntimeException(e);
        }
    }
}
```

### Common Leak Patterns

```java
// Pattern 1: Missing try-with-resources
public class LeakPattern1 {
    
    // ❌ LEAK: Exception before close
    public void leak() throws SQLException {
        Connection conn = dataSource.getConnection();
        PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
        
        // If exception thrown here, connection never closed
        throw new RuntimeException("Oops!");
        
        // conn.close(); // Never reached
    }
    
    // ✅ CORRECT: try-with-resources
    public void correct() throws SQLException {
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement("SELECT * FROM users")) {
            
            // Connection automatically closed even if exception
            ResultSet rs = ps.executeQuery();
            // Process results...
        }
    }
}

// Pattern 2: Storing connections in fields
public class LeakPattern2 {
    
    // ❌ LEAK: Connection stored in field
    private Connection connection;
    
    public void initialize() throws SQLException {
        this.connection = dataSource.getConnection();
        // Connection never returned to pool
    }
    
    // ✅ CORRECT: Get connection per method
    public void correct() throws SQLException {
        try (Connection conn = dataSource.getConnection()) {
            // Use connection
        }
    }
}

// Pattern 3: Async operations with connections
public class LeakPattern3 {
    
    // ❌ LEAK: Connection used in async task
    public CompletableFuture<List<User>> leakyAsync() {
        Connection conn = dataSource.getConnection(); // Leak!
        
        return CompletableFuture.supplyAsync(() -> {
            try {
                PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
                ResultSet rs = ps.executeQuery();
                // Process...
                return users;
            } catch (SQLException e) {
                throw new RuntimeException(e);
            }
            // Connection never closed
        });
    }
    
    // ✅ CORRECT: Get connection inside async task
    public CompletableFuture<List<User>> correctAsync() {
        return CompletableFuture.supplyAsync(() -> {
            try (Connection conn = dataSource.getConnection();
                 PreparedStatement ps = conn.prepareStatement("SELECT * FROM users")) {
                
                ResultSet rs = ps.executeQuery();
                // Process...
                return users;
            } catch (SQLException e) {
                throw new RuntimeException(e);
            }
        });
    }
}

// Pattern 4: Nested try blocks
public class LeakPattern4 {
    
    // ❌ LEAK: Inner try fails, outer connection leaks
    public void leak() throws SQLException {
        Connection conn = dataSource.getConnection();
        try {
            PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
            try {
                ResultSet rs = ps.executeQuery();
                // If exception here, connection not closed
                throw new RuntimeException("Error processing results");
            } finally {
                ps.close();
            }
        } finally {
            // May not execute if inner try throws
            conn.close();
        }
    }
    
    // ✅ CORRECT: try-with-resources for all
    public void correct() throws SQLException {
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement("SELECT * FROM users");
             ResultSet rs = ps.executeQuery()) {
            
            // All resources automatically closed
        }
    }
}
```

### Manual Leak Detection

```java
@Component
public class ConnectionLeakDetector {
    
    @Autowired
    private HikariDataSource dataSource;
    
    @Scheduled(fixedDelay = 60000) // Every minute
    public void detectLeaks() {
        HikariPoolMXBean poolMXBean = dataSource.getHikariPoolMXBean();
        
        int active = poolMXBean.getActiveConnections();
        int total = poolMXBean.getTotalConnections();
        int idle = poolMXBean.getIdleConnections();
        int waiting = poolMXBean.getThreadsAwaitingConnection();
        
        // Red flag: All connections active for extended period
        if (active == total && active > 0) {
            log.warn("Possible connection leak: all {} connections active", active);
        }
        
        // Red flag: Threads waiting for connections
        if (waiting > 0) {
            log.warn("Pool exhaustion: {} threads waiting for connection", waiting);
        }
        
        // Red flag: No idle connections over time
        if (idle == 0 && total > 5) {
            log.warn("No idle connections available (total: {})", total);
        }
    }
}
```

### Testing for Leaks

```java
@SpringBootTest
public class ConnectionLeakTest {
    
    @Autowired
    private DataSource dataSource;
    
    @Autowired
    private LeakyService leakyService;
    
    @Test
    public void testConnectionLeak() throws InterruptedException {
        HikariDataSource hikariDS = (HikariDataSource) dataSource;
        HikariPoolMXBean poolMXBean = hikariDS.getHikariPoolMXBean();
        
        // Get initial metrics
        int initialActive = poolMXBean.getActiveConnections();
        int initialTotal = poolMXBean.getTotalConnections();
        
        // Call leaky method multiple times
        for (int i = 0; i < 10; i++) {
            leakyService.leakyMethod();
        }
        
        // Wait for leak detection
        Thread.sleep(65000); // Wait for leak detection threshold
        
        // Check if connections leaked
        int finalActive = poolMXBean.getActiveConnections();
        int finalTotal = poolMXBean.getTotalConnections();
        
        // Assert leak occurred
        assertThat(finalActive).isGreaterThan(initialActive);
        assertThat(finalTotal).isEqualTo(hikariDS.getMaximumPoolSize());
        
        // Should see leak warnings in logs
    }
}
```

```java
@Component
public class PoolExhaustionDiagnostics {
```

## Interview Follow-Up Questions - Detailed Answers

### Q1: "How would you diagnose a sudden increase in connection pool wait times?"

**Answer**: Use a systematic approach: check pool metrics, identify slow queries, analyze database load, review application changes, and examine infrastructure issues.

**Step 1: Check Pool Metrics**

```java
@Component
public class ConnectionPoolDiagnostics {
    
    @Autowired
    private HikariDataSource dataSource;
    
    @Autowired
    private MeterRegistry meterRegistry;
    
    public DiagnosticReport diagnoseWaitTimeIncrease() {
        HikariPoolMXBean pool = dataSource.getHikariPoolMXBean();
        DiagnosticReport report = new DiagnosticReport();
        
        // Step 1: Collect current metrics
        int total = pool.getTotalConnections();
        int active = pool.getActiveConnections();
        int idle = pool.getIdleConnections();
        int waiting = pool.getThreadsAwaitingConnection();
        
        report.setTotalConnections(total);
        report.setActiveConnections(active);
        report.setIdleConnections(idle);
        report.setThreadsWaiting(waiting);
        
        // Step 2: Calculate utilization
        double utilization = (double) active / total * 100;
        report.setUtilization(utilization);
        
        // Step 3: Check historical metrics
        Timer acquireTimer = meterRegistry.find("hikaricp.connections.acquire")
            .timer();
        
        if (acquireTimer != null) {
            double avgAcquireTime = acquireTimer.mean(TimeUnit.MILLISECONDS);
            double maxAcquireTime = acquireTimer.max(TimeUnit.MILLISECONDS);
            
            report.setAvgAcquireTime(avgAcquireTime);
            report.setMaxAcquireTime(maxAcquireTime);
            
            // Red flag: Average wait time > 1 second
            if (avgAcquireTime > 1000) {
                report.addIssue("High average connection acquire time: " + 
                               avgAcquireTime + "ms");
            }
        }
        
        // Step 4: Identify root cause
        if (utilization > 90 && waiting > 0) {
            report.setProblemType("POOL_EXHAUSTION");
            report.addIssue("Pool is exhausted: " + utilization + "% utilized");
            report.addRecommendation("Check for connection leaks");
            report.addRecommendation("Identify slow queries");
            report.addRecommendation("Consider increasing pool size");
        }
        
        if (utilization < 50 && waiting > 0) {
            report.setProblemType("SLOW_QUERIES");
            report.addIssue("Low utilization but threads waiting");
            report.addRecommendation("Connections are being held too long");
            report.addRecommendation("Check for long-running queries");
        }
        
        return report;
    }
}

    private double avgAcquireTime;
```

**Step 2: Identify Slow Queries**

```java
@Component
public class SlowQueryAnalyzer {
    
    @Autowired
    private DataSource dataSource;
    
    public List<SlowQueryInfo> findSlowQueries() {
        // PostgreSQL: Use pg_stat_statements
        String sql = """
            SELECT 
                query,
                calls,
                total_exec_time,
                mean_exec_time,
                max_exec_time,
                stddev_exec_time
            FROM pg_stat_statements
            WHERE mean_exec_time > 100  -- Queries slower than 100ms
            ORDER BY mean_exec_time DESC
            LIMIT 20
            """;
        
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            
            List<SlowQueryInfo> slowQueries = new ArrayList<>();
            
            while (rs.next()) {
                SlowQueryInfo query = SlowQueryInfo.builder()
                    .query(rs.getString("query"))
                    .calls(rs.getLong("calls"))
                    .totalTime(rs.getDouble("total_exec_time"))
                    .avgTime(rs.getDouble("mean_exec_time"))
                    .maxTime(rs.getDouble("max_exec_time"))
                    .stddev(rs.getDouble("stddev_exec_time"))
                    .build();
                
                slowQueries.add(query);
            }
            
            return slowQueries;
            
        } catch (SQLException e) {
            log.error("Failed to retrieve slow queries", e);
            return Collections.emptyList();
        }
    }
    
    public List<BlockedQuery> findBlockedQueries() {
        // Find queries blocked by locks
        String sql = """
            SELECT
                blocked_locks.pid AS blocked_pid,
                blocked_activity.usename AS blocked_user,
                blocking_locks.pid AS blocking_pid,
                blocking_activity.usename AS blocking_user,
                blocked_activity.query AS blocked_statement,
                blocking_activity.query AS blocking_statement,
                blocked_activity.application_name
            FROM pg_catalog.pg_locks blocked_locks
            JOIN pg_catalog.pg_stat_activity blocked_activity 
                ON blocked_activity.pid = blocked_locks.pid
            JOIN pg_catalog.pg_locks blocking_locks 
                ON blocking_locks.locktype = blocked_locks.locktype
            JOIN pg_catalog.pg_stat_activity blocking_activity 
                ON blocking_activity.pid = blocking_locks.pid
            WHERE NOT blocked_locks.granted;
            """;
        
        try (Connection conn = dataSource.getConnection();
             PreparedStatement ps = conn.prepareStatement(sql);
             ResultSet rs = ps.executeQuery()) {
            
            List<BlockedQuery> blockedQueries = new ArrayList<>();
            
            while (rs.next()) {
                BlockedQuery query = BlockedQuery.builder()
                    .blockedPid(rs.getInt("blocked_pid"))
```

### Q2: "What's the impact of setting minimum-idle equal to maximum-pool-size?"

**Answer**: Setting `minimum-idle = maximum-pool-size` eliminates dynamic scaling, wastes resources during low traffic, increases startup time, and removes HikariCP's automatic optimization benefits. It should only be used for predictable, constant load scenarios.

**Impact Analysis**

```yaml

      minimum-idle: 5  # 25% of max

# Configuration 2: Fixed pool (NOT RECOMMENDED)
spring:
  datasource:
    hikari:
      maximum-pool-size: 20
      minimum-idle: 20  # Same as max
```

```java
                            HttpServletResponse response,

        String host = request.getServerName();
        if (host.contains(".")) {
            return host.substring(0, host.indexOf("."));
        }
        
        // Option 3: Path
        String path = request.getRequestURI();
        if (path.startsWith("/tenant/")) {
            return path.split("/")[2];
        }
        
        return null;
    }
```

```java
@Component
public class TenantConnectionThrottler {
    
    private final Map<String, Semaphore> tenantLimits = new ConcurrentHashMap<>();
    
    // Limit each tenant to maximum 5 concurrent connections
    private static final int MAX_CONNECTIONS_PER_TENANT = 5;
    
    public Connection acquireConnectionForTenant(DataSource dataSource, 
                                                 String tenantId) 
            throws SQLException, InterruptedException {
        
        Semaphore limit = tenantLimits.computeIfAbsent(tenantId, 
            id -> new Semaphore(MAX_CONNECTIONS_PER_TENANT));
        
        // Block if tenant already has MAX_CONNECTIONS_PER_TENANT active
        limit.acquire();
        
        try {
            return dataSource.getConnection();
        } catch (SQLException e) {
            limit.release();
            throw e;
        }
    }
    
    public void releaseConnection(Connection connection, String tenantId) 
            throws SQLException {
        try {
            connection.close();
        } finally {
            Semaphore limit = tenantLimits.get(tenantId);
            if (limit != null) {
                limit.release();
            }
        }
    }
}
```

```java
            .incrementAndGet();
    }
    
    public void recordConnectionRelease(String tenantId) {
        AtomicInteger counter = tenantActiveConnections.get(tenantId);
        if (counter != null) {
            counter.decrementAndGet();
        }
    }
    
    @Scheduled(fixedDelay = 60000)
    public void reportMetrics() {
        tenantActiveConnections.forEach((tenantId, activeCount) -> {
            log.info("Tenant {} active connections: {}", tenantId, activeCount.get());
            
            // Export to monitoring system
            meterRegistry.gauge("tenant.connections.active", 
                Tags.of("tenant", tenantId), 
                activeCount.get());
        });
    }
    
    public Map<String, Integer> getTopConsumers(int limit) {
        return tenantActiveConnections.entrySet().stream()
            .sorted((e1, e2) -> Integer.compare(
                e2.getValue().get(), 
                e1.getValue().get()
            ))
            .limit(limit)
            .collect(Collectors.toMap(
                Map.Entry::getKey,
                e -> e.getValue().get()
            ));
    }
}
```

### Q4: "Explain the difference between idle-timeout and max-lifetime."

**Answer**: `idle-timeout` removes connections that sit unused, while `max-lifetime` closes connections after a total age regardless of usage. Both prevent stale connections but serve different purposes: idle-timeout conserves resources, max-lifetime prevents connection corruption and respects database timeouts.

**idle-timeout: Removes Unused Connections**

```yaml
spring:
  datasource:
    hikari:
      idle-timeout: 600000  # 10 minutes (default)
      # Connections that sit idle for 10+ minutes are removed
```

```java
// How idle-timeout works:

public class IdleTimeoutExplained {
    
    public void explainIdleTimeout() {
        // Timeline for a connection:
        
        // T=0: Connection created
        // T=1min: Used for query
        // T=2min: Returned to pool (starts idle timer)
        // T=12min: Still idle (exceeded 10-minute idle-timeout)
        // → Connection closed and removed from pool
        
        // Timeline for an active connection:
        // T=0: Connection created
        // T=5min: Used for query
        // T=6min: Returned to pool (starts idle timer)
        // T=10min: Used again for query (idle timer resets)
        // T=11min: Returned to pool (starts new idle timer)
        // T=21min: Still idle (exceeded 10-minute idle-timeout)
        // → Connection closed and removed from pool
        
        // Key point: Timer only counts idle time, not total time
    }
}
```

**max-lifetime: Closes Old Connections**

```yaml
spring:
  datasource:
    hikari:
      max-lifetime: 1800000  # 30 minutes (default)
      # Connections older than 30 minutes are closed (even if actively used)
```

```java
// How max-lifetime works:

public class MaxLifetimeExplained {
    
    public void explainMaxLifetime() {
        // Timeline for a connection:
        
        // T=0: Connection created (max-lifetime timer starts)
        // T=5min: Used for query
        // T=10min: Used for query
        // T=15min: Used for query
        // T=30min: Connection reaches max-lifetime
        // → Connection marked for closing
        // → Next time it's returned to pool, it's closed
        
        // Key point: Timer counts total time since creation,
        //           regardless of usage pattern
    }
}
```

**Application-Level Alerting**

```java
@Component
public class ApplicationLevelAlerting {
    
    @Autowired
    private HikariDataSource dataSource;
    
    @Autowired
    private AlertingService alertingService;
    
    @Scheduled(fixedDelay = 30000) // Every 30 seconds
    public void checkPoolHealth() {
        HikariPoolMXBean pool = dataSource.getHikariPoolMXBean();
        
        PoolHealthCheck health = performHealthCheck(pool);
        
        if (health.isCritical()) {
            alertingService.sendCriticalAlert(
                "HikariCP Pool Health Critical",
                health.getMessage(),
                health.getDetails()
            );
        } else if (health.isWarning()) {
            alertingService.sendWarningAlert(
                "HikariCP Pool Health Warning",
                health.getMessage(),
                health.getDetails()
            );
        }
    }
    
    private PoolHealthCheck performHealthCheck(HikariPoolMXBean pool) {
        PoolHealthCheck health = new PoolHealthCheck();
        
        int total = pool.getTotalConnections();
        int active = pool.getActiveConnections();
        int idle = pool.getIdleConnections();
        int waiting = pool.getThreadsAwaitingConnection();
        
        double utilization = total == 0 ? 0 : (double) active / total * 100;
        
        // Check 1: Pool exhaustion
        if (utilization > 95) {
            health.setCritical(true);
            health.setMessage("Pool exhaustion: " + String.format("%.1f", utilization) + "% utilized");
            health.addDetail("Active: " + active + ", Total: " + total);
        } else if (utilization > 80) {
            health.setWarning(true);
            health.setMessage("High pool utilization: " + String.format("%.1f", utilization) + "%");
        }
        
        // Check 2: Threads waiting
        if (waiting > 0) {
            health.setCritical(true);
            health.setMessage(waiting + " threads waiting for connections");
            health.addDetail("Immediate action required");
        }
        
        // Check 3: No idle connections
        if (idle == 0 && total > 5) {
            health.setWarning(true);
            health.setMessage("No idle connections available");
            health.addDetail("No buffer for traffic spikes");
        }
        
        return health;
    }
}

    private boolean warning = false;
    private String message;
    private List<String> details = new ArrayList<>();
    
    public void addDetail(String detail) {
        details.add(detail);
    }
```

### Q7: "How do read replicas affect connection pool configuration?"

**Answer**: Read replicas require separate connection pools with different configurations: read replica pools can be larger (less critical), use longer timeouts, and should be load-balanced. Primary pool stays smaller with stricter limits to protect write performance.

```java
// Routing data source based on transaction type
public class ReadWriteRoutingDataSource extends AbstractRoutingDataSource {
    
    private final DataSource primaryDataSource;
    private final DataSource replicaDataSource;
    
    public ReadWriteRoutingDataSource(DataSource primary, DataSource replica) {
        this.primaryDataSource = primary;
        this.replicaDataSource = replica;
        
        Map<Object, Object> targetDataSources = new HashMap<>();
        targetDataSources.put("primary", primary);
        targetDataSources.put("replica", replica);
        
        setTargetDataSources(targetDataSources);
        setDefaultTargetDataSource(primary);
    }
    
    @Override
    protected Object determineCurrentLookupKey() {
        // Use replica for read-only transactions
        if (TransactionSynchronizationManager.isCurrentTransactionReadOnly()) {
            return "replica";
        }
        return "primary";
    }
}

@Target({ElementType.METHOD, ElementType.TYPE})
@Retention(RetentionPolicy.RUNTIME)
public @interface ReadOnly {
}

@Aspect
@Component
public class ReadOnlyRoutingAspect {
    
    @Around("@annotation(readOnly)")
    public Object route(ProceedingJoinPoint joinPoint, ReadOnly readOnly) throws Throwable {
        // Force transaction to be read-only
        TransactionSynchronizationManager.setCurrentTransactionReadOnly(true);
        try {
            return joinPoint.proceed();
        } finally {
            TransactionSynchronizationManager.setCurrentTransactionReadOnly(false);
        }
    }
```

```java
    public DataSource primaryDataSource() {

        config.setPoolName("HikariPool-Primary");
        return new HikariDataSource(config);
    }
    
    @Bean
    public List<DataSource> replicaDataSources() {
        List<DataSource> replicas = new ArrayList<>();
        
        String[] replicaUrls = {
            "jdbc:postgresql://replica1.db.com:5432/mydb",
            "jdbc:postgresql://replica2.db.com:5432/mydb",
            "jdbc:postgresql://replica3.db.com:5432/mydb"
        };
        
        for (int i = 0; i < replicaUrls.length; i++) {
            HikariConfig config = new HikariConfig();
            config.setJdbcUrl(replicaUrls[i]);
            config.setMaximumPoolSize(15);
            config.setReadOnly(true);
            config.setPoolName("HikariPool-Replica-" + (i + 1));
            replicas.add(new HikariDataSource(config));
        }
        
        return replicas;
    }
    
    @Bean
    @Primary
    public DataSource routingDataSource(
            DataSource primaryDataSource,
            List<DataSource> replicaDataSources) {
        
        return new LoadBalancedRoutingDataSource(primaryDataSource, replicaDataSources);
    }
}

public class LoadBalancedRoutingDataSource extends AbstractRoutingDataSource {
    
    private final DataSource primaryDataSource;
    private final List<DataSource> replicaDataSources;
    private final AtomicInteger counter = new AtomicInteger(0);
    
    public LoadBalancedRoutingDataSource(
            DataSource primary, 
            List<DataSource> replicas) {
        
        this.primaryDataSource = primary;
        this.replicaDataSources = replicas;
        
        Map<Object, Object> targetDataSources = new HashMap<>();
        targetDataSources.put("primary", primary);
        
        for (int i = 0; i < replicas.size(); i++) {
            targetDataSources.put("replica-" + i, replicas.get(i));
        }
        
        setTargetDataSources(targetDataSources);
        setDefaultTargetDataSource(primary);
    }
    
    @Override
    protected Object determineCurrentLookupKey() {
        if (TransactionSynchronizationManager.isCurrentTransactionReadOnly()) {
            // Round-robin load balancing across replicas
            int index = Math.abs(counter.getAndIncrement() % replicaDataSources.size());
            return "replica-" + index;
        }
        return "primary";
    }
}
```

```java
public class ReplicaHealthChecker {
    
    @Autowired

    private final Set<Integer> unhealthyReplicas = ConcurrentHashMap.newKeySet();
    
    @Scheduled(fixedDelay = 30000) // Every 30 seconds

                unhealthyReplicas.remove(i);
                log.debug("Replica {} is healthy", i);
            } else {
                unhealthyReplicas.add(i);
                log.warn("Replica {} is unhealthy", i);
            }
        }
    }
    
    private boolean isHealthy(DataSource dataSource) {
        try (Connection conn = dataSource.getConnection()) {
            return conn.isValid(5); // 5 second timeout
        } catch (SQLException e) {
            return false;
        }
    }
    
    public boolean isReplicaHealthy(int replicaIndex) {
        return !unhealthyReplicas.contains(replicaIndex);
    }
    
    public List<Integer> getHealthyReplicaIndices() {
        List<Integer> healthy = new ArrayList<>();
        for (int i = 0; i < replicaDataSources.size(); i++) {
            if (!unhealthyReplicas.contains(i)) {
                healthy.add(i);
            }
        }
        return healthy;
    }

    private ReplicaHealthChecker healthChecker;
    
    private final AtomicInteger counter = new AtomicInteger(0);
    
    @Override
    protected Object determineCurrentLookupKey() {
        if (TransactionSynchronizationManager.isCurrentTransactionReadOnly()) {
            List<Integer> healthyReplicas = healthChecker.getHealthyReplicaIndices();
            
            if (healthyReplicas.isEmpty()) {
                log.warn("No healthy replicas, routing to primary");
                return "primary";
            }
            
            // Load balance across healthy replicas only
            int index = Math.abs(counter.getAndIncrement() % healthyReplicas.size());
            return "replica-" + healthyReplicas.get(index);
        }
        return "primary";
    }
}
```

### Q8: "Explain how HikariCP's ConcurrentBag improves performance over traditional pools."

**Answer**: HikariCP's ConcurrentBag uses ThreadLocal storage and CAS operations to provide lock-free connection borrowing for the common case, eliminating synchronized blocks and reducing contention. Traditional pools use global locks causing thread blocking.

**Traditional Connection Pool (With Locks)**

```java
// Traditional pool implementation (simplified)
public class TraditionalConnectionPool {
    
    private final Queue<Connection> availableConnections = new LinkedList<>();
    private final Set<Connection> activeConnections = new HashSet<>();
    private final Object lock = new Object();  // Global lock
    
    public Connection getConnection() throws SQLException {
        synchronized (lock) {  // Thread blocks here if another thread holds lock
            // Wait if no connections available
            while (availableConnections.isEmpty()) {
                if (activeConnections.size() >= maxPoolSize) {
                    try {
                        lock.wait(connectionTimeout);  // Block and wait
                    } catch (InterruptedException e) {
                        throw new SQLException("Interrupted while waiting");
                    }
                }
                
                // Check again after waking up
                if (availableConnections.isEmpty()) {
                    throw new SQLException("Connection timeout");
                }
            }
            
            // Get connection
            Connection conn = availableConnections.poll();
            activeConnections.add(conn);
            return conn;
        }
    }
    
    public void returnConnection(Connection conn) {
        synchronized (lock) {  // Thread blocks here
            activeConnections.remove(conn);
            availableConnections.offer(conn);
            lock.notify();  // Wake up one waiting thread
        }
    }
    
    // Problems:
    // 1. Global lock causes thread contention
    // 2. All threads compete for same lock
    // 3. Thread blocking (wait/notify)
    // 4. Context switching overhead
    // 5. Scalability bottleneck
}
```

**HikariCP's ConcurrentBag (Lock-Free)**

```java
// HikariCP's ConcurrentBag implementation (simplified)
public class ConcurrentBag<T> {
    
    // ThreadLocal storage for thread-local connections
    private final ThreadLocal<List<Object>> threadList = 
        ThreadLocal.withInitial(ArrayList::new);
    
    // Shared bag of connections
    private final CopyOnWriteArrayList<T> sharedList = new CopyOnWriteArrayList<>();
    
    // State tracking (CAS operations)
    private final AtomicInteger waiters = new AtomicInteger(0);
    
    public T borrow(long timeout, TimeUnit timeUnit) throws InterruptedException {
        // FAST PATH: Check ThreadLocal first (no locking!)
        final List<Object> list = threadList.get();
        
        for (int i = list.size() - 1; i >= 0; i--) {
            final Object entry = list.remove(i);
            final T bagEntry = (T) entry;
            
            // Try to claim with CAS (lock-free)
            if (casState(bagEntry, STATE_NOT_IN_USE, STATE_IN_USE)) {
                return bagEntry;  // Got it! No locks needed
            }
        }
        
        // SLOW PATH: ThreadLocal miss, check shared list
        waiters.incrementAndGet();  // CAS operation
        
        try {
            for (T bagEntry : sharedList) {
                // Try to claim with CAS
                if (casState(bagEntry, STATE_NOT_IN_USE, STATE_IN_USE)) {
                    // Add to ThreadLocal for next time
                    list.add(bagEntry);
                    return bagEntry;  // Got it! Still no locks
                }
            }
            
            // No available connections, wait
            // This is the only place we might block
            return waitForConnection(timeout, timeUnit);
            
        } finally {
            waiters.decrementAndGet();
        }
    }
    
    public void requite(T bagEntry) {
        // Mark as available with CAS (lock-free)
        casState(bagEntry, STATE_IN_USE, STATE_NOT_IN_USE);
        
        // If threads waiting, wake them up
        if (waiters.get() > 0) {
            notifyWaiters();  // Uses synchronization only when needed
        }
    }
    
    // CAS operation (Compare-And-Swap, lock-free)
    private boolean casState(T entry, int expect, int update) {
        // Atomic CPU operation, no locks
        return STATE_UPDATER.compareAndSet(entry, expect, update);
    }
}
```
